> **핵심 메시지:** AI 시대의 웹 개발자는 기능을 구현하는 데서 멈추지 않고, CS 기본기로 결과를 검증하며 문제를 발견한 이유와 해결 과정을 자신의 언어로 설명할 수 있어야 한다.

## 1. 강의 개요

9번째 산업체 특강은 Bear Robotics에서 Software Engineer로 일하고 계신 이강호 연사님의 「웹 개발자를 위한 실무 역량과 웹서비스 현황」 강의였다. 강의는 웹 개발자가 실제로 맡는 역할, AI 도구가 개발 방식에 가져온 변화, 신입 개발자에게 요구되는 기본 역량, 그리고 면접과 포트폴리오에서 자신의 경험을 어떤 방식으로 전달해야 하는지를 중심으로 진행되었다.

가장 기억에 남은 부분은 웹 개발을 프론트엔드와 백엔드라는 단순한 구분으로만 설명하지 않았다는 점이다. 연사님은 현장에서 개발자의 업무 범위가 점점 넓어지고 있다는 점을 강조했다. 예전에는 프론트엔드, 백엔드, 모바일, 인프라가 비교적 분리된 영역처럼 인식되었지만, 현재는 한 명의 개발자가 기능의 흐름을 전체적으로 이해하고 구현해야 하는 경우가 많아졌다. 특히 AI 도구가 빠르게 발전하면서 개발자는 코드를 많이 작성하는 사람을 넘어, 문제를 정의하고 결과를 설계하며 AI가 만든 산출물을 검토하는 사람에 가까워지고 있다는 설명이 인상 깊었다.

## 2. 강의 핵심 내용 정리

웹 개발자는 보통 사용자가 직접 마주하는 화면을 구현하는 프론트엔드 개발자와, 데이터를 저장하고 처리해 전달하는 백엔드 개발자로 나뉜다. 프론트엔드 영역에서는 HTML, CSS, JavaScript, React, Vue, Next.js 등을 활용해 UI 컴포넌트, API 호출, 반응형 화면, 로딩 및 에러 상태를 다룬다. 백엔드 영역에서는 Node.js, Spring, Django 같은 기술을 사용해 API, 데이터베이스, 인증, 권한, 결제, 배포, 로깅, 모니터링 등을 담당한다.

하지만 강의에서는 이러한 경계가 점차 희미해지고 있다고 설명했다. AI가 익숙하지 않은 영역의 초안을 만들어 주고, 개발자가 이를 이해하고 조정하는 방식이 늘어나면서 화면, API, 배포 흐름까지 함께 파악해야 할 필요가 커지고 있다. 따라서 앞으로의 개발자는 특정 영역만 분리해서 잘하는 사람보다, 서비스가 처음부터 끝까지 어떻게 작동하는지 읽을 수 있는 사람이 되어야 한다.

AI를 대하는 태도 역시 중요한 주제였다. Claude Code, Codex CLI, Cursor, Devin과 같은 AI 기반 개발 도구가 등장하면서 개발 환경은 이미 빠르게 변하고 있다. 그러나 AI가 코드를 생성해 준다고 해서 개발 공부의 깊이가 덜 중요해지는 것은 아니다. 오히려 기초를 알고 사용하는 사람과 그렇지 않은 사람의 차이가 더 뚜렷해진다. 알고 쓰는 사람은 AI의 결과를 빠르게 검토하고 테스트로 확인할 수 있지만, 모르고 쓰는 사람은 문제가 생겨도 원인을 설명하지 못하고 비슷한 오류를 반복할 수 있다.

이 때문에 강의에서는 신입 개발자에게 CS 기초가 다시 중요해졌다고 강조했다. 자료구조와 알고리즘은 데이터를 어떤 방식으로 다룰지 판단하는 기준이 되고, 데이터베이스 지식은 인덱스, 트랜잭션, 쿼리 성능을 이해하는 데 필요하다. 운영체제는 프로세스, 스레드, 메모리, 입출력, 비동기 처리의 바탕이 되며, 네트워크는 HTTP, TCP, DNS, CDN처럼 웹 서비스의 성능과 안정성에 직접 연결된다. 결국 장애나 성능 문제가 발생했을 때 돌아가야 하는 기반은 CS 기본기라는 점을 배웠다.

## 3. 나만의 이야기: 왜 개발자를 목표로 하는가

강의에서 언급된 “나만의 이야기”는 단순한 개인 감상을 길게 쓰라는 의미가 아니었다. 개발자를 목표로 하는 이유와 문제를 해결해 온 과정을 자신의 언어로 설명할 수 있어야 한다는 뜻에 가까웠다. 기술 스택은 여러 지원자가 비슷하게 나열할 수 있지만, 왜 개발을 선택했는지, 어떤 문제를 중요하게 보았는지, 그 문제를 해결하기 위해 어떤 판단을 했는지는 각자 다르게 드러난다.

연사님은 면접관 역시 결국 사람이라는 점을 이야기했다. 따라서 “React를 사용했다”, “Spring으로 API를 만들었다”처럼 도구만 나열하는 설명은 설득력이 약하다. 그보다 “어떤 문제를 발견했고, 왜 이 기술을 선택했으며, 결과적으로 어떤 변화가 생겼는가”라는 흐름으로 말하는 편이 훨씬 분명하다. 개발자를 목표로 한다는 것은 코드를 작성하는 능력뿐 아니라, 문제를 인식하고 해결 과정을 설명할 수 있는 태도를 갖추는 일과 연결된다.

## 4. 기존 CS 지식과 AI 활용 능력의 균형

이번 강의에서 가장 크게 남은 메시지는 CS 지식과 AI 활용 능력이 서로 대체 관계가 아니라는 점이다. AI를 제대로 활용하려면 오히려 기존 지식이 더 필요하다. 예를 들어 AI가 코드를 생성했을 때 자료구조와 알고리즘을 모르면 시간 복잡도나 자료 선택이 적절한지 판단하기 어렵다. DB 지식이 부족하면 쿼리 한 줄이 왜 느린지 파악하기 어렵고, OS와 네트워크 지식이 약하면 비동기 처리나 API 지연의 원인을 좁히기 힘들다.

따라서 AI 시대의 개발자는 AI에게 일을 전부 맡기는 사람이 아니라, AI를 동료 도구처럼 활용하면서 최종 판단을 책임지는 사람이어야 한다. AI는 빠르게 초안을 만들 수 있지만, 그 코드가 요구사항을 충족하는지, 보안과 성능에 문제가 없는지, 실제 사용자의 상황을 반영하는지는 개발자가 검증해야 한다.

## 5. 문제 해결 경험과 문제 인식

강의에서는 연사님이 인턴 시절 부동산 매물 사진을 수동으로 보정하던 업무를 발견하고, OpenCV를 활용해 자동 보정 파이프라인을 만든 사례가 소개되었다. 이 이야기에서 핵심은 사용한 기술보다 문제를 바라보는 관점이었다. 누군가에게는 반복 업무로만 보였던 일이 개발자에게는 자동화할 수 있는 문제로 보였고, 그 해결책이 실제 업무 흐름 안에 적용되었다는 점이 인상적이었다.

이 사례는 포트폴리오나 면접에서 어떤 경험을 강조해야 하는지도 보여준다. 중요한 것은 프로젝트의 규모가 크거나 사용한 기술이 화려한지가 아니다. 실제 사용자가 겪는 불편함을 발견했는지, 그 불편함을 해결 가능한 문제로 정리했는지, 그리고 만든 해결책이 업무나 서비스 흐름 안에서 의미 있게 작동했는지가 더 중요하다.

강의에서 말한 “내가 해결한 문제”는 완성된 결과물만을 의미하지 않는다. 문제를 어떻게 발견했는지, 왜 해결할 가치가 있다고 보았는지, 어떤 제약이 있었는지, 선택 과정에서 무엇을 고려했는지까지 포함한다. 결국 좋은 개발 경험은 “무엇을 만들었는가”보다 “왜 만들었고 어떤 문제를 해결했는가”로 설명될 때 더 강하게 전달된다.

## 6. 커뮤니케이션 능력과 도메인 지식

강의에서 또 중요하게 느낀 부분은 면접도, 협업도 결국 사람과 사람 사이에서 이루어진다는 점이다. 개발자는 혼자 코드를 쓰는 직업처럼 보일 수 있지만, 실제 업무에서는 문제를 듣고 요구사항을 정리하며 해결 방향을 설명하고 팀원과 조율하는 시간이 많다. 그래서 커뮤니케이션 능력은 부가적인 장점이 아니라 실무 역량의 중요한 축이다.

도메인 지식의 필요성도 함께 느낄 수 있었다. Bear Robotics처럼 자율주행 서빙 로봇의 웹 플랫폼을 만드는 회사라면 웹 기술만 알고 있는 것으로는 충분하지 않다. 식당이라는 실제 공간, 직원과 손님의 동선, 로봇의 상태, 주문과 서빙 흐름, 장애 상황까지 이해해야 더 적절한 서비스를 설계할 수 있다. 어떤 산업의 문제를 해결하느냐에 따라 같은 기술도 전혀 다르게 쓰이기 때문에, 개발자는 기술 지식과 함께 도메인 지식도 꾸준히 쌓아야 한다.

## 7. 마지막 핵심 정리 및 앞으로의 방향

이번 강의는 웹 개발자가 되기 위해 무엇을 준비해야 하는지 현실적으로 정리해 준 시간이었다. 신입 채용 시장이 어려워지고, AI가 주니어 개발자의 일부 업무를 대신할 수 있다는 변화 속에서 단순히 기술 스택을 많이 적는 것만으로는 충분하지 않다는 점을 알 수 있었다. 결국 중요한 것은 기본기를 갖추고, AI를 올바르게 활용하며, 자신이 발견한 문제와 해결 과정을 설득력 있게 설명하는 능력이다.

앞으로 웹 개발을 준비하는 과정에서는 자료구조, 알고리즘, 데이터베이스, 운영체제, 네트워크 같은 CS 기초를 계속 학습해야 한다. 프로젝트를 진행할 때도 기능 구현에서 끝내지 않고, 사용자가 어떤 어려움을 겪는지, 그 문제가 왜 발생하는지, 선택한 해결 방식이 어떤 근거를 갖는지까지 정리할 필요가 있다. AI 도구는 적극적으로 활용하되, 그 결과를 그대로 받아들이기보다 테스트하고 설명할 수 있는 역량을 함께 키워야 한다.

결국 이번 강의의 핵심은 “본인의 이야기”라고 정리할 수 있다. 많은 지원자가 비슷한 기술 키워드를 적을 수 있지만, 왜 개발자를 지향하는지, 어떤 문제를 발견했고 어떻게 해결했는지는 각자의 경험과 관점에서 나온다. 개발자를 준비하는 과정에서는 기술을 배우는 것과 동시에, 문제를 인식하고 해결한 과정을 자신의 언어로 설명할 수 있는 이야기를 쌓아 가는 것이 중요하다.
