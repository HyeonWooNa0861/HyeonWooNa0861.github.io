## 1. 강의 개요

9번째 산업체 특강은 Bear Robotics의 Software Engineer인 이강호 연사님의 「웹 개발자를 위한 실무 역량과 웹서비스 현황」 강의였다. 강의는 웹 개발자의 역할, AI 시대의 개발 방식 변화, 신입 개발자에게 요구되는 역량, 그리고 면접과 포트폴리오에서 자신의 경험을 어떻게 설명해야 하는지를 중심으로 진행되었다.

강의에서 가장 인상 깊었던 점은 웹 개발을 단순히 프론트엔드와 백엔드로 나누어 설명하는 데서 끝나지 않고, 실제 현장에서 개발자의 일이 어떻게 바뀌고 있는지를 보여주었다는 점이다. 과거에는 프론트엔드, 백엔드, 모바일, 인프라가 비교적 분리된 영역처럼 여겨졌지만, 지금은 한 사람이 기능의 흐름을 처음부터 끝까지 이해하고 구현해야 하는 상황이 많아지고 있다. 특히 AI 도구가 발전하면서 개발자는 코드를 직접 많이 작성하는 사람이라기보다, 문제를 정의하고 결과를 설계하며 AI가 만든 결과를 검토하는 사람에 가까워지고 있다는 설명이 기억에 남았다.

## 2. 강의 핵심 내용 정리

웹 개발자는 크게 사용자가 보는 화면을 만드는 프론트엔드 개발자와, 데이터를 저장하고 처리하며 전달하는 백엔드 개발자로 나눌 수 있다. 프론트엔드는 HTML, CSS, JavaScript, React, Vue, Next.js 같은 기술을 이용해 UI 컴포넌트, API 호출, 반응형 화면, 로딩과 에러 상태 등을 다룬다. 백엔드는 Node.js, Spring, Django 같은 기술을 이용해 API, 데이터베이스, 인증, 권한, 결제, 배포, 로깅, 모니터링을 다룬다.

하지만 강의에서는 이 구분이 점점 흐려지고 있다고 설명했다. AI가 익숙하지 않은 영역을 보조해 주기 때문에 한 명의 개발자가 화면, API, 배포 흐름까지 함께 이해해야 하는 경우가 늘고 있다. 따라서 앞으로의 개발자는 “내 영역만 잘하는 사람”보다 서비스 전체 흐름을 이해하는 사람이 되어야 한다.

또 하나의 중요한 내용은 AI를 사용하는 태도였다. Claude Code, Codex CLI, Cursor, Devin 같은 AI 기반 개발 도구가 등장하면서 개발 현장은 이미 빠르게 바뀌고 있다. 그러나 AI가 코드를 대신 작성해 준다고 해서 개발 공부의 깊이가 덜 중요해지는 것은 아니다. 오히려 알고 쓰는 사람과 모르고 쓰는 사람의 차이가 더 커진다. 알고 쓰는 사람은 AI의 결과를 빠르게 검토하고 테스트로 증명할 수 있지만, 모르고 쓰는 사람은 오류가 나도 원인을 설명하지 못하고 같은 문제를 반복하게 된다.

그래서 강의에서는 신입 개발자에게 다시 CS 기초가 중요하다고 강조했다. 자료구조와 알고리즘은 어떤 데이터를 어떤 방식으로 다룰지 판단하게 해 주고, 데이터베이스는 인덱스, 트랜잭션, 쿼리 성능을 이해하게 해 준다. 운영체제는 프로세스, 스레드, 메모리, 입출력, 비동기 처리의 기반이 되고, 네트워크는 HTTP, TCP, DNS, CDN처럼 웹 서비스 성능과 안정성에 직접 연결되는 지식을 제공한다. 결국 장애가 발생하거나 성능 문제가 생기면 돌아가야 하는 곳은 CS 기본기라는 점을 배웠다.

## 3. 나만의 이야기: 왜 개발자를 목표로 하는가

강의에서 말한 “나만의 이야기”는 단순히 개인적인 감상을 길게 쓰라는 의미가 아니라, 개발자를 목표로 하는 이유와 문제를 해결해 온 과정을 본인의 언어로 설명할 수 있어야 한다는 뜻으로 이해할 수 있다. 기술 스택은 많은 지원자가 비슷하게 적을 수 있지만, 왜 개발을 선택했는지, 어떤 문제를 중요하게 보았는지, 그 문제를 해결하기 위해 어떤 판단을 했는지는 사람마다 다르다.

강의에서는 면접관도 결국 사람이라는 점을 강조했다. 따라서 단순히 “React를 사용했다”, “Spring으로 API를 만들었다”처럼 도구를 나열하는 것보다, “이런 문제를 발견했고, 이런 이유로 이 기술을 선택했으며, 결과적으로 이런 변화를 만들었다”는 구조로 말하는 것이 더 설득력 있다. 개발자를 목표로 한다는 것은 코드를 작성하는 능력만이 아니라, 문제를 인식하고 해결 과정을 설명할 수 있는 태도를 갖추는 것과 연결된다.

## 4. 기존 CS 지식과 AI 활용 능력의 균형

이번 강의에서 가장 크게 얻은 메시지는 “CS 지식과 AI 활용 능력은 둘 중 하나를 선택하는 관계가 아니다”라는 점이다. AI를 잘 활용하려면 오히려 기존 지식이 더 필요하다. 예를 들어 AI가 어떤 코드를 생성했을 때, 자료구조와 알고리즘을 모르면 시간 복잡도나 자료 선택이 적절한지 판단하기 어렵다. DB 지식이 부족하면 쿼리 한 줄이 왜 느린지 알 수 없고, OS와 네트워크 지식이 부족하면 비동기 처리나 API 지연의 원인을 파악하기 어렵다.

따라서 AI 시대의 개발자는 AI에게 일을 맡기는 사람이 아니라, AI를 동료 도구처럼 사용하면서 최종 판단을 책임지는 사람이어야 한다. AI가 빠르게 초안을 만들 수는 있지만, 그 코드가 서비스의 요구사항에 맞는지, 보안과 성능에 문제가 없는지, 사용자의 실제 상황을 반영하는지는 개발자가 검증해야 한다.

## 5. 문제 해결 경험과 문제 인식

강의에서 강사님은 인턴 시절 부동산 매물 사진을 수동으로 보정하던 문제를 발견하고, OpenCV를 활용해 자동 보정 파이프라인을 만든 경험을 소개했다. 이 사례에서 중요한 것은 기술 자체보다 문제 인식이었다. 누군가에게는 단순 반복 업무였던 일이 개발자에게는 자동화할 수 있는 문제로 보였고, 그 문제를 실제 업무 흐름 안에 녹여냈다는 점이 인상적이었다.

이 사례는 포트폴리오나 면접에서 어떤 경험을 말해야 하는지에 대한 기준도 보여준다. 중요한 것은 프로젝트의 규모가 크거나 사용한 기술이 화려한지가 아니라, 실제 사용자의 불편함을 발견했는지, 그 불편함을 해결 가능한 문제로 바꾸었는지, 그리고 해결책을 실제 업무나 서비스 흐름에 적용했는지이다.

강의에서 말한 “내가 해결한 문제”는 단순한 결과물이 아니라 문제를 바라본 과정까지 포함한다. 문제를 어떻게 발견했는지, 왜 그것이 해결할 가치가 있었는지, 어떤 제약이 있었는지, 해결 과정에서 어떤 선택을 했는지를 설명할 수 있어야 한다. 결국 좋은 개발 경험은 “무엇을 만들었다”보다 “왜 만들었고, 어떤 문제를 해결했는가”로 정리될 때 더 강하게 전달된다.

## 6. 커뮤니케이션 능력과 도메인 지식

강의에서 또 중요하게 느낀 부분은 면접을 보는 것도, 현장에서 함께 일하는 것도 결국 사람이라는 점이다. 개발자는 혼자 코드를 작성하는 직업처럼 보이지만 실제로는 문제를 듣고, 요구사항을 정리하고, 해결 방향을 설명하고, 팀원과 조율하는 시간이 많다. 따라서 커뮤니케이션 능력은 부가적인 능력이 아니라 실무 역량의 핵심이다.

또한 도메인 지식의 중요성도 느꼈다. Bear Robotics처럼 자율주행 서빙 로봇의 웹 플랫폼을 만드는 회사라면, 단순히 웹 기술만 아는 것으로는 부족하다. 식당이라는 실제 환경, 직원과 손님의 동선, 로봇의 상태, 주문과 서빙 흐름, 장애 상황까지 이해해야 더 좋은 서비스를 만들 수 있다. 어떤 산업의 문제를 해결하느냐에 따라 같은 기술도 전혀 다르게 쓰이기 때문에, 개발자는 기술 지식과 함께 도메인 지식을 계속 쌓아야 한다.

## 7. 느낀 점 및 앞으로의 방향

이번 강의는 웹 개발자가 되기 위해 무엇을 준비해야 하는지 현실적으로 정리해 준 강의였다. 신입 채용 시장이 어려워지고, AI가 주니어 개발자의 일부 업무를 대체할 수 있다는 변화 속에서 단순히 기술 스택을 많이 적는 것만으로는 충분하지 않다는 점을 보여주었다. 중요한 것은 기본기를 갖추고, AI를 올바르게 활용하며, 자신이 어떤 문제를 발견하고 어떻게 해결했는지를 설명할 수 있는 능력이다.

따라서 웹 개발자를 준비하는 과정에서는 자료구조, 알고리즘, 데이터베이스, 운영체제, 네트워크 같은 CS 기초를 꾸준히 학습해야 한다. 프로젝트를 수행할 때도 기능 구현에서 멈추지 않고, 사용자가 어떤 문제를 겪는지, 그 문제가 왜 발생하는지, 선택한 해결 방식이 어떤 근거를 가지는지까지 정리해야 한다. 또한 AI 도구를 적극적으로 활용하되, 결과를 그대로 믿기보다 테스트하고 설명할 수 있는 역량이 필요하다.

결국 이번 강의의 핵심은 “본인의 이야기”라고 정리할 수 있다. 많은 지원자가 비슷한 기술 키워드를 적을 수 있지만, 왜 개발자를 목표로 하는지, 어떤 문제를 발견했고 어떻게 해결했는지는 각자의 경험과 관점에서 나온다. 개발자를 준비하는 과정에서는 기술을 배우는 것과 동시에, 문제를 인식하고 해결한 과정을 설득력 있게 설명할 수 있는 이야기를 쌓아가는 것이 중요하다.
