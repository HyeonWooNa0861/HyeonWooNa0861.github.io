PinSpot은 K-pop 아티스트와 한국 배우, 드라마·영화·뮤직비디오에 연결된 장소를 검색하고 지도에서 탐색하는 모바일 우선 PWA다. 단순히 지도 위에 관광지를 나열하는 대신, 공개 출처를 검토해 만든 장소 이야기와 주변 로컬 스팟, 도보 동선, 기기 안에서 실행되는 사진 비교를 하나의 여행 흐름으로 연결한다.

이 프로젝트의 출발점은 분명하다. 글로벌 팬이 콘텐츠 속 장면이나 아티스트 관련 장소를 실제 여행 일정으로 옮기려면 장소의 정확성, 이동 방법, 주변 정보가 함께 필요하다. 그러나 검색 결과만으로는 같은 이름의 시설이나 근거가 약한 팬 게시물을 공식 촬영지처럼 오해하기 쉽다. PinSpot은 이 문제를 **장소 발견**, **관계 검증**, **지도 탐색**의 서로 다른 단계로 나누어 다룬다.

## 1. 핵심 사용자 경험

현재 앱은 다섯 개의 하단 탭을 중심으로 구성되어 있다.

| 탭 | 역할 | 사용자가 얻는 결과 |
|---|---|---|
| 홈 | 아티스트·작품·장소 검색과 추천 탐색 | 관심 있는 K-콘텐츠 장소와 코스를 빠르게 찾는다. |
| 지도 | 검증 장소, 현재 위치, 주변 스팟, 도보 경로 확인 | 선택 장소와 이동 흐름을 한 화면에서 파악한다. |
| 카메라 | 선택한 사진을 등록된 레퍼런스와 비교 | 비슷한 장소 후보를 기기 안에서 확인한다. |
| 스토어 | 공개된 행사·티켓·굿즈 정보를 탐색 | 공식 링크를 통해 최신 정보를 다시 확인한다. |
| 프로필 | 방문 기록, 위시리스트, 후기, 언어와 테마 관리 | 계정 없이 이 브라우저에 개인 여행 상태를 남긴다. |

각 탭은 하나의 주된 작업에 집중한다. 검색 결과에서 장소를 고르면 지도 포인트와 하단 카드가 같은 장소로 갱신되고, 현재 위치는 별도의 파란 점으로 유지된다. 사용자의 위치와 선택한 장소를 섞지 않기 때문에 지도 중심을 옮기거나 다른 스팟을 선택해도 현재 위치 기록이 임의로 바뀌지 않는다.

## 2. 검색 결과보다 중요한 데이터 신뢰 경계

PinSpot에서 아티스트 목록은 조사 범위이지 장소 관계의 증명이 아니다. 지도에 장소를 표시하려면 실제 방문 가능한 장소인지, 허용된 도시 안에 있는지, 아티스트·작품과의 관계를 설명할 공개 근거가 있는지를 별도로 검토해야 한다.

서비스의 공개 결과는 두 층으로 구분된다.

| 구분 | 의미 | 표시 원칙 |
|---|---|---|
| 출처 기반 관련 장소 | 공개 근거와 장소 정체성을 검토한 관계 | 구체적인 활동 유형과 정리된 장소 이야기를 제공한다. |
| 큐레이션 추천 | 팬 페이지·블로그·편집 자료에서 찾은 방문 아이디어 | 검증된 방문·촬영 관계로 승격하지 않고 추천임을 표시한다. |

Nominatim 지명 검색은 지도를 해당 지역으로 이동하는 용도다. 외부 검색 결과가 곧바로 K-콘텐츠 장소 카드가 되지는 않는다. 같은 이름의 식당이나 시설이 검색됐다는 이유만으로 아티스트 관련 장소로 노출하지 않는 구조다.

내부 데이터에는 출처와 검토 상태를 남기지만, 브라우저로 보내는 공개 응답은 별도의 계약을 거친다. 사용자는 읽기 쉬운 장소 이야기와 표시용 정보만 받으며, 내부 evidence ID나 조사 상태, 검색용 태그 같은 운영 데이터는 공개 API 응답에서 제외된다.

## 3. 키 없이 구성한 지도와 도보 탐색

지도는 MapLibre GL JS와 OpenFreeMap 스타일을 사용한다. 장소명 검색은 Nominatim, 주변 카페·식당·숍 탐색은 Overpass API, 도보 경로는 OSRM 계열 공개 라우팅을 이용한다. 모두 사용자가 검색이나 주변 필터, 경로 요청을 명시적으로 실행했을 때 동작한다.

주변 장소는 현재 위치를 읽었다는 이유만으로 자동 요청하지 않는다. 사용자가 `카페·식당` 또는 `숍` 같은 필터를 선택해야 반경 검색이 시작된다. 지도를 움직이는 행동과 외부 API 호출을 분리해 불필요한 요청을 줄이고, 이전 장소의 늦은 응답이 새 선택 결과를 덮어쓰지 않도록 한다.

도보 경로는 앱 안에 선으로 표시되고 거리, 예상 시간, 회전 안내를 함께 제공한다. 이는 실시간 내비게이션을 대체하기 위한 기능이 아니라, 선택한 장소와 주변 코스를 여행 전에 이해하기 위한 보조 흐름이다.

## 4. 사진은 서버로 보내지 않는 온디바이스 후보 검색

카메라 탭은 사용자가 고른 사진을 브라우저 안에서 해석한다. 오픈소스 CLIP vision encoder와 미리 만든 레퍼런스 벡터를 필요할 때만 불러와 이미지 간 유사도를 비교하고, 최소 점수와 1·2위 후보의 차이가 충분할 때만 장소 후보를 제시한다.

중요한 개인정보 경계는 다음과 같다.

- 선택한 이미지는 PinSpot API나 외부 AI 서비스로 전송하지 않는다.
- 모델과 레퍼런스 데이터는 첫 사용 시 별도 로딩해 초기 앱 번들에서 분리한다.
- 등록되지 않은 장소나 확신이 부족한 사진에는 결과가 없을 수 있다.
- 이미지 유사도는 장소 후보일 뿐, 아티스트 방문이나 촬영 관계를 증명하지 않는다.

현재 프로토타입의 사진 레퍼런스는 일부 궁궐 장소에 한정되어 있다. 비슷한 건축물이나 촬영 각도에 따라 잘못된 후보가 나올 수 있으므로, 사진 매칭과 장소 정체성 검증, 콘텐츠 관계 검증을 서로 다른 신뢰 단계로 유지한다.

## 5. 계정 없이 유지하는 개인 여행 상태

위시리스트, 방문 기록, 최근 검색, 후기, 큐레이터 팔로우, 언어와 테마 설정은 브라우저의 `localStorage`에 저장된다. 계정을 만들거나 서버에 개인 프로필을 보낼 필요가 없다. 현재 위치도 사용자가 권한을 허용했을 때만 읽으며 서버에 영구 저장하지 않는다.

이 방식은 기기 간 동기화를 제공하지 않는 대신, 프로토타입 단계에서 인증·개인정보 저장·계정 운영의 복잡성을 만들지 않는다. 브라우저 데이터를 지우거나 다른 기기를 사용하면 개인 상태가 이어지지 않는다는 점은 명확한 한계다.

## 6. 다국어와 설치 가능한 PWA

표시 언어는 한국어, 중국어 간체, 일본어, 영어, 스페인어, 프랑스어, 힌디어, 아랍어를 지원한다. 공통 메뉴와 프로필은 선택 즉시 바뀌고 아랍어에서는 문서 방향도 RTL로 전환된다. 다만 일부 세부 탐색 화면은 같은 사전 구조로 계속 옮기는 중이므로 모든 문구의 번역 범위가 완전히 같지는 않다.

Vite PWA 구성은 웹 매니페스트와 서비스 워커를 만들고, 앱 셸과 최근 사용 리소스를 브라우저에 보존한다. 지원 브라우저에서는 홈 화면에 설치해 독립 실행형 앱처럼 사용할 수 있다. 캐시되지 않은 새 장소 검색이나 지도 영역은 여전히 네트워크 연결이 필요하므로 완전한 오프라인 지도 앱은 아니다.

## 7. 기술 구조

| 영역 | 기술 | 역할 |
|---|---|---|
| Web UI | React, TypeScript, Vite | 모바일 탭, 검색, 지도, 프로필과 PWA 화면 구성 |
| Map | MapLibre GL JS, OpenFreeMap | 키 없는 벡터 지도와 라이트·다크 스타일 |
| API | Express | 검색, 주변 장소, 도보 경로와 공개 응답 경계 |
| Local data | Versioned JSON, SQLite FTS5 | 검토된 장소 데이터 적재와 접두 검색 |
| Photo matching | Transformers.js, ONNX Runtime Web, CLIP | 브라우저 안에서 사진과 레퍼런스 벡터 비교 |
| Offline/PWA | vite-plugin-pwa, Workbox | 앱 설치, 앱 셸 precache, 최근 리소스 캐시 |

런타임 검색 과정에서는 LLM을 호출하지 않는다. AI agent와 브라우저 자동화는 공개 출처 조사, 후보 검토, 데이터 계약 검사, 모바일 UI 검증 같은 개발·큐레이션 단계에서만 사용한다. 따라서 사용자의 검색 요청이 매번 생성형 AI 비용이나 외부 모델 호출로 이어지지 않는다.

## 8. 비용과 운영 원칙

PinSpot은 API 키나 카드 등록이 필요한 유료 제공자를 기본 구성에 넣지 않는다. 이 선택은 단순히 비용을 줄이기 위한 것이 아니라, 무료 공개 서비스의 사용 정책과 rate limit을 제품 구조에 반영하기 위한 제약이다.

- 공개 지오코딩 요청은 직렬화하고 같은 요청을 캐시한다.
- 주변 장소 조회도 짧은 캐시를 사용한다.
- OpenStreetMap 기반 attribution을 지도에서 유지한다.
- 외부 서비스 응답 실패가 검증 장소 데이터 자체를 오염시키지 않게 분리한다.
- 공개 오픈데이터 서비스에는 운영 SLA가 없으므로 상용 서비스 수준의 가용성을 전제로 하지 않는다.

## 9. 현재 한계와 다음 과제

PinSpot은 동작하는 PWA이지만 모든 K-콘텐츠 장소를 자동으로 알아내는 완성형 검색 엔진은 아니다.

- 사진 매칭 레퍼런스 범위가 제한적이다.
- 전체 화면의 다국어 적용 수준에는 차이가 있다.
- 무료 공개 지도·검색·라우팅 서비스의 가용성과 사용 정책에 영향을 받는다.
- 계정과 서버 동기화가 없어 개인 기록은 현재 브라우저에만 남는다.
- 큐레이션 범위를 넓히려면 장소마다 공개 근거와 지도 정체성을 계속 검토해야 한다.

이 한계들은 무리하게 감추기보다 제품의 신뢰 경계로 드러내는 편이 낫다. 장소 후보를 많이 보여주는 것보다, 사용자가 `관련 장소`, `큐레이션 추천`, `사진 유사 후보`를 구분해 이해할 수 있게 만드는 것이 PinSpot의 핵심 방향이다.

## 10. 핵심 정리

PinSpot은 K-콘텐츠 팬의 여행을 검색 결과에서 실제 장소 탐색으로 연결하는 프로젝트다. 지도, 도보 경로, 주변 상권, 로컬 기록, 다국어 PWA, 온디바이스 사진 비교를 한 앱에 담았지만, 각 기능이 같은 수준의 증거를 뜻하지 않도록 경계를 나눈다.

핵심은 다음과 같다.

- 검증 장소와 큐레이션 추천, 사진 유사 후보를 구분한다.
- 사용자의 사진과 개인 여행 상태를 가능한 한 기기에 남긴다.
- 키 없는 오픈데이터 지도를 사용하고 외부 요청을 사용자의 명시적 행동에 연결한다.
- 런타임 LLM 없이 버전 관리 데이터와 로컬 검색으로 결과를 제공한다.
- 모바일 여행 흐름을 홈, 지도, 카메라, 스토어, 프로필로 단순화한다.
