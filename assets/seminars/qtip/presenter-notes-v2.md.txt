## 1. QTIP: Trellis와 Incoherence Processing을 이용한 LLM 양자화

1. QTIP: Trellis와 Incoherence Processing을 이용한 LLM 양자화

발표 대본
QTIP은 이미 학습된 LLM weight를 낮은 비트로 압축하는 weight-only post-training quantization 방법입니다. 발표에서는 먼저 vector quantization이 왜 고차원에서 어려운지 살펴보고, RHT, bitshift trellis, computed 또는 hybrid code가 그 문제를 어떻게 나누어 푸는지 설명합니다. 수식의 최적성, tail-biting의 근사성, 실험 throughput의 하드웨어 조건도 구분합니다.

## 3. 고차원 VQ의 병목과 TCQ의 출발점

3. 고차원 VQ의 병목과 TCQ의 출발점

발표 대본
일반 vector quantization은 d차원 vector를 2의 kd승개 codeword 가운데 하나로 고르므로 codebook과 최근접 탐색의 비용이 빠르게 커집니다. TCQ는 긴 sequence 전체를 하나의 거대한 codebook으로 만들지 않고, 허용된 state walk를 고릅니다. 다만 vanilla TCQ도 큰 state-value table과 serial decode 문제가 있으므로 QTIP은 bitshift 구조와 code 재계산을 추가합니다.

## 5. RHT 전처리: Gaussian-like source를 만드는 이유

5. RHT 전처리: Gaussian-like source를 만드는 이유

발표 대본
논문은 QuIP#의 random Hadamard transform을 사용합니다. W와 H에 random sign과 Hadamard matrix를 곱해 coordinate energy의 집중을 줄이고, transformed weight entry가 approximately independently Gaussian distributed하다는 근거를 얻습니다. 이는 확률적이고 근사적인 설명입니다. 각 layer가 정확히 독립 Gaussian이 된다는 theorem이나 실제 task quality의 보장은 아닙니다.

## 6. TCQ: codeword 하나가 아니라 허용된 state walk를 고른다

6. TCQ: codeword 하나가 아니라 허용된 state walk를 고른다

발표 대본
L, k, V trellis에는 2의 L승 state가 있고, 각 state에는 V차원 value가 연결됩니다. sequence를 V개씩 묶어 state walk로 맞추며, reconstruction은 그 walk의 state value를 이어 붙인 것입니다. 각 state의 incoming/outgoing degree는 2^(kV)입니다. V개 weight 한 group마다 edge 선택에 kV bits를 쓰므로 weight당 k bits입니다. V=1일 때만 group당 bit 수와 weight당 bit 수가 같습니다.

## 7. Viterbi가 exact인 범위: additive distortion

7. Viterbi가 exact인 범위: additive distortion

발표 대본
논문은 additive squared-error metric에서 Viterbi dynamic programming이 가장 가까운 representable walk를 정확히 찾는다고 설명합니다. 이 경우 시간은 sequence length에 선형이고, 간단한 최적화 뒤 O(2의 L승 곱하기 T)입니다. 그러나 QTIP이 LLM에서 다루는 Hessian-weighted layer proxy는 sequence group별 additive error가 아니므로, 전체 W를 단일 TCQ sequence로 Viterbi하면 Eq. 1을 정확히 최소화하는 것이 아닙니다.

## 8. Bitshift trellis: 겹치는 bit window로 병렬 decode

8. Bitshift trellis: 겹치는 bit window로 병렬 decode

발표 대본
bitshift trellis에서는 다음 state의 상위 L-kV bits가 현재 state의 하위 L-kV bits와 같습니다. 그래서 t번째 V-weight group은 encoded bitstream의 연속된 L-bit window만 보면 됩니다. 다음 group으로 갈 때 window를 kV bit만 옮기므로 bit shift 연산으로 접근할 수 있고, 각 group의 window decode는 병렬화할 수 있습니다. c는 0부터 2^(kV)-1까지의 정수이며 각 state의 incoming/outgoing degree는 2^(kV)입니다. 이 병렬 decode 성질을 generic trellis 전체에 일반화하면 안 됩니다.

## 9. 교육용 검산: 원전 Fig. 2의 tail-biting walk

9. 교육용 검산: 원전 Fig. 2의 tail-biting walk

## 12. HYB decoder의 2D vector 복원 경로

12. HYB decoder의 2D vector 복원 경로

발표 대본
HYB는 x squared plus x modulo 2의 32승 hash로 state bit의 상관을 섞고, Q-bit slice를 2D FP16 lookup table index로 씁니다. bit 15는 vector의 두 번째 entry sign을 flip합니다. 논문의 modern-GPU hybrid setting은 L=16, V=2, T_x=T_y=16, Q=9이며 base codebook은 2 KiB입니다. bank conflict를 위한 32배 duplication 뒤 RTX 6000 Ada L1에 맞는다는 조건도 원문에 별도로 적혀 있습니다.

## 13. Tail-biting: 두 번 Viterbi로 하는 근사

13. Tail-biting: 두 번 Viterbi로 하는 근사

발표 대본
직접 bitshift encoding은 start state 때문에 kT에 더해 L-kV bit를 저장해야 합니다. tail-biting은 start와 end가 그 overlap를 공유하게 만들어 이 부담을 없앱니다. 하지만 exact tail-biting dynamic programming은 state-space에 대해 quadratic이어서 L이 충분히 크면 어렵습니다. Algorithm 4는 회전한 sequence에서 먼저 Viterbi를 실행해 overlap를 얻고, 원 sequence에서 그 overlap를 강제하는 두 번의 Viterbi를 사용합니다.

## 15. BlockLDLQ 안에서 TCQ를 쓰는 이유

15. BlockLDLQ 안에서 TCQ를 쓰는 이유

발표 대본
논문은 proxy error가 additive distortion이 아니므로 전체 W를 하나의 TCQ sequence로 직접 최소화하지 않습니다. 대신 QuIP#의 BlockLDLQ 안에서 QTIP을 drop-in quantizer로 씁니다. input dimension에 따른 Ty block feedback은 유지하면서, Tx rows를 함께 묶어 Tx 곱하기 Ty weight를 하나의 high-dimensional sequence로 Viterbi합니다. Algorithm 5의 regular BlockLDLQ feedback step은 그대로이고 Q가 round하는 방식만 QTIP으로 바뀝니다.

## 16. Algorithm 5의 block quantization 순서

16. Algorithm 5의 block quantization 순서

발표 대본
Algorithm 5는 W-hat를 0으로 시작하고 H의 Ty-block LDL decomposition에서 A를 만듭니다. input column block을 뒤에서 앞으로 처리하며, 이미 quantize한 block의 error가 A를 거쳐 current x에 반영됩니다. 그 x를 Tx by Ty tile sequence로 reshape한 뒤 각 row에 Viterbi를 적용하고, result를 W-hat의 현재 block으로 되돌립니다. 이 순서 때문에 QTIP은 단독 source coder가 아니라 proxy-aware rounding pipeline의 일부가 됩니다.

## 22. QTIP이 지지하는 결론과 남는 경계

22. QTIP이 지지하는 결론과 남는 경계

발표 대본
QTIP은 RHT로 Gaussian-like source를 만들고, bitshift trellis가 공유하는 state bits를 Viterbi로 고르며, computed 또는 small hybrid lookup decoder로 state value를 재생성합니다. BlockLDLQ는 Hessian-weighted proxy에 맞춘 feedback을 제공합니다. 다만 Viterbi exactness는 additive metric의 성질이고, tail-biting은 approximate이며, quality와 speed table에는 고정된 experimental conditions가 있습니다. NeurIPS checklist도 formal theoretical results가 없고 error bars를 report하지 않았다고 답합니다.
