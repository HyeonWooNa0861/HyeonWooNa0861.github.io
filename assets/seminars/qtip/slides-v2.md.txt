# QTIP: Trellis와 Incoherence Processing을 이용한 LLM 양자화

논문: QTIP: Quantization with Trellises and Incoherence Processing

저자: Albert Tseng, Qingyao Sun, David Hou, and Christopher De Sa (2024)

## 1. QTIP: Trellis와 Incoherence Processing을 이용한 LLM 양자화

Weight-only PTQ에서 고차원 trellis coding과 빠른 decode를 함께 설계하는 방법


근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) p. 1, Abstract

## 2. QTIP의 범위: PTQ와 fine-tuning 경로


| 항목 | 원전에서 하는 일 | 발표에서 구분할 점 |
| --- | --- | --- |
| 기본 대상 | 학습된 LLM weight의 weight-only PTQ | 모델을 처음부터 학습하는 방법이 아니다 |
| 1MAD·3INST | 계산만으로 trellis value를 decode | 논문 실험에서는 fine-tuning 없이 평가 |
| HYB | 작은 LUT와 계산을 함께 사용 | codebook과 아직 양자화하지 않은 block weight를 fine-tune 가능 |
| activation | weight code의 bit rate와 별도 | 논문은 일반 activation precision을 주장하지 않는다 |

핵심: QTIP은 PTQ이지만, 모든 결과가 training-free라는 뜻은 아니다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 1-2 and pp. 7-8, Sections 4.1-4.2

## 3. 고차원 VQ의 병목과 TCQ의 출발점


| 방식 | d차원 k-bit 표현 | 양자화 때 | 추론 때 |
| --- | --- | --- | --- |
| Unstructured VQ | 2의 kd승 개 codeword | 최근접 탐색 비용이 지수적으로 증가 | codebook을 cache에 두어야 빠른 lookup 가능 |
| TCQ | state walk로 긴 sequence를 표현 | additive distortion이면 Viterbi DP | trellis와 value table의 저장·serial decode가 병목 |
| QTIP | bitshift walk와 재계산 code | TCQ를 rounding framework 안에 사용 | graph와 큰 codebook 저장을 피하며 병렬 decode를 노림 |

핵심: QTIP은 고차원 표현 자체보다, 그 표현을 저장하고 decode하는 비용을 함께 다룬다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 1-4, Sections 1-3

## 4. 양자화가 줄이는 대상: layer proxy error


| 기호 | 뜻 | 해석 경계 |
| --- | --- | --- |
| W와 W-hat | 원래 linear-layer weight와 quantized 근사 | 전체 transformer를 한 번에 비교하지 않는다 |
| x | calibration에서 얻은 layer input activation | 모든 실제 입력 분포를 뜻하지 않는다 |
| H = E[xxᵀ] | input outer product의 평균인 proxy Hessian | end-to-end training loss가 아니다 |
| ell(W-hat) | E[\|\|(W-hat - W)x\|\|²] | 최종 PPL, accuracy, latency를 직접 최소화하지 않는다 |

핵심: QTIP의 최적화 출발점은 layer reconstruction proxy이며 최종 task metric과는 다르다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) p. 2, Eq. 1; p. 3, Section 2

## 5. RHT 전처리: Gaussian-like source를 만드는 이유

random sign과 Hadamard transform으로 weight와 proxy Hessian의 coordinate를 바꾼다

- **레인 layer coordinate**
  - **W와 H**: 원래 weight와 proxy Hessian
  - **random signs**: S_m과 S_n을 곱한다
  - **Hadamard**: V_m과 V_n으로 coordinate를 섞는다
  - **W-tilde와 H-tilde**: Gaussian-like source의 근사
- W와 H → random signs (실선, 단방향)
- random signs → Hadamard (실선, 단방향)
- Hadamard → W-tilde와 H-tilde (실선, 단방향)

핵심: RHT는 exact Gaussian이 아니라 trellis coding용 근사를 제공한다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) p. 3, Section 2.1

## 6. TCQ: codeword 하나가 아니라 허용된 state walk를 고른다

각 state에서 2^(kV)개 edge 중 하나를 선택해 V개 weight를 표현한다

- **레인 TCQ**
  - **input groups**: s1 → s2 → ... → sT/V
  - **L, k, V trellis**: 2의 L승 state와 V차원 state value
  - **allowed walk**: 각 group에 연결 가능한 state를 고른다
  - **reconstruction**: 선택한 state value를 이어 붙인다
- input groups → L, k, V trellis (실선, 단방향)
- L, k, V trellis → allowed walk (실선, 단방향)
- allowed walk → reconstruction (실선, 단방향)

핵심: 한 V-weight group의 edge 선택은 kV bits이며, weight당 bit rate는 k다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 2-4, Sections 1 and 2.3

## 7. Viterbi가 exact인 범위: additive distortion

1. **group error**: 각 s_i와 state value의 squared error를 계산한다
2. **DP recurrence**: 각 도착 state에 가장 작은 이전 누적 error를 남긴다
3. **best walk**: 마지막 state에서 역추적해 representable walk를 고른다
4. **boundary**: 이 exactness는 group error가 더해질 때만 성립한다

핵심: Viterbi의 최적 walk와 Eq. 1의 non-additive layer proxy 최소화는 같은 문제가 아니다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 2-4, Sections 1-3

## 8. Bitshift trellis: 겹치는 bit window로 병렬 decode

j=(i·2^(kV) mod 2^L)+c, 0≤c<2^(kV)

- **레인 contiguous windows**
  - **group 1**: bits 1부터 L까지를 읽는다
  - **group 2**: kV bit 옮긴 window를 읽는다
  - **group t**: 연속된 L-bit window 하나에만 의존
  - **parallel decode**: 각 window를 독립적으로 decode
- group 1 → group 2 (실선, 단방향)
- group 2 → group t (실선, 단방향)
- group t → parallel decode (실선, 단방향)

핵심: 병렬 decode는 일반 TCQ가 아니라 bitshift trellis의 overlapping-window 구조에서 나온다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) p. 4, Section 3.1; p. 5, Fig. 2

부분 group 값과 sequence 전체 결과를 구분한다

## 11. 세 decoder의 설계: 계산만 또는 작은 lookup


| code | state에서 value를 만드는 법 | 실험·구현 경계 |
| --- | --- | --- |
| 1MAD | LCG word의 네 byte를 합산하고 scale과 shift | lookup-free, NVIDIA GPU에서 최대 4 instructions per weight |
| 3INST | LCG word와 magic FP16 field를 XOR해 두 FP16을 합산 | 논문은 3 ALU instruction이라고 설명하며 split data movement도 언급 |
| HYB | hash index로 2D FP16 LUT를 읽고 sign bit를 flip | 작은 LUT를 fine-tune 가능, 실험 수치는 one-sign-flip version |
| 공통 | pseudorandom approximate Gaussian value | true random Gaussian sampling이나 unlimited codebook이 아니다 |

핵심: decoder는 같은 TCQ idea의 구현 선택지이며, cache와 instruction 제약이 서로 다르다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 5-7, Algorithms 1-3 and Fig. 3

## 12. HYB decoder의 2D vector 복원 경로

- **레인 HYB**
  - **L-bit state**: 0으로 left-pad한 integer x
  - **hash**: x²+x mod 2³²
  - **Q-bit index**: Q-bit LUT address
  - **2D FP16 LUT**: C에서 vector v를 읽는다
  - **sign flip**: bit 15: second sign flip
- L-bit state → hash (실선, 단방향)
- hash → Q-bit index (실선, 단방향)
- Q-bit index → 2D FP16 LUT (실선, 단방향)
- 2D FP16 LUT → sign flip (실선, 단방향)

핵심: L=16, V=2, Q=9의 base LUT 2 KiB와 cache 조건은 구분해야 한다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 6-8, Algorithm 3 and Section 4.2

## 13. Tail-biting: 두 번 Viterbi로 하는 근사

1. **rotate**: S를 floor(T/2)만큼 오른쪽으로 회전한다
2. **first Viterbi**: 회전된 sequence를 quantize한다
3. **extract overlap**: start와 end가 공유할 L-kV bit를 읽는다
4. **second Viterbi**: 원 sequence에서 그 overlap를 강제해 다시 quantize한다

핵심: tail-biting은 bit 낭비를 줄이며, Algorithm 4는 two-pass approximation이다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 6-8, Section 3.2 and Algorithm 4

## 15. BlockLDLQ 안에서 TCQ를 쓰는 이유

Hessian-weighted proxy는 additive sequence error가 아니므로 QTIP을 BlockLDLQ의 quantizer Q로 넣는다

- **레인 rounding block**
  - **H의 block LDL**: Ty block feedback 준비
  - **feedback residual**: earlier error를 current block에 반영
  - **Tx 곱하기 Ty tile**: TCQ sequence로 reshape
  - **QTIP Viterbi**: bitshift trellis code로 tile을 round
- H의 block LDL → feedback residual (실선, 단방향)
- feedback residual → Tx 곱하기 Ty tile (실선, 단방향)
- Tx 곱하기 Ty tile → QTIP Viterbi (실선, 단방향)

핵심: BlockLDLQ는 proxy feedback 틀이고, QTIP은 high-dimensional tile codec이다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) p. 7, Section 4; pp. 16-17, Appendix A.2 and Algorithm 5

## 16. Algorithm 5의 block quantization 순서

1. **initialize**: W-hat를 0으로 두고 H의 Ty-block LDL을 만든다
2. **select block**: input dimension에서 다음 Ty column block을 고른다
3. **add feedback**: W와 이전 W-hat error, A를 이용해 current x를 만든다
4. **reshape**: x를 m/Tx개의 Tx 곱하기 Ty sequence로 바꾼다
5. **Viterbi and write**: 각 row sequence를 quantize해 W-hat block에 되돌린다

핵심: Viterbi는 Algorithm 5에서 feedback이 반영된 tile에 row-wise로 적용된다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) p. 17, Algorithm 5

## 22. QTIP이 지지하는 결론과 남는 경계


| 원전이 지지하는 범위 | 원전만으로 말할 수 없는 범위 |
| --- | --- |
| bitshift와 codes는 storage·serial decode를 겨냥 | 모든 hardware에서 항상 더 빠름 |
| additive Viterbi와 Table 2의 close MSE | proxy global optimum·tail-biting exactness |
| named condition의 PPL·accuracy·throughput | 최신 SOTA·universal serving latency |
| checklist: formal theorem 없음, error bars 없음 | 작은 표 차이의 statistical superiority |

핵심: QTIP의 핵심은 RHT, bitshift TCQ, decoder, BlockLDLQ를 조건과 함께 연결하는 데 있다.

근거: [neurips2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/6de2e84b8da47bb2eb5e2ac96c63d2b0-Paper-Conference.pdf) pp. 3-10; pp. 19-21, NeurIPS checklist
