## 12. response time·jitter 생성

12. response time·jitter 생성

발표 대본
Response time은 request propagation, uplink, queueing, processing, downlink, response propagation을 합친다. Jitter는 bandwidth-load trend, user-server distance ratio, direction change, bandwidth demand ratio, instantaneous speed를 fuse한다. edge-context와 time perturbation은 each [0,0.2]로 scale된 뒤 generated QoS에 반영된다.

## 17. WS-DREAM과의 비교는 feature availability 표다

17. WS-DREAM과의 비교는 feature availability 표다

발표 대본
Table VIII에서 user ID/service ID, timestamp index, user-service QoS, server location metadata, response time은 두 dataset에 모두 있습니다. Throughput은 WS-DREAM에만 check가 있고 CHESTNUT에는 없습니다. CHESTNUT-only field는 server ID, user-server-service QoS, user trajectory, user-server coverage, server resource supply, dynamic server load, service demand attributes, network jitter입니다. 이 슬라이드는 표의 일부를 재배열한 것이며 checkmark는 feature availability이지 algorithm accuracy 또는 data quality superiority가 아닙니다.

## 21. CHESTNUT을 재현 가능하게 읽는 순서

21. CHESTNUT을 재현 가능하게 읽는 순서
