## 1. GPTQ: 대규모 언어 모델의 정확한 사후 양자화

1. GPTQ: 대규모 언어 모델의 정확한 사후 양자화

발표 대본
이 논문은 이미 학습된 대규모 언어 모델의 weight를 3비트나 4비트 수준으로 줄이는 사후 양자화 방법 GPTQ를 제안합니다. 핵심 질문은 단순히 각 weight를 가장 가까운 값으로 반올림하는 법이 아닙니다. 대표 입력을 layer에 통과시켰을 때 원래 출력과 양자화한 출력이 최대한 비슷하도록, 한 weight에서 생긴 오차를 아직 고정하지 않은 다른 weight에 보상하는 법입니다. 먼저 문제와 기호를 정의하고, 작은 계산으로 보상 원리를 확인한 뒤, 이 아이디어를 거대한 행렬까지 확장한 세 가지 변경과 실제 배포 조건을 구분해 보겠습니다.

## 2. 왜 weight memory가 출발점인가

2. 왜 weight memory가 출발점인가

발표 대본
논문은 1750억 개 parameter의 FP16 weight memory가 binary GB 관례로 약 326GB라고 설명합니다. 이것은 activation이나 KV cache까지 포함한 전체 추론 메모리가 아니라 weight 저장만을 강조한 출발점입니다. 당시 최고급 단일 GPU보다 컸기 때문에 모델을 여러 GPU에 나눠야 했습니다. GPTQ는 이미 학습된 모델을 다시 학습시키지 않고 weight bit-width를 낮추면서 정확도를 유지하려고 합니다. 따라서 목표는 파일 크기만 줄이는 것이 아니라, 양자화된 layer가 대표 입력에 대해 원래 layer와 비슷한 출력을 내도록 만드는 것입니다.

## 3. 먼저 구분할 네 가지 용어

3. 먼저 구분할 네 가지 용어

발표 대본
Weight-only는 weight를 낮은 정밀도로 바꾸되 activation은 원래 정밀도에 두는 설정입니다. PTQ는 post-training quantization의 약자로, 사전 학습을 끝낸 모델을 재학습하지 않고 양자화합니다. Calibration 데이터는 전체 학습 데이터가 아니라 layer가 실제로 자주 받는 입력 방향을 관찰하기 위한 작은 표본입니다. 마지막으로 inference kernel은 압축된 code를 읽어 실제 곱셈을 수행하는 실행 장치입니다. GPTQ 알고리즘은 어떤 양자화 값을 선택할지를 정하고, bit packing과 kernel은 그 값을 어떻게 저장하고 실행할지를 정합니다. 이 둘을 섞으면 정확도 개선과 속도 개선의 원인을 잘못 설명하게 됩니다.

## 4. 양자화 grid는 허용된 값의 집합이다

4. 양자화 grid는 허용된 값의 집합이다

발표 대본
양자화 grid는 weight가 선택할 수 있는 유한한 값들의 집합입니다. quant(w)는 주어진 weight를 이 grid의 한 값으로 보냅니다. 뒤의 계산 예시에서는 원리를 쉽게 확인하기 위해 0과 1만 있는 grid를 사용합니다. 실제 논문의 주요 실험은 각 row마다 범위를 정하는 균일한 비대칭 min-max grid를 사용합니다. 정수 code만으로 원래 수치 범위를 알 수 없으므로 scale과 zero point 같은 metadata도 필요합니다. 따라서 3비트 code라는 말이 모델 전체가 정확히 parameter당 3비트라는 뜻은 아닙니다.

## 5. 독립 반올림 전에 행렬 기호부터 읽자

5. 독립 반올림 전에 행렬 기호부터 읽자

발표 대본
W는 한 linear layer의 full-precision weight 행렬이고, w는 그중 한 row입니다. X의 각 column은 이 layer에 들어온 calibration 입력 하나입니다. 따라서 WX의 각 row는 해당 출력 channel이 calibration 표본에 대해 만든 값입니다. W_hat은 양자화된 weight 행렬입니다. 같은 크기의 weight 오차라도 X에서 자주 나타나는 방향과 겹치면 출력 오차가 커질 수 있습니다. 그래서 GPTQ는 W와 W_hat의 원소 차이만 최소화하지 않고, WX와 W_hat X의 차이를 줄입니다. 이 슬라이드의 숫자는 다음 계산을 위한 교육용 예시입니다.

6. GPTQ의 목표는 layer 출력 재구성이다

## 7. Hessian은 입력 방향의 민감도를 담는다

7. Hessian은 입력 방향의 민감도를 담는다

발표 대본
재구성 목적은 W의 각 row에 대해 분리할 수 있습니다. 양자화를 시작할 때 전체 좌표의 Hessian을 H=2XX^T로 씁니다. iteration이 진행되어 free 좌표 집합 F만 남으면 Eq. 2의 대상은 H_F=2X_F X_F^T이고, H_F^-1은 그 행렬의 mathematical inverse입니다. 이 true inverse의 q column이 한 weight 오차와 다른 free weight의 보상 방향을 연결합니다. 이미 고정한 q를 다시 full precision으로 복구하는 것이 아니라 F의 값만 조정합니다. 뒤의 Algorithm 1은 damping을 포함한 다른 시작 행렬과 Cholesky working factor를 쓰므로 이 기호와 구분하겠습니다.

## 8. OBQ의 핵심: 하나를 고정하고 나머지를 보상

8. OBQ의 핵심: 하나를 고정하고 나머지를 보상

발표 대본
GPTQ는 Optimal Brain Quantization, 즉 OBQ의 보상 아이디어에서 출발합니다. 원래 OBQ는 현재 양자화했을 때 추가 오차가 가장 작은 좌표 q를 greedy하게 고릅니다. q를 grid 값에 고정한 다음, 그 오차와 inverse Hessian의 q column을 이용해 아직 자유로운 weight F를 움직입니다. 이후 q를 inverse에서 제거하고 다시 다음 좌표를 고릅니다. scaled error에는 양자화 오차의 제곱과 inverse Hessian 대각이 함께 들어갑니다. 정확한 식 자체보다 중요한 점은, 한 weight를 고정한 오차가 다음 weight의 값과 반올림 결과까지 바꿀 수 있다는 것입니다.

## 10. 보상은 0.55의 최종 반올림을 바꾼다

10. 보상은 0.55의 최종 반올림을 바꾼다

## 11. 그대로의 OBQ는 거대 행렬에서 비싸다

11. 그대로의 OBQ는 거대 행렬에서 비싸다

발표 대본
OBQ는 각 row에서 양자화 오차를 보고 서로 다른 greedy 순서를 선택합니다. 한 weight를 고정할 때마다 inverse Hessian에서도 그 좌표를 제거하는 갱신이 필요합니다. 이 구조의 계산량은 d_row 곱하기 d_col의 세제곱으로 주어집니다. 논문은 2500만 parameter 규모의 ResNet-50도 단일 GPU에서 약 한 시간이 걸리는 예를 들며, 수십억에서 수천억 parameter 모델에는 그대로 적용하기 어렵다고 설명합니다. GPTQ는 순차 보상의 핵심을 유지하면서 모든 row가 공유할 수 있는 순서와 block 단위 실행으로 바꿉니다.

## 12. OBQ: row마다 active column이 다르다

12. OBQ: row마다 active column이 다르다

발표 대본

## 13. GPTQ: 같은 active column이 세로로 정렬된다

13. GPTQ: 같은 active column이 세로로 정렬된다

발표 대본
GPTQ에서는 같은 순간에 모든 row가 c2를 처리합니다. c1은 이미 Q로 고정되었고 c3와 c4는 모두 free이므로, 세 row가 하나의 공통 F mask를 갖습니다. H_F는 weight row가 아니라 공통 layer 입력 X_F에서 계산되므로 inverse 또는 Cholesky working progression도 row마다 다시 만들 필요가 없습니다. 이를 column마다 한 번 공유하면서 W의 모든 row를 병렬로 처리합니다. 논문은 큰 layer에서 이 arbitrary fixed order가 greedy order와 비슷한 오차를 보였다고 관찰했지만, 모든 순서가 동일하다는 정리는 아닙니다.

## 14. 공통 순서가 바꾸는 계산 복잡도

14. 공통 순서가 바꾸는 계산 복잡도

발표 대본
d_row는 weight 행렬의 row 수이고 d_col은 column 수입니다. 원래 OBQ는 row마다 inverse 갱신 진행을 되풀이하므로 O(d_row d_col^3)입니다. 모든 row가 같은 column 순서를 쓰면 inverse 관련 진행을 d_col번만 수행하고 row 계산을 행렬 연산으로 공유할 수 있습니다. 논문은 결과 복잡도를 O(max(d_row d_col^2, d_col^3))로 제시하며 원래보다 min(d_row,d_col) 계수만큼 줄었다고 설명합니다. 이것은 Step 1의 구조 변화이고, 다음 lazy block은 이 이론적 계산량 자체보다 GPU 실행 효율을 개선합니다.

15. Lazy block 상태: B=2 교육용 행렬

## 16. E buffer가 later column update를 모은다

16. E buffer가 later column update를 모은다

발표 대본
E는 현재 block의 scaled quantization error를 row별로 저장하는 실제 d_row×B buffer입니다. c2를 처리할 때 E의 첫 column이 즉시 채워지고, c3를 처리할 때 둘째 column이 채워집니다. 이 E는 block 내부 보상에도 사용되며, block이 끝난 뒤 working factor R의 block-to-later 조각과 곱해 c4 같은 later column을 한 번에 갱신합니다. 표의 E1, E2, E3는 E의 각 row이고 R_block,c4는 현재 block row와 later column을 잇는 working-factor 조각입니다. 따라서 미뤄지는 것은 E 기록이 아니라 later-column global update입니다. 이 행렬 연산 묶음이 memory-throughput 활용을 높이지만 nominal compute를 줄이지는 않습니다.

## 17. 변경 3: damping과 Cholesky로 안정화한다

17. 변경 3: damping과 Cholesky로 안정화한다

발표 대본
큰 모델에서는 block inverse update를 반복하면서 수치 오차가 누적되어 남은 inverse Hessian이 indefinite가 될 수 있습니다. 논문은 먼저 H_tilde=2XX^T+lambda I를 만들며 lambda는 H 평균 대각값의 1%입니다. H_tilde^-1은 이 damped Hessian의 mathematical inverse입니다. 이어서 그 inverse의 Cholesky factor를 전치한 working factor를 여기서는 R이라고 부릅니다. 원문 Algorithm 1은 편의상 R를 다시 H^-1이라는 변수 이름에 덮어쓰지만, 그 이후 entry는 raw inverse 원소가 아니라 Cholesky working factor의 원소입니다. 이 재구성은 안정성과 효율을 위한 것이며 양자화를 exact하게 만들지는 않습니다.

## 18. Algorithm 1을 다섯 동작으로 읽기

18. Algorithm 1을 다섯 동작으로 읽기

발표 대본
Algorithm 1은 먼저 calibration 입력 X로 damped inverse Hessian을 만들고 그 Cholesky working factor R를 계산합니다. 원문은 이 단계 뒤에도 변수 이름 H^-1을 재사용하지만, 수업에서는 true inverse와 구분하려고 R로 부릅니다. Q는 최종 양자화 행렬이고 E는 현재 block의 scaled error buffer입니다. column j를 모든 row에서 양자화한 뒤 E와 R[j,j:block]으로 block 안의 남은 weight를 갱신합니다. block 종료 뒤에는 E와 R[block,later]를 곱해 뒤쪽 모든 column을 한 번에 갱신합니다. W는 현재 linear layer의 행렬이지 Transformer 전체의 하나의 전역 행렬이 아닙니다.

## 19. Calibration은 quantized block 출력을 이어받는다

19. Calibration은 quantized block 출력을 이어받는다

발표 대본
논문의 calibration 데이터는 C4에서 무작위로 뽑은 길이 2048 token segment 128개입니다. 전체 full-precision 모델을 GPU에 동시에 올리지 않고 Transformer block 하나, 즉 여섯 layer를 차례로 적재합니다. 현재 block 입력으로 layer Hessian을 누적하고 weight를 양자화합니다. 그런 다음 같은 입력을 완전히 양자화된 현재 block에 다시 통과시켜 다음 block의 입력을 만듭니다. 따라서 뒤쪽 layer는 원래 full-precision 경로의 입력이 아니라 앞선 block의 양자화 영향이 포함된 입력을 봅니다. 이것은 global end-to-end retraining이 아니라 layer와 block 단위 calibration 전달입니다.

## 20. RTN과 GPTQ는 같은 grid에서 비교한다

20. RTN과 GPTQ는 같은 grid에서 비교한다

발표 대본
논문의 주요 대규모 baseline은 round-to-nearest, RTN입니다. RTN과 GPTQ는 정확히 같은 균일한 row별 비대칭 min-max grid를 사용합니다. RTN은 각 weight를 가장 가까운 grid 값으로 독립 반올림합니다. GPTQ는 calibration X에서 얻은 second-order 정보를 이용해 한 좌표의 오차를 남은 좌표에 보상합니다. 따라서 표의 accuracy 차이를 GPTQ만 더 세밀한 grid를 사용한 결과라고 설명하면 안 됩니다. 다만 grouping을 적용한 별도 행에서는 grid granularity와 metadata 비용이 달라지므로 구분해야 합니다.

## 22. Grouping은 정확도와 metadata를 함께 바꾼다

22. Grouping은 정확도와 metadata를 함께 바꾼다

발표 대본
Grouping은 연속 weight 묶음마다 별도의 quantization grid를 두는 방법입니다. 작은 group은 현재 weight 범위에 더 잘 맞을 수 있지만 scale과 zero point를 더 자주 저장해야 합니다. Table 5에서 OPT-175B의 3비트 GPTQ WikiText2 PPL은 8.68이고 g1024와 g128은 모두 8.45입니다. Table 7의 2비트 결과에서는 g128이 9.58, g32가 8.94입니다. 그러나 논문은 scale과 zero point metadata를 포함해 평균 bit 수를 각각 약 2.2와 2.6으로 계산합니다. 따라서 group 결과를 같은 정확한 저장비용의 비교로 읽으면 안 됩니다.

## 23. Algorithm, packing, kernel은 서로 다른 단계다

23. Algorithm, packing, kernel은 서로 다른 단계다

발표 대본
GPTQ 알고리즘은 calibration 재구성 오차를 줄이도록 각 weight의 grid 값을 결정합니다. 일반적인 packed deployment에서는 그 grid level을 3비트 같은 정수 code로 표현하고 scale과 zero point를 함께 저장합니다. 이 흐름은 Algorithm 1이 특정 byte layout까지 정의한다는 뜻이 아닙니다. 논문의 추론에서는 별도 kernel이 압축 weight를 동적으로 복원하면서 full-precision vector와 곱합니다. 이 kernel이 없다면 양자화된 값은 작게 저장되어도 논문의 latency 개선이 그대로 나오지 않습니다. 같은 표현도 다른 kernel과 batch 조건에서는 성능이 달라질 수 있습니다.

## 24. Memory와 latency 수치에는 실행 조건이 붙는다

24. Memory와 latency 수치에는 실행 조건이 붙는다

발표 대본
논문은 3비트 OPT-175B weight가 FP16으로 유지한 embedding과 output layer를 포함해 약 63GB이고, 2048 token의 전체 KV history가 약 9GB라고 설명합니다. 그래서 80GB A100 한 대에 들어갑니다. Table 6은 batch size 1로 길이 128을 생성할 때 A100에서는 5-GPU FP16 230ms와 1-GPU 3비트 71ms, A6000에서는 8-GPU FP16 589ms와 2-GPU 3비트 130ms를 비교합니다. 모델 표현, GPU 수, kernel이 함께 바뀐 end-to-end 조건입니다. 이 숫자를 현재 모든 하드웨어나 임의 batch에서의 GPTQ 고정 배율로 인용하면 안 됩니다.

## 25. 속도는 memory-bound 생성에서 나온다

25. 속도는 memory-bound 생성에서 나온다

발표 대본
Autoregressive 생성은 낮은 batch에서 token 하나씩 처리하므로 큰 weight 행렬과 vector의 곱이 반복되고 memory bandwidth가 병목이 되기 쉽습니다. 논문의 custom kernel은 계산 중 weight를 dequantize하는 추가 연산을 감수하는 대신 훨씬 적은 압축 데이터를 읽습니다. Appendix A.2.2에서 communication은 전체 runtime의 5% 미만이며 HuggingFace, attention, residual, LayerNorm 같은 비양자화 overhead는 두 비교에서 같다고 설명하므로, 논문은 speedup의 거의 전부를 quantized matrix-vector kernel에 귀속합니다. 큰 batch의 matrix-matrix 곱에는 같은 결과를 일반화할 수 없고, 실험은 activation quantization도 포함하지 않습니다.

## 26. GPTQ가 확립한 것과 남겨 둔 경계

26. GPTQ가 확립한 것과 남겨 둔 경계

발표 대본
정리하면 GPTQ는 calibration 입력에서 한 linear layer의 출력을 재구성하도록 weight를 순차 양자화하고, inverse-Hessian 정보로 남은 weight를 보상합니다. 거대 모델까지 확장하기 위해 모든 row가 column 순서를 공유하고, 128-column lazy block으로 update를 묶으며, damping과 Cholesky로 수치적으로 안정화합니다. 이 논문은 OPT와 BLOOM의 weight-only 결과와 특정 custom kernel 조건을 평가했습니다. C4 평가는 calibration도 C4 training에서 가져왔으므로 완전히 zero-shot이 아닙니다. 저자 repository의 후대 기능인 act-order, true-sequential, LLaMA 결과는 이 frozen ICLR 논문의 결과로 섞지 않아야 합니다.
