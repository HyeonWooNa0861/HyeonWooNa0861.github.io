1. UniCon: 범용 클러스터의 연결 요소 계산

## 2. Connected components의 정확한 출력

2. Connected components의 정확한 출력

발표 대본
입력은 totally ordered vertex IDs를 가진 undirected graph입니다. Edge는 큰 ID가 먼저 오도록 ordered pair로 기록합니다. CC output은 각 vertex u를 component Lambda of u의 가장 preceding vertex, 즉 minimum ID에 mapping하는 것입니다. 예시에서는 1, 4, 6이 같은 component라 모두 1에 mapping되고, 2와 9는 2에 mapping됩니다.

## 3. 기호와 상태의 의미

3. 기호와 상태의 의미

발표 대본
rho는 partition count이고 xi는 vertex를 partition ID로 보내는 random hash입니다. 이 color label은 작업 분할에 쓰이며 component 결과가 아닙니다. tau는 remaining edge count가 충분히 작아졌을 때 distributed UniStar 대신 single-machine Rem으로 전환하는 threshold입니다. F는 filtering case one과 two에서 sep로 분리한 edges를 누적하며 final finishing에 다시 사용합니다.

## 4. 대규모 CC에서 memory와 I/O가 함께 문제다

4. 대규모 CC에서 memory와 I/O가 함께 문제다

발표 대본
Distributed-memory algorithms는 input graph와 processing state를 aggregate RAM에 올려야 하므로 commodity cluster에서 OOM이 날 수 있습니다. MapReduce는 distributed storage를 사용해 이 조건을 완화하지만 각 round의 records를 disk에 쓰고 network로 shuffle합니다. UniCon은 I/O를 없애지 않습니다. 대신 star operations가 만드는 intermediate edges와 불필요한 next-round inputs를 줄입니다.

## 5. Alternating, PACC, UniCon의 차이

5. Alternating, PACC, UniCon의 차이

발표 대본
Alternating algorithm은 large-star와 small-star를 번갈아 실행합니다. PACC는 partition-aware versions로 reducer concentration을 줄였지만 두 operations를 계속 교대하며 intermediate data를 옮깁니다. UniCon은 두 operations를 단순히 합치지 않고, overlapping partition subgraph에서 local CC를 계산하는 UniStar를 도입합니다. DSP-CC는 external memory를 쓰는 separate single-machine algorithm이라 UniCon을 그 분산판으로 부르면 안 됩니다.

## 7. UniCon의 전체 pipeline

7. UniCon의 전체 pipeline

## 8. Partition은 disjoint output group이 아니다

8. Partition은 disjoint output group이 아니다

발표 대본
UniStar는 vertices를 random hash로 partitions에 배정합니다. 하지만 partition subgraph G_i는 vertex shard만 보는 것이 아니라 그 partition vertices에 incident한 edges를 모두 받습니다. Cross edge는 양 endpoint partitions의 local views에 들어갈 수 있습니다. 이 overlap을 제거한 disjoint sharding으로 바꾸어 설명하면 Theorem 1의 connectivity-preservation 논리와 intact-edge optimization을 모두 왜곡합니다.

## 9. 작은 path에서 overlap과 Rem 따라가기

9. 작은 path에서 overlap과 Rem 따라가기

발표 대본
Vertex 1과 6은 partition zero, vertex 4는 partition one입니다. G zero는 vertices 1과 6에 incident한 두 edges를 모두 포함합니다. G one도 vertex 4에 incident한 두 edges를 모두 포함합니다. 따라서 local graph는 두 views에서 같고 Rem은 parent mapping one to one, four to one, six to one을 계산합니다. 이 예시는 overlap semantics를 설명하며 각 edge를 exactly one worker에서만 처리한다는 뜻이 아닙니다.

## 10. Parent mapping에서 output edge까지

10. Parent mapping에서 output edge까지

발표 대본
Input edge set은 path one to four to six입니다. 각 local Rem parent는 all vertices를 one에 mapping합니다. UniStar output을 set union하고 duplicates를 제거하면 four to one과 six to one이 남습니다. Input과 output graph의 edge topology는 다르지만 connected component는 같습니다. Theorem 1은 각 local path를 direct 또는 two-hop path로 대체해 이 connectivity를 보존함을 보입니다.

## 11. UniStar 한 round의 실제 계산

11. UniStar 한 round의 실제 계산

발표 대본
각 G_i에서 Rem이 local component minimum p of u를 계산합니다. Node u가 자기 hash partition subset의 minimum이 아니면 먼저 그 subset minimum에 연결되고, 그 local minimum은 p of u에 연결됩니다. 이 two-hop structure는 load concentration을 줄이면서 local component connectivity를 유지합니다. 모든 local output edge sets를 union해 next graph를 만듭니다.

## 13. UniStar-opt의 세 filtering cases

13. UniStar-opt의 세 filtering cases

발표 대본
Case one은 same-partition edge에서 u에게 following neighbor가 없는 경우입니다. Case two는 xi(v)=i, 즉 v가 partition i에 속하고 G_i에서 v의 모든 incident edges가 intact인 경우입니다. 두 cases의 edges는 subsequent rounds에서 빼지만 sep로 F에 축적해 finishing input에 다시 넣습니다. Case three는 xi(u)=i이며 (u,v)가 G_i에서 u의 유일한 incident edge이고 그 edge가 intact인 경우입니다. 단지 intact edge가 하나라는 조건이 아닙니다. 반대 partition의 copy 또는 replacement edge가 남으므로 sep 없이 discard합니다.

14. Filtered edge의 state 변화

## 15. Case 3 discard의 보존 조건

15. Case 3 discard의 보존 조건

발표 대본
Theorem 2는 cross edge (u,v)가 xi(u)=i인 G_i에서 u의 유일한 incident edge일 때 반대 partition에도 해당 edge가 있음을 보입니다. Case three는 이 유일 edge가 intact라는 조건도 요구합니다. 다른 non-intact incident edge가 있는데 intact edge만 하나인 경우는 여기에 해당하지 않습니다. Non-intact edge는 두 views에 기본적으로 복제됩니다. Opposite view가 그대로 emit하면 copy가 남고, 바꾸면 u를 다른 node와 잇는 replacement edge가 생깁니다. 이 조건이 있으므로 u-side duplicate를 sep 없이 discard할 수 있습니다.

## 16. Threshold tau와 Rem 전환

16. Threshold tau와 Rem 전환

발표 대본
UniCon은 remaining edge count가 tau 이하가 되면 Rem으로 전환합니다. 이 choice는 correctness를 바꾸는 constant가 아니라 performance tuning입니다. Experiment에서 tau equals two thousand million은 GSH, CW, HL을 single machine으로 처리하려다 OOM을 냈습니다. 논문은 각 dataset에 optimal tau를 사용했으므로 하나의 tau를 모든 hardware에 권장할 수 없습니다.

## 17. HybridMap이 worker RAM을 구성하는 방법

17. HybridMap이 worker RAM을 구성하는 방법

발표 대본
Rem의 parent map p를 universe-size array로 만들면 each worker가 total vertex count size를 부담합니다. HybridMap은 자기 partition vertex range를 compact array에 두고, local subgraph에 incident하지만 partition 밖인 vertices만 hash table에 둡니다. Local keys가 대부분 array에 있으므로 all-hash보다 lookup을 줄이고, full array보다 memory를 크게 낮춥니다.

## 18. Theorem 3의 expected memory bound

18. Theorem 3의 expected memory bound

발표 대본
Theorem 3 assumes random vertex partition and evenly distributed edges. Expected local vertex count is V over rho, and expected edge-view count is two E over rho because a cross edge can enter two subgraphs. 따라서 HybridMap memory는 expected O of V plus E over rho입니다. 논문은 high-probability concentration이나 deterministic byte limit을 제공하지 않습니다. Rho를 늘리면 memory는 줄지만 partition-aware benefit와 performance가 약해질 수 있습니다.

## 19. 증명과 측정을 구분하는 기준

19. 증명과 측정을 구분하는 기준

발표 대본
Theorem one is a connectivity correctness result. Theorem two supports case-three filtering under its structural condition. Theorem three is an expected asymptotic memory result. In contrast, input reduction, intermediate-data reduction, speedups and maximum processable sizes are measurements. Edge record count가 줄어도 compression, sort spill, network bytes, JVM overhead가 같은 비율로 줄어든다는 theorem은 없습니다.

## 24. UniCon 결과의 적용 한계

24. UniCon 결과의 적용 한계

발표 대본
Connectivity preservation은 algorithm semantics에 대한 theorem이지만 performance claims는 system-dependent입니다. Expected memory bound를 worst-case 16-gigabyte guarantee로 바꿀 수 없습니다. Record reduction과 physical bytes reduction도 identical하지 않습니다. Tau와 rho tuning이 결과에 영향을 주며, 이 paper는 connected components만 다룹니다. 다른 graph algorithms나 current clusters에는 별도 evidence가 필요합니다.

## 25. UniCon의 기여를 이루는 네 요소

25. UniCon의 기여를 이루는 네 요소

발표 대본
UniStar alone은 overlapping partitions에서 local connectivity를 빠르게 압축합니다. Intact tag는 stable cross edge의 duplicate copy를 줄입니다. Filtering은 completed structures를 next rounds에서 제외하되 case one and two edges를 F에 보존합니다. HybridMap은 each worker의 parent state를 compact하게 유지합니다. 이 네 요소가 함께 commodity-cluster CC scalability를 목표로 합니다.

## 26. 정확한 UniCon 설명

26. 정확한 UniCon 설명
