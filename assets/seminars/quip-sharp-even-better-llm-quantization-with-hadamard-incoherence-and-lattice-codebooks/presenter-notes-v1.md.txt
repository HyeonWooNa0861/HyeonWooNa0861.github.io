## 1. QuIP#: Hadamard 변환과 lattice codebook을 이용한 LLM 양자화

1. QuIP#: Hadamard 변환과 lattice codebook을 이용한 LLM 양자화

발표 대본
QuIP#는 이미 학습된 LLM의 weight를 4 bits 이하로 압축하는 weight-only post-training quantization 방법입니다. 앞선 QuIP의 incoherence와 adaptive rounding을 출발점으로 삼되, Randomized Hadamard Transform, BlockLDLQ와 E8 기반 vector codebook, 선택적 fine-tuning을 추가합니다. 발표에서는 변환이 원래 linear layer 계산과 어떻게 대응되는지, 8개 weight가 하나의 16-bit index가 되는 방식, NoFT와 FT 결과의 차이, 그리고 theorem과 실험이 각각 무엇을 보장하는지 설명합니다.

## 2. QuIP#의 범위와 두 결과 경로

2. QuIP#의 범위와 두 결과 경로

발표 대본
논문은 QuIP#를 weight-only PTQ로 분류합니다. NoFT는 transform과 block quantization으로 끝납니다. FT는 quantized weight matrix를 고정한 채 sign vector, layer normalization, language-model head 같은 선택 parameter를 development data로 최적화합니다. 그러므로 모든 QuIP# 수치를 training-free라고 묶을 수 없습니다. Activation precision은 weight-code bit rate와 별도이며, Algorithm 1과 2는 activation precision을 일반적인 16-bit 경로로 명시하지 않습니다.

## 3. 앞선 QuIP에서 이어받은 세 가지 기반

3. 앞선 QuIP에서 이어받은 세 가지 기반

발표 대본
QuIP#는 처음부터 새로운 목적 함수를 만드는 방법이 아닙니다. QuIP의 layer-local reconstruction proxy, incoherence processing, LDLQ feedback을 배경으로 사용합니다. QuIP#의 변화는 coordinate transform을 RHT로 바꾸고, scalar rounding을 block vector quantization으로 확장하며, E8 기반 codebook과 optional fine-tuning을 결합한 데 있습니다. 두 논문의 기여를 섞지 않기 위해 QuIP의 RHT나 E8P라고 부르지 않습니다.

4. QuIP#가 추가한 세 단계

발표 대본

## 6. 교육용 4차원 RHT 계산

6. 교육용 4차원 RHT 계산

## 7. RHT와 추론의 대응 관계

7. RHT와 추론의 대응 관계

발표 대본
Algorithm 1의 NoFT 경로는 W와 H를 RHT basis로 옮긴 뒤 transformed W를 quantize하고 binary sign vector S_U, S_V를 함께 저장합니다. Algorithm 2의 순서는 Had(S_V 곱하기 x), decoded transformed-weight multiply, Had(S_U 곱하기 y)입니다. ## 8. Lemma 3.1의 보장 범위

8. Lemma 3.1의 보장 범위

발표 대본
Lemma 3.1은 H가 positive semidefinite이고 W가 주어졌을 때 random sign과 orthogonal scaled Hadamard를 적용하면 변환된 H와 W가 high probability로 incoherent해진다고 말합니다. Bound는 dimension과 failure probability delta를 포함합니다. 필요한 Hadamard factor를 구하기 어려운 차원에서는 논문이 RFFT fallback을 제시합니다. 이 lemma는 transform cost나 final language-model perplexity를 직접 보장하지 않습니다.

## 10. Scalar quantization과 vector quantization의 표현 단위

10. Scalar quantization과 vector quantization의 표현 단위

발표 대본
RHT-transformed weight는 논문의 설명에서 대략 ball-shaped Gaussian distribution을 이룹니다. Scalar quantization은 각 coordinate에 독립적인 level을 적용하므로 전체 codeword 배치는 hypercube 형태가 됩니다. Vector quantization은 g-dimensional vector를 한 codeword로 선택해 source distribution의 모양을 반영할 수 있습니다. 하지만 일반 codebook는 size가 2의 k 곱하기 g 제곱으로 늘어나므로 저장과 lookup 문제가 생깁니다.

## 11. Vector quantization의 code rate

11. Vector quantization의 code rate

발표 대본
Generic vector quantization의 rate를 정리합니다. g-dimensional block을 k bits per scalar로 표현하면 한 block에 k 곱하기 g bits를 쓰고 conceptual codebook에는 2의 k 곱하기 g 제곱 개 codeword가 필요합니다. E8P에서는 g가 8, k가 2이므로 16-bit index가 8개 weight를 가리킵니다. 이 계산은 code index rate이며 sign vector나 scale, shared codebook 같은 overhead를 포함한 전체 model footprint와 다릅니다.

## 13. BlockLDLQ의 앞방향 error feedback

13. BlockLDLQ의 앞방향 error feedback

발표 대본
BlockLDLQ는 scalar LDLQ의 adaptive feedback을 g-coordinate block으로 확장합니다. 첫 block을 vector quantizer로 codeword에 고정하면 original과 quantized block 사이 residual이 생깁니다. Hessian의 block LDL decomposition에서 얻은 feedback coefficient를 사용해 이 residual을 뒤 block의 아직 quantize하지 않은 값에 반영합니다. 그 다음 adjusted block을 quantize합니다. 피드백은 이전 block에서 이후 block으로만 진행하며 이미 고른 code를 다시 최적화하는 iterative refinement가 아닙니다.

## 14. Theorem 4.1의 조건과 결론

14. Theorem 4.1의 조건과 결론

발표 대본
Theorem 4.1의 기호를 화면에 정의했습니다. W는 m by n weight matrix이고 g는 n을 나누는 block size입니다. H는 mu-incoherent해야 하며 vector quantizer의 error covariance가 sigma squared identity 이하라는 조건이 필요합니다. 결론은 quantized W의 Hessian-weighted layer proxy에 대한 expectation bound입니다. 원문은 같은 조건에서 block을 독립적으로 quantize한 bound와 비교합니다. 이 식으로 final LLM perplexity나 zero-shot accuracy의 우위를 증명할 수는 없습니다.

## 15. E8P의 실제 표현 단위

15. E8P의 실제 표현 단위

발표 대본
E8P는 E8 Padded의 약자이며 8-dimensional 2-bit vector codebook입니다. 8개 scalar에 16-bit index 하나를 쓰므로 index rate가 2 bits per scalar입니다. Conceptually 65,536 codeword를 갖지만 E8 lattice의 sign symmetry와 shift 구조를 이용해 256 곱하기 8 source table과 간단한 operation으로 decode합니다. 논문은 그 representation이 1 KiB라고 보고합니다. 이 1 KiB는 전체 quantized model size가 아니라 shared codebook representation입니다.

## 16. 16-bit E8P index의 구조적 decode

16. 16-bit E8P index의 구조적 decode

발표 대본
16 bits의 분해를 정확히 읽겠습니다. 첫 8 bits는 source codebook S에서 pattern s를 고릅니다. 다음 7 bits는 sign flip을 지정하고, 여덟째 sign은 그 7개 flip과 선택된 s가 요구하는 parity를 함께 사용해 추론합니다. 마지막 1 bit는 D̂8−1/4 또는 D̂8+1/4 branch를 선택하며, 두 branch의 union이 E8+1/4입니다. 합계는 8+7+1인 16 bits이고 parity sign은 별도 저장 bit가 아닙니다. 이 구조가 65,536 곱하기 8 FP16 table을 직접 저장하는 방식과 다릅니다.

## 27. 2 bits per weight와 전체 배포 memory의 차이

## 29. QuIP#의 전체 논리

29. QuIP#의 전체 논리

발표 대본
QuIP#를 한 흐름으로 정리합니다. NoFT의 binary signs와 Hadamard는 quantization이 다루기 쉬운 basis를 만들고 inference activation에 matched transform을 적용합니다. Quantization error가 없다면 이 NoFT relation은 model-preserving입니다. FT에서는 S_U와 S_V가 real-valued optimized parameter가 되므로 같은 strict orthogonal identity로 해석하지 않습니다. BlockLDLQ는 vector block을 quantize하면서 이미 생긴 error를 뒤 block에 전달합니다. E8P는 16-bit index와 공유 1 KiB structure로 8D 2-bit code를 decode하고 RVQ가 3-bit와 4-bit를 구성합니다. 2-bit code rate는 일반 deployment memory 전체의 측정값이 아닙니다. Theory, PPL table, GPU throughput은 각각 다른 범위의 근거입니다.
