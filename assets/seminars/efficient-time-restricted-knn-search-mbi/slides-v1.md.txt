# 시간 제약 kNN 검색과 Multi-Level Block Indexing

논문: Efficient Time-Restricted kNN Search in High-Dimensional Data Using Multi-Level Block Indexing, with Extensions to Multi-Attribute Filtering

저자: Jisoo Kang · Changhun Han · Suji Kim · Ha-Myung Park (2026)

## 1. 시간 제약 kNN 검색과 Multi-Level Block Indexing

검색 범위가 좁아도 넓어도 대응하는 다중 해상도 인덱스


근거: [tkdd-paper](https://doi.org/10.1145/3789265) title page; publication footer

## 2. 벡터 유사도와 시간 조건을 동시에 만족해야 한다

가까운 벡터를 찾되, 지정한 시간 구간 밖의 벡터는 결과가 될 수 없다.

1. **질의 벡터 w**: 유사도 기준점
2. **시간 창**: 허용 후보 제한
3. **거리 계산**: 후보 안에서 순위
4. **top-k**: 가장 가까운 k개

핵심: 필터와 근접 검색 중 어느 것을 먼저 하느냐가 시간 창 크기에 따라 유불리를 바꾼다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §1; §3.1

## 3. T-kNN 질의의 정확한 의미

q=(w,k,t_s,t_e)는 벡터, 결과 수, 시작 시각, 종료 시각을 함께 지정한다.


| 기호 | 뜻 | 판정 |
| --- | --- | --- |
| w | 질의 벡터 | 거리의 기준 |
| k | 반환할 이웃 수 | 최종 결과 개수 |
| t_s | 포함되는 시작 | t_s <= t |
| t_e | 제외되는 끝 | t < t_e |
| D[t_s:t_e] | 허용된 벡터 집합 | 반개구간 [t_s,t_e) |

핵심: 종료 시각 t_e에 정확히 놓인 벡터는 후보에 포함되지 않는다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §3.1; Table 1

## 4. 이 논문이 푸는 것은 approximate kNN이다

빠른 검색을 위해 graph-based ANN을 사용하고, 정확도는 recall@k로 통제한다.

- 결과는 시간 또는 속성 조건을 만족해야 한다.
- 거리 기준의 진짜 top-k와 완전히 같다는 보장은 없다.
- 실험은 목표 recall@k에서 queries per second를 비교한다.
- 따라서 speedup은 같은 recall 조건 안에서 읽어야 한다.

핵심: 필터 조건의 준수와 최근접 이웃의 정확성은 서로 다른 평가 축이다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §2.1; Algorithms 3, 5; §5.1.3

## 5. 두 단순 전략은 반대 범위에서 강하다

필터를 먼저 할지, 근접 그래프를 먼저 탐색할지가 핵심 선택이다.


| 방법 | 먼저 하는 일 | 강한 조건 | 약한 조건 |
| --- | --- | --- | --- |
| BSBF | 시간 구간 찾기 | 좁은 시간 창 | 넓은 시간 창 |
| AFBF | 속성 전수 필터 | 통과 후보가 적음 | 통과 후보가 많음 |
| SF | 전체 graph 탐색 | 넓은 필터 | 좁은 필터 |
| MBI | 블록 크기 선택 | 범위에 맞춰 전환 | 추가 저장공간 필요 |

핵심: MBI는 하나의 고정 순서 대신, 질의 범위에 맞는 검색 해상도를 선택한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §3.2; Algorithms 1–3

## 6. BSBF: 시간으로 자른 뒤 전부 비교한다

1. **정렬된 시간축**: timestamp 순서
2. **binary search**: [t_s,t_e) 경계
3. **brute-force**: 구간 안 거리 계산
4. **top-k**: 가까운 k개

핵심: 구간 안 벡터 수 b가 작으면 빠르지만, b가 전체 n에 가까워지면 거의 전수 검색이다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 1; §3.2.1

## 7. SF: 근접 graph를 걷고 시간 조건으로 거른다

1. **임의 시작점**: candidate set 생성
2. **가까운 정점**: graph 이웃 확장
3. **시간 검사**: [t_s,t_e)만 채택
4. **k개 확보**: 근사 이웃 반환

핵심: 시간 창이 좁으면 방문한 가까운 정점 대부분이 탈락해 탐색 범위가 커질 수 있다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 3; §3.2.2

## 8. 시간 창이 바뀌면 병목도 바뀐다

같은 데이터와 질의 벡터라도 필터 비율이 계산량의 위치를 바꾼다.


| 시간 창 | BSBF의 일 | SF의 낭비 | 유리한 쪽 |
| --- | --- | --- | --- |
| 매우 좁음 | 소수만 거리 계산 | 탈락 정점 다수 | BSBF |
| 중간 | 거리 계산 증가 | 탈락 감소 | 교차 구간 |
| 매우 넓음 | 거의 전체 비교 | 대부분 채택 | SF |
| 질의마다 변화 | 고정 전략 불리 | 고정 전략 불리 | MBI 동기 |

핵심: MBI의 목적은 특정 baseline을 없애는 것이 아니라, 적절한 단위에서 사용하게 만드는 것이다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.1; Fig. 7

## 9. MBI의 핵심: 같은 데이터를 여러 크기로 본다

작은 시간 블록부터 전체 기간 블록까지, 각 수준에 검색 가능한 단위를 둔다.

1. **leaf blocks**: 짧은 연속 구간
2. **pair merge**: 인접 구간 합치기
3. **upper blocks**: 더 넓은 구간
4. **query match**: 맞는 크기 선택

핵심: 다중 해상도가 범위 적응성을 주지만, 벡터와 인덱스를 여러 수준에 중복 저장한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Fig. 1; §4.2

## 10. 블록 B_i는 구간만이 아니라 검색 단위다


| 구성 | 내용 | 역할 |
| --- | --- | --- |
| D_i | timestamped vectors | 블록의 데이터 |
| G_i | graph-based kNN index | 큰 블록의 근사 검색 |
| B_i.ts | 가장 이른 timestamp | 겹침 시작 계산 |
| B_i.te | exclusive upper timestamp | 겹침 종료 계산 |
| S_L | leaf 최대 크기 | 깊이·공간·build 조절 |

핵심: 블록 선택은 시간 범위를 고르고, 블록 내부 index는 고차원 근접 탐색을 맡는다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Table 1; Algorithm 5

## 11. 시간 블록은 포함 관계로 계층을 이룬다

아래는 구조를 읽기 위한 예시이며, 모든 구간은 끝점을 제외한다.


| 수준 | 블록 구간 | 포함 관계 |
| --- | --- | --- |
| root | [0,16) | 전체 |
| level 1 | [0,8), [8,16) | root를 둘로 분할 |
| level 2 | [0,4), [4,8) | 왼쪽 parent의 children |
| level 2 | [8,12), [12,16) | 오른쪽 parent의 children |

핵심: 인접한 두 child의 데이터 합집합이 parent 데이터를 만든다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Fig. 1; §4.2

## 12. 증분 삽입은 가장 최신 leaf에서 시작한다

1. **새 벡터 도착**: 최신 timestamp
2. **마지막 leaf**: 빈 자리 확인
3. **vector append**: D_i에 추가
4. **leaf full?**: S_L 도달 검사

핵심: 이 경로는 새 timestamp가 기존 모든 timestamp보다 늦다는 가정에 의존한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.2; Algorithm 4

## 13. leaf가 차면 아래에서 위로 index를 갱신한다

새 leaf의 graph를 만든 뒤, sibling과 합쳐 필요한 ancestor graph를 구축한다.

- **레인 index build**
  - **full leaf**: 크기 S_L 도달
  - **leaf graph**: BuildKNNIndex
  - **sibling union**: 두 vector set 합침
  - **parent graph**: ancestor 반복 구축
- full leaf → leaf graph: full (실선, 단방향)
- leaf graph → sibling union: vector set (실선, 단방향)
- sibling union → parent graph: bottom-up (실선, 단방향)

핵심: 부모 graph는 child graph를 이어 붙이는 것이 아니라, 합친 vector set에서 새로 구축한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Fig. 3; Algorithm 4

## 14. 서로 다른 블록 index는 병렬로 만들 수 있다

- **full leaf event**: ancestor block 확인
- **lower block**: G4 구축
- **upper blocks**: G5·G6 구축
- **index set**: 완성 graph 등록
- **query-ready MBI**: 각 block 독립 검색

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.2, Parallelization of MBI

## 15. virtual block은 불완전한 tree의 탐색 경로를 유지한다

- 증분 삽입 중에는 완전 이진 tree가 아닐 수 있다.
- virtual block은 시간 범위를 음의 무한대부터 양의 무한대로 둔다.
- 무한한 block 길이 때문에 threshold 선택 대상이 되지 않는다.
- 대신 실제 descendant까지 top-down 탐색을 이어 준다.

핵심: virtual block은 데이터나 결과를 담는 검색 블록이 아니라 구조적 연결 장치다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Figs. 2–3; §4.3

## 16. 질의는 block 선택, 내부 검색, 전역 병합으로 진행된다

- **레인 query**
  - **q input**: w,k,[t_s,t_e)
  - **BlockSelection**: top-down 선택
  - **per-block search**: BSBF 또는 SF
  - **global top-k**: 후보 union 후 정렬
- q input → BlockSelection: time window (실선, 단방향)
- BlockSelection → per-block search: search blocks (실선, 단방향)
- per-block search → global top-k: local candidates (실선, 단방향)

핵심: 선택된 block들은 시간상 겹치지 않으며, 최종 k개는 모든 block 후보를 함께 비교해 정한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 5; §4.3

## 17. overlap ratio는 block 중 실제 질의가 차지하는 비율이다

r_o = 겹치는 시간 길이 / block의 전체 시간 길이


| block | query와 겹침 | block 길이 | r_o |
| --- | --- | --- | --- |
| [0,16) | [5,14): 길이 9 | 16 | 9/16=.5625 |
| [0,8) | [5,8): 길이 3 | 8 | 3/8=.375 |
| [4,8) | [5,8): 길이 3 | 4 | 3/4=.75 |
| [8,16) | [8,14): 길이 6 | 8 | 6/8=.75 |

핵심: 같은 질의라도 작은 block에서는 overlap ratio가 커질 수 있다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.3, overlap ratio equation

## 18. top-down block 선택의 세 경우


| 조건 | 동작 | 이유 |
| --- | --- | --- |
| r_o = 0 | skip | 질의와 겹치지 않음 |
| leaf | select | 더 작은 실제 block이 없음 |
| r_o가 threshold 충족 | select | 현재 해상도가 충분함 |
| internal, threshold 미충족 | descend | 더 맞는 child 탐색 |

핵심: tau는 검색 정확도의 임계값이 아니라 block 해상도를 고르는 임계값이다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 5 lines 11–20; §4.3

## 19. tau가 block 해상도를 조절한다


| tau | 선택 경향 | 장점 | 위험 |
| --- | --- | --- | --- |
| 0에 가까움 | root 쪽 큰 block | block 수 감소 | 좁은 창에서 SF 낭비 |
| 약 0.5 | 중간 해상도 | 실험상 안정적 | dataset tuning 필요 |
| 1에 가까움 | leaf 쪽 작은 block | 불필요 후보 감소 | block 수와 overhead 증가 |

핵심: tau를 높이면 항상 빨라지는 것이 아니라, 검색 block 수와 내부 낭비 사이의 균형이 바뀐다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Fig. 4; §4.3; §5.4.2

## 20. 구성 예제: q=[5,14), tau=.6에서 block 고르기

논문 규칙을 작은 균형 tree에 적용한 교육용 계산이다.


| 검사 block | r_o | 판정 | 다음 |
| --- | --- | --- | --- |
| [0,16) | .5625 | 미충족 | 두 child로 이동 |
| [0,8) | .375 | 미충족 | 두 child로 이동 |
| [0,4) | 0 | skip | 종료 |
| [4,8) | .75 | select | 검색 집합에 추가 |
| [8,16) | .75 | select | 검색 집합에 추가 |

핵심: 최종 search block set은 {[4,8), [8,16)}이고 두 block은 시간상 겹치지 않는다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 5; §4.3

## 21. 구성 예제: block 탐색 결과를 전역 병합한다

- **block [4,8)**: X 제외, A .30, B .45
- **block [8,16)**: Y 제외, C .25, D .40
- **eligible union**: A, B, C, D
- **global top-3**: C .25, A .30, D .40

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 5 lines 3–10

## 22. 선택 뒤에는 block 상태에 따라 내부 검색이 달라진다


| 선택 block | 내부 index | 사용 방법 | 후처리 |
| --- | --- | --- | --- |
| non-full leaf | 비어 있음 | BSBF | 시간 조건 유지 |
| full leaf | graph 있음 | SF | 시간 조건 검사 |
| internal block | graph 있음 | SF | 시간 조건 검사 |
| 여러 block | 각자 독립 | 병렬 가능 | union 후 global top-k |

핵심: MBI는 block selection만 제안하는 것이 아니라, block 상태와 기존 검색법을 결합한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 5 lines 4–9

## 23. tau <= .5이면 처리 block은 최대 두 개다

- 질의 창을 처음 둘로 나누는 parent를 기준으로 본다.
- 왼쪽 조각은 한 descendant 경로에서만 선택된다.
- 오른쪽 조각도 대칭적으로 한 경로에서만 선택된다.
- 따라서 각 조각당 한 block, 전체 최대 두 block이다.

핵심: 작은 tau 영역의 block 호출 수는 tree 깊이에 비례해 폭증하지 않는다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.5.3, Lemma 1

## 24. 이론 비용은 index 선택과 graph 가정에 함께 의존한다


| 대상 | 논문 결과 | 전제 |
| --- | --- | --- |
| index size | O(\|D\| log \|D\|) | 수준별 중복 |
| total build | O(\|D\|^1.14) | NNDescent 경험 모델 |
| amortized append | O(\|D\|^0.14) | ordered arrival |
| query, tau<=.5 | O(log(N_q/tau)+k/tau) | 최대 두 block |
| query, tau>.5 | O(log²(N_q/tau)+(k/tau)log(N_q/tau)) | 여러 level 가능 |

핵심: N_q는 query 시간 창 안 벡터 수이며, 상한은 분석 가정에 조건부다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.5.1–4.5.3; Theorems 1–2

## 25. 빠른 범위 적응의 대가는 level별 중복이다

1. **leaf copy**: 짧은 구간 vector
2. **parent copy**: child union 저장
3. **ancestor copies**: 여러 level 반복
4. **total space**: O(|D| log |D|)

핵심: MBI는 한 벡터를 한 번만 저장하는 index가 아니며, 검색 속도와 공간을 교환한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.5.1; Table 4

## 26. m-AkNN은 시간 하나를 m개 수치 속성으로 확장한다


| 요소 | T-kNN | m-AkNN |
| --- | --- | --- |
| filter axes | timestamp 1개 | numeric attributes m개 |
| query bounds | [t_s,t_e) | 각 축 [lower_i,upper_i) |
| tree | binary | 2^m-ary |
| non-full leaf | BSBF | AFBF |
| updates | ordered append | static only |

핵심: 이 확장은 index 구성과 update 가능성을 함께 바꾼다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §3.1; §4.4; Table 1

## 27. multi-attribute 공간은 밀도에 따라 나눈다

1. **root range**: 속성별 min·max
2. **midpoint split**: 각 축을 둘로
3. **2^m children**: vector 재배치
4. **size <= S_L**: leaf에서 종료

핵심: m=2는 quadtree, m=3은 octree이며 데이터가 밀집한 영역이 더 깊게 나뉜다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Fig. 5; Algorithm 6; §4.4.1

## 28. 여러 속성의 overlap은 축별 비율을 곱한다

아래 수치는 공식을 읽기 위한 구성 예제이며, 축별 비율을 product로 결합한다.


| 속성 | block 범위 | query 범위 | 겹침 비율 |
| --- | --- | --- | --- |
| a1 | [0,10) | [2,8) | 6/10=.6 |
| a2 | [0,20) | [5,15) | 10/20=.5 |
| product | 두 축 결합 | 동시 조건 | .6×.5=.3 |

핵심: 한 축에서 overlap이 0이면 product도 0이므로 해당 block 전체를 건너뛴다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §4.4.2, overlap ratio equation

## 29. m-AkNN query는 같은 선택 틀에 다른 filter를 넣는다

1. **m ranges**: 속성별 반개구간
2. **product overlap**: top-down 선택
3. **AFBF 또는 SF**: block 내부 검색
4. **global top-k**: 후보 병합

핵심: 시간축의 binary search를 쓸 수 없으므로 non-full leaf에서 AFBF를 사용한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Algorithm 7; Fig. 6; §4.4.2

## 34. MBI는 시간 창 길이에 걸쳐 교차점을 완화한다


| 관찰 | 근거 | 경계 |
| --- | --- | --- |
| BSBF 하락 | window가 넓을수록 QPS 감소 | eligible count 증가 |
| SF 하락 | window가 좁을수록 QPS 감소 | filter reject 증가 |
| MBI 안정 | 여섯 dataset 전 범위 우세 | tuned tau 사용 |
| 최대 10.88× | faster-of-BSBF/SF보다 빠름 | hypothetical baseline |

핵심: 최대 speedup은 모든 질의의 평균이나 보장값이 아니라 Figure 7에서 관찰된 조건부 최대다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Fig. 7; §5.2

## 35. recall-speed curve 전체를 봐야 한다

- epsilon을 1.0부터 1.4까지 0.02 간격으로 바꾼다.
- 각 방법의 recall과 QPS trade-off를 곡선으로 만든다.
- Figure 8은 COMS의 10%, 30%, 80% window를 비교한다.
- recall=.995의 한 점뿐 아니라 frontier 형태도 확인한다.

핵심: 정확도를 낮춰 얻은 속도를 동일 정확도의 개선으로 읽으면 안 된다.

## 38. S_L과 tau는 서로 다른 비용을 조절한다


| parameter | 작게 두면 | 크게 두면 | 논문 관찰 |
| --- | --- | --- | --- |
| S_L | tree 깊고 index 많음 | leaf scan 커짐 | depth 5–10 균형 |
| tau | 큰 block, 적은 호출 | 작은 block, 많은 호출 | 약 .5가 대체로 양호 |
| epsilon | 좁은 graph 탐색 | 넓은 graph 탐색 | recall-QPS 조절 |

핵심: tau는 block 선택, epsilon은 graph 탐색 범위를 조절한다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) Figs. 10–11; §5.4

## 41. MBI가 보장하거나 지원하지 않는 것


| 경계 | 현재 범위 | 의미 |
| --- | --- | --- |
| neighbor accuracy | approximate | exact top-k 보장 아님 |
| T-kNN updates | 시간순 append | 임의 삽입·삭제 미지원 |
| m-AkNN updates | static dataset | 삽입·삭제 미지원 |
| space | O(\|D\| log \|D\|) | level별 중복 |
| optimality | open problem | 형식적 최적성 미증명 |

핵심: MBI는 범위 적응형 설계지만 모든 동적 update를 지원하지 않는다.

근거: [tkdd-paper](https://doi.org/10.1145/3789265) §6, Limitations and Future Work
