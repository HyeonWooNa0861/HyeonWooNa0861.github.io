## 1. Bancroft: HBM 밖 게놈 데이터를 위한 압축 경로

1. Bancroft: HBM 밖 게놈 데이터를 위한 압축 경로

발표 대본

## 2. 왜 빠른 HBM이 있어도 큰 게놈 작업은 멈추는가

2. 왜 빠른 HBM이 있어도 큰 게놈 작업은 멈추는가

발표 대본
논문은 가속기가 HBM처럼 빠르지만 비교적 작은 메모리를 가진다는 점을 출발점으로 둡니다. 여기서 on-device는 FPGA 또는 GPU 카드에 붙은 메모리라는 물리적 위치입니다. Bancroft가 해결하려는 것은 저장된 대규모 데이터에 가속기 연산을 연결하는 문제이지, HBM 용량 자체를 늘리는 기술이 아닙니다.

## 3. 용량과 대역폭은 다른 제약이다

3. 용량과 대역폭은 다른 제약이다

발표 대본
이 구분이 발표 전체의 핵심입니다. HBM capacity는 reference와 buffer를 몇 개나 둘 수 있는지를 제한합니다. HBM bandwidth는 이미 HBM에 있는 reference를 얼마나 빨리 읽는지를 말합니다. 압축 DB는 host 쪽에 있고, PCIe에는 여전히 compressed page가 흐릅니다. 따라서 논문의 effective bandwidth는 압축률의 도움을 받은 데이터 공급 효과이지 PCIe 사양의 교체가 아닙니다.

## 5. 전체 경로: host의 압축 DB를 FPGA 안에서 복원한다

5. 전체 경로: host의 압축 DB를 FPGA 안에서 복원한다

발표 대본
Fig. 3과 Fig. 5의 데이터 의존관계를 재구성했습니다. Host의 compressed page는 PCIe를 통해 decoder에 도달합니다. Decoder는 header의 offset에 따라 HBM reference의 실제 base data를 읽어 복원 stream을 user kernel에 보냅니다. 두 실선 입력은 압축 페이지와 reference data로 역할이 다릅니다. Host B+ tree는 원본 file-line offset을 compressed 4 KB page로 찾는 별도 metadata이며 HBM reference의 위치를 찾는 구조가 아닙니다. 도식은 data 공급만 나타내고 reference request나 buffer 제어의 모든 wire를 묘사하지 않습니다.

## 8. base compression: fixed K와 fixed S로 한 창씩 전진

8. base compression: fixed K와 fixed S로 한 창씩 전진

발표 대본
고정 K-mer가 exact match이면 32-bit offset으로 encode하고 K만큼 이동합니다. 어느 후보도 맞지 않으면 S base를 verbatim으로 encode하고 S만큼 이동합니다. cuckoo hash는 false negative를 낼 수 있으나, 그 경우 exact match를 놓쳐 압축률이 떨어질 뿐 decoder의 correctness는 깨지지 않습니다. 논문은 prototype에서 K=64, S=16을 사용합니다.

## 25. 정리: 압축 format이 memory hierarchy의 일부가 된다

25. 정리: 압축 format이 memory hierarchy의 일부가 된다

발표 대본
논문을 한 문장으로 요약하면, accelerator memory에 다 들어가지 않는 genomics data를 압축으로 host에 보관하고, hardware-friendly fixed format으로 FPGA에서 즉시 복원해 user kernel에 공급하는 platform입니다. 가장 중요한 비판적 독해는 capacity, raw bandwidth, effective bandwidth, and evaluation labels를 한 단어의 ‘성능’으로 섞지 않는 것입니다.
