## 3. 2-bit PTQ의 출발점: 작은 코드와 빠른 조회를 함께 얻기

가중치 하나씩 반올림하는 대신 8개를 묶어 벡터 코드로 표현하지만, 큰 코드북은 다시 병목이 된다

1. **학습 완료 LLM**: W를 재학습 없이 압축
2. **8개 묶음**: 한 열의 연속 8개 행
3. **벡터 코드**: 16-bit code 하나로 묶음 표현
4. **직접 E8 표**: 65,536개 8-D 점은 1 MiB
5. **EPTQ 질문**: 점 수는 유지하며 표를 줄일 수 있나

핵심: EPTQ의 설계 문제는 단지 bit 수가 아니라 코드북이 cache에 머무를 수 있는가다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) pp. 3–4, Sec. 4.1

## 4. 양자화 목표는 출력 변화가 작은 W-hat 찾기

입력 X에 대한 원래 출력과 양자화 출력의 차이를 작게 만들려 한다

- **원래 상태**: 가중치 W와 calibration 입력 X
- **원래 출력**: W와 X의 곱
- **양자화 출력**: W-hat와 X의 곱
- **출력 차이**: 두 출력의 Frobenius 거리
- **양자화 함수**: 낮은 bpw로 차이를 줄이는 W-hat

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 3, Eq. (1)

## 5. 양자화 단위는 한 column 안의 8-row vector

행 방향으로 8개를 잘라 같은 column j의 벡터 v를 만든다

- **레인 가중치 행렬**
  - **W의 일부**
    - row | col j
    - 8b | w
    - … | w
    - 8b+7 | w
  - **8-row 선택**: 8b부터 8b+7
  - **8-D vector v**: 고정된 column j
  - **16-bit code**: 정상 벡터 하나
- W의 일부 → 8-row 선택 (실선, 단방향)
- 8-row 선택 → 8-D vector v (실선, 단방향)
- 8-D vector v → 16-bit code (실선, 단방향)

핵심: 이 방향을 알아야 column-wise compensation과 scale alpha의 의미를 올바르게 읽을 수 있다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) pp. 5–7, Algorithms 2–3

## 6. 4-D half의 type은 좌표 형식과 합의 parity로 정한다

8-D E8 vector를 두 4-D half로 나눈 뒤, 각 half에 두 이진 속성을 붙인다


| type | 좌표 | 좌표합 parity | 강의용 예 |
| --- | --- | --- | --- |
| 0 | integer | even | (1,1,0,0) |
| 1 | half-integer | even | (.5,.5,.5,.5) |
| 2 | integer | odd | (1,0,0,0) |
| 3 | half-integer | odd | (-.5,.5,.5,.5) |

핵심: type은 값의 크기가 아니라 integer 여부와 parity를 함께 기록한 분류다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 3, Sec. 4.1.1

## 7. E8 후보는 같은 type의 두 half만 결합한다

E8은 네 개의 same-type 4-D product의 서로 겹치지 않는 합으로 분해된다

- **8-D vector**: 앞 4-D half a와 뒤 4-D half b
- **half a type**: integer/half와 parity 판별
- **half b type**: 같은 두 속성을 판별
- **same type 검사**: 두 type이 같아야 허용
- **E8 candidate**: F_t와 F_t의 pair

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 4, Eq. (2) and Sec. 4.1.1

## 8. 강의용 type 조합: parity가 다르면 결합할 수 없다

아래 숫자는 원문 실험이 아닌 같은-type 규칙을 확인하는 작은 예다


| 앞 half | 뒤 half | 판정 | 이유 |
| --- | --- | --- | --- |
| (1,1,0,0) | (2,0,0,0) | 가능 | 둘 다 integer-even |
| (1,0,0,0) | (0,0,1,0) | 가능 | 둘 다 integer-odd |
| (1,1,0,0) | (1,0,0,0) | 불가 | even과 odd가 다름 |
| (.5,.5,.5,.5) | (-.5,.5,.5,.5) | 불가 | half-even과 half-odd |

핵심: 두 half가 모두 integer여도 parity가 다르면 같은 E8 product에 속하지 않는다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 4, Eq. (2)

## 9. FE8: 512개 4-D vector로 65,536개 후보 만들기

각 type에서 원점에 가까운 128개 4-D point만 저장하고, 같은 type pair를 조합한다

1. **4개 type**: 각 type을 따로 보관
2. **128개씩**: 4-D representative 512개
3. **same-type pair**: type t 안에서 i와 j 결합
4. **4×128²**: 65,536개 8-D candidate
5. **한 code**: t, i, j를 16 bit에 pack

핵심: FE8은 후보 수를 줄인 것이 아니라 후보의 저장 표현을 factorization으로 바꾼다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 4, Sec. 4.1.1

## 10. 코드북 table footprint 계산

동일한 65,536개 8-D candidate 수에 대해 직접 저장과 FE8 저장은 다르다


| 표현 | 저장 대상 | 계산 | 크기 |
| --- | --- | --- | --- |
| 직접 E8 | 65,536개의 8-D FP16 | 65,536×8×2 B | 1 MiB |
| FE8 | 512개의 4-D FP16 | 4×128×4×2 B | 4 KiB |
| 비율 | 코드북 table만 | 1 MiB / 4 KiB | 256× |

핵심: 256×는 코드북 table만의 footprint 비율이지 전체 model 저장·속도 비율이 아니다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 4, Sec. 4.1.1

## 11. FE8 search는 type별 두 half 거리의 합을 비교한다

4개 type마다 128개 후보와의 거리를 계산한 뒤, 한 type 안의 최적 pair를 고른다

- **8-D vector v**: 앞 half a와 뒤 half b, scale alpha
- **앞 half 거리**: a와 type t의 128개 비교
- **뒤 half 거리**: b와 같은 type t의 128개 비교
- **type t 비용**: 두 최소 거리의 합
- **최종 pair**: 가장 작은 t와 i, j

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 4, Sec. 4.1.2 and Eq. (3)

## 12. 16-bit code는 type과 두 subindex를 pack한다

정상 code 하나가 type t와 두 7-bit 위치 i, j를 나타내며 마지막 code는 sentinel이다

1. **type t**: 0부터 3까지
2. **앞 index i**: 0부터 127까지
3. **뒤 index j**: 0부터 127까지
4. **강의용 계산**: t=2, i=3, j=5이면 33,157
5. **reserved code**: 65,535는 FP16 보존 표식

핵심: sentinel은 code 공간의 한 값을 쓰므로 normal quantization code 하나를 포기하는 설계다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) pp. 4, 6, Sec. 4.1.2 and Sec. 4.3

## 13. WSN: quantization 전 scale 불균형 줄이기

가중치의 평균은 대체로 0에 가깝지만 row와 column의 크기는 크게 다를 수 있다

- **원래 W**: row와 column별 magnitude가 불균일
- **row scale g**: |W|의 row쪽 L1 mean 맞춤
- **column scale h**: |W|의 column쪽 L1 mean 맞춤
- **normalized W-prime**: W를 g와 h로 나눈 표현
- **FE8 quantization**: W-prime에서 더 균일한 검색

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) pp. 4–5, Sec. 4.2 and Fig. 3

## 14. WSN의 alternating scale update

scale g와 h가 안정될 때까지 row와 column을 교대로 조정한다

1. **초기화**: g와 h를 all-ones로 둔다
2. **row update**: 현재 h로 row L1 mean을 맞춤
3. **column update**: 현재 g로 column L1 mean을 맞춤
4. **수렴**: scale factor가 안정될 때 종료
5. **재표현**: W = W-prime elementwise (g h-transpose)

핵심: WSN은 reversible한 재매개화이며, 양자화 전 W-prime를 정돈하는 단계다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 5, Algorithm 1 and Sec. 4.2

## 15. 강의용 WSN 계산: scale을 곱해도 양자화 전 출력은 같다

작은 2×2 예로 W = diag(g) W-prime diag(h)를 직접 확인한다


| 항 | 값 | 계산 결과 |
| --- | --- | --- |
| W | [[2,4],[1,2]] | x=[1,2]이면 Wx=[10,5] |
| g | [3,1.5] | row scale |
| h | [2/3,4/3] | column scale |
| W-prime | all ones | diag(g)W-prime diag(h)x=[10,5] |

핵심: 이 등식은 양자화 전 재표현의 동일성만 보이며, 양자화 뒤 품질 보장은 아니다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 5, Algorithm 1 and Sec. 4.2

## 16. CWP score: 한 vector의 local loss proxy

제곱 오차를 calibration Gram 역행렬의 j번째 대각 성분으로 나눈 local score다

- **8-D vector v**: v와 FE8 quantized v-hat
- **numerator**: squared L2 quantization error
- **denominator**: 역행렬 (XXᵀ)⁻¹의 j,j 성분
- **S b,j**: error divided by selected diagonal
- **mask 후보**: 큰 score부터 preservation 후보

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) pp. 5, 10, Eq. (5) and Eq. (12)

## 17. rho와 Kneedle은 서로 다른 역할을 한다

rho는 score 곡선의 앞부분을 탐색할 크기이고, Kneedle이 matrix별 threshold tau를 선택한다

1. **N scores**: 모든 8-D vector score
2. **top K**: K=max(2, floor(N rho))
3. **정규화**: rank와 log score를 0부터 1로
4. **knee**: 곡선과 대각선 거리 최대
5. **tau와 mask**: S가 tau 이상이면 FP16 보존

핵심: rho가 10%여도 최종 보존 fraction f가 10%라는 뜻은 아니다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 6, Algorithm 2 and Eqs. (7)–(8)

## 18. 강의용 Kneedle 계산: rho=.1이 f=.1은 아니다

N=40, top K=4인 constructed score 예로 threshold와 realized fraction을 분리한다


| 순위 k | score | 정규 rank | 정규 log score | 거리 |
| --- | --- | --- | --- | --- |
| 1 | 1000 | 0 | 1 | 0 |
| 2 | 10 | 1/3 | 1/3 | 1/3 |
| 3 | 2 | 2/3 | .10034 | .23299 |
| 4 | 1 | 1 | 0 | 0 |

핵심: threshold 10이면 40개 중 2개만 남아 f=5%가 된다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 6, Algorithm 2 and Eqs. (7)–(8)

## 19. sentinel은 mask만 없애고 FP16은 남긴다

normal FE8 block과 preserved block의 저장 단위를 구분해야 bpw를 해석할 수 있다


| block | 저장 | 8 weights 기준 | bpw |
| --- | --- | --- | --- |
| normal | 16-bit FE8 code | 16 bits | 2 |
| preserved | sentinel + 8 FP16 | 16+128=144 bits | 18 |
| mask | 별도 1-bit mask | sentinel로 대체 | 별도 mask 없음 |

핵심: zero bit-overhead는 별도 mask에 대한 말이며 preserved vector 자체가 무료라는 뜻은 아니다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) pp. 6, 10, Sec. 4.3 and Appendix B

## 20. Appendix B의 bpw는 f와 scale vector를 함께 센다

표시된 식은 normal 2 bpw, preservation cost, g와 h storage로 구성된다

- bpw = 2 + 16f + 16(1/d-row + 1/d-col)
- f는 실제 preserved vector fraction이다
- 마지막 항은 FP16 g와 h vector의 matrix당 overhead다
- Appendix B는 per-column alpha의 storage를 명시적으로 세지 않는다

핵심: reported bpw는 f에 따라 변하고, alpha storage는 원고의 accounting 빈칸이다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 10, Appendix B

## 21. EPTQ Algorithm 3: mask와 column compensation

WSN 뒤에는 effective input으로 state를 만들고, column과 8-row block을 순서대로 처리한다

- **레인 offline PTQ**
  - **W와 X**: weight와 calibration
  - **WSN**: W-prime, g, h
  - **X-prime state**: X-prime와 Hessian state
  - **CWP mask**: critical block 미리 표시
  - **column loop**: FE8 또는 FP16, compensation
- W와 X → WSN (실선, 단방향)
- WSN → X-prime state (실선, 단방향)
- X-prime state → CWP mask (실선, 단방향)
- CWP mask → column loop (실선, 단방향)

핵심: CWP mask는 quantization loop 전에 만들고, W-prime의 현재 상태를 순차적으로 갱신한다

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) pp. 6–7, Algorithm 3 and Sec. 4.4

## 22. block 처리: FP16 보존 또는 FE8 quantization

critical 여부에 따라 raw original W가 아니라 그 시점의 W-prime block을 사용한다

- **현재 W-prime block**: column j의 8-row vector
- **critical block**: 현재 block을 FP16으로 남김
- **normal block**: alpha로 FE8 quantize
- **quantization error**: 현재 block과 출력 차이
- **remaining update**: 남은 column에 error compensate

근거: [eptq-draft](https://hyeonwoona0861.github.io/assets/pdfs/research/eptq-cikm/eptq-cikm.pdf) p. 7, Algorithm 3, lines 8–18

## 25. 38% faster than FP16은 한 Table 1 조건에서 재계산된다

Llama-2-13B, FE8 rho=.1의 decode throughput과 FP16 row를 비교한 상대 차이다

1. **비교 조건**: Llama-2-13B, same Table 1
2. **FP16 row**: 104.4 tok/s
3. **FE8 rho=.1**: 144.4 tok/s
4. **상대 계산**: 144.4 / 104.4 - 1
5. **결과**: 0.3831, 약 38.31%

핵심: ‘up to 38%’는 이 H100 decode 조건의 상대 비교이며, 보편 성능 주장이 아니다

## 26. Table 1에는 FE8이 느린 비교도 있다

Llama-2-70B에서는 QTIP와 FE8 rho=.02의 decode throughput을 그대로 읽어야 한다


| model | method | rho | bpw | decode tok/s |
| --- | --- | --- | --- | --- |
| Llama-2-70B | QTIP | 표기 없음 | 2.00 | 38.9 |
| Llama-2-70B | EPTQ FE8 | .02 | 2.02 | 36.4 |

## 28. Figure 6: rho가 아닌 realized global fraction

adaptive CWP가 만든 실제 전체 critical-weight ratio를 fixed-ratio baseline에도 같은 예산으로 준다

- adaptive CWP는 rho마다 matrix별 tau를 다르게 찾는다
- 그 결과의 전체 preserved fraction을 먼저 계산한다
- fixed-ratio CWP는 그 global fraction을 동일한 ratio로 사용한다
- Figure 6은 같은 realized ratio에서 adaptive가 더 낮은 PPL이라고 보고한다

핵심: x축을 rho로 읽으면 같은 preservation budget이라는 비교 조건을 놓친다

## 31. EPTQ를 한 문장으로 다시 조립하면

작은 FE8 table만으로 끝내지 않고 WSN과 CWP를 함께 넣어 2-bit PTQ의 quality–efficiency trade-off를 다룬다

1. **FE8**: same-type factorization으로 4 KiB table
2. **WSN**: W-prime의 row·column scale 정렬
3. **CWP**: local score로 critical block FP16 보존
4. **compensation**: column-wise error propagation
5. **조건부 결과**: H100 Table 1·2에서 quality와 speed 보고

핵심: 핵심은 2-bit code 하나가 아니라 코드북·분포·예외 block의 연결 설계다
