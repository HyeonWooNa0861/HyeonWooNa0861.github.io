## 1. EPTQ: Factored E8로 2-bit LLM 양자화 읽기

1. EPTQ: Factored E8로 2-bit LLM 양자화 읽기

발표 대본

## 3. 2-bit PTQ의 출발점: 작은 코드와 빠른 조회를 함께 얻기

3. 2-bit PTQ의 출발점: 작은 코드와 빠른 조회를 함께 얻기

발표 대본
원고는 scalar rounding만의 문제보다 vector quantization의 코드북 접근 비용을 문제로 둡니다. 8개 가중치를 하나의 벡터로 보고 16-bit code 하나를 저장하면 정상 벡터는 2 bits per weight가 됩니다. 그러나 직접 E8 코드북은 65,536개의 8차원 FP16 점을 보관해야 해 1 MiB입니다. EPTQ는 이 65,536개 후보의 조합 능력은 유지하면서 실제 저장 테이블을 줄이려 합니다.

## 6. 4-D half의 type은 좌표 형식과 합의 parity로 정한다

6. 4-D half의 type은 좌표 형식과 합의 parity로 정한다

발표 대본
E8 정의에서 4차원 half는 좌표가 정수인지 half-integer인지, 그리고 좌표합이 짝수인지 홀수인지로 네 type 중 하나가 됩니다. 표의 벡터는 type을 판별하는 강의용 예입니다. 예를 들어 (1,1,0,0)은 integer이고 합이 2라 type 0이며, (1,0,0,0)은 integer지만 합이 1이라 type 2입니다.

## 7. E8 후보는 같은 type의 두 half만 결합한다

7. E8 후보는 같은 type의 두 half만 결합한다

발표 대본
p. 4 Eq. 2의 핵심은 E8이 F_t 곱하기 F_t의 네 product로 정확히 분해된다는 점입니다. a와 b는 같은 parity class이고 같은 coordinate type이어야 합니다. 따라서 integer-even half와 integer-odd half를 섞어 후보로 쓰면 안 됩니다. 최적화도 각 half가 독립적으로 type을 고르는 것이 아니라, 하나의 t를 정한 뒤 그 t 안에서 두 half 거리를 함께 최소화합니다.

## 8. 강의용 type 조합: parity가 다르면 결합할 수 없다

8. 강의용 type 조합: parity가 다르면 결합할 수 없다

발표 대본
이 표는 앞 슬라이드의 정의를 산술로 확인합니다. 첫 행은 두 half가 모두 integer이고 합이 짝수라 type 0입니다. 둘째 행은 모두 integer-odd라 type 2입니다. 셋째와 넷째는 좌표 표현은 비슷해 보여도 parity가 달라 허용되지 않습니다. 실제 FE8 검색은 허용된 각 type에 대해 두 half의 거리 합을 계산한 뒤 가장 작은 type을 선택합니다.

## 9. FE8: 512개 4-D vector로 65,536개 후보 만들기

9. FE8: 512개 4-D vector로 65,536개 후보 만들기

발표 대본
각 type에서 원점에 가까운 128개의 4차원 point를 retain합니다. 그러면 총 512개의 4차원 벡터만 저장하고도 각 type에서 128 곱하기 128 pair를 만들 수 있습니다. 네 type을 합치면 65,536개의 8차원 quantization point가 됩니다. 원고는 이것이 full E8 codebook capacity와 맞는다고 설명합니다. 다만 FE8은 full E8의 직접 8차원 table을 보관하는 방식과 동일하다고 말하면 안 됩니다.

## 10. 코드북 table footprint 계산

10. 코드북 table footprint 계산

발표 대본

Table 1에서 Llama-3-8B의 rho=.02 rows를 보면 VPTQ는 2.27 bpw, WikiText-2 PPL 13.01, average 60.30입니다. EPTQ FE8은 2.03 bpw, PPL 11.95, average 58.82입니다. PPL 하나에서는 FE8이 더 좋지만 five-task average에서는 VPTQ가 더 좋습니다. 게다가 bpw도 완전히 같지 않습니다. 이 비교는 보고된 조건에서의 trade-off를 보여 주며 universal winner를 정하지 않습니다.

## 31. EPTQ를 한 문장으로 다시 조립하면

31. EPTQ를 한 문장으로 다시 조립하면

발표 대본
마지막으로 EPTQ의 세 component를 연결합니다. FE8은 codebook footprint를 작게 만들고, WSN은 quantizer가 보는 weight distribution을 정돈하며, CWP는 score가 큰 block을 FP16으로 예외 처리합니다.
