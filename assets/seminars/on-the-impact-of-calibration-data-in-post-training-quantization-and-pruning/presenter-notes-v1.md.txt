## 1. Calibration Data가 LLM PTQ·Pruning에 미치는 영향

1. Calibration Data가 LLM PTQ·Pruning에 미치는 영향

발표 대본
이 논문은 post-training quantization과 pruning에서 calibration data가 단순한 준비물이 아니라 압축 알고리즘의 입력이라는 점을 실증적으로 살핍니다. 발표의 중심 질문은 같은 모델과 같은 압축 방법을 써도 calibration text가 바뀌면 결과가 달라질 수 있는가입니다. 먼저 activation-dependent compression의 구조를 보고, 실험 격자와 결과를 읽은 뒤, 이 논문이 지지하는 실무 교훈과 지지하지 않는 과잉 해석을 구분합니다.

## 2. 먼저 범위: calibration은 training data가 아니다

2. 먼저 범위: calibration은 training data가 아니다

발표 대본
이 구분이 발표 전체의 출발점입니다. calibration text는 모델을 통과해 각 layer의 input activation을 만듭니다. 이 activation을 보고 양자화 level이나 남길 weight를 고르지만, 논문은 그 text의 정답으로 gradient를 계산해 원래 모델 weight를 학습시키지 않습니다. 평가 data는 압축 뒤 zero-shot accuracy와 WikiText perplexity를 재기 위해 별도로 둡니다. 저자들은 zero-shot evaluation data를 calibration source로 쓰지 않아 평가 무결성을 지키려 했습니다.

## 3. Calibration text가 압축 선택에 들어가는 경로

3. Calibration text가 압축 선택에 들어가는 경로

발표 대본
논문은 layer l의 원 weight W와 compressed weight Wc가 calibration activation X에서 만드는 출력 차이를 작게 하려는 layer-wise reconstruction 문제를 출발점으로 둡니다. 식을 말로 읽으면 W X와 Wc X의 제곱 차이를 작게 만드는 Wc를 고르는 것입니다. X는 calibration text에서 오므로, text 표본이 달라지면 proxy의 우선순위가 달라질 수 있습니다. 여기서 Wc는 원래 weight를 압축해 만든 표현이고, supervised fine-tuning으로 모든 model weight를 다시 학습한 결과가 아닙니다. proxy가 작다고 downstream accuracy나 latency가 자동으로 최적이라는 뜻도 아닙니다.

## 4. 교육용 toy: activation 표본이 후보 순위를 바꾼다

4. 교육용 toy: activation 표본이 후보 순위를 바꾼다

발표 대본
이 예는 논문 실험값이 아닙니다. 원 weight W를 1과 1의 두 성분으로 두고, 압축 후보 C1과 C2를 비교합니다. xA에서는 C1이 원 output을 정확히 재현하고 C2는 큰 오차를 냅니다. xB에서는 반대입니다. 실제 논문은 한 activation이 아니라 2,048-token example 128개에서 얻은 activation을 쓰고, 후보 selection도 각 GPTQ, SpQR, SparseGPT, Wanda의 절차를 따릅니다. 이 toy가 보이는 것은 calibration sample이 proxy에 들어가는 구조뿐이며, 특정 corpus feature가 성능 차이의 원인이라는 증명은 아닙니다.

## 5. 같은 calibration도 compressor가 읽는 방식은 다르다

5. 같은 calibration도 compressor가 읽는 방식은 다르다

발표 대본
GPTQ와 SpQR은 weight quantization 방법이고, SparseGPT와 Wanda는 pruning 방법입니다. GPTQ와 SparseGPT는 inverse-Hessian 정보를 사용합니다. Wanda는 inverse Hessian을 피하고 weight magnitude와 input activation의 l2 norm을 결합한 기준으로 prune합니다. 논문은 양자화와 pruning의 sensitivity가 다를 수 있음을 관찰했지만, 이 표만으로 어느 method가 본질적으로 우월하거나 어떤 mechanism이 분산의 원인이라고 증명하지는 않습니다.

## 6. 연구는 calibration 선택을 큰 실험 격자로 바꿨다

6. 연구는 calibration 선택을 큰 실험 격자로 바꿨다

발표 대본
저자들의 목표는 calibration data robustness를 보는 것입니다. 다섯 source에서 각 열 개의 calibration set을 만들고, 네 compression method와 아홉 LLM에 적용해 1,800개 compressed model을 만들었습니다. 각 model은 10개 zero-shot task와 WikiText perplexity, 즉 11개 evaluation을 거치므로 19,800 model-evaluation 결과가 됩니다. 이 수는 independent training seed의 개수가 아니라, 명시된 calibration source·set·method·model·metric 조합의 개수입니다.

## 7. 50 calibration set의 생성 규칙

7. 50 calibration set의 생성 규칙

발표 대본
각 calibration set은 128 example이며 example 하나는 2,048 tokens입니다. 따라서 set 하나의 총량은 262,144 tokens입니다. Sampling은 without replacement이고, 각 source에서는 열 개 calibration set이 서로 겹치지 않습니다. 공개 Hugging Face Datasets version을 사용했으며 C4와 RefinedWeb은 first shard, RedPajama는 existing 1B-token extract에서 sampling했습니다. 본문과 appendix는 50개 set의 seed 값이나 text 목록을 나열하지 않습니다. 저자들은 software/platform 차이 때문에 seed만으로는 부족할 수 있다며 calibration data 자체의 release를 권고합니다.

## 8. Source 비교는 단일 속성의 조작 실험이 아니다

8. Source 비교는 단일 속성의 조작 실험이 아니다

발표 대본
저자들은 random web text와 curated pretraining dataset을 함께 보기 위해 C4, CNN/DM, RedPajama, RefinedWeb, English Wikipedia를 골랐습니다. 그러나 dataset source를 바꾸면 genre, filtering, deduplication, date, length, pretraining overlap 가능성 등 여러 속성이 동시에 바뀝니다. 그러므로 RefinedWeb이 어떤 row에서 좋았다는 관찰을 ‘curation이 원인’ 또는 ‘뉴스는 나쁘다’로 바꿀 수 없습니다. source effect는 이 논문에서 feature-level causal isolation이 아니라 dataset-level comparison입니다.

9. 나머지 조건도 함께 고정해 읽어야 한다

## 17. 저자들의 세 가지 권고: release · vary · inspect

17. 저자들의 세 가지 권고: release · vary · inspect

발표 대본
논문의 권고는 세 가지입니다. 첫째, calibration data를 release해 randomness를 줄이고 reproducibility를 높입니다. Footnote는 code로 seed를 주더라도 software/platform version 차이 때문에 같은 set이 보장되지 않을 수 있다고 지적합니다. 둘째, 개발 중 여러 calibration set에서 downstream performance를 보며 sensitivity를 살핍니다. 셋째, set이 작으므로 random sample을 inspect해 anomalous example을 찾을 수 있습니다. 이는 권고를 따르면 accuracy가 반드시 상승한다는 theorem이 아니라, 실험과 diagnosis의 품질을 높이는 행동입니다. Version 기록은 이 권고를 재현 가능한 artifact 관리로 옮긴 실무적 확장입니다.

## 18. 이식 가능한 연구·실무 습관

18. 이식 가능한 연구·실무 습관

발표 대본
논문의 가장 전이 가능한 교훈은 single best corpus의 선택이 아니라 실험 설계입니다. Calibration set을 source, set ID, tokenizer, code version과 함께 artifact로 기록하고, 하나의 set에서 좋은 숫자가 나왔다는 이유만으로 method를 결론내리지 않습니다. PPL과 실제 intended task를 함께 보고, bit width나 sparsity 같은 compressor configuration도 표시합니다. 이 슬라이드는 논문이 직접 검증한 artifact schema를 제안하는 것이 아니라, 저자 권고와 observed variation을 reproducible practice로 옮긴 것입니다.

## 19. 이 논문이 아직 답하지 않는 것

19. 이 논문이 아직 답하지 않는 것

발표 대본
논문의 limitation은 모든 model, evaluation task, calibration data가 English라는 점입니다. 저자들은 compression method가 일반적으로 language-agnostic하다고 가정하지만 linguistic diversity의 중요성을 인정하고 diverse language family를 future work로 둡니다. 또한 source를 바꾼 비교는 여러 data property를 함께 바꾸므로, content feature 하나의 causal mechanism을 보여 주지 않습니다. 발표의 좋은 마무리는 이 논문이 넓은 empirical grid를 제공했다는 장점과, universal generalization·causal explanation은 남았다는 한계를 같이 보여 주는 것입니다.

## 20. 마무리: calibration은 압축 과정의 숨은 입력이다

20. 마무리: calibration은 압축 과정의 숨은 입력이다

발표 대본
결론은 간단합니다. Calibration data는 작은 input set이지만 activation-dependent compression에서는 직접적인 algorithm input입니다. 이 논문은 다양한 source와 set, compressor, model, task를 교차해 결과가 달라질 수 있음을 보여 줍니다. 동시에 특정 source가 항상 최고라는 결론, 한 data feature가 원인이라는 결론, 모든 language로의 일반화는 제공하지 않습니다. 따라서 실제 압축 연구에서는 calibration artifact와 protocol을 기록하고, 여러 set과 intended downstream task에서 sensitivity를 함께 확인하는 것이 가장 근거 있는 행동입니다.
