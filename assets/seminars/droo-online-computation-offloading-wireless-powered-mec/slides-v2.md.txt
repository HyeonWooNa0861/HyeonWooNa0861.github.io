# DROO: 무선 전력 MEC의 온라인 오프로딩

논문: Deep Reinforcement Learning for Online Computation Offloading in Wireless Powered Mobile-Edge Computing Networks

저자: Liang Huang, Suzhi Bi, Ying-Jun Angela Zhang (2020)

## 1. DROO: 무선 전력 MEC의 온라인 오프로딩

신경망이 이진 후보를 제안하고 해석적 최적화가 물리 제약을 만족시키는 구조


근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 1, abstract, [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 4-6

## 2. 무선 전력 MEC 시스템

하나의 AP가 에너지를 보내고 여러 WD의 오프로딩 데이터를 받는다


| 구성 요소 | 논문에서 맡는 역할 | 프레임에서 관측되는 값 |
| --- | --- | --- |
| AP | RF 에너지 전송과 MEC 계산 | 안정적인 전원과 높은 계산 능력 |
| WD | 에너지 수확 뒤 로컬 계산 또는 전송 | AP와의 현재 채널 gain |
| 무선 채널 | 수확 에너지와 uplink rate에 함께 영향 | 프레임 안에서는 고정, 프레임마다 변화 |

핵심: 현재 채널 gain은 에너지 수확과 데이터 전송 성능을 동시에 바꾼다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 2-3, §3.1

## 3. 한 프레임의 WPT와 오프로딩 시간

AP가 먼저 α 비율 동안 에너지를 보내고 선택된 WD가 남은 시간을 TDMA로 나눈다

- **레인 프레임 시간**
  - **WPT α**: AP가 RF 에너지 전송
  - **WD 1의 τ1**: 선택된 task 전송
  - **WD 2의 τ2**: 선택된 task 전송
  - **프레임 종료**: α와 모든 τ의 합은 1 이하
- WPT α → WD 1의 τ1 (실선, 단방향)
- WD 1의 τ1 → WD 2의 τ2 (실선, 단방향)
- WD 2의 τ2 → 프레임 종료 (실선, 단방향)

핵심: TDD 모델에서는 에너지 전송이 먼저이고 오프로딩 전송은 그 뒤에 이어진다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 3 (2583), Eq. (2) and §3.3

## 4. 각 task의 두 가지 실행 모드

논문은 task 분할 없이 로컬 계산과 완전 오프로딩 중 하나만 선택한다

- **WD의 한 task**: 프레임 안에 처리할 분할 불가 작업
- **x_i=0 로컬**: 수확 에너지로 WD CPU에서 계산
- **x_i=1 오프로딩**: 수확 에너지로 AP에 전체 task 전송
- **binary gate x_i**: 두 경로 중 한 mode의 rate만 선택
- **WD i 처리량**: 선택 mode rate에 weight를 적용

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 3-4, Eqs. 1-4

## 5. 모델이 단순화한 범위


| 가정 | 계산에서의 처리 | 해석할 때의 경계 |
| --- | --- | --- |
| AP 계산 시간 | 무시 | AP가 WD보다 훨씬 빠르다는 전제 |
| 결과 download | 무시 | 반환 데이터가 짧다는 전제 |
| channel reciprocity | 같은 gain 표기 | uplink와 downlink가 같다는 단순화 |
| task 분할 | 허용하지 않음 | 로컬 또는 전체 오프로딩만 비교 |

핵심: DROO의 성능 주장은 이 시스템 모델과 시간 가정 안에서 읽어야 한다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 3, §§3.1-3.3

## 6. 지수적 탐색 공간의 원인

N개 WD의 이진 선택은 2^N개의 local·offload pattern을 만든다

- WD가 3개면 가능한 이진 pattern은 8개다.
- WD가 20개면 가능한 pattern은 1,048,576개다.
- WD가 30개면 가능한 pattern은 1,073,741,824개다.
- 연속 변수 α와 τ보다 먼저, 이진 vector x를 찾는 단계가 조합 폭발을 만든다.
- 채널이 달라질 때마다 coherence time 안에서 같은 문제를 다시 풀어야 한다.

핵심: DROO는 2^N pattern 전체를 평가하지 않고 DNN 주변의 K개 후보만 평가한다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 3-4, §3.4, [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 3 (2583), §2 continued: DQN action search

## 7. 고정된 이진 pattern과 P2

x를 고정하면 남은 α와 τ 최적화는 볼록 문제로 바뀐다

- **현재 channel h**: 수확 에너지와 uplink 품질을 결정
- **고정 pattern x**: 각 WD의 local 또는 offload를 지정
- **볼록 P2**: 시간 제약 안에서 α와 τ를 최적화
- **후보 평가값**: Q*와 feasible 자원 배분을 반환

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 4, P1-P2 and Fig. 2

## 8. P2는 무엇을 최대화하는가

고정된 x에서 Q=Σ w_i[(1−x_i)r_L,i* + x_i r_O,i*]를 최대화한다


| 구성 | 수학적 조건 | 의미 |
| --- | --- | --- |
| 선택 변수 | α, τ_i | WPT와 장치별 전송 시간 비율 |
| 시간 제약 | α+Στ_i≤1; α,τ_i≥0 | 프레임 시간을 함께 사용 |
| 에너지 처리 | 각 모드의 r_L*, r_O*에 반영 | 수확 에너지 전량 사용에서 유도 |
| 볼록 최적화 | 고정 x의 오목 목적함수 최대화 | 선형 시간 제약 아래 후보별 해 계산 |

핵심: 이진 후보는 DNN·OPQ가 만들고 연속 시간 배분은 P2가 최적화한다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 3–4 (2583–2584), Eqs. (1)–(4), P2

## 9. DROO에서 구분해야 할 네 값


| 값 | 형식 | 역할 | 아직 아닌 것 |
| --- | --- | --- | --- |
| 현재 h_t | 연속 channel vector | DNN 입력 | 미래 channel 예측 |
| relaxed x_hat | 0과 1 사이 score | offload 순위 제안 | 실행 가능한 최종 action |
| binary x^k | 0 또는 1 vector | P2에 넣을 후보 | 자원 배분이 끝난 해 |
| α*, τ* | 연속 시간 배분 | P2가 계산 | DNN의 직접 출력 |

핵심: DNN score, binary action, 자원 배분을 한 단계로 합쳐 이해하면 안 된다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 5-6, Eqs. 5-10

## 10. OPQ의 네 후보 생성 예시

논문의 relaxed output [0.2, 0.4, 0.7, 0.9]에서 K=4 후보를 만든다


| 후보 | 적용한 경계 | binary action | 변경되는 위치 |
| --- | --- | --- | --- |
| x^1 | score>0.5이면 1 | [0,0,1,1] | 0.5와 같으면 0 |
| x^2 | threshold=0.4 | [0,1,1,1] | 경계값 0.4는 1 |
| x^3 | threshold=0.7 | [0,0,0,1] | 경계값 0.7은 0 |
| x^4 | threshold=0.2 | [1,1,1,1] | 경계값 0.2는 1 |

핵심: OPQ는 0.5와 가까운 score의 순서를 따라 서로 다른 binary 후보를 만든다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 5-6, Eqs. 7-9

## 11. OPQ에서 경계와 같은 값은 어떻게 처리하는가

기본 후보와 나머지 후보의 동률 처리 규칙을 구분한다


| 경우 | 이진 값 | 예시 |
| --- | --- | --- |
| 기본 후보 | score>0.5 →1; 그 외0 | score=0.5 →0 |
| 나머지 후보: score>b | 1 | b=0.4, score=0.7 →1 |
| 나머지 후보: score<b | 0 | b=0.7, score=0.4 →0 |
| score=b, b≤0.5 | 1 | b=score=0.4 →1 |
| score=b, b>0.5 | 0 | b=score=0.7 →0 |

핵심: 일반 K≤2^N과 이 OPQ의 K≤N+1은 서로 다른 범위다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 5–6 (2585–2586), Eqs. (7)–(9)

## 12. order-preserving의 정확한 뜻

- score_i≥score_j이면, 모든 후보에서 x_i^k≥x_j^k다.
- score 순위를 유지하면서 threshold를 바꿔 K개의 후보를 만든다.
- KNN 후보보다 서로 떨어진 pattern을 만들어 탐색 다양성을 높이려는 설계다.
- 모든 2^N action을 확인하지 않으므로 전역 최적 action 포함을 보장하지 않는다.

핵심: OPQ는 DNN의 상대 순위를 보존하는 후보 생성 규칙이지 exhaustive search가 아니다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 5-6, Eqs. 7-9, [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 10, Fig. 10

## 13. 한 프레임의 online 실행 경로

1. **channel 관측**: 프레임 시작에 현재 h_t를 읽는다.
2. **relaxed score**: DNN이 x_hat_t를 출력한다.
3. **K개 후보**: OPQ가 binary x_t^k를 만든다.
4. **P2 평가**: 각 후보의 Q*와 α*, τ*를 계산한다.
5. **선택과 실행**: 가장 큰 Q*의 x*_t와 자원을 실행한다.

핵심: 실행 action은 DNN 출력이 아니라 K번의 P2 평가 뒤에 결정된다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 5-6, Algorithm 1

## 14. P2는 후보별 자원 최적화·평가를 맡는다

‘analytical critic’은 이 역할을 설명하는 교육용 이름이며 원문의 P2를 가리킨다


| 구성 | 입력 | 출력 | 보장하거나 학습하는 것 |
| --- | --- | --- | --- |
| DNN | 현재 h_t | relaxed x_hat_t | binary 후보의 순위를 학습 |
| OPQ | relaxed score | K개 binary pattern | 순서를 보존한 후보 생성 |
| P2 | h_t와 x_t^k | Q*, α*, τ* | 시간 제약을 만족하는 최적 배분 |
| argmax | K개의 Q* | x*_t | 후보 집합 안에서 최고값 선택 |

핵심: P2는 learned value network가 아니라 후보마다 호출되는 볼록 optimizer다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 4-6, P2 and Algorithm 1

## 15. 실행 경험에서 다음 policy까지

online 선택 결과를 label로 저장하고 매 d 프레임마다 replay batch로 DNN을 갱신한다

- **레인 replay 학습**
  - **선택 pair**: 현재 h_t와 선택 x*_t
  - **replay memory**: 최근 pair → 이전 pair → 오래된 pair
  - **uniform batch**: 저장 pair를 무작위 추출
  - **Adam update**: cross-entropy loss 감소
  - **다음 policy**: 다음 프레임 DNN에 사용
- 선택 pair → replay memory (실선, 단방향)
- replay memory → uniform batch (실선, 단방향)
- uniform batch → Adam update (실선, 단방향)
- Adam update → 다음 policy (실선, 단방향)

핵심: runtime은 매 프레임 수행되지만 DNN training은 d 프레임 간격으로 수행된다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 6, §4.3 and Algorithm 1

## 16. adaptive K의 갱신 규칙

t mod D=0일 때, 현재 프레임 이전 D개의 선택 순위로 갱신한다

- **레인 K 갱신**
  - **초기 K1=N**: 넓은 후보 집합으로 시작
  - **최근 선택 순위**: 2위 → 3위 → 1위
  - **최대 순위+1**: 예시는 3+1로 계산
  - **다음 K=4**: 상한 N 안에서 적용
- 초기 K1=N → 최근 선택 순위 (실선, 단방향)
- 최근 선택 순위 → 최대 순위+1 (실선, 단방향)
- 최대 순위+1 → 다음 K=4 (실선, 단방향)

핵심: adaptive K는 P2 호출 수를 줄이는 경험적 cost·quality 조절이며 최적성 보장이 아니다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 6-7, §4.4

## 19. OPQ와 KNN 결과의 조건부 비교

N=10 fading simulation의 200-frame 이동평균으로 수렴을 비교했다


| 조건 | 논문 관측 | 말할 수 있는 범위 |
| --- | --- | --- |
| N=10, K=N | 두 방법 모두 normalized rate 1에 수렴 | 충분한 후보를 둔 simulation 결과 |
| N=10, K=2 | 두 방법 모두 약 0.95에 수렴 | 작은 K에서는 suboptimal 가능 |
| K가 2 이상 | OPQ가 KNN보다 빠르게 수렴 | 논문의 fading simulation 안의 비교 |
| K=1 | 두 방법 모두 수렴하지 않음 | action selection이 없어 policy 개선이 막힘 |

## 22. 적용 범위와 남은 한계

- binary policy는 한 task의 partial offloading을 허용하지 않는다.
- AP 계산 시간과 결과 download 시간은 모델에서 제외한다.
- state는 channel gain이며 queue·battery backlog를 포함하지 않는다.
- 각 후보마다 P2를 풀어야 하므로 analytical optimization 비용은 남는다.
- WD mobility는 channel 분포를 바꿔 policy 수렴을 어렵게 할 수 있다.

핵심: DROO는 후보 탐색을 줄이지만 모델 가정과 P2 호출 비용까지 제거하지는 않는다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 3-6, [ieee](https://doi.org/10.1109/TMC.2019.2928811) p. 12, §6

## 23. DROO와 LyDROO의 경계


| 비교 항목 | DROO | LyDROO |
| --- | --- | --- |
| 문제 환경 | 무선 전력 MEC | stochastic task arrival MEC |
| state | 현재 channel gain | channel·실제 큐·가상 전력 큐 |
| 목적 | 프레임별 weighted rate | 장기 처리량과 queue 안정성 |
| candidate | OPQ | OPQ + noisy OPQ (NOP) |
| 이론 경계 | queue 안정성 보장 없음 | 가정 아래 queue 안정성 분석 |

핵심: queue backlog와 Lyapunov 안정성은 후속 LyDROO의 문제이며 DROO에 소급되지 않는다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 3-6, [lydroo](https://doi.org/10.1109/TWC.2021.3085319) pp. 5–11 (7523–7529), Eqs. (5), (7), (20), (25)–(28), Theorem 1

## 24. DROO의 핵심 계산 구조

1. **현재 channel**: h_t가 수확과 uplink 조건을 정한다.
2. **DNN proposal**: relaxed score로 offload 순위를 제안한다.
3. **OPQ candidates**: 순위를 보존한 K개 binary action을 만든다.
4. **후보별 P2**: 각 후보의 feasible 자원과 Q*를 계산한다.
5. **선택과 학습**: 최고 후보를 실행하고 pair를 replay에 저장한다.

핵심: 학습이 이진 후보를 줄이고 P2가 각 후보 안의 연속 배분을 최적화한다

근거: [ieee](https://doi.org/10.1109/TMC.2019.2928811) pp. 4-7, Fig. 3 and Algorithm 1
