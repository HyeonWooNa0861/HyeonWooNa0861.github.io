# 의미 추출과 작업 전송의 공동 최적화

논문: QoE-Driven Multi-Task Offloading for Semantic-Aware Edge Computing Systems

저자: Xuyang Chen, Daquan Feng, Wei Jiang, Qu Luo, Gaojie Chen, Yao Sun (2026)

## 1. 의미 추출과 작업 전송의 공동 최적화

지연·에너지·정확도를 함께 고려하는 다중 작업 MEC와 MAPPO


근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) title page; abstract

## 2. 이 논문이 푸는 문제

서로 다른 작업의 지연·에너지·정확도를 한 QoE 척도로 맞춘 뒤, 의미 추출과 MEC 자원을 공동 최적화한다

- 텍스트·이미지·시각 질의응답은 계산량과 정확도 척도가 다르다
- 단말 실행, 직접 전송, 의미 추출 후 전송 중 실행 방식을 고른다
- 의미 추출 수준과 무선·계산 자원을 함께 선택한다
- 목표: 지연·에너지·정확도로 정의한 전체 QoE의 합을 높인다

핵심: 얼마나 전송할지와 어디서 계산할지를 함께 결정한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 1-2; §III-A; Eq. 11

## 3. 먼저 구분할 구성요소와 기호

장치·작업·학습 방법을 구분하고, 결정변수는 다음 그림에서 연결한다


| 기호·약자 | 뜻 | 역할 |
| --- | --- | --- |
| UE / ES | 사용자 단말 / 엣지 서버 | 작업 실행 위치 |
| OFDMA | 직교 주파수 분할 다중 접속 | 상향 전송 자원 배분 |
| VQA | 이미지에 관한 질문에 답하기 | 텍스트와 영상을 함께 처리 |
| ρ / μ | 전송 여부 / 의미 추출 계수 | 실행 방식과 전송량 결정 |
| MAPPO | 다중 에이전트 정책 학습 | 여러 UE의 선택 학습 |

핵심: μ가 작으면 더 압축하지만, 단말 계산 부담이 늘 수 있다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 1, 5–6; Table II

## 4. 작업마다 세 실행 경로 중 하나를 고른다

단말에서 완료하거나, 원래 데이터를 보내거나, 의미를 추출한 특징을 ES에 보낸다

- **레인 단말 완료**
- **레인 직접 전송**
- **레인 의미 추출 전송**
  - **UE 작업 큐**: 다양한 작업 유형 → 현재 작업 선택
  - **ρ, μ 선택**: 상태·자원에 맞춰 결정
  - **단말 실행**: ρ=0; UE에서 완료
  - **직접 전송**: ρ=1; μ=1
  - **의미 추출**: ρ=1; μ<1; encoder
  - **ES 실행**: 전송 데이터로 작업 완료
- UE 작업 큐 → ρ, μ 선택 (실선, 단방향)
- ρ, μ 선택 → 단말 실행 (실선, 단방향)
- ρ, μ 선택 → 직접 전송 (실선, 단방향)
- ρ, μ 선택 → 의미 추출 (실선, 단방향)
- 직접 전송 → ES 실행 (실선, 단방향)
- 의미 추출 → ES 실행 (실선, 단방향)

핵심: 단말 완료 경로는 ES로 가지 않으며, 직접 전송은 의미 추출을 생략한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 5; Fig. 1; §III

## 5. ρ와 μ가 세 실행 방식을 구분한다

한 작업의 완료 위치를 고르되, 의미 전송에서는 일부 모델 계산을 단말이 수행한다


| 모드 | 선택 조건 | 단말에서 하는 일 | ES에서 하는 일 |
| --- | --- | --- | --- |
| 단말 완료 | ρ=0 | 전체 작업 계산 | 해당 작업 실행 없음 |
| 직접 전송 | ρ=1, μ=1 | 의미 추출 없이 전송 | 전송된 작업 실행 |
| 의미 전송 | ρ=1, μ<1 | 특징 추출 후 전송 | 특징으로 작업 완료 |

핵심: atomic task는 임의의 작업 비율을 나누는 결정변수가 없다는 뜻이다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 5–6; §III-A,C; Eqs. 2–3

## 6. μ가 작아질수록 무엇이 바뀌나

더 강한 의미 추출은 전송량을 줄이지만, 단말 부담과 server-side task 성능 손실 가능성을 함께 만든다


| μ의 선택 | 단말 의미 추출 | 상향 전송 | 작업 성능 |
| --- | --- | --- | --- |
| μ=1 | 추가 추출 없음 | 추출에 의한 축소 없음 | 추출 손실 없음;<br>채널 영향 별도 |
| μ_min≤μ<1 | 더 작으면 부담 증가 | 더 작으면 전송량 감소 | 과도한 압축 시 저하 |
| 최소 μ | 정확도·배터리 고려 | 허용 범위의 최소 계수 | 설정만으로 충족 보장 아님 |

핵심: 추출 계산·전송량·정확도의 상충관계를 함께 고려한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 5-6; Fig. 2; §III-A

## 7. OFDMA 전송: 채널을 받은 UE만 upload한다

x_kn은 채널 k의 UE n 할당 여부, R_n은 업로드 속도다


| 항 | 원문 정의 | 제약/해석 |
| --- | --- | --- |
| rate R_n | Σ_k B log2(1+x_kn\|g_kn\|²p_n/σ_z²) | Rayleigh fading, AWGN |
| upload time t_n | ρ_n s_n(μ_n)^p / R_n | ρ_n=0이면 offload upload 없음 |
| UE별 channel | Σ_k x_kn≤ρ_n | UE당 최대 한 채널 |
| channel별 UE | Σ_n x_kn≤1 | 채널당 최대 한 UE |

핵심: 전송량 μ와 채널·전력 배분은 함께 결정한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 6; Eqs. 1-2; Eq. 11d-e

## 8. 실행 time과 energy를 어떻게 세나

offload면 upload와 ES compute를 더하고, semantic mode면 UE extraction time도 남는다

1. **단말 계산**: t_U: 전체 local 계산 또는 의미 추출
2. **상향 전송**: t_tx: ρ=1일 때 데이터 업로드
3. **서버 계산**: t_S: 전체 offload 계산량 / 서버 처리 능력
4. **작업 지연**: t_task = t_U + ρ(t_tx + t_S)
5. **에너지**: 원문 Eq. 8: E_task = E_UE + E_ES

핵심: 작업 지연에서 단말 추출·업로드·서버 계산을 빠뜨리지 않는다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 6-7; Eqs. 3-8

## 9. 서로 다른 작업을 local 기준으로 QoE화한다

time·energy는 작을수록, accuracy는 클수록 높은 logistic score가 되며, 세 weight의 합은 1이다

- **레인 per-task QoE**
  - **task M**: t_n^M → E_n^M → ε_n^M
  - **local baseline**: 같은 단말·작업의
local 실행 값
  - **logistic scores**: 지연·에너지: 감소
정확도: 증가
  - **QoE_n**: queue 평균
ω_t+ω_e+ω_a=1
- task M → local baseline (실선, 단방향)
- local baseline → logistic scores (실선, 단방향)
- logistic scores → QoE_n (실선, 단방향)

핵심: 각 지표를 local 기준 점수로 바꾼 뒤, 가중합과 큐 평균을 구한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 7; Fig. 3; Eqs. 9-10

## 10. 교육용 계산: local 기준보다 얼마나 좋아졌나

σ(z)=1/(1+exp(−z)); 가상 입력 z=(1, 0.5, −0.1), 한 작업·세 가중치 1/3


| 지표 | local 대비 방향 | 점수 σ(z) |
| --- | --- | --- |
| 지연 | 단축: z_t=1 | 0.7311 |
| 에너지 | 절약: z_e=0.5 | 0.6225 |
| 정확도 | 하락: z_a=−0.1 | 0.4750 |
| 가중 평균 | (0.7311+0.6225+0.4750)/3 | 약 0.6095 |

핵심: local과 같으면 각 z=0, 세 점수는 0.5이므로 QoE도 0.5다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 7, Eq. 10; p. 12; constructed example

## 11. P0가 요구하는 조건과 학습 결과를 구분한다

원래 최적화 문제에는 제약이 있지만, 아래 조건이 모든 학습 행동에서 자동으로 만족된다는 보장은 없다


| 결정변수 | 범위 | 의미 |
| --- | --- | --- |
| ρ, x | 0 또는 1 | 전송 여부·채널 선택 |
| μ | μ_min≤μ≤1 | 의미 추출 수준 |
| p, f | p≤p_max; f≤f_max | 송신 전력·GPU 주파수 |
| 지연·에너지 | t≤t_max; E≤E_max | 서비스·배터리 한계 |
| 정확도 | ε≥ε_min | 작업별 최소 요구 |

핵심: 이산·연속 변수와 비선형 QoE가 결합된 혼합 정수 최적화 문제다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 8; Eq. 11; §IV

## 12. 관측 → 공동 행동 → 결과 → 벌점 포함 보상

단말별 QoE에서 지연·에너지·정확도 위반 벌점을 빼고, 모든 단말의 보상을 합친다

1. **관측**: 채널·계산량·지연·에너지·정확도·제약
2. **행동**: 전송 ρ, 전력 p, 주파수 f, 추출 μ, 채널 x
3. **환경 실행**: 선택한 계산·전송으로 다음 상태와 성과 관측
4. **단말 보상**: QoE_n − 지연 벌점 − 에너지 벌점 − 정확도 벌점
5. **학습 목표**: 전체 r_t = Σ_n r_n의 기대 할인 누적값 최대화

핵심: 유한한 벌점을 주는 것은 위반 행동을 항상 금지하는 것과 다르다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 8; Eqs. 12-15; §IV-A

## 13. actor와 critic은 서로 다른 출력을 학습한다

각 경로는 상태 입력을 받아 두 개의 256-unit MLP와 GRU를 거친다; 화살표는 신경망 계산 순서다

- **레인 actor θ**
- **레인 critic ϕ**
  - **MLP 1**: 256 units; 상태 입력
  - **MLP 2**: 256 units; 특성 추출
  - **multi-layer GRU**: 시간적 의존성 표현
  - **행동 분포**: 최종 FC 출력
  - **MLP 1**: 256 units; 상태 입력
  - **MLP 2**: 256 units; 특성 추출
  - **multi-layer GRU**: 시간적 의존성 표현
  - **상태 가치 V**: 최종 FC 출력
- MLP 1 → MLP 2 (실선, 단방향)
- MLP 2 → multi-layer GRU (실선, 단방향)
- multi-layer GRU → 행동 분포 (실선, 단방향)
- MLP 1 → MLP 2 (실선, 단방향)
- MLP 2 → multi-layer GRU (실선, 단방향)
- multi-layer GRU → 상태 가치 V (실선, 단방향)

핵심: actor는 행동 확률분포를, critic은 상태의 누적 보상 추정값을 출력한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 10–11; Table III

## 14. semantic-aware MAPPO의 학습 순서

sampling policy로 trajectory를 모으고, GAE와 clipped objective로 actor·critic을 여러 epoch 갱신한다

1. **초기화**: 학습 정책 θ, 수집 정책 θ′, critic ϕ
2. **복사**: episode 시작: θ′ ← θ
3. **자료 수집**: 고정된 θ′로 T step 실행, trajectory 저장
4. **기대 이득 추정**: 보상·critic으로 GAE 계산
5. **여러 epoch**: actor: clip+entropy; critic: value loss

핵심: 같은 수집 정책의 자료를 여러 번 학습하고, 다음 수집 전에 정책을 갱신한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 9-10; Fig. 4; Algorithm 1; Eqs. 22-28

## 15. PPO clip은 확률 비율을 강제로 고정하지 않는다

교육용 ε=0.2: 한 표본의 목적값은 min(rA, g)이며, r은 새 정책 / 수집 정책의 행동 확률 비율이다


| r, A | rA | 경계 항 g | 목적값 min |
| --- | --- | --- | --- |
| 1.1, +2 | 2.2 | 1.2×2=2.4 | 2.2 |
| 1.4, +2 | 2.8 | 1.2×2=2.4 | 2.4 |
| 0.9, −2 | −1.8 | 0.8×(−2)=−1.6 | −1.8 |
| 0.6, −2 | −1.2 | 0.8×(−2)=−1.6 | −1.6 |

핵심: r=1.4가 존재해도 목적값은 더 커지지 않는다; r≤1.2 보장은 아니다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 9–11; Eqs. 23–28; constructed example

## 16. 교육용 계산: 의미 추출이 줄인 전송 시간

가상 시간 단위: local=4, 추출=0.2/μ, 업로드=3μ, ES=0.5; p=q=1인 한 작업을 가정한다


| 경로 | 단말 계산 | 업로드 + ES | 총 지연 |
| --- | --- | --- | --- |
| local: ρ=0 | 4 | 없음 | 4 |
| 직접: μ=1 | 0 | 3+0.5 | 3.5 |
| 의미: μ=0.5 | 0.2/0.5=0.4 | 1.5+0.5 | 2.4 |
| 의미: μ=0.1 | 0.2/0.1=2 | 0.3+0.5 | 2.8 |

핵심: 더 작은 μ가 항상 더 빠르지는 않다; 최종 선택에는 에너지·정확도도 필요하다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 6–7; Eqs. 2–5; constructed example

## 19. 비교 baseline이 무엇을 바꾸고 무엇을 고정했나

semantic awareness와 continuous/hybrid action 처리의 차이를 분리해 읽는다


| 방법 | 의미 추출 μ | 행동 공간 |
| --- | --- | --- |
| 제안 MAPPO | 적응적으로 선택 | 이산·연속 혼합 |
| MAPPO-discrete | 적응적으로 선택 | 연속 행동을 이산화 |
| unaware MAPPO | 1로 고정 | 그 외 설정 동일 |
| D3QN / unaware D3QN | 적응 선택 / 1 | 둘 다 이산화 |
| Local | 전송 없음 | 전부 단말 실행 |

핵심: 의미 추출 유무와 행동 이산화 여부는 서로 다른 비교 축이다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 11; §V-A

## 20. QoE 곡선의 조건부 결론

10 MHz에서 학습한 policy를 bandwidth·noise·UE 수 조건에서 시험했을 때 semantic-aware MAPPO가 가장 높았다


| 보고 항목 | 원문 관찰 | 해석 경계 |
| --- | --- | --- |
| 학습 곡선 | MAPPO 약100; D3QN 약2000 episode | 같은 벽시계 시간이 아님 |
| 대역폭 | 제시한 모든 B에서 제안 QoE 최고 | 10 MHz 학습 후 평가 |
| unaware MAPPO 대비 | QoE 12.68% 개선 | 논문이 보고한 상대값 |
| unaware D3QN 대비 | QoE 14.48% 개선 | 이산 행동 비교 포함 |

핵심: 개선율에는 비교 방법·QoE 정의·학습과 평가 조건을 함께 붙인다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 11-12; Figs. 6-10; §V-B

## 21. QoE weight를 바꾸면 ‘최선’도 바뀐다

각 preference에 맞춰 다시 학습한 결과이며, 한 policy를 즉시 재가중한 결과라고 읽으면 안 된다


| preference | delay (ms) | energy (J) | accuracy (%) |
| --- | --- | --- | --- |
| no preference | 0.523 | 0.0186 | 51.37 |
| delay: ω_t=1 | 0.369 | 0.0192 | 43.08 |
| energy: ω_e=1 | 3.50 | 0.0163 | 56.85 |
| accuracy: ω_a=1 | 1.67 | 0.0682 | 71.99 |

핵심: 지연 우선의 정확도 43.08%는 설정표의 최소 50%와 맞지 않아 주의가 필요하다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 13-14; Table V; §V-C

## 22. 벌점이 있다는 것과 제약을 지킨다는 것은 다르다

보고된 설정과 결과를 나란히 놓고, 논문이 설명하지 않은 차이는 남겨 둔다


| 근거 | 내용 | 해석 |
| --- | --- | --- |
| P0, Eq. 11 | 정확도 ε≥ε_min | 최적화 문제의 요구 |
| 학습, Eq. 12 | 위반량에 유한한 벌점 | 위반 금지와 다름 |

핵심: 논문은 임계값 변경 여부를 명확히 설명하지 않아 충족 보장을 주장할 수 없다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) p. 8, Eqs. 11–12; pp. 11,13, Tables IV–V

## 23. 무엇이 아직 모델 밖에 남나

logistic slope와 μ 관계는 empirical abstraction이며, 논문도 더 일반적인 codec과 정량 관계를 향후 과제로 둔다

- 기울기가 크면 logistic 점수가 0 또는 1에 가까워져 포화될 수 있다
- 기울기가 0에 가까우면 점수가 0.5에 몰려 차이를 구별하기 어렵다
- μ와 계산·전송·정확도 관계는 경험적 모델이며 보편 법칙이 아니다
- 작업은 atomic이고 결과 다운로드 지연은 생략한다

핵심: 가중치별 재학습과 고정 정책의 점수 함수 민감도 실험은 다르다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 5–7; pp. 14–15; Fig. 17; §VI

## 24. 한 줄로 다시 읽기

의미 추출·계산·전송의 상충관계를 모델링하고 정책으로 선택한다; 작은 μ 자체가 목적은 아니다

- 모형: 작업별 코덱과 세 실행 경로
- 목표: local 기준의 지연·에너지·정확도 QoE
- 방법: 이산·연속 결정을 함께 학습하는 MAPPO
- 근거: 조건부 시뮬레이션 결과와 미해결 제약 차이

핵심: 실행 경로 → 비용·QoE → 벌점과 학습 → 조건부 결과로 이해한다

근거: [paper-v3](https://arxiv.org/abs/2407.11018v3) pp. 5–15; Algorithm 1; §VI
