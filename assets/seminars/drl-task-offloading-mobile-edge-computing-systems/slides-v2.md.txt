# 대기열·마감시한 MEC Offloading을 위한 분산 DRL

논문: Deep Reinforcement Learning for Task Offloading in Mobile Edge Computing Systems

저자: Ming Tang and Vincent W. S. Wong (2022)

## 1. 대기열·마감시한 MEC Offloading을 위한 분산 DRL

새 task의 위치 선택이 이전 task의 대기와 미래 edge load에 의해 바뀌는 상황을 다룬다


근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) title, abstract

## 2. 왜 한 slot 안에 끝난다고 가정할 수 없을까

새 task의 지연은 자기 선택만이 아니라 앞선 task의 service·transfer와 다른 device의 edge load에 영향을 받는다

1. **새 task**: slot 시작에 확률적으로 도착
2. **위치 선택**: local 또는 edge 하나를 선택
3. **FIFO 대기**: 앞선 task가 남아 있으면 기다림
4. **여러 slot service**: 처리·전송은 이어질 수 있음
5. **완료 또는 drop**: deadline 끝에서 아직 미완료면 drop

핵심: 이 논문의 난점은 multi-slot queue가 action의 결과와 feedback 시점을 밀어낸다는 것이다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1986–1988, §1–2

## 3. 먼저 고정해야 하는 모델 경계

이 덱의 algorithm 설명은 논문이 둔 task·wireless·edge scheduling 가정 안에서만 성립한다


| 항목 | 논문의 모델 | 설명 경계 |
| --- | --- | --- |
| task | non-divisible, deadline 보유 | 분할·병렬 edge 실행 아님 |
| device queue | local compute와 transmission FIFO | 새 task는 둘 중 하나만 선택 |
| wireless | orthogonal channel, constant rate | error·interference 미포함 |
| edge CPU | device별 FIFO queue의 equal-share GPS | 우선순위 scheduler 아님 |
| decision | device가 local observation으로 선택 | runtime central selector 아님 |

핵심: 결과를 읽기 전에 task non-divisibility와 queue service rule을 함께 확인해야 한다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1986–1989, §2

## 4. 새 task가 만나는 세 대기 지점

local 선택은 device compute queue로, offload 선택은 transmission queue와 선택 edge의 device queue로 간다

- **레인 local path**
- **레인 offload path**
  - **new task**: x = 1 선택
  - **compute FIFO**: earlier job → new task
  - **device CPU**: 완료 또는 deadline drop
  - **new task**: x = 0, edge n
  - **tx FIFO**: prior tx → new task
  - **wireless link**: chosen edge로 transfer
  - **edge m queue**: earlier task → received task
  - **edge CPU share**: active queues와 equal share
- new task → compute FIFO (실선, 단방향)
- compute FIFO → device CPU (실선, 단방향)
- new task → tx FIFO (실선, 단방향)
- tx FIFO → wireless link (실선, 단방향)
- wireless link → edge m queue (실선, 단방향)
- edge m queue → edge CPU share (실선, 단방향)

핵심: offload path는 transmission wait만이 아니라 edge-side queue와 CPU share까지 포함한다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1987–1989, Fig. 1, §2

## 5. slot 순서: enqueue 뒤 service, 다음 job은 다음 slot

완료된 job이 있어도 같은 slot 안에서 뒤 job을 즉시 시작시키지 않는 규칙이 waiting calculation의 기준이다

1. **slot 시작**: 새 task arrival과 state 관측
2. **action**: queue와 edge destination 결정
3. **enqueue**: 선택한 FIFO에 task 추가
4. **service**: 현재 job이 transfer 또는 process
5. **다음 slot**: 완료 뒤 다음 job이 시작

핵심: ‘완료 slot’과 ‘다음 job의 start slot’을 구분해야 queue waiting을 한 칸 틀리지 않는다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) p. 1987, §2.1; Eqs. 2–6

## 6. local FIFO wait은 completion·drop slot으로 계산한다

source Eq. 2는 이전 local jobs가 끝나는 가장 늦은 slot을 사용한다


| 상황 | 계산 | 뜻 |
| --- | --- | --- |
| new task at slot t | latest earlier l_comp − t + 1 | 아직 남은 FIFO wait |
| earlier job ends at 5 | task arrives at 3 | wait = 5 − 3 + 1 = 3 |
| local service | ceil(size / per-slot capacity) | 필요한 service slot 수 |
| deadline | min(service end, t + tau − 1) | 완료 또는 drop slot |

핵심: deadline은 대기 뒤의 service가 끝나는 시점과 경쟁하며, 늦으면 task를 drop시킨다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1987–1988, Eqs. 2–6

## 7. edge 처리 지연은 왜 action 순간에 확정되지 않는가

edge n의 active queue 수가 slot마다 바뀌면 task m이 받는 CPU share도 바뀐다

- **edge n**: one CPU, per-device FIFO queues
- **active queue count**: B_n(t)가 slot마다 변화
- **equal CPU share**: active queue마다 f_n / B_n(t)
- **future edge service**: 앞으로의 B_n을 몰라 확정 불가
- **history를 사용**: past load counts를 state에 포함

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1988–1989, Eqs. 7–13

## 8. state에는 관측 가능한 것과 예측해야 할 것을 분리한다

device는 자신의 queue state와 edge load history를 쓰지만, future edge queue waiting은 모른다


| state component | 어떻게 얻나 | 의미 |
| --- | --- | --- |
| task size | 새 arrival에서 local observation | 이번 task의 service량 |
| local·tx wait | device FIFO completion history | 이미 생긴 device backlog |
| 내 edge queue 벡터 | 전송·완료·drop 기록 | 각 edge에서 남은 own bits |
| 부하 이력 H(t) | edge의 active-count broadcast | 최근 edge congestion pattern |
| future edge wait | 결정 시 알 수 없음 | state에 직접 넣지 않음 |

핵심: LSTM의 입력은 미래 정답이 아니라 공개된 과거 active-queue count sequence다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) p. 1989, Eqs. 12–13, footnotes 2–3

## 9. action은 ‘local인가’와 ‘어느 edge인가’의 결합이다

새 task가 있을 때 action a_m(t)는 binary x와 destination vector y로 구성된다


| 선택 | x | y의 조건 | queue 결과 |
| --- | --- | --- | --- |
| local | 1 | 모든 y_m,n = 0 | device computation FIFO |
| edge n 전송 | 0 | 선택 n만 y_m,n = 1 | device tx FIFO → edge n |
| 선택 조건 | x = 0 | sum over n of y_m,n = 1 | edge 하나만 선택 |
| 허용 안 됨 | — | 여러 y가 동시에 1 | task splitting 아님 |

핵심: binary offloading은 edge 하나를 고르는 whole-task placement이며 splitting이 아니다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) p. 1987, Eq. 1; p. 1989, Eq. 14

## 10. reward가 아니라 discounted cost를 최소화한다

이 논문에서 Q가 작다는 것은 state-action pair의 expected long-term cost가 작다는 뜻이다

1. **processed task**: arrival부터 completion까지 delay
2. **dropped task**: positive fixed penalty C
3. **no arrival**: cost 0
4. **discount**: future cost에 gamma 적용
5. **policy**: expected long-term cost 최소화

핵심: processed-task delay뿐 아니라 deadline drop penalty까지 action cost에 넣는다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1989–1990, Eqs. 15–19

## 11. current feature와 load history의 두 input path

LSTM은 H(t)의 temporal pattern을, FC path는 현재 task·queue feature를 Q estimation에 연결한다

- **레인 current observation**
- **레인 load history**
  - **current state**: size; comp/tx wait; q_edge
  - **FC layers**: two ReLU FC layers
  - **A and V heads**: advantage와 state value
  - **Q values**: 각 action의 long-term cost
  - **H(t)**
    - past | edge 1 | edge 2
    - older | 2 | 1
    - recent | 3 | 2
  - **LSTM sequence**: load dynamics를 encode
- current state → FC layers (실선, 단방향)
- FC layers → A and V heads (실선, 단방향)
- A and V heads → Q values (실선, 단방향)
- H(t) → LSTM sequence (실선, 단방향)
- LSTM sequence → FC layers: encoded history (실선, 단방향)

핵심: history path는 future load 정답이 아니라 past load variation을 Q estimator에 전달한다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1990–1991, Figs. 2–3, §4.1

## 12. dueling DQN: state 자체의 비용과 action 차이를 나눈다

Q는 state value V와 action advantage A를 결합하되, A의 평균을 빼 identifiability를 맞춘다

- **encoded state**: 현재 특성 + 부하 이력 표현
- **V head**: state가 만드는 expected cost
- **A head**: action별 cost difference
- **center A**: A에서 action 평균 A를 뺌
- **Q(s,a)**: V + A − mean(A)

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) p. 1991, §4.1.4, Eq. 20

## 13. runtime action과 edge-assisted learning은 분리된다

device는 current Net parameter로 행동하고, assigned edge node는 device별 memory와 networks를 training한다

- **레인 at mobile device m**
- **레인 at assigned edge n_m**
- **레인 delayed feedback**
  - **new task**: current state와 parameter request
  - **epsilon-greedy**: random 또는 min-Q action
  - **execute action**: queue에 넣고 service 진행
  - **current Net_m**: parameter request에 u_m reply
  - **completed experience**: cost 관측 뒤 device가 전송
  - **replay memory D_m**: s, a, c, s-next → older experiences
  - **update Net_m**: sample, target, loss minimize
  - **Target Net_m**: periodic parameter copy
- new task → current Net_m: parameter request (점선, 단방향)
- current Net_m → epsilon-greedy: u_m reply (점선, 단방향)
- epsilon-greedy → execute action (실선, 단방향)
- completed experience → replay memory D_m (실선, 단방향)
- replay memory D_m → update Net_m (실선, 단방향)
- update Net_m → Target Net_m (실선, 단방향)

핵심: action은 decentralized지만, replay와 learning computation은 edge가 보조한다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1991–1993, Algorithms 1–2

## 14. multi-slot task의 delayed cost feedback

논문은 task가 실제로 processed 또는 dropped된 slot에 그 task의 experience를 보낸다

1. **slot t**: state s_t에서 action a_t 선택
2. **slot t+1**: next state s_t+1 관측
3. **service 계속**: task t의 delay·drop은 미확정 가능
4. **finish slot**: processed 또는 dropped task 확인
5. **experience**: s_t, a_t, c_t, s_t+1 전송

핵심: next state와 cost observation 시점이 분리되므로 completed-task set을 따로 만든다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1992–1993, Eq. 23, Algorithms 1–2

## 15. double DQN target: action 선택과 평가를 분리한다

evaluation Net이 next action을 고르고, Target Net이 그 action의 discounted future cost를 평가한다

1. **replay sample**: s_i, a_i, c_i, s_i+1
2. **choose next action**: Net에서 min-Q action 선택
3. **evaluate target**: Target Net에서 next-action Q
4. **target cost**: c_i + gamma times target Q
5. **periodic copy**: Target Net ← Net parameters

핵심: double DQN은 target에서 next-action choice와 value evaluation을 분리한다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) p. 1993, Eqs. 24–26

## 16. 구성 예시: local queue만으로 기다림을 다시 계산해 보자

아래 숫자는 source result가 아닌, Eq. 2–3의 queue accounting을 확인하기 위한 구성 예시다


| slot / 조건 | 계산 | 결과 |
| --- | --- | --- |
| prior local job | completion slot = 5 | queue가 5까지 점유 |
| new task | arrival t = 3 | local 선택 |
| waiting | max(5 − 3 + 1, 0) | 3 slots |
| service | 2 slots, deadline end slot 8 | unbounded end = 7 |
| cost | completion at 7 | delay = 7 − 3 + 1 = 5 |

핵심: task는 deadline 전 slot 7에 끝나 delay cost를 받고, edge future wait은 예측하지 않는다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1987–1988, Eqs. 2–3; constructed example

## 17. 비교 방법은 무엇을 다르게 가정하는가

source baselines는 같은 metric 아래 비교되지만, feedback·capacity model과 queue assumptions가 완전히 같지는 않다


| method | 선택 방식 | 논문이 밝힌 차이 |
| --- | --- | --- |
| No Offl. | 언제나 local | edge capacity를 사용하지 않음 |
| R. Offl. | random offloading | load-aware policy 아님 |
| PGOA | potential-game best response | 각 task가 one slot 내 끝난다고 가정 |
| ULOOF | historical capacity estimation | 다른 load-estimation route |
| proposed DRL | history-based Q learning | multi-slot queue·delayed cost를 모델링 |

핵심: 비교 핵심은 DRL 이름보다 multi-slot queue와 unknown edge load를 다루는 방식이다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1994–1995, §5.2, footnote 8

## 19. drop ratio와 average delay는 반드시 함께 읽는다

source average delay는 processed tasks만 평균내므로, drop이 늘면 average delay가 내려갈 수도 있다

- **task arrivals**: 모든 새 task를 denominator로 추적
- **dropped-task ratio**: dropped tasks / total arrivals
- **average delay**: processed tasks의 delay만 평균
- **high-load reading**: drop이 delay average에서 빠질 수 있음
- **paired interpretation**: 두 metric을 함께 비교

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) p. 1995, §5.2, Fig. 5

## 21. 논문이 보여 주지 않은 것까지 확장하지 않는다

DRL-based Q approximation과 simulation evidence는 valuable하지만, source가 보장하지 않은 범위를 따로 남겨야 한다


| source establishes | not established |
| --- | --- |
| multi-slot FIFO simulation | DRL convergence proof |
| history-input LSTM-DQN | exact future edge-delay observation |
| fixed wireless and GPS comparison | error·interference field deployment |
| edge-assisted training | no-overhead unlimited scaling |
| cost extension mention | energy-optimality result |

핵심: convergence, wireless realism, parameter overhead, non-stationarity는 여전히 열린 범위다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) pp. 1993, 1995–1996, §4.2.3, §6

## 22. 핵심 정리

이 논문은 offloading action 하나를 queue, deadline, hidden edge load, delayed feedback과 함께 다시 정의한다

- whole task는 local 또는 one edge로 가며 queue에서 대기한다
- state는 known local queue와 broadcast edge-load history를 구분한다
- LSTM·dueling DQN·double DQN은 history, Q decomposition, target 역할을 맡는다
- device action은 decentralized이고 edge node는 replay·training을 보조한다
- drop ratio와 processed-task delay를 함께 읽어야 result를 오독하지 않는다

핵심: ‘어디로 보낼까’는 queue-aware delayed-feedback decision으로 이해해야 한다

근거: [paper](https://doi.org/10.1109/TMC.2020.3036871) abstract; §§2–6
