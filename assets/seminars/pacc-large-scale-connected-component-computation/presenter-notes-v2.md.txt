## 1. PACC: 대규모 연결 요소 계산

1. PACC: 대규모 연결 요소 계산

발표 대본

## 3. 분산 CC의 세 병목

3. 분산 CC의 세 병목

발표 대본
분산 connected component는 세 비용을 함께 봐야 합니다. Round가 많으면 MapReduce job 준비와 저장소 입출력이 반복됩니다. Intermediate edge가 많으면 shuffle과 disk 비용이 커집니다. Graph가 별 모양으로 수렴하면 최소 ID 정점의 이웃이 한 key로 모여 last reducer가 느려질 수 있습니다. PACC는 partition-aware 연산, edge filtering, sketching을 서로 다른 병목에 대응시킵니다. 이 세 효과를 하나의 메모리 보장으로 합쳐 설명하면 안 됩니다.

## 4. Hash 계열과 alternating 비교

4. Hash 계열과 alternating 비교

발표 대본
관련연구 비교입니다. PACC 논문은 Hash-Greater-to-Min에 O(log |V|) round 보장이 있다고 인용하고, Hash-to-Min은 그 보장이 없지만 실무상 더 빠르다고 설명합니다. 두 hash 방법 모두 원래 graph의 두 배를 넘는 intermediate data를 만들 수 있다고 서술합니다. Alternating은 한 round의 intermediate를 입력 이하로 유지하지만 별 모양 수렴 과정에서 중심 key가 커집니다. Alt-opt는 고차 정점 복제로 분산을 시도하지만 edge 수가 늘 수 있고 편향이 남습니다. 이 주장은 PACC 논문의 관련연구 요약과 실험 비교 범위입니다.

## 5. Alternating의 last reducer 경로

5. Alternating의 last reducer 경로

발표 대본
Alternating의 large-star와 small-star는 이웃을 minimum ID 방향으로 재연결합니다. 반복하면 각 connected component가 minimum ID를 중심으로 한 star graph가 됩니다. 다음 MapReduce round는 node ID를 key로 이웃을 모으므로 component가 크면 minimum ID의 neighbor list가 한 reducer로 들어갑니다. 이 reducer가 마지막까지 남아 전체 running time을 결정하는 현상을 논문은 curse of the last reducer라고 설명합니다. PACC는 global minimum으로 바로 모으는 대신 partition local minimum을 경유시킵니다.

## 6. PACC 전체 파이프라인

6. PACC 전체 파이프라인

발표 대본
PACC 계열의 포함 관계를 먼저 고정하겠습니다. PACC-base는 partitioning과 최종 CC-Computation만 사용합니다. PACC-ef는 여기에 edge filtering을 더합니다. 완전한 PACC는 입력 앞에 두 단계 sketching까지 추가합니다. ## 7. Hash partition은 작업 라벨이다

7. Hash partition은 작업 라벨이다

발표 대본
PACC는 hash function ξ로 각 정점을 ρ개 partition 중 하나에 배정합니다. 이 partition은 connected component를 미리 아는 분할이 아닙니다. 서로 다른 partition의 정점 사이 edge도 존재할 수 있고, local minimum을 global minimum에 잇는 edge가 connectivity를 유지합니다. 마지막 CC-Computation은 undirected edge (u,v)에서 큰 endpoint u의 partition ξ(u)로 edge를 보냅니다. 각 reducer가 받는 것은 partition 정점 집합 자체가 아니라 그 정점에 incident한 edge-induced subgraph이므로 subgraph끼리 정점을 공유할 수 있습니다.

## 12. Partition별 LocalCC가 가능한 이유

12. Partition별 LocalCC가 가능한 이유

발표 대본
Partitioning이 끝나면 partition i의 정점들은 그 partition의 local minimum에 연결되고, local minimum은 component의 global minimum과 연결됩니다. CC-Computation은 edge (u,v)에서 큰 endpoint u의 ξ(u)를 key로 보내 edge-induced subgraph를 만듭니다. Subgraph는 정점을 공유할 수 있지만 각 partition의 정점이 global minimum까지 가는 path를 포함합니다. 각 reducer가 Union-Find 기반 LocalCC를 독립 실행한 뒤 대표 ID를 결합하면 원래 component를 복원할 수 있습니다.

## 14. Edge filtering의 세 출력

14. Edge filtering의 세 출력

발표 대본
PACC-ef는 매 round에서 out, in, cc를 만듭니다. Out은 다음 star round에서 계속 처리할 edge입니다. In은 같은 partition 안에서 정착해 독립 LocalCC가 가능한 forest edge이고, cc는 더 이상 바뀌지 않는 완성된 star edge입니다. In과 cc는 분산 저장소에 누적됩니다. Out edge 수가 threshold τ 이하이면 반복 MapReduce 대신 잔여 out만 single-machine LocalCC로 바꿉니다. 마지막 CC-Computation 입력은 out과 누적 in, cc의 union입니다.

## 15. 보관 edge와 잔여 edge의 합류

15. 보관 edge와 잔여 edge의 합류

발표 대본
Edge filtering의 보존 관계를 데이터 흐름으로 확인하겠습니다. In과 cc는 다음 반복의 out에서 빠지지만 분산 저장소에 누적됩니다. 반복이 끝난 final out 또는 threshold 아래에서 LocalCC로 정리한 out이 다른 입력 경로입니다. 마지막에는 두 경로를 out union in union cc로 결합하고 CC-Computation을 수행합니다. 따라서 filtered edge를 삭제했다고 표현하면 정답 복원에 쓰이는 경로를 놓치게 됩니다. Threshold 전환은 잔여 out 처리 방식을 바꿀 뿐 final distributed computation을 없애지 않습니다.

## 16. Sketching 1단계: chunk LocalCC

16. Sketching 1단계: chunk LocalCC

발표 대본
완전 PACC의 sketching은 input storage chunk에서 시작합니다. 각 edge는 정확히 한 chunk에 들어가므로 chunk끼리 edge가 겹치지 않습니다. 각 machine은 chunk의 edge-induced subgraph에서 LocalCC를 실행하고, 각 정점을 그 chunk component의 최소 대표자 r_i(u)에 잇는 edge만 출력합니다. 이 단계는 논문에서 network communication 없이 병렬 수행된다고 설명합니다. Edge 수는 줄지만 여러 chunk의 대표자가 같은 작은 ID에 모이면 reduced graph G'가 skew될 수 있습니다. 그래서 두 번째 localization이 필요합니다.

## 17. Sketching 2단계: localization

17. Sketching 2단계: localization

발표 대본
Chunk LocalCC만 적용하면 작은 대표자에 많은 edge가 모일 수 있습니다. Localization은 node u와 partition i마다 그 partition의 큰 이웃 중 최소인 m_i⁺(u)를 anchor로 고릅니다. Anchor는 u와 직접 연결한 채로 두고, 같은 partition의 나머지 큰 이웃 v가 u로 향하던 edge를 anchor로 바꿉니다. 그러면 v는 anchor를 거쳐 u에 도달하므로 connectivity가 유지됩니다. 이 연산은 edge를 새로 복제하지 않고 각 edge를 다른 edge로 바꿉니다.

## 20. Hadoop와 Spark 구현 선택

20. Hadoop와 Spark 구현 선택

발표 대본
알고리즘의 edge-count 결과만으로 구현이 끝나지 않습니다. Hadoop에서 PA-large와 PA-small Map은 edge를 양방향으로 emit합니다. Combiner는 reduce에 필요 없는 이웃을 shuffle 전에 줄입니다. Neighbor grouping은 groupByKey 대신 partitionBy와 external sort를 사용합니다. 논문은 memory를 사용하지 않는다고 주장하지 않습니다.

## 22. 세 기법의 실험 효과

22. 세 기법의 실험 효과

## 24. PACC 결과의 적용 한계

24. PACC 결과의 적용 한계

발표 대본
PACC의 실험은 2020년 software와 HDD cluster 조건입니다. Hash partition에 대한 Lemma 9는 기대값이며 구체적인 independence나 high-probability tail bound를 제시하지 않습니다. Edge-count lemma는 shuffle byte, disk spill, peak RAM의 상한이 아닙니다. ClueWeb12 성공은 Hadoop 결과이고 Spark에서는 모두 실패했습니다. 마지막으로 정확성 증명은 undirected connected component와 minimum-root forest 구조에 의존합니다. Triangle enumeration이나 shortest path에 같은 filtering 논리를 자동으로 적용할 근거는 없습니다.

## 25. PACC의 핵심 흐름

25. PACC의 핵심 흐름

발표 대본
PACC의 핵심을 한 흐름으로 정리하겠습니다. 모든 변환은 원래 connectivity를 유지합니다. Partition local minimum을 경유해 edge가 global minimum 하나로 바로 집중되는 현상을 줄입니다. Edge filtering은 이미 정착한 in과 cc를 다음 round에서 제외하지만 final union까지 보관합니다. 종료 시 forest와 overlapping edge-induced subgraph는 각 partition의 정점이 global minimum까지 가는 path를 포함합니다. 그래서 independent LocalCC가 원래 component representative를 복원합니다.
