## 1. Labidus: Streaming Async Instruction RISC-V Overlay

1. Labidus: Streaming Async Instruction RISC-V Overlay

발표 대본
Labidus는 FPGA 위에 RISC-V soft processor cluster를 만들고, application에 맞춘 custom operator를 자동 구성하는 overlay입니다. 연구 질문은 software programming의 편의성을 유지하면서 application-specific accelerator에 가까운 utilization을 얻을 수 있는가입니다. 이를 위해 asynchronous completion queue, stream-semantic memory, four-core shared operator pool을 결합합니다.

## 2. FPGA 개발의 두 비용

2. FPGA 개발의 두 비용

발표 대본
FPGA는 application-specific hardware를 만들 수 있지만 높은 성능을 얻으려면 pipeline과 signal timing을 다뤄야 합니다. HLS도 regular kernel에서는 효과적이지만 dynamic loop bound와 irregular control flow에서는 hardware-aware guidance가 필요할 수 있습니다. Soft processor overlay는 software 개발을 쉽게 만들지만 범용 processor control이 chip resource를 사용해 custom accelerator보다 느리기 쉽습니다.

## 3. Labidus의 설계 목표

3. Labidus의 설계 목표

발표 대본
Labidus는 C kernel의 compute-heavy region을 분석해 application-specific fused operator를 구성합니다. 그러나 복잡한 operator는 latency가 길 수 있으므로, operator를 추가하는 것만으로는 utilization이 높아지지 않습니다. Completion queue와 stream memory가 여러 request를 동시에 진행시키고, shared pool과 trimming이 남는 hardware instance를 줄입니다.

9. 4-core tile과 shared operator pool

## 11. Asynchronous completion queue의 기본 동작

11. Asynchronous completion queue의 기본 동작

발표 대본
Operation을 issue하면 completion queue tail에 slot을 예약합니다. Core는 result를 기다리지 않고 다음 custom operation이나 memory request를 issue합니다. Operator가 끝나면 response가 예약한 slot을 채우고, program이 head에서 ready result를 읽습니다. Reserved slot이 아직 incomplete라면 read는 stall하므로 asynchronous semantics가 latency 자체를 제거하는 것은 아닙니다.

## 12. Circular buffer와 epoch tracking

12. Circular buffer와 epoch tracking

발표 대본
Completion queue는 fixed-size BRAM circular buffer입니다. Tail이 buffer 끝을 지나면 같은 physical address를 다시 쓰므로 address만으로는 old result와 new reservation을 구분하기 어렵습니다. Labidus는 global epoch를 wrap 때 증가시키고 request와 response에 epoch를 붙입니다. Slot epoch가 이전 generation이면 아직 새 request가 complete되지 않은 것으로 판단합니다.

## 13. Latency hiding이 성립하는 조건

13. Latency hiding이 성립하는 조건

발표 대본
Long-latency operator가 fully pipelined라면 latency와 throughput을 분리할 수 있습니다. Queue capacity가 여러 request를 담고 input stream이 매 cycle 새 operand를 주면 core는 기다리는 시간을 다른 issue work와 겹칠 수 있습니다. 반대로 incomplete head를 읽거나 queue가 가득 차면 stall합니다. 따라서 paper의 표현은 latency hiding이지 latency elimination이 아닙니다.

## 14. 교육용 M=3 streaming trace

14. 교육용 M=3 streaming trace

발표 대본

15. Multiply stage의 두 operand stream

## 16. Stream-semantic memory path

16. Stream-semantic memory path

발표 대본
Labidus는 off-chip access를 word가 아니라 burst로 request합니다. Stream-semantic cache는 RISC-V core의 normal memory hierarchy에 포함되지 않고 completion queue에 연결됩니다. Software가 x29, x30, x31 중 하나를 반복해 읽으면 burst의 다음 word가 이어서 나오고, 반복 write는 write burst를 만듭니다. 세 register만 확장해 hardware overhead를 제한합니다.

## 17. Memory request immediate의 12-bit 구성

17. Memory request immediate의 12-bit 구성

발표 대본
Modified I-type과 S-type memory instruction의 12-bit immediate는 6-bit burst length, 5-bit repeat count, 1-bit uncached flag로 나뉩니다. Repeat count는 coefficient처럼 같은 memory region을 여러 번 읽을 때 유용합니다. Uncached request는 off-chip access가 cache를 오염시키지 않도록 bypass queue로 보냅니다. 이 encoding은 operator custom instruction의 R-type encoding과 구분해야 합니다.

## 18. Operator repeat와 stream의 결합

18. Operator repeat와 stream의 결합

발표 대본

## 19. Custom operator instruction encoding

19. Custom operator instruction encoding

발표 대본
Operator pool은 new R-type opcode로 호출됩니다. Paper는 register fields를 normal R-type처럼 사용하고, func7으로 operation, func3으로 repeat parameter를 encode한다고 설명합니다. ## 20. Shared operator pool과 trimming

20. Shared operator pool과 trimming

발표 대본
Repeat와 stream이 있어도 모든 operator가 항상 바쁘지는 않습니다. Labidus는 operator를 tile마다 공유하고 static analysis가 relative frequency를 보수적으로 추정해 각 operator를 one to four instances만 둡니다. Paper는 tested configurations에서 trimming으로 performance loss를 관찰하지 않았고 operator utilization이 benchmarks across average로 'over 100% points' 개선됐다고 표현합니다. 산식은 따로 정의되지 않아 이를 정확한 2배나 100 percentage-point 증가로 재해석하지 않습니다.

## 28. Labidus의 전체 연결

28. Labidus의 전체 연결

발표 대본
Labidus는 C kernel을 분석해 operator pool hardware와 custom-instruction software를 함께 생성합니다. Runtime에는 burst memory와 stream registers가 operator에 data를 공급하고, completion queue가 long-latency requests를 동시에 진행시킵니다. Four cores가 operator pool을 공유하고 static analysis가 instance 수를 줄입니다. 실험 결과는 2025 paper의 FPGA, workload, normalization 조건 안에서 해석해야 합니다.
