# TOICA: 작업의 실행 위치와 채널 수를 함께 정하기

논문: Joint Task Offloading and Channel Allocation in Spatial-Temporal Dynamic for MEC Networks

저자: Tianyi Shi, Tiankui Zhang, Jonathan Loo, Rong Huang, Yapeng Wang (2025)

## 1. TOICA: 작업의 실행 위치와 채널 수를 함께 정하기

이동하는 단말의 의존 작업을 강화학습과 동적 계획법으로 연결한다


근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 1–11; arXiv2505.04272v1

## 2. 서버가 빠르다고 오프로딩도 빠른 것은 아니다

작업 순서·무선 전송·서버 내부 간섭이 함께 완료 시간을 바꾼다


| 요인 | 무엇이 달라지나 | 필요한 판단 |
| --- | --- | --- |
| 작업 의존성 | 앞 작업의 결과가 필요 | 실행 가능한 순서 |
| 단말 이동 | 거리·채널 이득 변화 | 어느 서버에 보낼지 |
| 공유 통신 | 같은 주파수의 간섭 | 채널을 얼마나 줄지 |
| 서버 병렬 실행 | VM 사이 I/O 간섭 | 한 서버에 몰릴 비용 |

핵심: 오프로딩 위치만 고르고 통신 자원을 무작위로 주면 좋은 선택도 비싸질 수 있다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 1–4, §§I–II

## 3. 먼저 구분할 네 가지 이름

서버 선택과 채널 배분은 같은 행동 변수가 아니다


| 표기 | 뜻 | 이 논문의 역할 |
| --- | --- | --- |
| MT / ES | 이동 단말 / 엣지 서버 | 결정 주체 / 실행 자원 |
| DTO | D3QN-based Task Offloading | 로컬 또는 서버 선택 |
| DCA | DP-based Channel Allocation | 서버별 채널 수 배분 |
| TOICA | DTO와 DCA의 결합 | 배분 결과까지 보상에 반영 |

핵심: DTO가 서버를 고르면, 그 서버에 모인 단말들을 대상으로 DCA가 작동한다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 1, 5–7, Algorithms 1–2, Fig. 4

## 4. 의존 관계: 화살표는 선행 작업 완료를 요구한다

설명용 DAG: A 다음 B·C, 둘 다 끝난 다음 D가 실행 가능하다

- **레인 경로 B**
- **레인 분기·결합**
- **레인 경로 C**
  - **작업 A**: 추정 비용 q = 2
  - **작업 B**: 추정 비용 q = 6
  - **작업 C**: 추정 비용 q = 3
  - **작업 D**: 추정 비용 q = 1
- 작업 A → 작업 B (실선, 단방향)
- 작업 A → 작업 C (실선, 단방향)
- 작업 B → 작업 D (실선, 단방향)
- 작업 C → 작업 D (실선, 단방향)

핵심: D의 준비 시점은 B와 C의 완료 시점 중 더 늦은 시점이다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 3–5, Fig. 2, Eqs. 1–3, 12–13; constructed example

## 5. 우선순위: 뒤에 남은 큰 비용을 역방향으로 누적한다

종료 작업은 P=q, 나머지는 P=q+max(후속 작업의 P)


| 작업 | 계산 | 우선순위 P |
| --- | --- | --- |
| D | 종료: qD | 1 |
| B / C | 6+1 / 3+1 | 7 / 4 |
| A | 2+max(7,4) | 9 |
| 내림차순 | A → B → C → D | 의존성을 지키는 한 순서 |

핵심: 우선순위는 작업 순서를 정하는 규칙이며, 실행 위치를 고르는 DTO와 역할이 다르다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 4–5, Eqs. 12–13; constructed example

## 6. 슬롯 길이: 단말들의 처리시간 중 최댓값

논문은 단말별 현재 작업 하나를 한 슬롯 안에 끝내는 모델을 사용한다


| 슬롯 | 두 단말의 처리시간 | 슬롯 길이 D[t] |
| --- | --- | --- |
| 1 | 0.05s / 0.08s | 0.08s |
| 2 | 0.02s / 0.04s | 0.04s |
| 합계 | 작업시간 합은 0.19s | 슬롯 길이 합은 0.12s |

핵심: 각 단말의 시간을 줄이는 것과 시스템의 가장 긴 시간을 줄이는 것은 다를 수 있다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 3, 5–7, Eqs. 1–3, 14a; constructed example

## 7. 두 종류의 간섭은 서로 다른 단계에 작용한다

같은 셀에서는 채널을 나누고, 이웃 셀은 같은 채널을 재사용할 수 있다


| 간섭 | 발생 조건 | 처리시간에 미치는 영향 |
| --- | --- | --- |
| 셀 간 무선 간섭 | 다른 셀의 동일 채널 사용 | SINR·전송률 감소 |
| 같은 셀의 채널 | 한 채널에 최대 한 단말 | 셀 안의 중복 배정 금지 |
| 서버 I/O 간섭 | 여러 단말의 VM 동시 실행 | 계산시간 증가 |
| 이동·페이딩 | 거리와 무선 상태 변화 | 같은 배분도 성능 변화 |

핵심: DCA는 채널 수를 배분하지만, 그 사실만으로 셀 간 간섭을 제거하지는 않는다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 4–5, Eqs. 6–8, 14e

## 8. 계산 예: 서버 혼잡은 무선이 같아도 비용을 바꾼다

설명용: 입력 2Mbit, 20Mbit/s, 50Mcycles, 서버 5GHz; 송신 1W·대기 0.3W


| 조건 | 전체 처리시간 | 단말 에너지 |
| --- | --- | --- |
| VM 1개 | 0.10+0.010 = 0.110s | 0.10+0.003 = 0.103J |
| VM 3개 | 0.10+0.0144 = 0.1144s | 0.10+0.00432 = 0.10432J |
| 계산시간 배율 | (1+0.2)² = 1.44 | 서버 전력은 제외 |

핵심: 엣지 실행 에너지는 단말의 송신·대기 에너지이며 시스템 전체 에너지가 아니다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 4, Eqs. 7–10; constructed example

## 9. 목표: 지연과 단말 에너지의 가중 비용을 줄인다

ω는 지연에 줄 가중치이고, 1−ω는 에너지에 줄 가중치다


| 수준 | 비용 표현 | 읽는 방법 |
| --- | --- | --- |
| 단일 작업 | ωd + (1−ω)e | 선택한 모드의 시간·에너지 |
| 시스템 | ωΣD[t] + (1−ω)Σe | 슬롯 최대 지연 + 단말 에너지 |
| 큰 ω | 지연에 더 큰 비중 | 에너지가 늘 수도 있음 |
| 모델 범위 | 작업 전체를 한 위치에서 | 분할·반환 통신은 제외 |

핵심: ω=0.5는 선택한 수치 단위에서의 가중치이지 물리적으로 같은 비중의 보장이 아니다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 4–6, Eqs. 11, 14, 18

## 10. TOICA 한 슬롯: 서버 선택 뒤 채널 배분이 이어진다

DTO의 행동을 DCA로 평가한 결과가 다시 DTO 학습의 보상이 된다

1. **관측**: 단말 위치와 현재 작업의 크기
2. **위치 선택**: DTO: 로컬 또는 한 서버
3. **자원 배분**: DCA: 서버별 채널 수와 ID
4. **비용 평가**: 전송·계산 후 보상과 다음 상태

핵심: 학습과 최적화가 결합된 방식이며, 모든 결정을 하나의 신경망이 출력하지 않는다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 6–7, Algorithms 1–2, Fig. 4

## 11. DCA: 한 단말에 줄 채널 개수를 후보로 만든다

서버 m에 접속한 Nm개 단말과 K개 채널을 놓고 배분한다


| 기호 | 의미 | 제약 |
| --- | --- | --- |
| z | 한 단말에 줄 채널 수 | 1부터 K−Nm+1 |
| v[n,z] | z개를 줄 때 추정 통신 비용 | 후보별 주어진 값 |
| y[n,z] | 그 후보를 선택했는가 | 단말마다 정확히 하나 |
| 합계 | 선택된 z의 합 | 정확히 K |

핵심: 먼저 오프로딩 단말 집합을 고정한 뒤 그 집합 안에서 채널 수를 최적화한다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 5–6, Eq. 15, Algorithm 1

## 12. 배분 예: 4개 채널을 두 단말에 모두 나눈다

설명용 비용표: 숫자는 작은 것이 좋고, 가능한 z는 1·2·3이다


| 채널 수 z | 단말 A의 비용 | 단말 B의 비용 |
| --- | --- | --- |
| 1 | 24 | 6 |
| 2 | 12 | 3 |
| 3 | 8 | 2 |

핵심: 모든 단말에게 같은 수를 주는 것이 최소 비용 배분은 아닐 수 있다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 5–6, Eq. 15; constructed example

## 13. 가능한 배분을 계산하면 A에 3개, B에 1개

K=4, Nm=2에서 모든 유효한 채널 개수 조합을 비교한다


| A / B 채널 수 | 합산 비용 | 판정 |
| --- | --- | --- |
| 1 / 3 | 24+2 = 26 | 가능 |
| 2 / 2 | 12+3 = 15 | 가능 |
| 3 / 1 | 8+6 = 14 | 이 표의 최솟값 |
| 4 / 0 | B에 채널이 없음 | 제약 위반 |

핵심: A에 한 채널을 더 주는 이득이 B에서 한 채널을 줄이는 손실보다 크다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 5–6, Eq. 15; constructed example

## 14. 동적 계획법: 앞 단말들의 최솟값을 재사용한다

dp[n,j]: 앞 n개 단말에 정확히 j개 채널을 쓴 최소 비용


| 단계 | 계산 또는 상태 | 값 |
| --- | --- | --- |
| 시작 | dp[0,0]=0, 나머지 불가 | 불가는 ∞ |
| A만 | dp[1,1..3] | 24 / 12 / 8 |
| A·B, 채널 4개 | min(24+2,12+3,8+6) | dp[2,4]=14 |
| 역추적 | B에 1개 → A에 3개 | 총 4개 |

핵심: DP는 채널을 임의로 조금씩 주는 것이 아니라 모든 유효한 후보의 최솟값을 누적한다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 6, Algorithm 1; constructed example

## 15. 채널 3개와 채널 ID 1·2·4는 다른 정보다

DCA의 DP는 개수를 구하고, 구체적 채널은 그 개수에 맞춰 무작위로 붙인다


| 단계 | 예 | 의미 |
| --- | --- | --- |
| 개수 최적화 | A=3, B=1 | 비용표 기준 결과 |
| ID 배정 예 | A={1,2,4}, B={3} | 가능한 한 배정 |
| 같은 셀 | 서로 겹치는 ID 없음 | 셀 안 충돌 방지 |
| 다른 셀 | ID 1을 재사용 가능 | 셀 간 간섭은 남음 |

핵심: 배분 개수의 최적성과 특정 주파수 조합의 최적성을 구분한다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 4, 6, Eq. 6, Algorithm 1 and following paragraph

## 16. 채널보다 단말이 많으면 제약부터 충돌한다

각 단말 최소 1개와 총 K개 사용을 동시에 만족하려면 Nm≤K여야 한다


| 상황 | 가능성 | 필요한 해석 |
| --- | --- | --- |
| K=4, Nm=2 | 가능 | z 후보는 1..3 |
| K=4, Nm=4 | 각 단말 1개 | 배분 자유도 없음 |
| K=4, Nm=5 | 현재 제약에서는 불가 | 접속·오프로딩 결정 조정 |
| 오프로딩 단말 0개 | 활성 배분 대상 없음 | 빈 서버 처리 별도 |

핵심: 서버를 선택하는 것과 자원 제약 아래 그 선택을 실행하는 것은 다르다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 5–6, Eqs. 14f–g, 15; feasibility consequence

## 17. Q값: 지금 행동의 장기 보상을 예측한다

DQN은 행동별 기대 보상을 표 대신 신경망으로 추정하는 방식이다


| 개념 | 뜻 | TOICA에서의 역할 |
| --- | --- | --- |
| 상태 s | 현재 결정에 쓰는 정보 | 위치·현재 작업 |
| 행동 a | 지금 선택할 실행 위치 | 로컬 또는 서버 |
| 보상 r | 선택 결과의 개선 신호 | 로컬 대비 비용 감소 |
| Q(s,a) | 미래 보상까지 고려한 값 | 행동 간 비교 |

핵심: Q값이 큰 행동을 고르는 것이 목표이며, Q값 자체가 초나 줄은 아니다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 6–7, §III-B, Eqs. 18–22

## 18. DTO: 현재 작업의 상태로 로컬 또는 서버를 고른다

각 단말은 s={현재 위치, 입력 크기, 계산량}을 관측한다


| 구분 | 논문에 명시된 값 | 출력 해석 |
| --- | --- | --- |
| 위치 Xn[t] | 단말의 현재 공간 위치 | 시간에 따라 변화 |
| 작업 b / c | 입력 비트 / CPU cycles | 현재 작업의 요구 |
| 행동 a=0 | 단말에서 실행 | 채널 배분 불필요 |
| 행동 a=m | 서버 m에서 실행 | DCA의 접속 집합에 포함 |

핵심: D3QN 출력 개수는 단말당 M+1이며, 채널 ID 전체 조합을 직접 출력하지 않는다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 6, Eqs. 16–17

## 19. Dueling: 상태 공통값과 행동별 차이를 나눈다

D3QN의 Q망 안에서는 두 출력 갈래가 다시 한 Q벡터로 합쳐진다

- **공통 표현**: 현재 상태의 특징
- **V 갈래**: 상태에 공통인 값 1개
- **A 갈래**: 행동별 raw 점수
- **평균 제거·합산**: Q = V + A − mean(A)
- **Q 벡터**: 로컬·서버별 Q값

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 7, Eq. 22

## 20. Double DQN: 고르는 망과 평가하는 망을 구분한다

설명용 다음 상태: Main Q=[2,3], Target Q=[4,1], 보상 0.2, γ=0.9


| 계산 | 선택·평가 | 목표 y |
| --- | --- | --- |
| Main에서 선택 | 두 번째 행동: Q=3 | argmax 행동만 전달 |
| Target에서 평가 | 그 행동의 값은 1 | 0.2+0.9×1 = 1.1 |
| Target 자체 max | 첫 번째 행동 값 4 | DQN이라면 3.8 |

핵심: D3QN은 Dueling Q망을 사용하면서 Double DQN 방식으로 목표를 만든다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 7, Eq. 21; constructed example

## 21. 보상: 로컬 실행보다 얼마나 비용을 줄였는가

r=tanh(로컬 비용−선택한 실행 비용), DCA 결과가 선택 비용에 들어간다


| 설명용 비용 차이 | 보상 r | 해석 |
| --- | --- | --- |
| +0.4 | 약 +0.380 | 로컬보다 개선 |
| 0 | 0 | 로컬과 같음 |
| −0.3 | 약 −0.291 | 로컬보다 나쁨 |
| tanh 변환 | −1과 1 사이 | 큰 차이를 압축 |

핵심: 이 보상은 학습을 위한 개선 신호이며, 전역 최적해의 증명은 아니다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 6, Eq. 18; constructed example

## 22. 학습: 배분까지 끝난 전이를 경험으로 저장한다

DCA를 제외하고 DTO만 학습하면 평가하는 환경 자체가 달라진다

1. **행동·배분**: ε-greedy 선택 후 DCA
2. **경험 저장**: 상태·행동·보상·다음 상태
3. **표본 학습**: replay에서 batch를 뽑아 갱신
4. **Target 복사**: 정해진 주기에 Main을 복사

핵심: 과거 경험의 재사용과 느리게 바꾸는 Target이 학습을 안정화하려는 장치다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 7, Algorithm 2; p. 8, Table II

## 23. 학습과 실제 의사결정에서 필요한 계산을 나눈다

논문은 오프라인 학습과 온라인 의사결정의 두 단계를 구분한다


| 활동 | 학습 단계 | 온라인 단계 |
| --- | --- | --- |
| DTO Q값 계산 | 필요 | 필요 |
| DCA 배분 | 매 환경 상호작용 | 현재 접속 집합에 필요 |
| Replay·망 갱신 | 경험으로 수행 | 추론만 할 때는 제외 |
| 상태·비용 측정 | 학습 환경의 입력 | 실제 수집·제어 연동 필요 |

핵심: 오프라인으로 정책을 학습해도 온라인에서 상태 수집과 DCA 실행은 사라지지 않는다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 7, §III-B, Fig. 4; p. 8, §IV

## 24. 최적화의 범위: DCA와 전체 TOICA를 구분한다

고정된 비용표의 최적 배분은 전체 시스템의 전역 최적성보다 좁은 주장이다


| 구성 | 직접 다루는 것 | 자동으로 보장하지 않는 것 |
| --- | --- | --- |
| 우선순위 | 추정 비용의 후속 경로 | 최적 작업 순서 |
| DCA | 고정 v의 채널 개수 | ID별 간섭의 전역 최적 |
| DTO 보상 | 로컬 대비 tanh 개선 | 전역 makespan 최소 |
| 공동 실행 | 선택·배분을 매번 연결 | 모든 조건의 성능 보장 |

핵심: 이 논문의 기여는 결합 설계와 조건부 실험 성과로 읽는다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 5–7, Eqs. 14–18; mathematical consequence

| --- | --- | --- |
| ω 증가 | 대체로 지연↓·에너지↑ | 개별 점은 엄격 단조 아님 |

## 29. 36.8ms는 무엇을 나누어 얻은 시간인가

논문은 1,000 episode 시뮬레이션에 551.5초를 보고한다


| 계산·범위 | 값 | 판정 |
| --- | --- | --- |
| 총 시뮬레이션 | 551.5s / 1,000 episode | 약 0.5515s/episode |
| 15개 작업으로 나눔 | 0.5515/15 ≈ 0.0368s | 약 36.8ms/작업 |
| 포함 범위 | 시뮬레이션 평균 | 순수 추론 지연 아님 |
| 실시간 적용 | 실장치 수집·DCA·제어 | 별도 end-to-end 검증 |

핵심: 평균 시뮬레이션 시간을 실제 장치의 추론·마감시간 보장으로 옮기지 않는다

근거: [paper](https://arxiv.org/abs/2505.04272v1) p. 8, paragraph following Fig. 5; recomputed arithmetic

## 30. 수식의 빈틈은 성과와 구분해서 읽는다

논문의 설명을 그대로 인용하는 것과 증명을 확인하는 것은 다르다


| 항목 | 인쇄된 내용 | 안전한 해석 |
| --- | --- | --- |
| Eq.12 | 평균이라 부르지만 합 표기 | 추정 비용 q로 설명 |
| NP-hard 주장 | 문제에서 GKP로 매핑 | 이 방향만으로 증명 안 됨 |

핵심: 비판은 제시된 증명·표기의 범위에 한정하며 전체 실험이 무효라고 단정하지 않는다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 4–7, Eqs. 4–5, 12, 14–15, Algorithm 1, complexity paragraph

## 31. 핵심 정리: 실행 위치와 자원 배분을 함께 본다

TOICA는 작업 순서, 서버 선택, 채널 배분을 연결하는 설계다

1. **순서**: DAG 후속 비용으로 우선순위
2. **위치**: D3QN으로 로컬·서버 선택
3. **채널**: DCA로 수량 최적화 후 ID 배정
4. **검증 범위**: 조건부 시뮬레이션과 한계

핵심: DCA의 부분 문제 최적성과 TOICA 전체의 조건부 성과를 함께 구분해 이해한다

근거: [paper](https://arxiv.org/abs/2505.04272v1) pp. 1–10, §§II–V
