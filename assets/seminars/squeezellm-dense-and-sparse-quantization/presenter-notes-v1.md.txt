## 1. SqueezeLLM: Dense-and-Sparse Quantization

1. SqueezeLLM: Dense-and-Sparse Quantization

발표 대본
SqueezeLLM은 생성형 LLM의 single-batch decoding을 위한 weight-only post-training quantization 방법입니다. 핵심은 모든 값을 같은 방식으로 낮은 bit에 넣지 않는 것입니다. 대부분의 weight는 sensitivity-weighted non-uniform lookup table로 압축하고, 소수의 outlier와 highly sensitive value는 sparse FP16 예외로 보존합니다. 발표에서는 왜 이 구성이 memory wall에 맞는지, 실제 kernel이 두 경로를 어떻게 계산하는지, 결과가 어떤 조건에서 측정됐는지를 분리해 설명합니다.

## 2. 논문의 범위를 먼저 고정한다

2. 논문의 범위를 먼저 고정한다

발표 대본
Weight-only라는 말은 activation은 FP16으로 유지한다는 뜻입니다. Quantized weight도 packed index로 저장되지만 lookup 뒤 계산은 FP16입니다. 논문의 memory-wall 설명은 batch size 1에서 token 하나의 activation vector와 weight matrix를 곱하는 상황을 전제로 합니다. 여러 request를 큰 batch로 묶어 GEMM을 수행하면 weight reuse가 커져 compute-bound가 될 수 있으므로 같은 속도 논리를 그대로 적용할 수 없습니다.

## 3. Token decoding은 weight를 계속 다시 읽는다

3. Token decoding은 weight를 계속 다시 읽는다

발표 대본
Autoregressive decoding은 token을 하나씩 생성합니다. Batch 1에서는 각 layer의 weight matrix가 한 activation vector와 곱해지므로 한 번 읽은 weight를 여러 vector에 재사용하기 어렵습니다. Arithmetic intensity, 즉 memory operation 대비 compute operation 비율이 낮습니다. 이런 상황에서는 weight를 16 bit에서 3 bit 수준으로 줄이면 같은 memory bandwidth로 더 빨리 weight를 공급할 수 있습니다.

## 4. Memory-bound와 compute-bound를 구분해야 한다

4. Memory-bound와 compute-bound를 구분해야 한다

발표 대본
Uniform integer quantization은 정수 연산 효율이라는 장점이 있지만, memory-bound decoding에서는 더 중요한 것이 읽는 weight byte입니다. SqueezeLLM은 weight index를 compact하게 읽고 필요할 때 FP16 centroid로 복원합니다. 추가 lookup과 FP16 multiply-add가 있어도 compute unit이 놀고 있다면 end-to-end latency를 줄일 수 있다는 설계입니다. 이는 모든 batch와 device에서 자동으로 성립하는 정리가 아닙니다.

## 5. 3 bit는 representative value 여덟 개를 뜻한다

5. 3 bit는 representative value 여덟 개를 뜻한다

발표 대본
3 bit index는 0부터 7까지 여덟 상태를 표현합니다. SqueezeLLM은 output channel마다 별도의 FP16 centroid table을 학습합니다. Dense matrix에는 이 centroid의 index가 packed되어 있습니다. 따라서 낮은 bit budget의 핵심 질문은 여덟 representative를 range에 균등 배치할지, 실제 weight density와 sensitivity가 중요한 위치에 비균일하게 배치할지입니다.

## 6. Uniform bin은 제한된 codebook을 낭비할 수 있다

6. Uniform bin은 제한된 codebook을 낭비할 수 있다

발표 대본
Uniform quantization은 weight range를 같은 폭의 bin으로 나눕니다. 구현은 단순하지만 weight distribution이 비균일하면 representative를 효율적으로 쓰지 못합니다. 또한 어떤 weight가 최종 loss에 더 민감한지 구분하지 않습니다. SqueezeLLM은 저비트 budget을 단순 거리 평균이 아니라 sensitivity-weighted error를 줄이는 데 배분합니다.

## 7. Non-uniform LUT는 필요한 구간에 centroid를 모은다

7. Non-uniform LUT는 필요한 구간에 centroid를 모은다

발표 대본
단순 non-uniform k-means도 distribution density는 반영하지만 모든 weight를 같은 중요도로 봅니다. SqueezeLLM은 diagonal Fisher weight를 sample weight로 사용해 민감한 값의 quantization error에 더 큰 비용을 부여합니다. 그 결과 centroid가 sensitive value 근처로 끌려갈 수 있습니다. Codebook은 vector codebook이 아니라 output channel별 scalar representatives입니다.

## 8. Weight distance를 final-loss perturbation으로 바꾼다

8. Weight distance를 final-loss perturbation으로 바꾼다

발표 대본
논문은 단순한 L2 reconstruction에서 시작하지만 최종 loss에 대한 weight perturbation을 더 직접적인 목표로 선택합니다. Taylor expansion의 quadratic term에 Hessian이 등장하고, 이를 sample gradient로 계산한 Fisher matrix로 근사합니다. 다시 diagonal만 남겨 각 weight의 독립 sensitivity score Fᵢᵢ를 얻습니다. 이 근사 덕분에 문제는 weighted one-dimensional k-means가 되지만 cross-weight interaction은 반영하지 않습니다.

## 9. 같은 오차 거리도 sensitivity가 크면 더 비싸다

9. 같은 오차 거리도 sensitivity가 크면 더 비싸다

발표 대본
Weighted objective를 말로 읽으면 Fᵢᵢ 곱하기 wᵢ와 Q(wᵢ)의 거리 제곱을 모든 weight에 대해 더하는 것입니다. Fᵢᵢ가 20이면 같은 quantization distance에 대해 F가 1인 weight보다 penalty가 20배입니다. 이 점수는 calibration sample의 gradient에서 계산한 proxy이며 실제 inference마다 다시 계산하지 않습니다.

## 12. 각 output channel은 자체 scalar LUT를 갖는다

12. 각 output channel은 자체 scalar LUT를 갖는다

발표 대본
논문 Quantization Details는 output channel마다 separate lookup table을 할당합니다. 3 bit는 여덟 centroid, 4 bit는 열여섯 centroid입니다. ## 15. W=D+S로 분리한 뒤, D만 양자화한다

15. W=D+S로 분리한 뒤, D만 양자화한다

발표 대본
Decomposition은 low-rank factorization이나 pruning이 아닙니다. 선택한 value는 D에서 0으로 두고 같은 coordinate와 원래 FP16 값을 S에 저장하므로 양자화 전 W=D+S는 정확한 표현입니다. 그다음 D를 low-bit LUT로 양자화한 Q(D)를 사용합니다. 실제 inference는 Q(D)X+SX로서 원래 WX의 근사값입니다. Sparse로 이동한 값은 원래 FP16 값을 보존하지만 dense quantization error는 남습니다. 논문은 dense와 sparse kernel을 함께 launch하고 두 contribution을 합산합니다.

## 16. Sparse S에는 두 종류의 individual value가 들어간다

16. Sparse S에는 두 종류의 individual value가 들어간다

발표 대본

## 19. Runtime은 dense와 sparse path를 함께 실행한다

19. Runtime은 dense와 sparse path를 함께 실행한다

발표 대본
Dense kernel은 packed 3/4-bit index를 읽어 FP16 LUT value로 piecewise dequantize하고 activation vector와 곱합니다. Sparse kernel은 CSR coordinate와 FP16 exception을 읽어 별도의 matrix-vector product를 계산합니다. 두 kernel은 함께 launch되어 overlap할 수 있고 마지막에 DX와 SX를 더합니다. Sparse path는 정확한 selected values를 복원하지만 전체 W가 exact라는 뜻은 아닙니다. D의 나머지 값은 quantized approximation입니다.

## 20. Dense kernel은 lookup 뒤 바로 누적한다

20. Dense kernel은 lookup 뒤 바로 누적한다

## 22. Balanced kernel은 thread마다 nonzero 열 개를 맡긴다

22. Balanced kernel은 thread마다 nonzero 열 개를 맡긴다

발표 대본
SqueezeLLM의 balanced hybrid kernel은 thread 수를 정해 각 thread가 열 개 nonzero를 처리하게 합니다. 긴 row가 여러 thread에 나뉘어 load balance가 좋아지지만 같은 row contribution을 합치는 synchronization이 필요합니다. Dense non-uniform kernel과 balanced sparse kernel은 한 call로 launch해 두 output을 더하는 overhead를 줄입니다. 열 개는 저자 구현 선택이지 모든 GPU의 최적값이 아닙니다.

## 32. 논문 결과에서 말할 수 있는 범위를 지킨다

32. 논문 결과에서 말할 수 있는 범위를 지킨다

발표 대본
논문은 여러 model과 dataset을 평가하지만 모든 architecture와 hardware에 대한 theorem을 제시하지 않습니다. Dense+sparse는 selected exceptions만 exact하고 나머지 D는 quantized입니다. Diagonal Fisher는 cross-weight interaction을 버립니다. Latency는 저자 kernel과 A6000 또는 appendix A100 조건입니다. 이런 경계를 명시하면 결과를 약화하는 것이 아니라 무엇이 실제로 검증됐는지 더 정확히 전달할 수 있습니다.

## 34. SqueezeLLM을 기억하는 다섯 문장

34. SqueezeLLM을 기억하는 다섯 문장

발표 대본
SqueezeLLM의 논리를 한 문장으로 줄이면 제한된 memory bandwidth budget을 weight 중요도에 따라 다르게 배분하는 방법입니다. Dense path는 sensitivity-weighted non-uniform scalar LUT를 쓰고, sparse path는 dense range와 centroid를 망가뜨리는 예외를 exact하게 보존합니다. Runtime에서는 두 contribution을 모두 계산합니다. 결과를 인용할 때는 average bit width, model과 dataset, GPU, batch와 generated-token 조건을 함께 붙여야 합니다.
