# 일반 Task Graph MEC Offloading

논문: Offloading and Resource Allocation with General Task Graph in Mobile Edge Computing: A Deep Reinforcement Learning Approach

저자: Jia Yan, Suzhi Bi, Ying-Jun Angela Zhang (2020)

## 1. 일반 Task Graph MEC Offloading

DNN이 적은 location 후보를 만들고, 최적화 기반 evaluator가 CPU 자원까지 포함한 ETC를 고른다


근거: [paper](https://arxiv.org/abs/2002.08119) title page, abstract; arXiv v1

## 2. 왜 task 하나씩 독립적으로 offload할 수 없을까

child task는 parent의 결과 data를 받아야 하므로, 한 task의 location이 다음 task의 ready time을 바꾼다

1. **DAG 입력**: vertex는 compute task
edge는 data dependency
2. **location 선택**: 각 task를 local 또는 edge에 둔다
3. **boundary 발생**: 서로 다른 location이면
uplink 또는 downlink
4. **critical path**: 가장 늦은 dependency path가
application 종료를 결정

핵심: 일반 graph에서는 task별 빠른 선택이 아니라 dependency와 transfer를 함께 비교해야 한다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 2-3, Fig. 1, Sec. II-A

## 3. location 경계가 uplink와 downlink를 만든다

a_i는 task i 전체를 local 또는 edge에 배치하는 binary 변수다

- **레인 의존 경로**
  - **parent k**: compute L_k
output O_k,i
  - **location 비교**: a_k와 a_i
local 또는 edge
  - **필요한 transfer**: edge로: uplink
local로: downlink
  - **child i**: data가 ready된 뒤
compute L_i
- parent k → location 비교 (실선, 단방향)
- location 비교 → 필요한 transfer (실선, 단방향)
- 필요한 transfer → child i (실선, 단방향)

핵심: a_i=0은 local, a_i=1은 edge이며 partial execution은 이 논문의 action이 아니다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 3-5, Eqs. 1-12

## 4. device energy와 종료시간을 함께 최소화한다

ETC는 MD가 쓰는 energy와 virtual exit가 local에서 끝나는 time의 가중합이다


| 항 | 무엇을 세나 | location의 영향 | 주의 |
| --- | --- | --- | --- |
| local compute time | L_i / local CPU | local task일 때 | frequency가 클수록 짧음 |
| local energy | kappa L_i f_i² | local task일 때 | frequency가 클수록 큼 |
| transfer | uplink 또는 downlink | location boundary | dependency data에 따라 발생 |
| ETC | beta_e E + beta_t finish time | 모든 decision | beta_e + beta_t = 1 |

핵심: 모든 task를 edge로 보내는 선택도, 모두 local에 두는 선택도 항상 ETC 최소가 아니다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 3-5, Eqs. 1-15

## 5. 고정 action의 종료시간은 가장 늦은 path가 만든다

task의 location a를 먼저 고정하면, local CPU frequency allocation을 풀 수 있다

- **고정된 a**: 각 task의 local 또는 edge
location을 정함
- **path o1**: dependency와 transfer를
포함한 time T_o1
- **path o2**: dependency와 transfer를
포함한 time T_o2
- **path maximum**: 모든 loop-free path의
최대 time을 취함
- **terminal finish**: virtual exit의
completion time

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 7-13, Lemma 3.1, P2, Algorithm 1

## 6. critic은 학습 network가 아니라 optimizer다

candidate a마다 Algorithm 1이 local CPU frequency를 최적화하고 ETC를 계산한다

1. **candidate a**: binary location vector를
하나 고정
2. **P2 구성**: path maximum과
frequency constraint를 반영
3. **dual update**: subgradient로
multiplier를 갱신
4. **ETC 평가**: optimal frequency와
eta star를 반환

핵심: DNN이 ETC value를 근사하도록 critic을 학습하는 방식과 구별해야 한다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 11-13, Eq. 19, Algorithm 1; p. 16

## 7. actor는 state에서 relaxed location vector를 낸다

output은 final binary action이 아니라 M개 task별 0과 1 사이의 score다

- **레인 epoch t**
  - **state**: wireless channel h_t → edge CPU f_c,t
  - **actor DNN**: fully connected DNN
g_theta(state)
  - **relaxed output**: a-bar in [0,1]^M
task별 score
  - **binary candidates**: GNOP가 B개 action
vector를 생성
- state → actor DNN (실선, 단방향)
- actor DNN → relaxed output (실선, 단방향)
- relaxed output → binary candidates (실선, 단방향)

핵심: continuous score를 바로 실행하지 않고, GNOP로 제한된 binary candidate set을 만든다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 12-15, Fig. 3, Eqs. 25-29

## 8. GNOP는 순서를 보존해 binary 후보를 만든다

정확한 2의 M제곱 search 대신 actor가 제안한 B개만 evaluator가 검사한다

1. **first candidate a1**: 각 score를 0.5에서
threshold
2. **ordinary B/2**: 0.5와 거리 순으로
threshold를 이동
3. **noise B/2**: noise와 sigmoid 뒤
같은 quantization
4. **Omega_t**: B개의 binary vector를
evaluator로 전달

핵심: noise의 역할은 후보 다양화이며, noise가 ETC를 직접 최소화하는 것은 아니다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 14-15, Eqs. 26-29

## 9. best candidate가 replay label이 된다

학습 target은 return이 아니라 같은 state에서 evaluator가 고른 binary action이다

1. **candidate evaluation**: 각 a_b의 eta star를
Algorithm 1로 계산
2. **selection**: 최소 ETC candidate
a_t star 선택
3. **replay memory**: state와 a_t star를
limited memory에 저장
4. **cross-entropy**: batch를 Adam으로 학습
periodic update

핵심: 이 update는 optimization-selected action을 모방하도록 actor를 학습시키는 절차다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 15-16, Eqs. 30-31

## 10. one-climb: path별 MD에서 edge로 한 번만 이동

candidate filter가 evaluator 호출 수를 줄이지만, 일반 graph 전체에서 무조건 optimal이라는 뜻은 아니다


| path location pattern | MD to edge 이동 | filter | source의 qualification |
| --- | --- | --- | --- |
| local -> edge | 1회 | 허용 | one-climb definition |
| local -> edge -> local | 1회 | 허용 | return은 허용 |
| local -> edge -> local -> edge | 2회 | 제거 | two-time offloading |
| overlapping paths | path마다 다름 | 주의 | 추가 mild condition 필요 |

핵심: one-climb은 speed heuristic이다. 전체 DAG optimality는 조건부다

근거: [paper](https://arxiv.org/abs/2002.08119) p. 17, Definition 3; pp. 27-31, App. D

## 11. 구성 예시: parallel parent는 maximum으로 합친다

toy DAG start -> A,B -> C -> exit에서 resource를 고정해 completion-time 계산만 보인다


| candidate | A/B branch ready | C와 exit | completion time |
| --- | --- | --- | --- |
| all local | max(4.0, 2.0) = 4.0 | C local 6.0 | 10.0 time unit |
| all edge | max(0.2+0.8, 0.2+0.4) = 1.0 | C edge 1.2 + return 0.2 | 2.4 time unit |
| what changes | location boundary adds transfer | evaluator would also optimize CPU | ETC needs energy too |

핵심: 이 toy는 parallel maximum만 보이며, reported ETC나 energy result가 아니다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 5, 7-11; constructed example

## 12. 한 epoch의 hybrid decision loop

search 공간을 줄이는 learner와 feasibility·ETC를 보장하는 optimizer가 역할을 나눈다

1. **observe**: h_t와 f_c,t를
actor에 입력
2. **propose**: GNOP로 B개의
binary candidate 생성
3. **evaluate**: candidate마다 P2와
Algorithm 1 실행
4. **execute and learn**: best action 실행
replay update

핵심: learner는 후보를, optimizer는 B개 후보의 ETC 평가를 맡는다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 12-17, Fig. 3, Algorithm 1

## 17. source가 보인 것과 보이지 않은 것

hybrid candidate-search pattern은 유용하지만, model assumptions가 결과의 범위를 정한다


| established in source | not established by source |
| --- | --- |
| fixed action에서 path-aware CPU allocation을 풀 수 있음 | arbitrary workflow or partial-task execution |
| DNN proposal와 optimizer evaluation을 결합함 | learned Q critic 또는 policy-gradient method |
| 8-task simulation에서 near-optimal ETC evidence | multi-user, real deployment, arbitrary graph guarantee |
| one-climb으로 candidate evaluation을 줄임 | overlapping DAG에서 unconditional optimality |

핵심: 핵심 contribution은 candidate proposal와 model-based evaluation의 결합이다

근거: [paper](https://arxiv.org/abs/2002.08119) pp. 5, 17, 22-24, App. D

## 18. 핵심 정리

일반 task graph MEC에서는 route, transfer, critical path, and CPU resource allocation이 한 decision problem이다

- task location은 dependency transfer와 child ready time을 바꾼다
- fixed location 뒤에는 continuous CPU allocation을 푼다
- GNOP가 candidate set을 만들고 optimizer가 ETC로 고른다
- replay update는 actor가 selected action을 더 잘 제안하게 한다
- reported result는 8-task source simulation condition에 한정된다

핵심: DNN 단독 solver가 아니라 candidate proposal와 model evaluation의 결합이다

근거: [paper](https://arxiv.org/abs/2002.08119) abstract; pp. 7-17, 22-24
