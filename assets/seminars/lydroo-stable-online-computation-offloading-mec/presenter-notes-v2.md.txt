## 2. 좋은 channel의 한 frame 선택만으로는 충분하지 않다

2. 좋은 channel의 한 frame 선택만으로는 충분하지 않다

발표 대본
논문의 출발점은 fast-varying channel과 random task arrival에서의 online offloading입니다. 한 frame에서 큰 computation rate를 얻는 선택은 다음 frame의 budget pressure나 unserved workload를 표현하지 않습니다. LyDROO는 real data queue Q와 virtual energy queue Y를 state에 넣어 이 시간 연결을 보입니다. 이는 단순히 reward 항 하나를 더하는 것이 아니라, 장기 제약을 current decision에 반영하는 Lyapunov control formulation입니다.

## 3. 한 device의 한 frame: route와 연속 resource를 분리한다

3. 한 device의 한 frame: route와 연속 resource를 분리한다

발표 대본
Frame 시작에는 current channel h와 waiting task Q가 state로 주어집니다. 각 device는 binary x로 local computing 또는 edge offloading 중 하나를 고릅니다. Local이면 CPU frequency f가, offload이면 uplink duration tau와 power consumption e가 completed data D를 결정합니다. e는 E/T로 정의된 power consumption입니다. 여러 device가 offload할 때 tau들의 합은 frame 길이를 넘을 수 없습니다. 새 arrival A는 action 뒤 queue update에 들어갑니다. 논문은 edge execution과 result download delay를 무시하는 model simplification을 둡니다.

## 4. Q는 실제 workload, Y는 average-power 압력 기록이다

4. Q는 실제 workload, Y는 average-power 압력 기록이다

발표 대본
Real queue Q는 아직 처리되지 않은 task data입니다. Virtual queue Y는 average-power constraint를 나타내기 위해 만든 수학적 queue이며 battery state가 아닙니다. e=E/T는 frame power consumption이고 gamma는 long-term average-power threshold입니다. e가 gamma보다 크면 Y가 증가하고, 다음 frame objective에서 power consumption이 더 비싸게 취급됩니다. Q update에는 service causality가 있어 D는 현재 Q를 넘을 수 없습니다.

## 5. 작은 queue trace: Q와 Y의 다른 변화

5. 작은 queue trace: Q와 Y의 다른 변화

발표 대본
이 슬라이드의 모든 숫자는 teaching-only construction입니다. Q=5에서 D=3을 service하고 A=2가 도착하면 Q(next)=5-3+2=4입니다. 동시에 power e=0.8, average-power threshold gamma=0.5, nu=1이면 Y(next)=max(0.2+0.8-0.5,0)=0.5입니다. D가 Q를 넘지 않으므로 queue-causality 조건에서는 feasible합니다. Y=0.5는 energy가 저장되었다는 뜻이 아니라, future power-heavy action의 objective penalty가 커진다는 뜻입니다.

## 6. Lyapunov objective: service와 power pressure

6. Lyapunov objective: service와 power pressure

발표 대본
Reduced per-frame expression은 P2의 objective로, sum of (Q_i+V c_i)r_i minus sum of Y_i e_i입니다. 큰 Q는 served rate의 value를 높이고 큰 Y는 power-consumption cost를 높입니다. V는 neural-network parameter나 learning rate가 아니라 utility와 queue trade-off를 조절하는 Lyapunov parameter입니다. P3/P4는 P2를 fixed binary x와 continuous resource allocation으로 분해한 뒤의 subproblems입니다.

## 8. LyDROO online loop

8. LyDROO online loop

발표 대본
이 그림은 Algorithm 1의 causal order입니다. Frame t 시작에 channel h와 previous queue Q,Y가 actor input이 됩니다. Actor output은 relaxed binary vector이고 NOP가 binary candidate set을 만듭니다. Critic은 candidate마다 P4 continuous resource allocation을 풀어 drift-plus-penalty objective를 계산합니다. Chosen action 뒤 served data D와 arrival A로 Q를, frame power e로 Y를 update해 next frame input을 만듭니다.

## 9. Actor와 critic은 모두 neural network가 아니다

9. Actor와 critic은 모두 neural network가 아니다

발표 대본
LyDROO에서 actor만 DNN입니다. Critic은 action value를 neural network로 approximate하지 않고, each binary candidate에 대해 customized convex/dual resource optimizer를 실행합니다. 따라서 critic의 target value는 model과 P4 solution에서 나옵니다. 선택된 state-action pair는 replay memory에 저장되고 actor DNN은 cross-entropy regression으로 update됩니다. 이 separation이 feasibility와 explanation을 제공하지만, channel/energy model이 맞는다는 가정에도 의존합니다.

## 10. NOP: actor 후보와 noise 후보

10. NOP: actor 후보와 noise 후보

발표 대본
OPQ는 relaxed output의 entries가 0.5에서 얼마나 떨어져 있는지를 기준으로 threshold를 바꾸며 binary vectors를 만듭니다. LyDROO의 NOP는 여기에 Gaussian noise를 더하고 sigmoid를 거친 output에도 OPQ를 적용합니다. Algorithm 1은 M_1=2N으로 시작합니다. 이후 Candidate budget M_t는 최근 delta_M frame에서 선택된 best action의 half-group index m-star를 사용해 M_t=2 min(max(m-star)+1,N)로 update하며 2N 이하입니다. 즉, actor output의 가장 큰 rounded entry를 세는 규칙이 아닙니다. Candidate는 actor proposal 주변을 중심으로 하되 noisy branch가 추가 exploration을 담당합니다.

## 11. P4는 binary candidate에 조건부로 연속 resource를 푼다

11. P4는 binary candidate에 조건부로 연속 resource를 푼다

발표 대본
P4는 fixed binary offloading vector에 조건부로 정의됩니다. Local device는 closed-form CPU-frequency solution을 갖고, offloading device는 shared uplink-time constraint 아래 dual problem, bisection, linear-program recovery로 풉니다. Critic은 candidate마다 이 계산을 반복한 뒤 best score를 선택합니다. 이것은 online action selection의 일부이며, replay sample로 network weight를 update하는 periodic actor DNN training과 구분해야 합니다.

## 18. DROO와 LyDROO의 control-state 차이

18. DROO와 LyDROO의 control-state 차이

발표 대본
DROO는 DNN input h_t에서 relaxed output을 만들고 OPQ가 binary candidate를 만들며, fixed x에 조건부인 convex allocation P2로 candidate를 평가합니다. LyDROO는 actor state에 Q와 Y를 더하고, Lyapunov-weighted objective와 noisy OPQ를 사용합니다. 이 비교는 두 original formulation의 control state와 per-frame optimization을 가리킵니다. 후속 repository나 derivative의 구현이 같다고 주장하지 않습니다.

## 19. 모델의 경계도 controller 해석의 일부다

19. 모델의 경계도 controller 해석의 일부다

발표 대본
Source는 binary offloading, shared TDMA uplink를 가정하고 edge-computing과 result-download delay를 무시합니다. Exposition을 위해 linear computation-rate utility를 쓰며 corresponding P4가 efficiently solvable하면 broader concave utility도 가능하다고 말합니다. Analytical tractability를 위해 infinite queue capacity도 가정합니다. 이 model choice가 P4와 theorem의 범위를 정하므로 LyDROO를 다른 MEC나 edge application으로 옮기기 전에 확인해야 합니다.

## 20. LyDROO를 읽는 네 가지 연결

20. LyDROO를 읽는 네 가지 연결

발표 대본
마지막으로 LyDROO의 구조를 네 연결로 기억하면 됩니다. Q는 unserved workload, Y는 average-power pressure를 다음 frame state에 남깁니다. Lyapunov objective는 이 둘로 service와 energy를 비교합니다. Actor DNN은 binary candidate search를 좁히고 P4 optimizer가 continuous resources와 feasibility를 평가합니다. Theorem 1은 stated assumptions and bounded approximation gap 아래의 result이며, runtime and queue plots are reported simulation evidence under their own conditions.
