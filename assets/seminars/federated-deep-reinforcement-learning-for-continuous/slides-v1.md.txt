# Federated DRL: 종속 task offloading의 연구 구상

논문: Federated Deep Reinforcement Learning for Continuous Improving Intradependente Task Offloading in Mobile Edge Computing Network

저자: Iman Rahmati (연도 미상)

## 1. Federated DRL: 종속 task offloading의 연구 구상

Task Call Graph와 분산된 장치의 공동 학습을 연결하려는 연구 제안


근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) pp. 1–2, title and document structure

## 2. 제안한 것과 아직 검증하지 않은 것

성능 결과가 아니라 어떤 연구 문제를 구성하려는지 읽는 자료다


| 항목 | 원문의 내용 | 해석 범위 |
| --- | --- | --- |
| 문제 | 서로 종속된 task의 offloading | task 독립 가정의 한계 |
| 표현 | Task Call Graph 도입 | 구체적 encoder는 미정 |
| 학습 | federated Actor-Critic 또는 D3QN | 완성 구조를 확정하지 않음 |
| 평가 | 시뮬레이션을 개발할 계획 | 실험 수치·성능 비교 없음 |

핵심: 학습 가속·privacy·지속 개선은 이 문서에서 측정된 성과가 아니다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) p. 1, Motivation and Research Methodology

## 3. 종속 task는 실행 순서와 데이터 전달을 함께 정한다

뒤 task가 앞 task의 결과를 요구하면 두 offloading 결정을 따로 볼 수 없다

1. **앞 task A**: 먼저 결과를 계산
2. **A의 출력**: 뒤 task가 사용할 데이터
3. **위치가 다르면**: 결과 전달 비용 발생
4. **뒤 task B**: 필요한 결과 이후 실행

핵심: 화살표는 강의용 선후관계 예시이며 원문이 정한 encoder나 scheduling 규칙이 아니다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) p. 1, Problem Statement

## 4. 강의용 계산: 전송을 빠뜨리면 완료 시간을 작게 센다

A가 2 ms, B가 3 ms 걸리고 B는 A 뒤에 시작한다고 가정한다


| 조건 | 계산 | 완료 시간 |
| --- | --- | --- |
| 같은 위치·전달 비용 0 | 2 + 0 + 3 | 5 ms |
| 서로 다른 위치·전달 1 ms | 2 + 1 + 3 | 6 ms |
| 잘못된 독립·병렬 계산 | max(2,3) | 3 ms: 의존성 무시 |

핵심: 이 숫자는 연구 결과가 아니라 dependency와 전송 비용의 역할을 보여 주는 예다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) p. 1, Problem Statement; constructed teaching example

## 5. 공동 학습: local data 대신 model update를 모은다

여러 장치의 local 학습 결과를 중앙에서 결합하고 다음 local 학습에 반영한다

- **레인 장치 A**
- **레인 서버**
- **레인 장치 B**
  - **local 관측**: A의 환경·경험
  - **local 관측**: B의 환경·경험
  - **local 학습**: model update
  - **local 학습**: model update
  - **집계**: 업데이트 결합
  - **global model**: 학습 결과 공유
  - **다음 학습**: A가 model 반영
  - **다음 학습**: B가 model 반영
- local 관측 → local 학습 (실선, 단방향)
- local 관측 → local 학습 (실선, 단방향)
- local 학습 → 집계 (실선, 단방향)
- local 학습 → 집계 (실선, 단방향)
- 집계 → global model (실선, 단방향)
- global model → 다음 학습 (실선, 단방향)
- global model → 다음 학습 (실선, 단방향)

핵심: 집계 공식·통신 주기·client 선택은 미정이며, 이 흐름을 FedAvg 구현으로 단정하지 않는다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) p. 1, Motivation

## 6. Actor-Critic과 D3QN은 연구 후보로 제시된다

서로 다른 후보를 한 개의 확정된 network 구조로 합치지 않는다


| 설계 요소 | 원문 수준 | 추가로 정해야 할 것 |
| --- | --- | --- |
| MDP | 관측으로 상호작용하며 공동 목표 학습 | state·action·reward·transition |
| Actor-Critic | 후보 방법으로 언급 | network와 policy update |
| D3QN | 또 다른 후보 방법으로 언급 | 행동 정의와 Q update |
| Task Call Graph | 종속성 표현을 제안 | feature·encoder·제약 처리 |

핵심: 원문의 참고문헌이 구현한 방법을 이 제안이 이미 구현했다고 옮겨 적으면 안 된다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) pp. 1–2, Problem Model, Methodology and references [3]–[4]

## 7. local data를 보내지 않는 것과 privacy 보장은 다르다

문서는 privacy를 기대하지만 공격 모델이나 보호 메커니즘을 정의하지 않는다


| 구분 | 문서가 제안한 것 | 입증되지 않은 것 |
| --- | --- | --- |
| 데이터 위치 | 각 장치가 local data로 학습 | 어떤 정보도 유출되지 않음 |
| 통신 내용 | 주기적 model update 전송 | 업데이트가 항상 안전함 |
| privacy | 설계의 기대 방향 | 정량적 보호 수준·위협 모델 |
| 효율 | 통신 효율을 핵심 과제로 명시 | 학습·통신 비용이 항상 감소 |

핵심: 데이터를 중앙에 모으지 않는 구조만으로 privacy와 통신 절감 성과를 확정할 수 없다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) p. 1, Motivation and Key Challenges

## 8. 새 장치와 이질적인 환경을 어떻게 받아들일 것인가

지속 개선의 동기와 실제 lifelong learning 보장은 구별해야 한다


| 문제 | 연구 제안의 방향 | 아직 없는 명세 |
| --- | --- | --- |
| 새 장치 참여 | 새 경험으로 공동 model 개선 | 참여·이탈 protocol |
| 장치 이질성 | 다양한 network 구성요소 수용 | model·action 호환 방식 |
| 통신 비용 | 장치·서버 교환 효율 개선 | 주기·선택·전송량 |
| 지속 학습 | 참여 장치의 학습을 반복 | 망각·수렴·성능 보장 |

핵심: continuous improving은 연구 목표이며, 망각 없는 continual learning의 증명은 아니다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) p. 1, Motivation and Key Challenges

## 9. 연구 제안을 검증할 때 분리해야 할 효과

다음은 발표자가 정리한 평가 설계이며 원문이 수행한 실험이 아니다


| 비교 축 | 확인할 결과 | 왜 필요한가 |
| --- | --- | --- |
| dependency 처리 | 완료 시간·전송량·실행 가능성 | 종속성 모델의 효과 분리 |
| federation | local 학습과 공동 학습의 차이 | 협력 효과와 통신 비용 분리 |
| 새 장치·이질성 | 환경별 적응 성능 | 평균 개선만으로 차이를 숨기지 않음 |
| privacy·자원 | 보호 범위·학습량·통신량 | 기대 장점의 근거 확보 |

핵심: 먼저 정확한 문제·알고리즘·평가 조건을 채워야 성능 논문으로 확장할 수 있다

근거: [research-idea](https://imanrht.github.io/assets/FederatedDRL.pdf) p. 1, Research Methodology; teaching evaluation design
