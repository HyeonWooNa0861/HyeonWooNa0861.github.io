## 1. DMRO: 환경 변화에 적응하는 작업 오프로딩

1. DMRO: 환경 변화에 적응하는 작업 오프로딩

발표 대본
이 발표는 DMRO 논문이 의존 작업을 local, edge, cloud 중 어디에서 실행할지 결정하는 문제를 어떻게 학습 문제로 바꾸는지 설명합니다. 핵심은 두 층입니다. 안쪽에서는 여러 Q-network가 한 환경의 workflow 배치 후보를 만들고, 바깥에서는 서로 다른 환경의 경험을 이용해 새 환경에서 쓸 초기 파라미터를 학습합니다. 세 위치의 비용 모델, 상태와 행동, Algorithm 1과 2, 그리고 시뮬레이션 결과의 조건과 한계를 차례로 살펴봅니다.

## 2. 왜 실행 위치를 작업마다 결정해야 하는가

2. 왜 실행 위치를 작업마다 결정해야 하는가

발표 대본
논문은 하나의 cloud server, 하나의 edge server, 여러 IoT device로 구성된 환경을 가정합니다. Local은 전송이 없지만 계산 능력이 작을 수 있고, edge는 장치에 가깝지만 cloud보다 계산 능력이 작을 수 있습니다. Cloud는 계산이 빠르더라도 전송이 병목이 될 수 있습니다. 따라서 offloading은 단순히 가장 빠른 CPU를 고르는 문제가 아니라 계산 지연, 통신 지연, 에너지의 결합을 비교하는 문제입니다.

## 3. 논문의 workflow는 순차 의존 작업으로 표현된다

3. 논문의 workflow는 순차 의존 작업으로 표현된다

발표 대본
논문은 workflow x를 task v1, data flow e1,2, task v2처럼 이어지는 순차 구조로 정의합니다. 이 그림의 task 이름은 구조를 읽기 쉽게 줄인 것입니다. 중요한 점은 다음 task의 실행비용이 자기 계산량만으로 결정되지 않는다는 것입니다. 선행 task가 어디에서 실행됐는지에 따라 중간 data를 전송해야 할 수 있습니다. 따라서 이 발표에서는 이를 의존 workflow라고 부르되, 임의 모양의 일반 DAG를 해결했다고 확대 해석하지 않습니다.

## 4. 각 task는 정확히 한 위치를 선택한다

4. 각 task는 정확히 한 위치를 선택한다

## 5. 선행 task 위치가 전송 지연을 결정한다

5. 선행 task 위치가 전송 지연을 결정한다

발표 대본
식 (4)의 transmission delay를 읽는 표입니다. 인접한 두 task가 같은 위치에서 실행되면 중간 data의 전송 지연은 0입니다. 위치가 다르면 두 위치를 연결하는 bandwidth로 data size를 나눕니다. 이 때문에 현재 task의 상태에는 이전 action, 즉 선행 task의 실행 위치가 포함됩니다. 논문은 전송 중의 에너지는 단순화를 위해 무시하지만 전송 지연은 목적 함수에 포함합니다.

## 6. 목적 함수는 지연과 에너지를 한 비용으로 묶는다

6. 목적 함수는 지연과 에너지를 한 비용으로 묶는다

## 7. 비용 모델이 포함하는 것과 제외하는 것

7. 비용 모델이 포함하는 것과 제외하는 것

## 8. 교육용 계산: cloud가 가장 빠른데 edge가 이길 수 있다

8. 교육용 계산: cloud가 가장 빠른데 edge가 이길 수 있다

발표 대본
이 수치는 개념을 설명하기 위해 만든 예시이며 논문의 실험값이 아닙니다. 계산량을 1000 million cycles, local·edge·cloud capacity를 각각 100, 500, 1000 million cycles per second로 두었습니다. Edge로 가는 전송은 0.1초, cloud로 가는 전송은 2초라고 가정했습니다. Cloud의 계산만 보면 1초로 가장 빠르지만 총 지연은 3초이고, edge는 2.1초이므로 edge가 선택됩니다. 실제 논문 모델에서는 앞 task의 위치와 energy도 함께 비용을 바꿉니다.

## 10. Inner loop: 이전 배치가 다음 결정으로 전달된다

10. Inner loop: 이전 배치가 다음 결정으로 전달된다

발표 대본
한 task를 처리하는 inner loop입니다. State를 Q-network에 넣어 세 action의 가치를 얻고 epsilon-greedy로 action을 고릅니다. 선택한 위치로 local objective와 reward를 계산하고 transition을 replay memory에 저장합니다. 식 (17)처럼 지금 고른 action이 다음 state의 첫 항목으로 이동합니다. 따라서 task 2는 task 1의 위치를 알고 전송비용을 계산할 수 있습니다. 이 과정은 하나의 MEC 환경 안에서 일어나는 ordinary Q-learning입니다.

## 14. Replay memory와 frozen target은 학습 신호를 분리한다

14. Replay memory와 frozen target은 학습 신호를 분리한다

발표 대본
Replay memory는 연속해서 생성된 transition의 상관을 줄이기 위해 과거 경험을 무작위로 다시 뽑습니다. Frozen network는 online network와 구조가 같지만 매 update마다 바뀌지 않고 일정 횟수 뒤에 online parameter를 복사합니다. 식 (18)에서 현재 Q는 최신 parameter network가 계산하고, next state의 maximum Q는 frozen parameter network가 계산합니다. 이 두 장치는 DQN 계열의 inner learning 안정화 장치입니다. Outer meta-initialization과 구분해야 합니다.

## 15. 식 (18): 현재 추정과 bootstrap target을 섞는다

15. 식 (18): 현재 추정과 bootstrap target을 섞는다

식 (18)은 표준 Q-learning 형태로, 기존 Q에 학습률 theta만큼 새 target을 반영합니다. Target은 즉시 reward R과 discount factor mu를 곱한 next-state maximum Q의 합입니다. 논문은 theta를 learning rate, mu를 discount factor로 씁니다. 여기서 theta는 network parameter를 뜻하는 다른 문맥과도 겹쳐 사용되므로 발표에서는 학습률과 weight를 구분해서 읽습니다. 이 식은 inner model의 업데이트이고 meta-parameter psi는 Algorithm 2의 여러 환경 학습 뒤에 얻습니다.

## 17. 새 환경마다 처음부터 학습하는 문제

발표 대본
DMRO는 Finn 등의 MAML을 기반 배경으로 인용합니다. MAML은 task별 inner adaptation을 수행한 뒤 adaptation 결과의 loss를 통해 초기 parameter를 meta-gradient로 갱신합니다. 반면 DMRO Algorithm 2는 환경을 무작위로 바꾸고 Q-learning 경험으로 DNN을 갱신한 뒤 parameter를 psi로 출력합니다. 원문에는 MAML의 이중 gradient 목적식이 없습니다. 따라서 공통점은 좋은 initialization이라는 목적이고, 학습 절차는 동일하다고 단정하지 않습니다.

27. 논문의 결과를 안전하게 읽는 경계

## 28. DMRO를 한 흐름으로 다시 읽기

28. DMRO를 한 흐름으로 다시 읽기

발표 대본
전체 논문을 다섯 단계로 정리합니다. 첫째, workflow는 의존 task와 data flow의 순서입니다. 둘째, 각 task는 local, edge, cloud 중 하나를 고르고 계산·통신·energy 비용이 생깁니다. 셋째, inner model의 여러 Q-network가 complete placement sequence 후보를 만들고 비용이 작은 후보를 고릅니다. 넷째, outer model은 여러 environment 경험으로 initialization psi를 학습합니다. 다섯째, 저자들은 simulator에서 fixed placement와 DQN baseline, 그리고 일반 initialization과 비교합니다. 이 구조와 근거의 범위를 함께 기억하면 meta-learning이 action을 직접 고른다는 오해를 피할 수 있습니다.
