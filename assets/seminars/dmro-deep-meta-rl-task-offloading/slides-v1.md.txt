# DMRO: 환경 변화에 적응하는 작업 오프로딩

논문: DMRO: A Deep Meta Reinforcement Learning-based Task Offloading Framework for Edge-Cloud Computing

저자: Guanjin Qu and Huaming Wu (2020)

## 1. DMRO: 환경 변화에 적응하는 작업 오프로딩

Local·edge·cloud 배치와 Q-learning, meta-initialization의 두 학습 시간축


근거: [dmro-paper](https://arxiv.org/abs/2008.09930) title page and Abstract

## 2. 왜 실행 위치를 작업마다 결정해야 하는가


| 위치 | 장점 | 비용과 제약 |
| --- | --- | --- |
| Local | 전송 없이 바로 실행 | IoT 계산 능력과 에너지 제약 |
| Edge | 장치와 가깝고 대역폭이 큼 | cloud보다 계산 자원이 작을 수 있음 |
| Cloud | 가장 큰 계산 자원 | 먼 통신 경로와 낮은 대역폭 가능성 |

핵심: 가장 빠른 서버가 항상 가장 작은 전체 비용을 만드는 것은 아니다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 1–4, Sections 1 and 3

## 3. 논문의 workflow는 순차 의존 작업으로 표현된다

각 task의 출력 data가 다음 task의 입력으로 이어진다

- **레인 의존 workflow**
  - **Task v1**: 첫 작업
  - **Data e1,2**: v1 출력
  - **Task v2**: 둘째 작업
  - **Data e2,3**: v2 출력
  - **Task v3**: 셋째 작업
- Task v1 → Data e1,2 (실선, 단방향)
- Data e1,2 → Task v2 (실선, 단방향)
- Task v2 → Data e2,3 (실선, 단방향)
- Data e2,3 → Task v3 (실선, 단방향)

핵심: 일반적인 임의 DAG 전체가 아니라, 논문 식 (1)의 순차 workflow가 모델 대상이다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 4, eq. 1

## 4. 각 task는 정확히 한 위치를 선택한다

행동은 binary offload가 아니라 세 가지 discrete placement다


| 행동 a_i | 배치 벡터 | 실행 위치 | 의미 |
| --- | --- | --- | --- |
| 0 | [1, 0, 0] | Local | IoT device에서 실행 |
| 1 | [0, 1, 0] | Edge | edge server로 offload |
| 2 | [0, 0, 1] | Cloud | cloud server로 offload |

핵심: 한 task를 여러 위치에 나누어 실행하는 partial partition 모델은 아니다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 4–5, eqs. 2, 11–12

## 5. 선행 task 위치가 전송 지연을 결정한다


| 선행 위치 | 현재 위치 | 전송 지연 |
| --- | --- | --- |
| 같은 위치 | 같은 위치 | 0 |
| Local | Edge | data size ÷ IoT–edge bandwidth |
| Edge | Cloud | data size ÷ edge–cloud bandwidth |
| Local | Cloud | data size ÷ IoT–cloud bandwidth |

핵심: 현재 task의 최선은 선행 task가 어디에 있었는지에 따라 달라질 수 있다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 4, eq. 4 and Section 3.3

## 6. 목적 함수는 지연과 에너지를 한 비용으로 묶는다

1. **계산 지연**: task work를 선택 위치의 계산 능력으로 나눈다
2. **전송 지연**: 위치가 바뀌면 data size를 link bandwidth로 나눈다
3. **에너지**: task 크기와 위치별 energy 계수를 곱한다
4. **Workflow 비용**: 전체 지연에 delta × 전체 energy를 더한다
5. **배치 선택**: 모든 task가 세 위치 중 하나를 고르도록 최소화한다

핵심: delta는 energy와 delay 사이의 상대적 중요도를 조절한다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 4, eqs. 3–11

## 7. 비용 모델이 포함하는 것과 제외하는 것


| 항목 | 모델 처리 | 발표에서의 해석 |
| --- | --- | --- |
| 계산 지연 | 위치별 computing capacity 반영 | task work가 클수록 증가 |
| 전송 지연 | 인접 task 위치가 다르면 반영 | link bandwidth가 작으면 증가 |
| 계산 에너지 | 위치별 energy 계수 반영 | alpha·beta로 서버 energy 가중 |
| 전송 에너지 | 단순화를 위해 제외 | 실제 장치 비용 전체는 아님 |
| 결정 지연 | 짧다고 가정하여 제외 | 실시간 latency 측정은 아님 |

핵심: 최적이라는 표현은 이 논문이 정의한 비용과 가정 안에서만 성립한다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 4, Sections 3.2–3.4

## 8. 교육용 계산: cloud가 가장 빠른데 edge가 이길 수 있다

논문 결과가 아닌 단일 task 예시이며 energy는 제외한다


| 선택 | 계산 지연 | 추가 전송 | 합계 |
| --- | --- | --- | --- |
| Local | 1000 ÷ 100 = 10.0 s | 0 s | 10.0 s |
| Edge | 1000 ÷ 500 = 2.0 s | 0.1 s | 2.1 s |
| Cloud | 1000 ÷ 1000 = 1.0 s | 2.0 s | 3.0 s |

핵심: 서버 계산 속도와 network 이동 비용을 함께 봐야 placement가 정해진다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 4, eqs. 3–4; invented example

## 9. 한 task의 결정을 RL transition으로 바꾼다


| 요소 | 논문의 정의 | 필요한 이유 |
| --- | --- | --- |
| State S_i | 이전 action, incoming flow, 현재와 남은 task 정보 | 앞선 배치와 남은 일을 함께 본다 |
| Action a_i | 0 local, 1 edge, 2 cloud | 현재 task의 위치를 고른다 |
| Local cost F | 계산 지연 + 이전 전송 지연 + delta × energy | 현재 action을 비용으로 비교한다 |
| Reward R | 최적 action: −min F; 그 외: −max F | 원문 고유의 두 수준 reward 규칙 |
| Next state | 현재 action이 다음 state의 이전 위치가 됨 | 의존 전송비용을 다음 결정에 전달한다 |

핵심: Meta-learning이 action을 고르는 것이 아니라 inner Q-network가 이 transition을 학습한다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 5, eqs. 12–17

## 10. Inner loop: 이전 배치가 다음 결정으로 전달된다

- **레인 한 환경 안의 결정**
  - **State S_i**: 이전 위치와 남은 workflow
  - **Q-network**: 세 action value 계산
  - **Action a_i**: Local 0 → Edge 1 → Cloud 2
  - **Cost와 reward**: F를 평가하고 경험 저장
  - **State S_i+1**: a_i가 이전 위치가 됨
- State S_i → Q-network (실선, 단방향)
- Q-network → Action a_i (실선, 단방향)
- Action a_i → Cost와 reward (실선, 단방향)
- Cost와 reward → State S_i+1 (실선, 단방향)

핵심: Task를 순서대로 처리하므로 현재 action은 다음 state의 일부가 된다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 5, eqs. 12–17

## 11. 교육용 trace: 두 task의 배치가 이어지는 방식

논문 결과가 아닌 계산 예시이며, 각 단계에서 energy는 0으로 둔다


| 단계 | State의 이전 위치 | 비교한 총 지연 | 선택과 다음 state |
| --- | --- | --- | --- |
| Task 1 | 시작 위치 Local | Local 10.0, Edge 2.1, Cloud 3.0 s | Edge 선택 → 이전 위치 Edge |
| Task 2 | 이전 위치 Edge | Local 5.2, Edge 1.0, Cloud 0.9 s | Cloud 선택 → 이전 위치 Cloud |

핵심: 두 번째 비교에는 첫 번째 선택에서 생긴 위치 정보가 실제로 들어간다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 4–5, eqs. 4 and 13–17; invented example

## 12. 여러 Q-network가 서로 다른 전체 배치 후보를 만든다

s개의 parallel unit은 물리적으로 분리된 서버라는 뜻이 아니다

- **레인 후보 1**
- **레인 후보 2**
- **레인 후보 s**
  - **Workflow와 S_i**: 같은 state를 복제
  - **Q-unit 1**: epsilon-greedy action
  - **Q-unit 2**: epsilon-greedy action
  - **Q-unit s**: epsilon-greedy action
  - **Sequence A1**: a1, a2, …, aN
  - **Sequence A2**: a1, a2, …, aN
  - **Sequence As**: a1, a2, …, aN
  - **최소 비용 후보**: Q(x,b)가 가장 작은 sequence
- Workflow와 S_i → Q-unit 1 (실선, 단방향)
- Workflow와 S_i → Q-unit 2 (실선, 단방향)
- Workflow와 S_i → Q-unit s (실선, 단방향)
- Q-unit 1 → Sequence A1 (실선, 단방향)
- Q-unit 2 → Sequence A2 (실선, 단방향)
- Q-unit s → Sequence As (실선, 단방향)
- Sequence A1 → 최소 비용 후보 (실선, 단방향)
- Sequence A2 → 최소 비용 후보 (실선, 단방향)
- Sequence As → 최소 비용 후보 (실선, 단방향)

핵심: 병렬성의 역할은 한 workflow에 대해 여러 placement sequence를 탐색하는 것이다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 5–7, Fig. 3 and Algorithm 1

## 13. Algorithm 1: 후보 생성과 Q-learning을 함께 수행한다

원문 26개 줄을 학습 흐름 중심으로 압축한 구조다

1. **Meta 초기화**: s개 DNN을 같은 psi로 초기화하고 memory를 비운다
2. **Task별 action**: S_i를 복제하고 각 unit이 epsilon-greedy action을 낸다
3. **후보 완성**: 각 unit의 action을 A_j에 누적해 전체 배치를 만든다
4. **최종 선택**: Workflow 비용이 가장 작은 A_j를 출력한다
5. **Replay 학습**: 경험을 저장하고 표본화해 s개 network를 갱신한다

핵심: 최종 후보 선택과 network 학습은 관련되지만 같은 연산 단계는 아니다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 7, Algorithm 1

## 14. Replay memory와 frozen target은 학습 신호를 분리한다

- **저장 transition**: S_i, a_i, reward, S_i+1
- **Online network**: 현재 Q(S_i,a_i)를 갱신
- **Frozen network**: 다음 state의 최대 Q를 계산
- **Q-learning target**: 즉시 reward와 할인된 미래값 결합
- **Parameter update**: online weight를 학습

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 5–7, eq. 18 and Algorithm 1, [dqn-paper](https://www.nature.com/articles/nature14236) Methods, experience replay and target network

## 15. 식 (18): 현재 추정과 bootstrap target을 섞는다


| 항 | 역할 | 원문 기호 |
| --- | --- | --- |
| 현재 추정 | Online network가 계산한 Q(S_i,a_i) | Q |
| 즉시 신호 | 선택한 action에서 받은 reward | R |
| 미래 추정 | Frozen network의 next-state 최대 Q | max Q |
| 학습률 | 새 target을 반영하는 비율 | theta |
| 할인율 | 미래 reward의 비중 | mu |

핵심: 이 업데이트는 한 환경의 action value를 학습하며, psi를 직접 만드는 식은 아니다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 6, eq. 18

## 16. 논문의 DQN baseline과 DMRO의 차이


| 구성 | DQN baseline | DMRO |
| --- | --- | --- |
| 후보 network | Parallel network 1개로 단순화 | s개 parallel unit |
| 새 환경 시작 | 일반 초기 parameter | 학습된 meta-parameter psi |
| Action | Local·edge·cloud 중 선택 | 동일한 세 action |
| Inner update | Q-learning | Replay와 frozen target을 쓰는 Q-learning |
| 검증 범위 | Fig. 6과 8의 simulator baseline | 같은 simulator 조건의 제안법 |

핵심: DMRO의 차별점은 action 공간이 아니라 병렬 후보와 환경 간 초기화 학습이다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 8, Section 5.3, [dqn-paper](https://www.nature.com/articles/nature14236) Methods

## 17. 새 환경마다 처음부터 학습하는 문제

1. **환경 변화**: 계산 능력과 link bandwidth 조건이 달라진다
2. **비용 관계 변화**: 같은 task라도 좋은 placement가 달라질 수 있다
3. **기존 초기화**: 한 환경에 맞춘 weight가 새 환경에 맞지 않을 수 있다
4. **Meta 목표**: 여러 환경에서 빠르게 학습할 시작점 psi를 만든다

핵심: DMRO에서 meta-learning의 출력은 placement가 아니라 inner network의 초기값이다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 1–2 and pp. 5–7, Sections 1 and 4.2

## 18. Algorithm 2: 여러 환경을 바꾸며 초기값 psi를 학습한다

Meta algorithm의 출력은 최종 DNN parameter다

1. **일반 초기화**: DNN을 theta0로 시작하고 memory를 비운다
2. **환경 표본화**: 한 환경을 무작위로 골라 state와 action을 만든다
3. **경험 저장**: 환경에서 얻은 transition을 memory에 넣는다
4. **환경 재표본화**: 환경을 다시 고르고 random replay로 weight를 갱신한다
5. **Meta 출력**: 훈련된 DNN parameter를 psi로 내보낸다

핵심: Outer loop는 특정 환경의 최적점보다 여러 환경에 쓸 시작점을 목표로 한다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 6–7, Section 4.2 and Algorithm 2, [maml-paper](https://proceedings.mlr.press/v70/finn17a.html) Sections 2–3, cited background

## 19. 두 시간축: 환경 간 초기화와 환경 안의 적응

- **레인 환경 간 학습**
- **레인 새 환경 학습**
  - **Train 환경**: E1 → E2 → E3
  - **Algorithm 2**: 환경을 바꾸며 학습
  - **초기값 psi**: Inner DNN 공통 시작점
  - **새 환경**: 새 capacity와 bandwidth
  - **Algorithm 1**: Workflow Q-learning
  - **배치 sequence**: Local → Edge → Cloud
- Train 환경 → Algorithm 2 (실선, 단방향)
- Algorithm 2 → 초기값 psi (실선, 단방향)
- 새 환경 → Algorithm 1 (실선, 단방향)
- 초기값 psi → Algorithm 1: 초기값 전달 (점선, 단방향)
- Algorithm 1 → 배치 sequence (실선, 단방향)

핵심: Meta-learning은 action selector가 아니라 inner learner의 시작점을 만든다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 5–7, Fig. 2 and Algorithms 1–2

## 20. DMRO의 meta algorithm과 표준 MAML을 구분한다


| 항목 | MAML 원 논문 | DMRO 원문 |
| --- | --- | --- |
| 공통 목표 | 적은 update로 적응할 초기 parameter | 새 MEC 환경에 쓸 초기 parameter psi |
| Task 또는 환경 | Task distribution에서 표본화 | 서로 다른 MEC environment를 표본화 |
| Inner update | Task별 gradient adaptation | Q-learning 경험으로 DNN 갱신 |
| Outer update | Adaptation 뒤 meta-gradient 명시 | 별도 meta-gradient 식을 제시하지 않음 |
| 안전한 명칭 | Model-Agnostic Meta-Learning | MAML에서 영감을 받은 초기화 학습 |

핵심: 빠른 적응이라는 목표는 공유하지만 Algorithm 2를 그대로 MAML이라 부를 수는 없다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 6–7, Section 4.2 and Algorithm 2, [maml-paper](https://proceedings.mlr.press/v70/finn17a.html) Sections 2–3

## 21. 실험은 simulator의 한 edge·한 cloud 환경이다


| 항목 | 설정 | 해석 경계 |
| --- | --- | --- |
| 사용자와 workflow | IoT user 4명, 각 5개 workflow | 실장치 trace가 아님 |
| Task data | 첫 task 50–100 MB, 이후 10–50 MB | 무작위 생성 workload |
| Task work | 10^3–10^5 MHz로 무작위 표기 | 원문 단위를 그대로 인용 |
| DNN | 입력층, hidden layer 2개, 출력층 | 세부 layer 폭은 제시되지 않음 |
| Energy weight | alpha = beta = 1 | 서버 energy도 동일 weight로 포함 |

핵심: 결과는 실제 edge hardware benchmark가 아니라 설정된 simulator 비교다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) p. 7, Section 5.1

## 23. 수렴 실험이 알려 주는 training 설정


| 그림 | 비교 | 원문 관찰 | 후속 설정 |
| --- | --- | --- | --- |
| Fig. 4 | 여러 learning rate | 0.01이 표시된 조건 중 가장 좋은 수렴 | 이후 0.01 사용 |

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 8–9, Sections 5–6

## 28. DMRO를 한 흐름으로 다시 읽기

1. **의존 workflow**: 각 task와 중간 data flow를 순서대로 입력한다
2. **세 위치 비용**: 계산·전송 지연과 weighted energy를 평가한다
3. **Inner Q-learning**: 병렬 network가 placement sequence 후보를 만든다
4. **Outer 초기화**: 여러 환경에서 새 learner의 시작점 psi를 학습한다
5. **조건부 평가**: 정해진 simulator와 environment shift에서 비교한다

핵심: DMRO의 핵심은 세 위치의 순차 결정과 환경 간 초기화 학습을 분리해 결합한 것이다.

근거: [dmro-paper](https://arxiv.org/abs/2008.09930) pp. 3–9, Sections 3–6
