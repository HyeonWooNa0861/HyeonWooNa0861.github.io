# LyDROP: WP-MEC 부분 오프로딩의 온라인 제어

논문: Online Partial Computation Offloading Optimization in Wireless Powered Mobile Edge Computing Network

저자: Lu Sun, Rina Liang, Liangtian Wan, Kaihui Liu, Zhaolong Ning, Jie Wang (2026)

## 1. LyDROP: WP-MEC 부분 오프로딩의 온라인 제어

무선 전력, 부분 에너지 분할, uplink 시간을 함께 정해 데이터 큐를 다룬다


근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) title, abstract

## 2. 왜 매 frame마다 다시 결정해야 하는가

channel과 새 task 도착이 변하면, 전력 수확과 데이터 처리의 균형도 함께 바뀐다

1. **현재 channel**: 수확 가능한 에너지 E가 달라진다
2. **기다리는 data**: 현재 queue Q가 service의 가치를 바꾼다
3. **공유 frame**: WPT 시간과 모든 uplink 시간이 경쟁한다
4. **온라인 control**: 이번 frame의 delta, a, tau를 선택한다

핵심: LyDROP은 고정된 offload 선택이 아니라 매 frame의 공동 자원 결정을 다룬다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 1–4, §§1–3

## 3. 한 frame의 물리적 분할: 전력 수확에서 service까지

AP의 WPT 시간 a가 에너지 E를 만들고, E와 uplink 시간 tau가 local·offload service를 결정한다

- **레인 one WD, one frame**
  - **AP WPT**: WPT: a
power transfer
  - **energy E**: E=sigma P_a h aT
channel h
  - **split delta**: local (1-d)E
offload dE
  - **uplink tau**: tau_i per WD
a+sumtau<=1
  - **data D**: D=D_L+D_O
D <= Q
- AP WPT → energy E (실선, 단방향)
- energy E → split delta (실선, 단방향)
- split delta → uplink tau (실선, 단방향)
- uplink tau → data D (실선, 단방향)

핵심: a, delta, tau는 서로 다른 자원 결정이며 하나의 offload label로 합치면 안 된다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 4–5, Eqs. 1–9

## 4. delta: binary route가 아닌 연속 에너지 분할

0과 1 사이의 delta는 local과 offload 처리량을 같은 frame에 함께 만들 수 있다

- **harvested E**: 현재 frame에서
쓸 수 있는 에너지
- **delta = 0**: 모든 E를 local
D = D_L
- **0 < delta < 1**: E를 두 branch에 분할
D = D_L + D_O
- **delta = 1도 가능**: 모든 E를 offload에
배정할 수 있다
- **partial decision**: 어떤 비율이 좋은지는
h, Q, a, tau에 의존

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 4–5, Eqs. 1–6

## 5. service는 현재 data와 frame budget을 넘을 수 없다

새 arrival은 이번 service 뒤 queue에 들어오므로 actor의 현재 state와 구분된다


| 제약 또는 상태 | 의미 | 잘못 읽기 쉬운 점 |
| --- | --- | --- |
| a + sum tau <= 1 | WPT와 모든 WD uplink가 한 frame을 공유 | 각 WD가 tau를 독립 선택하지 않는다 |
| D_i <= Q_i(t) | 현재 queue에 있던 data만 service 가능 | 이번 arrival을 미리 처리하지 않는다 |
| Q_i(next) = Q_i - D_i + R_i | service 뒤 새 arrival을 더한 data queue | virtual energy queue가 아니다 |
| actor state xi | current h와 Q | R은 actor input으로 명시되지 않는다 |

핵심: queue update의 순서를 지켜야 partial offloading의 인과관계가 보인다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 4–6, Eqs. 9–11

## 6. 강의용 한 WD 계산: 분할·제약·queue를 함께 확인한다

아래 수치는 논문 실험값이 아니라 식의 인과관계를 보이는 재계산 예시다

1. **energy**: a=0.5이면 E=0.5×4×1×0.5×1 = 1 J
2. **split**: delta=0.5로 local과 offload에 각 0.5 J
3. **service**: D_L=1.587, D_O=1.098, total D=2.685 bits
4. **causal checks**: a+tau=0.75<=1, D=2.685<=Q=3
5. **next queue**: arrival R=0.2 뒤 Q(next)=3−2.685+0.2=0.515

핵심: 수확 에너지, shared time, 현재 queue 검사를 통과한 뒤에만 새 arrival을 더한다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 4–6, Eqs. 1–10

## 7. P1의 장기 목표를 P2의 현재 frame score로 읽는다

Lyapunov drift-plus-penalty는 queue backlog와 weighted computation rate를 같은 frame 결정에 넣는다


| 수준 | 원문의 질문 | 발표에서 읽을 핵심 |
| --- | --- | --- |
| P1 long run | weighted rate를 높이고 strong data-queue stability를 만족 | 장기 목표와 제약을 정의한다 |
| Lyapunov L | data queue 제곱합으로 congestion을 표현 | 큰 Q는 미처리 data가 많음을 뜻한다 |
| P2 per frame | Q_i + V omega_i로 현재 rate를 가중 | backlog와 rate 선호를 함께 반영 |
| V > 0 | penalty scaling parameter | 실험 tuning 관찰을 보장으로 바꾸지 않는다 |

핵심: P2는 이번 frame의 candidate를 비교하는 score이며 learned-policy 최적성 정리는 아니다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) p. 6, Eqs. 11–16; Lemma 1

## 8. Q와 V omega가 P2에서 하는 일

P2는 한 WD의 score를 Q_i와 V omega_i가 곱해진 current computation rate로 높이려 한다

- Q_i가 크면 오래 기다린 data를 service하는 항의 비중이 커진다.
- omega_i는 device별 weighted-rate priority를 표현한다.
- V는 rate objective의 scale을 조절하는 control parameter다.
- 이 score만으로 모든 future channel·arrival을 예측하거나 learned policy의 안정성을 증명하지는 않는다.

핵심: P2는 backlog를 반영한 current-frame rate 기준이다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) p. 6, Eqs. 14–16; p. 10, Fig. 6

## 9. LyDROP: DNN 제안과 model-based 선택

actor는 relaxed delta를 제안하고, critic은 candidate별 P2 resource solve로 최종 joint action을 고른다

- **레인 one-frame control**
  - **state xi**: current h → current Q
  - **actor DNN**: input h, Q
output d-hat
  - **2K+1 delta**: delta list
search
  - **P2 critic**: fixed d solve
P2 score G
  - **action**: d*, tau*, a*
update Q
- state xi → actor DNN (실선, 단방향)
- actor DNN → 2K+1 delta (실선, 단방향)
- 2K+1 delta → P2 critic (실선, 단방향)
- P2 critic → action (실선, 단방향)

핵심: critic은 learned value network가 아니라 fixed-delta resource optimizer다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 7–9, Fig. 3; Algorithm 1

## 11. noisy order: near-0.5 entry의 순서를 사용

교육용 vector는 후보가 여전히 연속 partial ratio임을 보여 주며, 원문의 수치 예시는 아니다

1. **relaxed vector**: delta-hat = [0.18, 0.47, 0.82]
2. **distance**: 0.5와의 거리로 entry order를 만든다
3. **shifted branch**: ranked entry에 partial shift를 적용한다
4. **noise branch**: Gaussian white noise를 더해 candidate를 넓힌다
5. **ratio candidates**: 각 entry가 local·offload energy split을 유지

핵심: candidate search는 binary action 조합 나열이 아니라 partial vector 주변의 탐색이다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 7–8, Eqs. 18–20; p. 13, Fig. 16

## 12. fixed delta 뒤의 연속 resource solve

candidate delta가 고정되면 a와 tau를 푸는 P2 subproblem은 convexity를 이용할 수 있다

- **레인 one candidate**
  - **input**: fixed delta → current h, Q
  - **P2**: maximize G
queue, time
  - **bisection**: dual epsilon
monotone
  - **score G**: a*, tau*
return G
- input → P2 (실선, 단방향)
- P2 → bisection (실선, 단방향)
- bisection → score G (실선, 단방향)

핵심: fixed-delta solver는 candidate 평가용 P2 subproblem을 푼다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 8–9, Eqs. 21–28; Algorithm 2

## 13. bisection으로 dual epsilon을 찾는다

Algorithm 2의 목적은 candidate별 timing resource allocation을 빠르게 계산하는 것이다

1. **bounds**: LB와 UB로 epsilon search interval을 둔다
2. **midpoint**: epsilon을 midpoint로 잡고 condition Omega를 계산
3. **bound update**: condition 부호에 따라 LB 또는 UB를 갱신
4. **stop**: |UB−LB|가 tolerance 이하면 멈춘다
5. **resources**: a*와 tau*를 계산해 G evaluation에 쓴다

핵심: Lambert-W 유도식의 상세 암기는 필요 없지만 fixed-delta 이후의 계산 역할은 알아야 한다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) p. 9, Eq. 28; Algorithm 2; Appendix

## 14. online action과 periodic DNN training

Algorithm 1은 매 frame의 joint action과 replay-memory batch training을 같은 순서에 두지만 역할은 구분한다


| 과정 | 언제 쓰는가 | 무엇을 하는가 |
| --- | --- | --- |
| online action | 각 frame의 current h, Q | delta candidate를 평가해 delta*, tau*, a* 실행 |
| queue update | 현재 service 뒤 | D를 반영하고 새 R을 더해 Q 갱신 |
| replay memory | joint action 실행 뒤 | Fig. 3의 (xi, delta) 경험으로 memory 갱신 |
| DNN training | mod(t, gamma)=0일 때 | 갱신된 memory의 sample batch로 학습 |

핵심: training interval gamma와 on-device training latency는 다른 문제다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 7-8, Fig. 3 and Algorithm 1

## 17. K와 V는 paper의 simulation tuning 변수다

- Table IV의 K=8, 9, 10 CPU computation time은 각각 0.1833, 0.1636, 0.1551이다.
- Fig. 5와 Table IV를 바탕으로 authors는 K=10을 선택한다.
- Fig. 6은 kappa_i=8 Mbps에서 V가 커질수록 weighted rate가 증가하는 실험 관찰을 보인다.
- K=10과 특정 V가 모든 topology·arrival·hardware에서 최적이라는 뜻은 아니다.

## 21. Melbourne: location-based simulation

real user locations를 활용했지만 WPT field deployment measurement로 읽을 근거는 없다

- source는 Melbourne BS 위치를 정하고 주변 latitude·longitude 범위의 816 user groups를 사용한다.
- Figs. 14–15는 user count를 바꾸며 네 알고리즘을 비교한다.
- location distribution이 균등 거리 가정과 다르다는 점을 experiment input에 반영한다.
- 실제 AP charging, device battery, MEC execution trace를 현장에서 측정한 결과라고 주장하지 않는다.

핵심: real location data와 field deployment evidence는 서로 다른 수준의 근거다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 12–13, Figs. 14–15

## 22. 모델 가정은 결과를 어디까지 일반화할지 정한다

paper의 positive result와 system omission을 함께 읽어야 LyDROP의 적용 경계를 알 수 있다


| 가정 또는 omission | 왜 중요한가 |
| --- | --- |
| same-frame energy use | controller state에 inter-frame battery dynamics를 두지 않는다 |
| one AP, fixed WD locations | mobile·multi-AP coordination을 직접 다루지 않는다 |
| AP compute and feedback delay omitted | task complexity·concurrency가 커지면 schedule 판단이 달라질 수 있다 |
| Lyapunov-guided DNN candidate control | learned policy의 global optimality theorem을 source가 제시하지 않는다 |

핵심: LyDROP은 명시된 WP-MEC model에서의 방법이며 모든 deployment 조건의 보장은 아니다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 5–6, 13–14; §§3, 6

## 23. LyDROP을 이해하는 네 연결

부분 에너지 분할, data queue, candidate selection, fixed-delta solver가 함께 있어야 논문의 control loop가 완성된다

1. **physical split**: a가 E를 만들고 delta가 E를 local·offload에 나눈다
2. **queue guidance**: Q와 V omega가 P2에서 현재 service 가치를 만든다
3. **candidate selection**: DNN delta-hat에서 2K+1 partial vector를 생성한다
4. **resource solve**: fixed delta마다 dual/bisection으로 a*, tau*, G를 계산한다

핵심: LyDROP은 partial split, queue control, P2 solve를 결합한다

근거: [ieee-paper](https://doi.org/10.1109/TCCN.2025.3612741) pp. 4–13, §§3–6
