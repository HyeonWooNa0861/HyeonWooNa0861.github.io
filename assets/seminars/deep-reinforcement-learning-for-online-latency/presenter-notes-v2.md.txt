## 1. DECENT: 온라인 MEC Offloading의 지연·자원 결정

1. DECENT: 온라인 MEC Offloading의 지연·자원 결정

발표 대본
이 발표는 Akhavan 등의 DECENT 논문을 소개합니다. 논문은 이미 offloading하기로 결정된 IoT task가 도착할 때, 어느 MEC server로 보낼지와 얼마나 많은 computing resource를 줄지를 함께 고릅니다. 핵심 목적은 priority를 반영한 cumulative response time을 낮추는 것입니다. 여기서 제시되는 결과는 특정 simulation의 비교 결과이며, global optimality나 field deployment 보장은 아닙니다.

## 2. 가장 가까운 MEC server가 항상 최선은 아닌 이유

2. 가장 가까운 MEC server가 항상 최선은 아닌 이유

발표 대본
MEC는 remote cloud보다 가까운 compute resource를 제공할 수 있지만, 논문은 가까운 MEC server가 computing resource의 제한 때문에 최선이 아닐 수 있다고 설명합니다. BS는 destination별 communication queue를, MEC server는 computing queue를 유지합니다. 따라서 어떤 server가 좋은지는 network side와 compute side의 현재 적체, 그리고 task priority에 따라 달라집니다.

## 3. 이 논문이 결정하는 것과 결정하지 않는 것

3. 이 논문이 결정하는 것과 결정하지 않는 것

발표 대본
논문은 tasks have already been determined to be offloaded라고 명시합니다. 그러므로 local versus offloading policy로 확장해서 설명하면 안 됩니다. resource management는 MEC server에서 task에 줄 compute resource의 양입니다. 또한 return result를 device로 보내는 delay는 모델에서 고려하지 않습니다.

## 4. MEC 시스템에서 BS가 보는 두 종류의 대기열

4. MEC 시스템에서 BS가 보는 두 종류의 대기열

발표 대본
Figure 1은 BS가 여러 communication queue를 갖고, 각 MEC server가 computing queue를 갖는 구조를 보여줍니다. communication queue는 task가 해당 MEC server로 전송되기 전 대기하는 곳이고, computing queue는 충분한 compute resource가 풀리기까지 대기하는 곳입니다. 이 도식은 한 task의 logical path를 설명하며, training episode의 시간축은 아닙니다.

## 5. response time은 network path와 computing path를 합친다

5. response time은 network path와 computing path를 합친다

발표 대본
Network delay는 transmission time, BS와 MEC server 사이 E2E delay, 그리고 해당 destination의 communication-queue wait를 합칩니다. Computing delay는 execution time과 computing-queue wait를 합칩니다. source Eq. 3에서 execution time은 μlᵢ/rᵢₖ이므로, resource allocation은 computing path를 바꿉니다. split branches는 논리적 분해이며, 두 branch가 병렬로 독립 실행된다는 뜻은 아닙니다.

## 6. P0: priority를 반영한 response time 최소화

6. P0: priority를 반영한 response time 최소화

발표 대본
P0의 ηᵢ는 task priority 또는 weight입니다. ηᵢ가 크면 system이 그 task의 response time을 더 줄이려 한다고 논문은 설명합니다. constraint 5는 task 하나가 하나의 MEC server에만 offload됨을, constraint 7은 rᵢₖ가 CPU core 수 같은 discrete computing-resource block임을 뜻합니다. 논문은 P0를 NP-hard라고 부르고 DRL로 sub-optimal solution을 찾습니다. 별도의 NP-hardness proof는 제공하지 않습니다.

8. action·reward: server와 resource의 짝

## 9. A2C에서 actor와 critic이 나누는 일

9. A2C에서 actor와 critic이 나누는 일

발표 대본
이 slide는 action generation이 아니라 replay에서 sample한 transition의 update dependency를 보여 줍니다. 원문 Eq. 8은 discounted expected cumulative reward J(theta)를, Eq. 9는 policy-gradient expression을, Eq. 10은 TD advantage를, Eq. 11은 printed actor update를 제시합니다. 원문은 critic input을 state-action pair라고 설명하면서 output은 state value V(s)로 표기합니다. 이 interface를 특정 implementation으로 정규화하지 않습니다. Arrows는 learning dependency이며 physical MEC queue의 time axis가 아닙니다. Eq. 11의 sign convention도 원문만으로 해결되지 않습니다.

## 10. 원문의 actor·critic update와 구현 경계

10. 원문의 actor·critic update와 구현 경계

발표 대본
Source text는 actor가 J(theta)를 maximize한다고 말하지만 Eq. 11은 theta에서 beta_a times gradient J를 빼는 형태로 print되어 있고 gradient descend라고 부릅니다. 따라서 source만으로는 implementation이 negative loss를 minimize했는지, gradient sign을 바꿨는지, 표기에 부호 문제가 있는지 결정할 수 없습니다. Softmax probabilities와 stated epsilon-greedy selection을 어떻게 연결하는지, legal server-resource pair encoding과 masking도 source는 정하지 않습니다. 이 덱은 printed update를 제시하지만 특정 code correction을 단정하지 않습니다. Algorithm 1의 replay buffer도 source에 명시되므로 standard on-policy A2C라고 덧붙이지 않습니다.

## 11. Algorithm 1: training에서 transition을 모아 update한다

11. Algorithm 1: training에서 transition을 모아 update한다

발표 대본
Algorithm 1은 training episode와 task arrival의 nested loop를 보입니다. 각 arrival에서 state를 얻고, epsilon-greedy로 [xᵢₖ,rᵢₖ]를 계산하고, reward를 계산해 transition을 replay buffer에 넣습니다. 그 후 sampled transitions로 actor Eq. 11과 critic Eq. 13을 update합니다. 논문은 epsilon-greedy가 10% random, 90% greedy action이라고 명시하지만, replay sampling batch size나 convergence criterion은 주지 않습니다. 이 flow는 training procedure 순서입니다.

## 18. 이 논문을 적용 주장으로 바꾸기 전에 남는 경계

18. 이 논문을 적용 주장으로 바꾸기 전에 남는 경계

발표 대본
마지막으로 scope를 확인합니다. Source의 explicit MDP state는 eta_i, l_i, C, D, B입니다. E2E delay는 network delay model 항이며 source는 network controller가 이를 monitor할 수 있다고 설명하지만 separate state component로 열거하지 않습니다. Action은 one MEC destination과 discrete resource level이지만 exact softmax action encoding은 명시하지 않습니다. Algorithm 1은 replay storage와 sampling을 적습니다. Evidence는 one BS와 four servers의 simulation이고 source는 global optimality, convergence theorem, field deployment overhead를 제공하지 않습니다.
