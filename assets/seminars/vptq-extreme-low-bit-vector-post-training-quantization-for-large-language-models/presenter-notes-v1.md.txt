## 1. VPTQ: 초저비트 벡터 사후 양자화

1. VPTQ: 초저비트 벡터 사후 양자화

발표 대본
VPTQ는 이미 학습된 대규모 언어 모델의 weight를 매우 낮은 유효 bit 폭으로 줄이는 post-training quantization 방법입니다. 출발점은 2비트 스칼라 양자화가 각 weight에 네 개의 값만 허용한다는 한계입니다. 이 논문은 인접한 weight를 짧은 vector로 묶고, vector 전체를 대표 vector 하나의 index로 저장합니다. 발표에서는 vector quantization의 저장 구조, column을 순서대로 처리하며 오차를 전달하는 방법, 선택적으로 붙는 residual과 outlier 경로, 그리고 실제 추론 경로를 차례로 구분합니다.

## 2. 초저비트 weight-only PTQ의 문제

2. 초저비트 weight-only PTQ의 문제

발표 대본
이 논문이 다루는 것은 weight-only PTQ입니다. Activation을 함께 낮은 bit로 바꾸는 방법이 아니라 weight 표현을 줄이는 방법입니다. 저자는 극저비트 스칼라 양자화의 표현력 부족, vector 방법에서 생길 수 있는 오차 누적, 그리고 codebook을 읽어 복원하는 비용을 함께 문제로 둡니다. 따라서 VPTQ의 결과를 단순한 k-means 결과나 단순한 파일 압축 결과로 설명하면 부족합니다. 정확도와 속도는 표현 형식, 양자화 순서, 그리고 kernel 구현의 결합된 결과입니다.

## 3. 스칼라 양자화와 벡터 양자화

3. 스칼라 양자화와 벡터 양자화

발표 대본
스칼라 양자화에서는 weight마다 허용된 scalar level 하나를 고릅니다. 반면 vector quantization에서는 column 안의 인접 weight들을 길이 v의 vector로 만들고, 그 vector에 가장 가까운 centroid를 찾습니다. 저장되는 것은 centroid vector 자체가 아니라 그 codebook의 index이며 centroid는 많은 vector가 공유합니다. 그래서 index 하나가 여러 scalar를 동시에 복원합니다. 다만 codebook도 저장해야 하므로 index bit 수만 보면 전체 bit 폭을 잘못 이해할 수 있습니다.

## 4. 두 entry codebook으로 보는 VQ

4. 두 entry codebook으로 보는 VQ

발표 대본
이 슬라이드의 값은 논문 실험이 아니라 vector quantization의 단위를 보여 주는 교육용 계산입니다. Codebook entry가 정확히 두 개이므로 index는 0 또는 1이며 vector 하나당 1 bit입니다. Vector 길이가 2이므로 index 비용만 보면 scalar 하나당 0.5 bit입니다. v1은 C0로, v2는 C1로 복원됩니다. 각 좌표 차이를 제곱해 더하면 0.02와 0.04입니다. 이 예에서 완전 복원이 나오지 않는 점이 중요합니다. VQ는 오차를 없애는 기법이 아니라 제한된 index와 codebook으로 오차를 줄이는 표현입니다.

## 5. index bit와 유효 bit 폭은 다르다

5. index bit와 유효 bit 폭은 다르다

발표 대본
두 entry 예시에서는 index 비용이 vector당 1 bit이지만 codebook을 저장하는 비용은 따로 있습니다. 실제 VPTQ의 Appendix B는 index와 codebook 모두를 포함해 effective bitwidth를 계산합니다. Residual VQ를 쓰면 추가 index와 codebook이 들어가고, outlier tile에 별도 codebook을 쓰는 경우도 형식 비용이 달라집니다. 따라서 논문의 2.02-bit나 2.26-bit 표기는 LLaMA-2의 transformer block별로 계산한 format-effective bitwidth입니다. 한 scalar가 똑같이 두 개 또는 두 점 이육 bit로 저장된다는 뜻으로 읽으면 안 됩니다.

## 6. 양자화 오차를 단순 거리보다 민감하게 본다

6. 양자화 오차를 단순 거리보다 민감하게 본다

발표 대본
논문은 양자화된 weight를 원래 weight에 Delta W를 더한 것으로 두고 loss 변화의 Taylor 근사를 사용합니다. Local optimum 근처에서는 first-order gradient가 작다고 보고 Hessian을 포함한 quadratic term에 주목합니다. 이 관점에서는 숫자상 같은 weight 오차라도 민감한 방향에서는 더 큰 손실을 낼 수 있습니다. 하지만 실제로 전체 모델의 full Hessian을 저장해 정확히 최소화하는 것은 아닙니다. 논문은 diagonal Hessian 근사와 inverse-Hessian 기반 보상을 사용하며, 이를 설계 근거로 읽어야 합니다.

## 7. VPTQ의 핵심 선택: column을 순서대로 고정

7. VPTQ의 핵심 선택: column을 순서대로 고정

발표 대본
VPTQ는 vector codebook을 쓰지만 column 전체를 한꺼번에 고정하지는 않습니다. 한 column을 선택하고 그 column을 길이 v의 vector들로 나누어 병렬로 양자화합니다. 그때 생긴 오차는 아직 양자화하지 않은 뒤 column에 반영됩니다. 논문은 GPTVQ가 여러 column을 동시에 처리하는 방식과 이 순서를 대조하며, VPTQ의 순서가 error propagation을 더 이르게 적용한다는 동기를 제시합니다. 여기서 channel-independent는 column별 schedule을 뜻합니다. Vector 안의 scalar가 서로 무관하다는 뜻은 아닙니다.

## 8. 한 column의 오차를 뒤 column으로 전달한다

8. 한 column의 오차를 뒤 column으로 전달한다

발표 대본
이 도식은 Algorithm 1의 순서를 축소해 보여 줍니다. 먼저 현재 column W[:, t]를 선택합니다. 그 안의 길이 v vector 조각들을 병렬로 codebook index에 할당합니다. 선택 결과와 원래 vector의 차이에서 current-column error가 생기며, inverse-Hessian 관련 계수를 사용해 아직 양자화하지 않은 뒤 column을 update합니다. 이미 index가 정해진 현재 column을 다시 full precision으로 되돌리는 절차가 아닙니다. 따라서 순서가 중요합니다. 다음 column은 이미 앞쪽의 근사 오차를 고려하도록 수정된 값에서 출발합니다.

## 9. Codebook 초기화에 diagonal Hessian을 쓴다

9. Codebook 초기화에 diagonal Hessian을 쓴다

발표 대본
VPTQ는 Hessian-weighted proxy를 diagonal part와 off-diagonal part로 나누고, diagonal term이 지배적이라는 근사 아래 weighted k-means를 codebook initialization에 사용합니다. 가중치가 큰 coordinate의 대표 오차는 더 크게 취급됩니다. 이 단계는 centroid를 시작시키는 방법이며 모든 codebook 결과가 diagonal Hessian만으로 정해진다는 뜻은 아닙니다. 또한 off-diagonal interaction이 수학적으로 zero라고 주장하지 않습니다. 논문의 선택은 극저비트에서 좋은 시작점을 만들기 위한 계산 가능한 근사입니다.

## 10. VPTQ의 기본 양자화 흐름

10. VPTQ의 기본 양자화 흐름

## 11. Residual VQ는 첫 근사의 남은 오차를 다시 code화한다

11. Residual VQ는 첫 근사의 남은 오차를 다시 code화한다

발표 대본
Residual VQ는 첫 번째 codebook centroid C만으로 남는 vector 차이를 다시 하나의 vector로 보고 두 번째 codebook으로 표현합니다. 복원할 때는 C와 residual centroid R을 더합니다. 그래서 표현력이 늘 수 있지만 residual index와 residual codebook 저장 비용이 생깁니다. 교육용 두 entry 예시와 달리 이 절차가 항상 exact reconstruction을 만드는 것은 아닙니다. 논문은 이를 선택적 refinement로 제시하며, 2.02-bit 같은 표의 행이 residual VQ를 반드시 사용한다는 식으로 일반화하면 안 됩니다.

## 12. Outlier와 fine-tuning은 선택 경로다

12. Outlier와 fine-tuning은 선택 경로다

발표 대본
논문은 기본 vector PTQ 외에 세 가지 선택 경로를 제시합니다. Outlier elimination은 특정 outlier를 가진 tile에 별도 codebook을 배정합니다. Residual VQ는 base approximation의 residual을 추가 codebook으로 표현합니다. ## 14. Prompt와 decode는 다른 실행 경로를 쓴다

14. Prompt와 decode는 다른 실행 경로를 쓴다

발표 대본
Appendix D.2는 prompt phase와 decode phase를 다르게 구현합니다. Long prompt를 처리할 때는 weight를 FP16으로 복원한 뒤 torch.matmul을 사용합니다. 반면 autoregressive decoding에서는 index lookup, dequantization, GEMV를 QGemv kernel에서 결합해 FP16 weight를 매번 별도 materialize하지 않도록 합니다. 따라서 논문의 tok/s는 decode-phase throughput입니다. 이를 prompt latency, time-to-first-token, 또는 모든 PyTorch 구현의 속도로 해석하면 안 됩니다. 성능을 설명할 때 model, phase, GPU, kernel을 함께 말해야 합니다.

## 19. 가까운 방법과 다른 표현 단위

19. 가까운 방법과 다른 표현 단위

발표 대본
RTN이나 GPTQ 같은 scalar PTQ는 weight 하나를 scalar level에 배정합니다. VPTQ는 vector를 centroid index에 배정하고 column-by-column compensation을 사용합니다. GPTVQ도 vector codebook을 쓰므로 차이는 단순히 VQ 사용 여부가 아니라 논문이 강조한 channel-independent processing schedule에 있습니다. AQLM은 additive vector codebook을 쓰지만 codebook 구성, optimization 또는 fine-tuning, runtime path가 다를 수 있으므로 표의 숫자만으로 구조가 같다고 할 수 없습니다. SqueezeLLM은 scalar LUT와 sparse FP16 value path를 결합한다는 점에서 VPTQ의 vector codebook format과 다릅니다.

20. 논문이 남긴 경계와 한계

발표 대본
논문 자체의 한계를 마지막에 분명히 해야 합니다. Diagonal Hessian을 사용하는 것은 계산 가능한 proxy를 위한 근사이고, weight 사이의 모든 상호작용을 보존하지는 않습니다. Residual VQ, outlier elimination, fine-tuning은 각기 다른 configuration입니다. Decode-phase tok/s는 prompt 처리나 전체 request latency와 다릅니다. 또한 저자는 긴 70B fine-tuning을 수행할 GPU resource의 제한과 LLaMA-3에서 일부 baseline을 비교하지 못한 점을 언급합니다. 따라서 발표자는 VPTQ를 extreme low-bit PTQ의 한 설계와 측정 결과로 소개해야 합니다.

## 21. VPTQ를 한 문장씩 정리하면

21. VPTQ를 한 문장씩 정리하면

발표 대본
VPTQ는 vector codebook만으로 요약하면 중요한 절반을 놓칩니다. Weight는 vector index와 shared centroid로 저장되고, quantization 절차는 한 column을 처리한 뒤 그 오차를 미래 column에 전달합니다. Deployed system에서는 prompt와 decode가 다른 path를 사용하며, paper의 throughput claim은 fused decode kernel이라는 조건을 포함합니다. 결과를 비교할 때는 유효 bit 폭, optional residual 또는 outlier path, fine-tuning 유무, model과 dataset, phase와 hardware를 확인합니다. 이 구분이 있으면 VPTQ를 단순한 2-bit 숫자가 아니라 재현 가능한 설계로 설명할 수 있습니다.
