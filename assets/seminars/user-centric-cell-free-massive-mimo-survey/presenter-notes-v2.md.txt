## 3. 왜 더 촘촘한 무선망이 자동으로 쉬워지지 않는가

3. 왜 더 촘촘한 무선망이 자동으로 쉬워지지 않는가

발표 대본
원문은 network densification이 셀 경계의 간섭과 overhead 문제를 키운다고 설명합니다. Cell-free massive MIMO는 공간적으로 분산된 DU가 협력하여 이 문제를 다루려 하지만, 모든 DU가 모든 사용자에 관여하면 CSI, fronthaul, computation 부담이 커집니다. User-centric은 이 협력의 범위를 사용자별로 제한하는 출발점입니다.

## 4. 먼저 구분할 네 가지 용어

4. 먼저 구분할 네 가지 용어

발표 대본
DU는 distributed unit, CU는 central unit입니다. 원문에서 fronthaul은 CU와 DU를 잇는 link이고, user-centric cluster는 무선 access에서 한 사용자를 서비스할 DU 집합입니다. 따라서 ‘cell edge가 없다’는 표현은 access service 관점이지, backhaul과 control 계층이 사라졌다는 뜻이 아닙니다. Cooperation과 coordination의 구분도 공유 정보의 양에 관한 구분입니다.

## 5. Cell-free와 user-centric의 차이는 협력 집합의 범위다

5. Cell-free와 user-centric의 차이는 협력 집합의 범위다

발표 대본
원문은 기존 cell-free가 모든 DU가 모든 사용자를 서비스하는 형태로 자주 모델링되지만, 실제로는 path loss 때문에 먼 DU의 기여가 작을 수 있다고 설명합니다. User-centric 방식은 이 암묵적 효과를 사용자별 serving set 제한으로 명시합니다. 이 그림의 두 갈래는 두 선택지를 비교하는 것이며, 같은 frame에 두 방식이 동시에 수행된다는 뜻이 아닙니다.

## 26. 정리: 선택적 협력은 단일 knob가 아니다

26. 정리: 선택적 협력은 단일 knob가 아니다

발표 대본
이 survey의 가장 교육적인 결론은 user-centric cell-free를 하나의 protocol로 외우지 않는 것입니다. Serving cluster 선택은 useful signal만 남기는 동시에 CSI, fronthaul, computation, scheduling 변수와 latency model을 다시 바꿉니다. 따라서 한 방법의 성능이나 open issue를 재사용할 때는 source가 둔 topology, information, objective, metric을 보존해야 합니다.
