## 2. 환경이 바뀌면 기존 DRL policy가 다시 학습해야 한다

2. 환경이 바뀌면 기존 DRL policy가 다시 학습해야 한다

발표 대본
논문은 기존 DRL 오프로딩 방법이 새로운 환경에서 낮은 sample efficiency 때문에 policy를 다시 학습해야 한다고 문제를 제기합니다. MRLCO는 여러 MEC 맥락에서 meta policy를 학습한 뒤, 새 맥락에서 소수의 gradient update로 task-specific policy를 얻으려 합니다. 이 슬라이드의 새 맥락은 새 computation task 하나가 아니라, DAG 집합이나 전송률 조건이 달라진 learning task를 뜻합니다.

## 3. DAG 오프로딩은 의존성을 지키며 task를 배치하는 문제다

3. DAG 오프로딩은 의존성을 지키며 task를 배치하는 문제다

발표 대본

## 4. local과 offload의 latency는 같은 task에도 달라진다

4. local과 offload의 latency는 같은 task에도 달라진다

발표 대본
논문에서 local latency는 필요한 CPU cycle을 UE capacity로 나눈 값입니다. Offload latency는 uplink data transmission, MEC VM computation, downlink result transmission의 합입니다. 실제 finish-time equation은 parent task의 finish time과 해당 resource가 비는 시각의 최댓값을 사용합니다. 전체 DAG latency는 exit task의 finish time으로 정의됩니다.

## 6. MRLCO의 MDP: 상태는 DAG와 지금까지의 배치다

6. MRLCO의 MDP: 상태는 DAG와 지금까지의 배치다

발표 대본
논문은 각 learning task Ti를 MDP로 표현하고, Ti는 task distribution rho(T)에서 샘플됩니다. State는 단순 channel vector가 아니라 DAG의 encoded representation과 앞선 placement plan입니다. Action은 다음 computation task의 local 또는 MEC placement입니다. Reward는 그 decision 뒤 증가한 end-to-end latency의 음수입니다. 서로 다른 learning task는 reward나 transition, initial distribution이 달라질 수 있습니다.

## 7. seq2seq: DAG를 action 순서로 바꾸는 policy

7. seq2seq: DAG를 action 순서로 바꾸는 policy

발표 대본

## 9. first-order meta: 여러 context의 초기값 갱신

9. first-order meta: 여러 context의 초기값 갱신

발표 대본
Algorithm 1은 task distribution rho(T)에서 learning task batch를 샘플하고, 각 task에서 θ_i를 θ로 초기화해 inner PPO update를 합니다. Inner loop 결과는 θ′_i로 복사됩니다. 원문 Eq. (22)의 first-order meta gradient는 sampled contexts에 대해 (θ′_i − θ)/(αm)을 평균낸 값입니다. 이는 gradients of gradients 비용을 줄이기 위한 first-order approximation이며, outer loop는 이 g_MRLCO로 θ를 Adam update합니다.

## 10. meta-training과 새 환경 적응의 차이

10. meta-training과 새 환경 적응의 차이

발표 대본
이 슬라이드는 분기 그림을 비교 장식으로 쓰는 것이 아니라, 실제 parameter 흐름을 보입니다. Meta-training은 여러 MDP context로 θ를 업데이트합니다. New context adaptation은 그 θ에서 시작해 local trajectory로 θ_i를 만듭니다. 그 결과 θ_i가 scheduler에서 사용됩니다. Fine-tuning DRL도 pretrained parameter를 시작점으로 쓸 수 있지만, MRLCO는 post-update performance를 목표로 meta objective를 구성한다는 점에서 다릅니다.

## 14. 일반 DRL·DMRO·MRLCO의 문제 설정 차이

14. 일반 DRL·DMRO·MRLCO의 문제 설정 차이

발표 대본
이 비교는 각 원문이 정의한 formulation에 한정합니다. DMRO는 local, edge, cloud의 세 위치와 parallel Q-learning DNN을 사용하며 meta parameter psi를 학습합니다. MRLCO는 binary UE versus MEC placement, PPO inner loop, first-order outer meta update, DAG seq2seq policy를 사용합니다. 일반 DRL은 하나의 stationary environment에서 policy를 training하고 새로운 context에서 full retraining 또는 fine-tuning을 요구할 수 있다는 논문의 대비 대상입니다.

## 15. 논문이 남긴 가정과 한계

15. 논문이 남긴 가정과 한계

발표 대본
논문의 Discussion은 stable wireless channel, reliable mobile device, sufficient computation resource를 가정한다고 밝힙니다. Outer loop는 모든 UE로부터 task-specific parameter를 모은 뒤 meta policy를 갱신하는 synchronous process이므로, network connection이나 power 부족으로 발생한 straggler가 training performance에 영향을 줄 수 있다고 설명합니다. 또한 first-order approximation은 second-order gradient의 computation cost와 implementation difficulty를 피하기 위한 선택입니다.

## 16. MRLCO의 핵심 연결

16. MRLCO의 핵심 연결

발표 대본
정리하면, MRLCO는 dependency가 있는 DAG를 rank 순서의 decision sequence로 표현하고 seq2seq policy로 local/offload placement를 만듭니다. 새 context에서는 meta initialization θ에서 시작한 inner PPO update가 θ_i를 만들며, outer loop는 많은 context에서 그 시작점을 개선합니다. 실험은 held-out topology, task count, and transmission-rate context에서 낮은 latency와 빠른 adaptation을 보고하지만, 그 결과는 source의 synthetic simulator와 stated assumptions 안에서 해석해야 합니다.
