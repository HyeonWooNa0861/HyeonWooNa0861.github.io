# Meta-RL 기반 MEC 작업 스케줄링 연구 구상

논문: Meta-Reinforcement Learning for Optimized Task Scheduling in Heterogeneous Edge Computing Systems

저자: Iman Rahmati (연도 미상)

## 1. Meta-RL 기반 MEC 작업 스케줄링 연구 구상

완성 알고리즘이 아니라, 새로운 MEC 환경에 빠르게 적응하는 정책을 설계하기 위한 2쪽 제안서 읽기


근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) title page

## 2. 먼저 확인할 것: 제안서가 말하는 범위

문제와 연구 방향은 제시되지만, 완성된 방법과 결과는 제시되지 않는다.


| 확인된 내용 | 아직 없는 내용 |
| --- | --- |
| P1·P2·P3라는 세 결정 계층 | 상태·행동·보상 정의 |
| 여러 MDP에서 meta-policy 학습 | meta-loss와 업데이트 식 |
| Meta-Actor·Meta-Critic 사용 가능성 | 확정된 네트워크 구조 |
| Python 기반 시뮬레이션 계획 | 데이터·기준선·수치 결과 |

핵심: 이후의 도식은 제안된 연구 질문을 이해하기 위한 구조이며 구현 결과가 아니다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) pp. 1–2

## 3. 핵심 문제: 환경이 바뀔 때 다시 오래 학습해야 하는가


| 관점 | 한 환경용 정책 | 제안이 원하는 meta-policy |
| --- | --- | --- |
| 학습 경험 | 현재 환경에 맞춘 경험 | 여러 환경에서 공통 지식 학습 |
| 새 환경 | 성능 회복에 재학습 필요 | 적은 추가 학습으로 적응 목표 |
| 근거 수준 | 개념적 비교 | 달성 결과가 아닌 연구 목표 |

핵심: Meta-RL의 약속은 즉시 최적화가 아니라, 새 환경에 필요한 추가 학습량을 줄이는 것이다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) p. 1, Motivation

## 4. MEC 자원 관리는 서로 다른 세 결정으로 나뉜다


| 계층 | 결정 대상 | 쉬운 판별 기준 |
| --- | --- | --- |
| P1 서비스 배치 | 어떤 서비스를 어느 edge에 둘지 | 서비스가 그 edge에 존재하는가 |
| P2 계산 오프로딩 | 작업을 어느 edge로 보낼지 | 어느 서버가 계산하는가 |
| P3 자원 할당 | 한 edge의 자원을 작업별로 나눌지 | CPU·통신 자원을 얼마나 받는가 |

핵심: 배치, 서버 선택, 서버 내부 할당은 관련되지만 같은 결정이 아니다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) p. 1, Problem Statement

## 5. 세 결정은 서로의 선택 가능성에 영향을 준다

의존성을 설명하는 교육용 해석이며, 원문이 정한 실행 순서는 아니다.

1. **P1 서비스 배치**: edge별로 실행 가능한 서비스 집합이 정해진다.
2. **P2 서버 선택**: 서비스와 네트워크 조건 안에서 작업 목적지를 고른다.
3. **P3 자원 할당**: 선택된 edge 안에서 여러 작업에 자원을 배분한다.
4. **시스템 성능**: 지연·에너지·실행 가능성은 세 결정의 결합으로 달라진다.

핵심: 제안서는 각 계층을 개별 MDP로 보지만, 공동 최적화 방식은 아직 정하지 않았다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) p. 1, P1–P3 and Problem Model

## 6. Meta-RL 적용 흐름은 아직 설계 가설이다

1. **여러 MEC 환경**: 부하·네트워크·자원 조건이 다른 MDP들을 경험한다.
2. **meta-policy 학습**: 환경들에 공통으로 유용한 초기 정책을 찾는 단계다.
3. **낯선 환경**: 학습 때와 다른 작업 또는 네트워크 조건을 만난다.
4. **제한된 추가 학습**: 새 경험을 이용해 정책을 빠르게 조정하는 것이 목표다.
5. **P1·P2·P3 결정**: 조정된 정책으로 세 계층의 결정을 수행한다.

핵심: 무엇을 meta-knowledge로 공유하고 무엇을 현장에서 적응할지는 미정이다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) p. 1, Problem Model

## 7. Meta-Actor·Critic은 완성 구조가 아니다


| 원문 표현 | 안전한 해석 | 단정하면 안 되는 것 |
| --- | --- | --- |
| Multi-Agent Meta-RL 개발 | 여러 결정 주체를 고려하는 방향 | agent 수와 역할이 확정됨 |
| Meta-Actor 사용 가능 | 정책을 meta-learning할 후보 | 구체적 actor 구조가 구현됨 |
| Meta-Critic 사용 가능 | 가치 평가를 활용할 후보 | loss와 업데이트가 확정됨 |

핵심: 후보 기술 이름은 연구 방향을 좁히지만 재현 가능한 알고리즘을 정의하지 않는다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) p. 1, Research Methodology

## 8. 실제로 학습하려면 먼저 채워야 할 설계


| 설계 항목 | 필요한 정의 | 현재 상태 |
| --- | --- | --- |
| MDP | 상태·행동·보상·전이 | 제안서에 미정 |
| 계층 연결 | P1·P2·P3의 순서와 제약 전달 | 제안서에 미정 |
| meta-learning | 공유 목표와 적응 업데이트 | 제안서에 미정 |
| 다중 agent | agent 정체·관측·조정 방식 | 제안서에 미정 |
| 평가 | 기준선·지표·환경 분할 | 시뮬레이션 계획만 제시 |

핵심: 이 빈칸을 명시해야 연구 구상이 재현 가능한 방법으로 바뀐다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) pp. 1–2

## 9. 제안을 검증 가능한 연구로 바꾸는 평가 기준

아래 항목은 원문 결과가 아니라 제안의 타당성을 확인하기 위한 교육용 평가 설계다.


| 검증 질문 | 필요한 비교 또는 측정 |
| --- | --- |
| 새 환경에 정말 빨리 적응하는가 | 비-meta RL 대비 적응 단계와 누적 비용 |
| 세 계층 결정이 실행 가능한가 | 서비스·서버·자원 제약 위반 여부 |
| 시스템 효율이 좋아지는가 | 지연·에너지·마감시간·제어 오버헤드 |
| 일반화가 재현되는가 | 학습에 없던 부하와 네트워크 조건에서 반복 평가 |

핵심: Meta-RL의 가치는 적응 속도와 전체 시스템 비용을 함께 측정할 때 검증된다.

근거: [research-idea](https://imanrht.github.io/assets/MetaRL.pdf) p. 1, Simulation and Challenges
