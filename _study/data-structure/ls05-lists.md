## 1. 리스트란?

리스트는 순서가 있는 데이터의 나열이다. 각 원소는 리스트 안에서 자신의 위치, 즉 인덱스를 가진다.

```text
index: 0   1   2   3
value: 10  20  30  40
```

리스트는 단순히 값을 모아 둔 것이 아니라, **위치 기반 접근**을 제공한다는 점이 중요하다.

## 2. 리스트의 주요 연산

| 연산 | 의미 |
|---|---|
| 탐색 Search | 특정 인덱스 또는 특정 값을 가진 원소를 찾는다. |
| 갱신 Update | 특정 위치의 원소를 새 값으로 교체한다. |
| 삽입 Insert | 원하는 위치에 새 원소를 추가한다. |
| 삭제 Delete | 특정 위치의 원소를 제거한다. |
| 순회 Traverse | 모든 원소를 차례대로 읽는다. |

스택, 큐, 데크 같은 선형 자료구조는 리스트를 제한하거나 확장해서 구현할 수 있다.

## 3. List ADT

List ADT는 구현 방법과 상관없이 "위치를 가진 원소들의 유한 순서열"을 정의한다.

ADT 관점에서는 배열을 쓰는지, 연결 리스트를 쓰는지 알 필요가 없다. 사용자는 `get`, `insert`, `remove` 같은 연산이 어떤 의미를 갖는지만 알면 된다.

| 관점 | 질문 |
|---|---|
| ADT | 리스트로 무엇을 할 수 있는가? |
| 자료구조 | 리스트를 메모리에 어떻게 배치할 것인가? |

## 4. 배열 기반 리스트 구현

배열 기반 리스트는 보통 두 정보를 가진다.

| 구성 요소 | 역할 |
|---|---|
| 배열 | 실제 원소를 저장하는 고정 크기 공간 |
| `size` 변수 | 현재 저장된 원소 개수 |

`size`가 필요한 이유는 배열의 전체 용량과 실제 원소 개수가 다를 수 있기 때문이다.

```text
capacity = 8
size = 4

[10, 20, 30, 40, _, _, _, _]
```

순회할 때는 배열 전체가 아니라 `0`부터 `size - 1`까지만 읽어야 한다.

## 5. 배열 기반 리스트의 연산 복잡도

| 연산 | 시간 복잡도 | 이유 |
|---|---|---|
| 인덱스 탐색 | `O(1)` | 인덱스로 바로 접근할 수 있다. |
| 특정 값 탐색 | `O(n)` | 앞에서부터 비교해야 한다. |
| 갱신 | `O(1)` | 인덱스를 알고 있으면 바로 바꾼다. |
| 삽입 | `O(n)` | 뒤 원소들을 한 칸씩 밀어야 한다. |
| 삭제 | `O(n)` | 뒤 원소들을 한 칸씩 당겨야 한다. |
| 순회 | `O(n)` | 모든 원소를 한 번씩 읽는다. |

배열 기반 리스트의 핵심 장점은 빠른 임의 접근이고, 핵심 단점은 중간 삽입/삭제 시 원소 이동 비용이다.

## 6. 장단점 해석

| 장점 | 설명 |
|---|---|
| 인덱스 접근이 빠름 | `list[i]`를 바로 찾을 수 있다. |
| 구현이 단순함 | 포인터 관리가 필요 없다. |
| 캐시 친화적 | 메모리에 연속 저장되어 CPU 캐시 효율이 좋다. |

| 단점 | 설명 |
|---|---|
| 삽입/삭제가 느림 | 중간 위치에서는 원소 이동이 필요하다. |
| 크기가 고정됨 | 용량 초과 시 재할당이 필요하다. |
| 메모리 낭비 가능 | 실제 원소보다 큰 배열을 잡으면 빈 공간이 생긴다. |
