Source PDF: `LS13_sorting.pdf`

|---|---|---|

## 1. 정렬이 필요한 이유

정렬은 리스트의 원소를 특정 기준에 따라 순서화하는 작업이다.

정렬을 해 두면 다음 작업이 쉬워진다.

| 목적 | 설명 |
|---|---|
| 탐색 성능 향상 | 이진 탐색 같은 빠른 탐색을 적용할 수 있다. |
| 데이터 분석 | 중앙값, 분위수, 이상치 탐지가 쉬워진다. |
| 사용자 경험 | 가격순, 인기순 정렬처럼 원하는 정보를 빨리 찾게 한다. |
| 다른 알고리즘의 기반 | 많은 알고리즘이 정렬된 입력을 전제로 한다. |

## 2. 정렬 알고리즘의 비용 기준

정렬에서는 보통 두 비용을 본다.

| 비용 | 의미 |
|---|---|
| 비교 횟수 | 두 원소의 대소를 비교한 횟수 |
| 교환 횟수 | 두 원소의 위치를 바꾼 횟수 |

비교 횟수는 전체 시간 복잡도에 직접 연결되고, swap은 실제 데이터 이동 비용과 연결된다.

## 3. 버블 정렬 Bubble Sort

버블 정렬은 인접한 두 원소를 비교해 큰 값을 오른쪽으로 보낸다. 한 회전이 끝나면 가장 큰 값이 맨 오른쪽에 확정된다.

```java
void bubbleSort(List<Integer> list) {
    for (int i = 0; i < list.size() - 1; i++) {
        for (int j = 0; j < list.size() - 1 - i; j++) {
            if (list.get(j) > list.get(j + 1)) {
                swap(list, j, j + 1);
            }
        }
    }
}
```

| 항목 | 내용 |
|---|---|
| 전략 | 큰 값을 오른쪽 끝으로 밀어낸다. |
| 비교 횟수 | 대략 \(n^2/2\) |
| swap 횟수 | 최선 0, 최악 대략 \(n^2/2\) |
| 시간 복잡도 | \(O(n^2)\) |

버블 정렬은 직관적이지만 swap이 많이 발생할 수 있어 효율적이지 않다.

## 4. 선택 정렬 Selection Sort

선택 정렬은 정렬되지 않은 구간에서 가장 작은 값을 찾아 맨 앞 원소와 교환한다.

```java
void selectionSort(List<Integer> list) {
    int n = list.size();
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;
        for (int j = i + 1; j < n; j++) {
            if (list.get(j) < list.get(minIndex))
                minIndex = j;
        }
        swap(list, i, minIndex);
    }
}
```

| 항목 | 내용 |
|---|---|
| 전략 | 가장 작은 값을 왼쪽부터 확정한다. |
| 비교 횟수 | 대략 \(n^2/2\) |
| swap 횟수 | 최선 0, 최악 \(n - 1\) 수준 |
| 시간 복잡도 | \(O(n^2)\) |

선택 정렬은 비교는 많지만 swap 횟수가 적다. 데이터 이동 비용이 큰 상황에서는 버블 정렬보다 나을 수 있다.

## 5. 삽입 정렬 Insertion Sort

삽입 정렬은 왼쪽에 이미 정렬된 구간을 유지하고, 현재 원소를 그 구간의 적절한 위치에 끼워 넣는다.

```java
void insertionSort(int[] list) {
    for (int i = 1; i < list.length; i++) {
        for (int j = i; j > 0 && list[j] < list[j - 1]; j--) {
            int temp = list[j];
            list[j] = list[j - 1];
            list[j - 1] = temp;
        }
    }
}
```

| 항목 | 내용 |
|---|---|
| 전략 | 현재 원소를 앞쪽 정렬 구간에 삽입한다. |
| 비교 횟수 | 최선 \(n - 1\), 최악 대략 \(n^2/2\) |
| swap 횟수 | 최선 0, 최악 대략 \(n^2/2\) |
| 시간 복잡도 | 최악 \(O(n^2)\) |

삽입 정렬은 거의 정렬된 리스트에서 매우 효과적이다. 이미 순서가 맞으면 내부 반복문이 거의 실행되지 않는다.

## 6. 세 기본 정렬 비교

| 알고리즘 | 전략 | 시간 복잡도 | 특징 |
|---|---|---|---|
| Bubble Sort | 큰 값을 뒤로 이동 | \(O(n^2)\) | swap이 많다. |
| Selection Sort | 작은 값을 앞으로 이동 | \(O(n^2)\) | swap이 적다. |
| Insertion Sort | 정렬 구간에 삽입 | \(O(n^2)\) | 거의 정렬된 입력에 강하다. |

## 복습 질문

<details>
<summary>1. `[7, 4, 5, 1, 3]`에서 버블 정렬 1회전 후 배열은 어떻게 되는가?</summary>

답변: `[4, 5, 1, 3, 7]`이 된다. 인접한 원소를 비교하며 큰 값인 `7`이 오른쪽 끝까지 이동하고, 첫 번째 회전이 끝나면 `7`의 위치가 확정된다.

</details>

<details>
<summary>2. 선택 정렬과 삽입 정렬 중 거의 정렬된 배열에 더 적합한 것은?</summary>

답변: 삽입 정렬이 더 적합하다. 이미 대부분 정렬되어 있으면 현재 원소가 앞쪽 정렬 구간에서 거의 이동하지 않으므로 내부 반복이 적게 수행된다.

</details>

<details>
<summary>3. 비교 횟수와 swap 횟수는 항상 같은가?</summary>

답변: 아니다. 비교는 두 원소의 대소를 확인하는 작업이고, swap은 실제 위치를 바꾸는 작업이다. 선택 정렬처럼 비교는 많이 하지만 swap은 적게 하는 알고리즘도 있다.

</details>

## Study Notes

기본 정렬 알고리즘은 모두 최악 시간 복잡도가 \(O(n^2)\)이지만, 작동 방식은 서로 다르다. 이 차이를 알아야 나중에 merge sort, quick sort, heap sort가 왜 개선인지 이해할 수 있다.

버블 정렬은 인접한 두 값을 비교해 큰 값을 오른쪽으로 보낸다. 한 번의 바깥 반복이 끝날 때마다 가장 큰 값 하나가 오른쪽 끝에 확정된다.

```text
[7, 4, 5, 1, 3]

7과 4 비교 -> swap: [4, 7, 5, 1, 3]
7과 5 비교 -> swap: [4, 5, 7, 1, 3]
7과 1 비교 -> swap: [4, 5, 1, 7, 3]
7과 3 비교 -> swap: [4, 5, 1, 3, 7]
```

선택 정렬은 정렬되지 않은 구간에서 최솟값을 찾아 앞쪽으로 보낸다. 비교는 많지만 swap은 바깥 반복마다 최대 한 번이다. 데이터 이동 비용이 큰 경우에는 이 특징이 의미가 있다.

삽입 정렬은 앞쪽을 이미 정렬된 구간으로 보고, 현재 원소를 알맞은 위치에 끼워 넣는다. 이미 거의 정렬된 배열에서는 이동이 적어 매우 빠르게 동작할 수 있다.

## Stability and In-Place

정렬 알고리즘을 비교할 때는 시간 복잡도 외에도 안정성과 추가 공간을 본다.

| 용어 | 의미 |
|---|---|
| stable sort | 같은 key를 가진 원소들의 상대적 순서를 유지한다. |
| in-place sort | 입력 배열 외에 큰 추가 배열을 쓰지 않는다. |

일반적인 구현 기준으로 insertion sort와 bubble sort는 안정적으로 만들기 쉽다. selection sort는 swap 방식 때문에 안정성이 깨질 수 있다. 세 알고리즘 모두 보통 in-place로 구현한다.

## Comparison Table

| 알고리즘 | 최선 | 평균 | 최악 | 특징 |
|---|---|---|---|---|
| Bubble Sort | \(O(n)\) 가능 | \(O(n^2)\) | \(O(n^2)\) | 조기 종료 최적화가 있으면 이미 정렬된 입력에 빠름 |
| Selection Sort | \(O(n^2)\) | \(O(n^2)\) | \(O(n^2)\) | swap 횟수가 적음 |
| Insertion Sort | \(O(n)\) | \(O(n^2)\) | \(O(n^2)\) | 거의 정렬된 입력에 강함 |

기본 정렬은 큰 입력에는 적합하지 않지만, 작은 입력이나 부분적으로 정렬된 입력에서는 실제로도 자주 사용된다.
