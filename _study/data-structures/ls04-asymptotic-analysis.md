# LS04 Asymptotic Analysis

Source PDF: `LS04_asymptotic_analysis.pdf`

> **핵심:** **\(T(n)=10n^2+3n+7\)의 점근적 성장 함수는** \(n^2\). **Big-O와 Big-Θ의 차이는** Big-O는 상한, Big-Θ는 상한과 하한이 모두 같은 경우.

## 전체 흐름

| 순서 | 주제 | 핵심 질문 |
|---|---|---|
| 1 | 수행 시간 함수 | `T(n)`을 어떻게 단순화하는가? |
| 2 | 점근적 성장 함수 | 최고차항만 보는 이유는 무엇인가? |
| 3 | Big-O | 실행 시간이 얼마나 느려질 수 있는가? |
| 4 | Prefix Average | 같은 문제도 구현 방식에 따라 어떻게 달라지는가? |
| 5 | Big-Ω, Big-Θ | 하한과 정확한 차수는 어떻게 표현하는가? |

## 1. 점근적 성장 함수

점근적 성장 함수 `f(n)`은 수행 시간 함수 `T(n)`에서 입력 크기 `n`이 커질 때 지배적인 항만 남긴 것이다.

$$
T(n) = 3n^2 + 2n + 5 \quad\Rightarrow\quad f(n)=n^2
$$

상수 계수와 낮은 차수 항은 큰 입력에서 영향이 상대적으로 작아지므로 생략한다.

## 2. Big-O

Big-O는 점근적 상한을 표현한다.

$$
T(n) \in O(f(n))
$$

이는 충분히 큰 `n`에 대해 `T(n)`이 `c * f(n)`보다 커지지 않는다는 뜻이다.

$$
T(n) \le c f(n) \quad \text{for all } n > n_0
$$

직관적으로는 "이 알고리즘은 `f(n)`보다 더 빠르게 나빠지지는 않는다"라고 해석하면 된다.

## 3. Big-O 예제

| 수행 시간 함수 | Big-O | 이유 |
|---|---|---|
| \(7n+3\) | \(O(n)\) | 선형항이 지배한다. |
| \(3n^3+7n+5\) | \(O(n^3)\) | 세제곱항이 지배한다. |
| \(5n^2+100n\) | \(O(n^2)\) | 큰 입력에서는 \(n^2\)이 더 빠르게 증가한다. |

Big-O 증명에서는 적절한 양의 상수 \(c\)와 기준점 \(n_0\)를 찾으면 된다. 예를 들어 \(7n+3 \le 8n\)은 \(n \ge 3\)에서 성립하므로 \(7n+3 \in O(n)\)이라고 할 수 있다.

## 4. Prefix Average 예제

Prefix Average 문제는 길이 `n` 배열에서 각 위치 `i`마다 `A[0]`부터 `A[i]`까지의 평균을 계산하는 문제다.

### 구현 1: 매번 다시 합산

```text
for i = 0 to n-1:
    sum = 0
    for j = 0 to i:
        sum += A[j]
    B[i] = sum / (i + 1)
```

각 \(i\)마다 앞부분을 다시 더하므로 총 연산 수는 \(1+2+\cdots+n\)에 비례한다. 따라서 시간 복잡도는 \(O(n^2)\)이다.

### 구현 2: 누적합 사용

```text
sum = 0
for i = 0 to n-1:
    sum += A[i]
    B[i] = sum / (i + 1)
```

각 원소를 한 번씩만 더하므로 시간 복잡도는 \(O(n)\)이다.

이 예제의 핵심은 같은 문제라도 **이전 계산 결과를 재사용하면 차수가 달라질 수 있다**는 점이다.

## 5. Big-Ω

Big-Ω는 점근적 하한을 표현한다.

$$
T(n) \in \Omega(f(n))
$$

이는 충분히 큰 \(n\)에 대해 \(T(n)\)이 \(cf(n)\) 이상이라는 뜻이다.

$$
T(n) \ge c f(n) \quad \text{for all } n > n_0
$$

직관적으로는 "아무리 잘 되어도 이 정도 시간은 든다"에 가깝다.

## 6. Big-Θ

Big-Θ는 상한과 하한이 같은 차수임을 뜻한다.

$$
T(n) \in \Theta(f(n))
$$

즉 충분히 큰 \(n\)에서 다음이 성립한다.

$$
c_1f(n) \le T(n) \le c_2f(n)
$$

Big-Θ는 실행 시간의 정확한 차수를 말할 때 쓴다.

## 표기법 비교

| 표기 | 의미 | 한 줄 해석 |
|---|---|---|
| \(O(f(n))\) | 상한 | 이보다 더 나빠지지는 않는다. |
| \(\Omega(f(n))\) | 하한 | 이보다 더 좋아지지는 않는다. |
| \(\Theta(f(n))\) | tight bound | 이 차수로 증가한다. |

## 마지막 핵심 정리

### 시험 포인트

| 질문 | 답의 방향 |
|---|---|
| \(T(n)=10n^2+3n+7\)의 점근적 성장 함수는? | \(n^2\) |
| Big-O와 Big-Θ의 차이는? | Big-O는 상한, Big-Θ는 상한과 하한이 모두 같은 경우 |
| Prefix Average 구현 1과 2의 차이는? | 중복 합산 때문에 \(O(n^2)\), 누적합 사용 시 \(O(n)\) |
| 상수 계수는 왜 무시하는가? | 큰 입력에서 성장 차수를 바꾸지 않기 때문 |

## Study Guide

T(n)에서 최고차항을 찾고 상수와 낮은 차수 항을 제거하는 과정을 몇 식에 직접 적용한다. Prefix Average의 중복 합산 구현과 누적합 구현을 반복문 횟수로 풀어 O(n²)와 O(n)의 차이를 재현하는 것이 핵심이다. Big-O는 상한, Big-Ω는 하한, Big-Θ는 tight bound라는 구분을 실제 부등식 해석과 함께 점검한다.

<summary>1. \(T(n)=n\log n+100n\)의 점근적 성장 함수는 무엇인가?</summary>

답변: \(n\log n\)이다. 큰 \(n\)에서는 \(n\log n\)이 \(n\)보다 더 빠르게 증가하므로 \(100n\) 항보다 지배적이다.

</details>

<details>
<summary>2. 어떤 알고리즘이 \(O(n^2)\)라고 해서 반드시 \(\Theta(n^2)\)라고 할 수 있는가?</summary>

답변: 아니다. \(O(n^2)\)는 상한만 의미한다. 예를 들어 \(O(n)\) 알고리즘도 넓게는 \(O(n^2)\)에 포함될 수 있지만, \(\Theta(n^2)\)는 상한과 하한이 모두 \(n^2\)일 때만 말할 수 있다.

</details>

<details>
<summary>3. 누적합은 어떤 종류의 중복 계산을 줄여 주는가?</summary>

답변: 앞에서 이미 더한 값들을 매번 다시 더하는 중복을 줄여 준다. Prefix Average 예제에서는 이전까지의 합을 저장해 두면 각 위치에서 처음부터 다시 합산하지 않아도 된다.

</details>

## Study Notes

점근적 분석은 정확한 실행 시간 식을 단순화해서 큰 입력에서의 성장률만 보는 방법이다. \(T(n)=3n^2+100n+50\)이라는 식에서 작은 입력에서는 \(100n\)이나 \(50\)도 보일 수 있지만, \(n\)이 충분히 커지면 \(n^2\) 항이 전체 성장을 지배한다.

성장률의 크기는 다음 순서로 기억하면 좋다.

$$
1 < \log n < n < n\log n < n^2 < n^3 < 2^n
$$

이 순서는 알고리즘 선택에서 매우 중요하다. 작은 입력에서는 \(O(n^2)\) 알고리즘도 충분히 빠를 수 있지만, 입력이 커질수록 \(O(n\log n)\)과의 차이가 급격히 커진다.

Big-O는 상한이다. 즉 "이 함수가 이 정도보다 더 빠르게 커지지는 않는다"는 말이다. 그래서 \(3n+5\)는 \(O(n)\)이기도 하고, 넓게 말하면 \(O(n^2)\)이기도 하다. 하지만 가장 유용한 표현은 보통 가장 타이트한 상한인 \(O(n)\)이다.

Big-Ω는 하한이고, Big-Θ는 상한과 하한이 같은 경우다.

$$
T(n)=5n+3
$$

$$
T(n)\in O(n),\qquad
T(n)\in \Omega(n),\qquad
T(n)\in \Theta(n)
$$

Prefix Average 예제는 이 강의의 핵심이다. 첫 번째 구현은 매 위치마다 처음부터 다시 더한다. 이미 계산한 합을 버리고 다시 계산하기 때문에 중복이 생긴다. 두 번째 구현은 누적합을 유지해서 이전 계산 결과를 재사용한다. 이 차이 하나로 \(O(n^2)\)이 \(O(n)\)이 된다.

## Proof Pattern

Big-O 증명은 보통 다음 모양을 가진다.

$$
T(n) \le cf(n) \quad \text{for all } n \ge n_0
$$

예를 들어 \(T(n)=7n+3\)이 \(O(n)\)임을 보이고 싶다면, 충분히 큰 \(n\)에서 \(7n+3 \le 8n\)이 되는지 보면 된다. \(n \ge 3\)이면 \(3 \le n\)이므로 \(7n+3 \le 8n\)이다. 따라서 \(c=8\), \(n_0=3\)으로 잡을 수 있다.

## Common Pitfalls

| 실수 | 올바른 이해 |
|---|---|
| Big-O를 정확한 시간이라고 생각한다. | Big-O는 상한이며 성장률 표현이다. |
| 낮은 차수 항을 항상 의미 없다고 본다. | 큰 입력 분석에서는 무시하지만, 실제 작은 입력에서는 영향이 있을 수 있다. |
| \(O(n^2)\)이면 무조건 느리다고 판단한다. | 입력 크기와 상수, 구현 환경도 실제 성능에 영향을 준다. |
| \(O\)와 \(\Theta\)를 같은 의미로 쓴다. | \(\Theta\)가 더 정확한 tight bound다. |
