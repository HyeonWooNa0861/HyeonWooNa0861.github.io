# LS03 Algorithm Analysis

Source PDF: `LS03_algorithm_analysis.pdf`

> **핵심:** **실험적 분석과 이론적 분석의 차이는** 직접 실행 측정 vs 연산 횟수 계산. **기본 연산이란** 수행 시간이 고정되어 있다고 보는 핵심 연산.

## 1. 알고리즘의 조건

알고리즘은 문제 해결 절차를 명확한 단계로 표현한 것이다. 좋은 알고리즘은 다음 조건을 만족한다.

| 조건 | 의미 |
|---|---|
| 입력 | 하나 이상의 입력을 받을 수 있어야 한다. |
| 출력 | 최소 하나 이상의 결과를 산출해야 한다. |
| 명확성 | 각 단계가 애매하지 않아야 한다. |
| 유한성 | 유한한 단계 안에 반드시 종료해야 한다. |
| 효율성 | 각 단계가 실제로 실행 가능한 연산이어야 한다. |

자료구조 수업에서 특히 중요한 조건은 효율성이다. 같은 문제를 풀더라도 알고리즘과 자료구조 선택에 따라 실행 시간이 크게 달라진다.

## 2. 알고리즘 표현 방식

| 표현 방식 | 장점 | 단점 |
|---|---|---|
| 자연어 | 직관적이고 이해하기 쉽다. | 모호해질 수 있다. |
| 순서도 | 흐름을 시각적으로 파악하기 좋다. | 복잡한 알고리즘에는 번거롭다. |
| 의사코드 | 실제 구현에 가깝고 언어 독립적이다. | 완전히 표준화된 문법은 없다. |
| 프로그래밍 언어 | 실행과 테스트가 가능하다. | 언어 문법 때문에 핵심 로직이 묻힐 수 있다. |

공부할 때는 의사코드로 알고리즘의 흐름을 먼저 잡고, 그다음 실제 언어로 구현하는 방식이 좋다.

## 3. 성능 분석의 두 방법

| 분석 방법 | 설명 | 장점 | 한계 |
|---|---|---|---|
| 실험적 분석 | 직접 구현한 뒤 여러 입력으로 실행 시간을 측정 | 현실적인 실행 시간 확인 가능 | 하드웨어, 언어, 입력 데이터에 영향을 많이 받음 |
| 이론적 분석 | 실행하지 않고 기본 연산 횟수를 수학적으로 계산 | 입력 크기에 따른 증가 추세 파악 가능 | 실제 상수 시간, 캐시, 구현 세부사항은 반영하기 어려움 |

자료구조 시험에서는 보통 이론적 분석이 중심이다. 핵심은 실행 시간을 초 단위로 맞히는 것이 아니라, 입력 크기 `n`이 커질 때 연산 횟수가 어떤 차수로 증가하는지 보는 것이다.

## 4. 수행 시간 함수 `T(n)`

`T(n)`은 입력 크기 `n`에 대한 기본 연산 실행 횟수로 생각할 수 있다.

기본 연산의 예시는 다음과 같다.

| 연산 | 예시 |
|---|---|
| 할당 | `x = 3` |
| 산술 | `a + b`, `a * b` |
| 비교 | `x < y`, `x == y` |
| 배열 접근 | `arr[i]` |

반복문은 내부 기본 연산 횟수와 반복 횟수를 곱해서 계산한다.

```text
for i = 0 to n-1:
    sum = sum + A[i]
```

위 코드에서 핵심 연산을 덧셈 또는 배열 접근으로 잡으면 반복 횟수는 `n`이므로 전체 수행 시간은 `n`에 비례한다.

## 5. 피보나치 예제 해석

강의의 반복문 기반 피보나치 알고리즘은 입력 `n`에 따라 경우가 나뉜다.

| 입력 조건 | 수행 시간 |
|---|---|
| `n < 0` | 상수 시간 |
| `n = 0` | 상수 시간 |
| `n = 1` | 상수 시간 |
| `n > 1` | 반복문이 `n-1`번 실행되므로 선형 시간 |

슬라이드에서는 $$n > 1$$일 때 $$T(n)=4n+1$$ 형태로 계산한다. 정확한 계수보다 중요한 해석은 **입력 크기에 비례해 증가한다**는 점이다.

### $$T(n)=4n+1$$이 나오는 과정

> **분류:** 이 식은 알고리즘 결과에 관한 정리가 아니라, 슬라이드가 선택한 비용 모형에 따른 **연산 횟수 정의식**이다.
>
> **원문 추적:** Source PDF 20--21쪽의 피보나치 의사코드별 기본 연산 표와 $$T(n)$$ 합계를 보충 해설한다.

`n`이 정수이고 $$n>1$$이며, 초기화·검사와 반복 본문의 각 기본 연산을 1회로 센다고 가정한다. 반복 인덱스가 $$2,3,\ldots,n$$을 지나므로 반복 횟수는

$$
n-2+1=n-1
$$

이다. 반복마다 덧셈과 세 갱신 등 4개의 기본 연산을 센다면 반복 비용은 $$4(n-1)$$이다. 반복 밖의 고정 비용 5를 더하면

$$
T(n)=4(n-1)+5=4n+1.
$$

따라서 충분히 큰 $$n$$에서 $$T(n)$$은 $$n$$의 두 양의 상수배 사이에 있으므로 $$T(n)\in\Theta(n)$$이다. 대입·비교를 몇 회로 세는지는 비용 모형에 따라 달라져 계수와 상수항은 바뀔 수 있다. **변하지 않는 결론은 반복형 알고리즘의 선형 성장률**이다.

## 6. 점근적 분석으로 넘어가는 이유

정확한 `T(n)`을 항상 구하기는 어렵다.

데이터 값이나 분포에 따라 분기 횟수가 달라질 수 있고, 실제 실행 시간은 컴퓨터 환경에도 영향을 받는다. 그래서 큰 입력에서의 증가 추세를 단순화해 바라본다.

예를 들어 $$T(n)=4n+1$$은 큰 $$n$$에서 $$n$$에 비례한다고 보고, $$T(n)=3n^2+2n+5$$는 $$n^2$$에 비례한다고 본다.

### Big-O, Big-Omega, Big-Theta의 정량적 의미

> **분류:** Source PDF 24쪽의 점근 표기를 수학적 정의로 연결한 **작성자 보충 증명**이다. 입력 크기 $$n$$은 0 이상의 무차원 정수이고, 수행 시간 함수 $$T(n)$$과 비교 함수 $$f(n)$$은 충분히 큰 $$n$$에서 음이 아니라고 가정한다.

어떤 양의 상수 $$c$$와 기준점 $$n_0$$가 존재해 모든 $$n\ge n_0$$에서 $$T(n)\le c f(n)$$이면 $$T(n)\in O(f(n))$$이다. 부등호가 $$T(n)\ge c f(n)$$이면 $$T(n)\in\Omega(f(n))$$이고, 양의 상수 $$c_1,c_2$$에 대해

$$
c_1f(n)\le T(n)\le c_2f(n)
$$

이면 $$T(n)\in\Theta(f(n))$$이다. 따라서 Big-O는 상한, Big-Omega는 하한, Big-Theta는 같은 차수의 상·하한을 동시에 주는 분류다.

피보나치 예제에서는 $$n\ge1$$일 때

$$
4n\le4n+1\le5n
$$

이므로 $$c_1=4$$, $$c_2=5$$, $$n_0=1$$을 택할 수 있다. 이것으로 $$T(n)=4n+1\in\Theta(n)$$이 직접 증명된다. 이 결론은 연산 횟수의 성장률에 관한 것이며, 실제 벽시계 시간이 정확히 $$4n+1$$초라는 뜻은 아니다.

### 성장률 표의 순서가 의미하는 것

> **원문 추적:** Source PDF 22쪽의 $$\log n,n,n\log n,n^2,n^3,2^n$$ 비교표를 보충한다.

표의 순서는 작은 모든 $$n$$에서 성립하는 산술 부등식이 아니라, $$n\to\infty$$일 때의 **점근적 지배 관계**다. 로그의 밑을 1보다 큰 고정 상수로 두면

$$
\frac{\log n}{n}\to0,
\qquad
\frac{n}{n\log n}=\frac1{\log n}\to0,
\qquad
\frac{n\log n}{n^2}=\frac{\log n}{n}\to0,
\qquad
\frac{n^2}{n^3}=\frac1n\to0.
$$

또한 고정 차수의 다항식은 지수함수보다 느리게 자라므로 $$n^3/2^n\to0$$이다. 따라서 충분히 큰 입력에서는 $$\log n\prec n\prec n\log n\prec n^2\prec n^3\prec2^n$$이다. 작은 입력에서는 상수항·계수와 구현 비용 때문에 실제 실행 순서가 달라질 수 있다.

## Study Guide

의사코드에서 입력 크기와 기본 연산을 먼저 표시한 뒤, 조건문별 경로와 반복 횟수를 세어 T(n)을 만든다. n=1과 n>1처럼 실행 횟수가 달라지는 경우는 하나의 평균값으로 덮지 말고 piecewise하게 계산한다. 마지막에는 실제 실행시간을 재는 실험적 분석과 연산 성장률을 구하는 이론적 분석의 장단점을 비교한다.

## Study Notes

알고리즘 분석은 "내 컴퓨터에서 몇 초 걸렸는가"보다 더 일반적인 질문을 다룬다. 같은 프로그램이라도 컴퓨터 성능, 언어, 컴파일러, 입력 데이터의 형태에 따라 실제 실행 시간은 달라진다. 그래서 강의에서는 실제 초 단위 시간보다 **입력 크기 `n`이 커질 때 기본 연산 횟수가 어떻게 늘어나는지**를 본다.

기본 연산은 보통 수행 시간이 상수라고 볼 수 있는 작은 작업이다. 대입, 비교, 산술 연산, 배열 인덱스 접근이 대표적이다. 정확히 어떤 연산을 기본 연산으로 잡는지는 문제마다 다를 수 있지만, 중요한 것은 일관성이다.

```text
for i = 0 to n - 1:
    if A[i] == target:
        return i
```

위 코드는 최선의 경우 첫 번째 원소에서 찾으면 상수 시간이다. 최악의 경우 끝까지 찾거나 없으면 `n`번 비교한다. 그래서 입력 상황에 따라 best case, worst case, average case가 달라질 수 있다.

반복문 분석은 안쪽에서 바깥쪽으로 본다.

```text
for i = 0 to n - 1:
    for j = 0 to n - 1:
        count = count + 1
```

안쪽 연산은 상수 시간이고, 안쪽 반복문이 $$n$$번, 바깥 반복문도 $$n$$번 돈다. 따라서 전체 연산 횟수는 $$n \times n = n^2$$에 비례한다.

반면 다음 코드는 모양이 비슷해도 다르다.

```text
for i = 0 to n - 1:
    for j = 0 to i:
        count = count + 1
```

반복 횟수는 $$1+2+\cdots+n = n(n+1)/2$$이다. 정확한 식은 $$0.5n^2+0.5n$$이지만, 큰 입력에서는 $$n^2$$이 지배한다.

### 삼각합이 $$n(n+1)/2$$가 되는 이유

> **분류:** 유한 등차수열의 **정확한 항등식**을 이용한 작성자 보충 해설이다. Source PDF 20--24쪽은 기본 연산 계수와 성장률 비교를 다루지만, 이 중첩 반복문 예제 자체는 원문 슬라이드에 없다.

$$n$$이 0 이상의 정수라고 하자. 같은 합을 정방향과 역방향으로 한 번씩 쓰면

$$
S=1+2+\cdots+(n-1)+n,
$$

$$
S=n+(n-1)+\cdots+2+1
$$

이고, 같은 열끼리 더한 $$n$$개의 합이 모두 $$n+1$$이다. 따라서

$$
2S=n(n+1),
\qquad
S=\frac{n(n+1)}{2}.
$$

반복 횟수의 단위는 `회`이고 $$n$$은 원소 수를 나타내는 무차원 정수다. 그러므로 정확한 반복 횟수는 $$\frac12n^2+\frac12n$$이며, $$n\ge1$$에서 이 값은 $$\frac12n^2$$ 이상이고 $$n^2$$ 이하이므로 $$\Theta(n^2)$$이다. 내부 반복의 상한이나 시작 index가 달라지면 상수항과 선형항은 달라질 수 있지만, 삼각형 모양의 반복 범위가 유지되는 한 이차 성장률은 변하지 않는다.

## How to Read Pseudocode

의사코드는 실제 언어가 아니라 알고리즘의 핵심 흐름을 보여 주는 표기다. 세미콜론, 타입 선언, 라이브러리 호출보다 중요한 것은 조건, 반복, 반환 위치다.

| 의사코드 요소 | 읽는 법 |
|---|---|
| `if` | 입력에 따라 실행 경로가 나뉜다. |
| `for` | 반복 횟수를 계산해야 한다. |
| `while` | 종료 조건과 반복 횟수의 상한을 찾아야 한다. |
| `return` | 알고리즘이 언제 끝나는지 확인한다. |

시험에서는 코드를 그대로 외우기보다 "어떤 연산을 몇 번 수행하는가"를 말로 설명할 수 있어야 한다.
