# LS02 Data Structures and Algorithms

## 1. 자료구조란?

자료구조는 데이터를 효율적으로 저장, 검색, 처리하기 위한 방법이다. 핵심 질문은 "정보를 컴퓨터 메모리에 어떤 모양으로 담아 둘 것인가?"이다.

자료구조를 잘 고르면 같은 문제도 며칠 걸릴 일이 몇 초 안에 끝날 수 있다. 이 차이는 보통 다음 두 비용에서 나온다.

| 비용 | 의미 |
|---|---|
| 시간 비용 | 삽입, 삭제, 탐색, 순회 같은 연산을 수행하는 데 걸리는 시간 |
| 공간 비용 | 데이터를 저장하기 위해 필요한 메모리 |

자료구조 수업의 중심은 "모든 상황에서 좋은 구조"를 찾는 것이 아니라, **문제의 요구에 맞는 구조**를 선택하는 것이다.

## 2. 좋은 프로그래밍과 효율성

좋은 프로그램은 두 기준을 동시에 만족해야 한다.

| 기준 | 설명 |
|---|---|
| 이해 가능성 | 구현, 디버깅, 유지보수가 쉬워야 한다. |
| 효율성 | CPU, 메모리 같은 자원 제약 안에서 문제를 해결해야 한다. |

자료구조는 특히 효율성에 강하게 연결된다. 하지만 구현이 너무 복잡해서 실수하기 쉬우면 좋은 선택이라고 보기 어렵다. 좋은 자료구조 선택은 성능과 구현 난이도 사이의 균형이다.

## 3. 자료구조 선택 방법

자료구조를 고를 때는 다음 순서로 생각한다.

1. 문제를 풀기 위해 필요한 연산을 나열한다.
2. 각 연산이 얼마나 자주 실행되는지 확인한다.
3. 시간, 공간, 구현 난이도 제약을 정량화한다.
4. 요구 조건을 가장 잘 만족하는 자료구조를 고른다.

예를 들어 은행 시스템에서 계좌 생성은 몇 분 걸려도 되지만, 입출금은 몇 초 안에 끝나야 한다. 따라서 모든 연산을 같은 기준으로 최적화하는 것이 아니라, **중요하고 자주 실행되는 연산**을 중심으로 고른다.

## 4. Exact Query와 Range Query

학생 GPA 데이터베이스 예시는 자료구조 선택의 감각을 잘 보여준다.

| 작업 | 질의 종류 | 적절한 자료구조 |
|---|---|---|
| 특정 수업에서 `B0`를 받은 학생 모두 찾기 | Exact query | 해시 테이블 |
| GPA가 `1.0`부터 `2.5` 사이인 학생 찾기 | Range query | 이진 탐색 트리, B-tree |

해시 테이블은 특정 키 하나를 빠르게 찾는 데 강하다. 반면 범위 검색은 정렬 관계가 필요하므로 트리 계열이 더 자연스럽다.

## 5. ADT, 자료구조, 자료형

ADT(Abstract Data Type)는 자료형을 **값과 연산의 명세**로 정의한다. 구현 방법은 숨기고, 사용자가 어떤 동작을 할 수 있는지만 보여준다.

자료구조는 ADT를 실제 메모리와 알고리즘으로 구현한 것이다.

| 구분 | 핵심 | 예시 |
|---|---|---|
| ADT | 무엇을 할 수 있는가 | 스택: `push`, `pop` |
| 자료구조 | 어떻게 구현하는가 | 배열 기반 스택, 연결 리스트 기반 스택 |
| 자료형 | 값의 종류와 허용 연산 | 정수형, 문자열, 사용자 정의 클래스 |

Java에서는 ADT를 `interface`로 표현하고, 실제 자료구조는 `class`로 구현할 수 있다. Python에서는 추상 클래스를 비슷한 목적으로 사용할 수 있다.

## 6. Problem, Algorithm, Program

| 개념 | 의미 |
|---|---|
| Problem | 풀어야 할 작업. 입력과 출력 조건은 있지만 해결 방법은 포함하지 않는다. |
| Algorithm | 문제를 해결하기 위한 정확하고 유한한 절차. |
| Program | 알고리즘을 특정 프로그래밍 언어로 구현한 결과. |

예를 들어 "웹 문서 중 `Data Mining`을 포함하는 문서를 모두 찾기"는 문제다. 선형 탐색, 색인 기반 탐색 등은 알고리즘이고, Java나 Python으로 작성한 코드는 프로그램이다.

## 시험 포인트

| 질문 | 답의 방향 |
|---|---|
| ADT와 자료구조의 차이는? | ADT는 인터페이스/명세, 자료구조는 실제 구현이다. |
| 해시 테이블과 트리는 언제 다르게 쓰는가? | exact query는 해시, range query는 트리가 유리하다. |
| 자료구조 선택 시 먼저 봐야 하는 것은? | 필요한 연산, 연산 빈도, 시간/공간 제약이다. |
| 알고리즘의 조건은? | 입력, 출력, 명확성, 유한성, 효율성을 만족해야 한다. |

## 복습 질문

<details>
<summary>1. 배열 기반 스택과 연결 리스트 기반 스택은 같은 ADT인가, 다른 ADT인가?</summary>

답변: 같은 Stack ADT를 구현한 서로 다른 자료구조다. 둘 다 `push`, `pop`, `top` 같은 스택 연산을 제공하지만, 배열 기반 스택은 배열과 인덱스로 구현하고 연결 리스트 기반 스택은 노드와 포인터로 구현한다.

</details>

<details>
<summary>2. 도서 관리 시스템에서 "특정 ISBN 찾기"와 "가격이 1만 원에서 2만 원 사이인 책 찾기"는 각각 어떤 질의인가?</summary>

답변: 특정 ISBN 찾기는 exact query다. 정확히 하나의 key 값을 찾기 때문이다. 가격이 1만 원에서 2만 원 사이인 책 찾기는 range query다. 값의 구간을 기준으로 검색하므로 정렬 관계를 활용할 수 있는 구조가 유리하다.

</details>

<details>
<summary>3. 프로그램 성능을 개선하려면 알고리즘만 바꾸면 충분한가, 자료구조도 함께 봐야 하는가?</summary>

답변: 자료구조도 함께 봐야 한다. 같은 알고리즘이라도 데이터를 배열, 리스트, 트리, 해시 테이블 중 어디에 저장하느냐에 따라 탐색, 삽입, 삭제 비용이 크게 달라진다.

</details>

## Study Notes

이 강의는 자료구조 과목 전체의 입구다. 외워야 할 용어가 많아 보이지만, 중심 질문은 하나다. **데이터를 어떤 모양으로 저장해야 필요한 작업을 빠르고 안전하게 할 수 있는가?**

자료구조를 선택할 때는 자료의 이름보다 연산을 먼저 본다. 예를 들어 "학생 목록"이라는 말만으로는 배열, 연결 리스트, 트리, 해시 테이블 중 무엇이 좋은지 판단할 수 없다. 학생을 학번으로 자주 찾는다면 해시 테이블이 자연스럽고, 성적 순서로 범위를 자주 찾는다면 정렬 구조나 트리가 더 적합하다.

ADT와 자료구조의 차이는 계속 반복해서 나온다. ADT는 사용자가 기대하는 동작의 약속이고, 자료구조는 그 약속을 실제 메모리 위에 구현한 방식이다. 스택 ADT는 `push`, `pop`, `top`을 제공한다는 약속이고, 이것을 배열로 만들 수도 있고 연결 리스트로 만들 수도 있다.

```text
Stack ADT
    무엇을 할 수 있는가: push, pop, top

Array Stack
    어떻게 구현하는가: 배열 + top 인덱스

Linked Stack
    어떻게 구현하는가: 노드 + next 포인터
```

문제, 알고리즘, 프로그램도 구분해야 한다. "정렬하라"는 문제이고, merge sort나 quick sort는 알고리즘이며, Java로 작성한 `mergeSort()` 함수는 프로그램이다. 시험 답안에서 이 셋을 섞어 쓰면 설명이 흐려진다.

자료구조 선택 문제를 풀 때는 다음 순서로 정리하면 좋다.

1. 데이터가 무엇인지 적는다.
2. 자주 수행되는 연산을 적는다.
3. 각 연산이 exact query인지 range query인지 확인한다.
4. 시간 제약과 공간 제약을 확인한다.
5. 구현 난이도까지 고려해서 자료구조를 고른다.

예를 들어 exact query는 특정 key 하나가 목표다. `studentId == 2025001`처럼 정확히 하나의 조건을 찾는다. Range query는 구간이 목표다. `1.0 <= GPA <= 2.5`처럼 정렬 관계가 필요하다. 그래서 exact query는 해싱이 강하고, range query는 트리나 정렬 배열이 강하다.

## Common Pitfalls

| 실수 | 올바른 이해 |
|---|---|
| ADT와 자료구조를 같은 말로 본다. | ADT는 명세, 자료구조는 구현이다. |
| 가장 빠른 자료구조 하나가 항상 있다고 생각한다. | 연산 종류와 빈도에 따라 좋은 선택이 달라진다. |
| 해시 테이블이 모든 검색에서 최고라고 생각한다. | 범위 검색이나 정렬 순회에는 트리 계열이 더 적합할 수 있다. |
| 알고리즘과 프로그램을 구분하지 않는다. | 알고리즘은 절차, 프로그램은 특정 언어로 구현한 결과다. |
