# LS18 Hash Search

Source PDF: `LS18_hash_search.pdf`

> **핵심:** **해싱의 핵심은** key를 해시 함수로 배열 인덱스에 매핑. **해시 테이블 평균 탐색 시간은** 충돌이 적다는 가정하에 $$O(1)$$.

## 전체 흐름

| 순서 | 주제 | 핵심 질문 |
|---|---|---|
| 1 | 딕셔너리 복습 | key-value 구조는 어떤 연산을 제공하는가? |
| 2 | 자료구조별 탐색 비용 | 리스트, BST, 해싱은 어떤 차이가 있는가? |
| 3 | 해싱 | key를 배열 인덱스로 어떻게 바꾸는가? |
| 4 | 충돌 | 서로 다른 key가 같은 슬롯으로 가면 어떻게 되는가? |
| 5 | 좋은 해시 함수 | 균등 분포와 테이블 크기 선택이 왜 중요한가? |

## 1. 딕셔너리 복습

딕셔너리는 데이터를 key-value 쌍으로 저장한다.

| 연산 | 의미 |
|---|---|
| `put(key, value)` | 삽입 또는 기존 key의 value 수정 |
| `get(key)` | key로 value 탐색 |
| `remove(key)` | key-value 쌍 삭제 |
| `containsKey(key)` | key 존재 여부 확인 |

key는 유일해야 하고, value는 중복될 수 있다.

## 2. 자료구조별 시간 복잡도

| 구조 | Search | Insert / Remove |
|---|---|---|
| Unsorted list | $$O(n)$$ | 삽입 $$O(1)$$, 삭제 $$O(n)$$ |
| Sorted list | $$O(\log n)$$ | $$O(n)$$ |
| Binary Search Tree | 균형 시 $$O(\log n)$$ | 균형 시 $$O(\log n)$$ |
| Hash Table | 평균 $$O(1)$$ | 평균 $$O(1)$$ |

해싱의 목표는 key를 배열 인덱스로 빠르게 변환해 탐색, 삽입, 삭제를 평균 상수 시간에 수행하는 것이다.

## 3. 해싱 Hashing

해싱은 해시 함수 $$h(k)$$를 사용해 key $$k$$를 해시 테이블의 인덱스로 매핑한다.

| 구성 요소 | 의미 |
|---|---|
| 해시 테이블 `HT` | 아이템을 저장하는 크기 $$m$$의 배열 |
| 해시 함수 $$h(k)$$ | key를 $$0$$부터 $$m - 1$$ 사이의 인덱스로 변환 |

가장 기본적인 예시는 modular hash function이다.

$$
h(k) = k \bmod m
$$

예를 들어 $$m = 12$$, $$k = 100$$이면 다음과 같다.

$$
h(100) = 100 \bmod 12 = 4
$$

따라서 key $$100$$은 해시 테이블의 4번 슬롯에 저장된다.

## 4. 해싱이 유용한 상황

키의 실제 개수 $$n$$은 작지만 가능한 키 범위가 매우 큰 경우 해싱이 유용하다.

예를 들어 key 범위가 $$0$$부터 $$K_{\max}$$까지라면 단순 배열은 $$K_{\max}+1$$칸이 필요하다. 하지만 실제 key가 조금만 존재한다면 대부분의 공간이 빈칸이 된다.

해싱은 key 개수와 비슷한 크기의 테이블 $$m$$만 사용해 공간을 아낀다. 강의에서는 보통 $$m$$을 $$n$$보다 조금 큰 정도, 예를 들어 $$1.3n \le m \le 2n$$ 범위로 설명한다.

> **분류:** $$1.3n\le m\le2n$$은 정확한 정리나 필수 조건이 아니라 Source PDF 11쪽의 **용량 선택 heuristic**이다. $$n$$은 저장 key 수, $$m$$은 슬롯 수로 모두 무차원 정수다. 같은 $$n$$이라도 충돌 해결 방식과 메모리 예산에 따라 적절한 $$m$$은 달라진다.

## 5. 충돌 Collision

충돌은 서로 다른 key가 같은 해시값을 갖는 상황이다.

$$
h(k_1) = h(k_2),\qquad k_1 \ne k_2
$$

충돌이 많아지면 한 슬롯에 여러 아이템이 몰리고, 탐색/삽입/삭제에 추가 작업이 필요해진다. 이 경우 평균 $$O(1)$$ 성능이 깨지고 최악 $$O(n)$$까지 갈 수 있다.

충돌을 줄이려면 좋은 해시 함수와 적절한 테이블 크기가 필요하다. 그래도 key 수가 슬롯 수보다 많으면 충돌은 원리적으로 피할 수 없다.

## 6. 좋은 해시 함수의 조건

이상적인 해시 함수는 단순 균등 해싱을 만족해야 한다.

| 조건 | 의미 |
|---|---|
| 균등성 | 모든 key가 $$m$$개 슬롯에 비슷한 확률로 배치된다. |
| 독립성 | 한 key의 해시 결과가 다른 key의 결과와 무관하다. |
| 계산 효율 | 실제 시스템에서는 빠르게 계산 가능해야 한다. |

현실에서는 입력 key 분포를 미리 알기 어렵다. 따라서 계산이 간단하면서 key를 골고루 퍼뜨리는 함수를 선택한다.

## 7. 문자열 key를 정수로 바꾸기

해시 함수는 보통 key를 정수로 보고 계산한다. 문자열은 문자 코드를 이용해 정수로 변환할 수 있다.

예를 들어 `"CLRS"`를 ASCII 값으로 보면:

$$
C=67,\quad L=76,\quad R=82,\quad S=83
$$

이를 128진법처럼 해석하면 하나의 큰 정수로 바꿀 수 있다.

$$
67\cdot128^3 + 76\cdot128^2 + 82\cdot128^1 + 83\cdot128^0
$$

그 정수에 $$\bmod m$$을 적용해 슬롯을 정한다.

### 문자열 변환식이 순서를 보존하는 이유

> **분류:** 위치 기수법의 **정의식**이다. 문자 코드 $$c_0,\ldots,c_{L-1}$$가 $$0\le c_i<b$$이고 기수 $$b$$를 고정한다고 가정한다.
>
> **원문 추적:** Source PDF 17--20쪽의 `CLRS` ASCII 변환과 modular hash 예제를 보충 해설한다.

길이 $$L$$ 문자열은

$$
K=\sum_{i=0}^{L-1}c_i b^{L-1-i}
$$

로 정수화할 수 있다. 왼쪽 문자는 더 큰 거듭제곱 자리, 오른쪽 문자는 더 작은 자리를 차지하므로 `CLRS`의 순서 정보가 반영된다. 직접 거듭제곱을 계산하는 대신 Horner 형태

$$
K_0=0,
\qquad K_{i+1}=bK_i+c_i
$$

로 한 글자씩 계산하면 같은 값을 $$O(L)$$에 얻는다. 최종 슬롯은 $$h=K\bmod m$$이다. 고정 폭 정수에서는 $$K$$가 overflow할 수 있으므로 각 단계에 $$\bmod m$$을 적용해도 $$(a+b)\bmod m$$, $$(ab)\bmod m$$의 합동 성질 때문에 최종 나머지는 같다.

## 8. `m`을 소수로 잡는 이유

$$h(k)=k\bmod 8$$처럼 테이블 크기 $$m$$이 2의 거듭제곱이면 문제가 생길 수 있다.

| 문제 | 설명 |
|---|---|
| 짝수 key 편향 | 모든 key가 짝수라면 홀수 슬롯을 쓰지 못한다. |
| 하위 비트 의존 | $$\bmod 2^p$$는 key의 하위 $$p$$비트에만 의존한다. |

그래서 modular hash에서는 테이블 크기 `m`을 소수로 잡는 경우가 많다. key 패턴과 테이블 크기가 특정 공약수 관계로 맞물려 충돌이 증가하는 일을 줄일 수 있다.

> **분류:** 소수 크기 선택은 모든 입력에 균등 분포를 보장하는 정리가 아니라 **설계 heuristic**이다.
>
> **원문 추적:** Source PDF 21--24쪽의 $$h(k)=k\bmod 8$$ 반례, 소수 테이블 크기 권고와 합동식 논증을 보충 해설한다.

원문의 짝수 key 반례는 나머지의 짝홀성으로 확인할 수 있다. $$k=8q+r$$, $$0\le r<8$$이라 두면 $$8q$$는 짝수이므로 $$k$$와 $$r=k\bmod8$$의 짝홀성이 같다. 따라서 $$k$$가 모두 짝수이면 가능한 나머지는 $$0,2,4,6$$뿐이고 홀수 슬롯은 사용되지 않는다. 일반적으로 $$m=2^p$$이면 나머지는 key의 하위 $$p$$비트만으로 정해지므로, 입력의 하위 비트에 규칙성이 있을 때 편향이 생긴다.

Source PDF 23쪽의 좁은 조건에서는 소수 modulus의 효과를 정확히 증명할 수 있다. $$m$$이 소수이고 $$m\nmid c$$이며 key가 $$k_i=ci$$ 꼴이고 $$0\le i<m$$이라고 하자. 두 key가 같은 슬롯으로 간다면

$$
ci\equiv cj\pmod m
$$

이므로 $$m\mid c(i-j)$$이다. $$m$$은 소수이고 $$m\nmid c$$이므로 Euclid's lemma에 의해 $$m\mid(i-j)$$다. 그런데 $$i,j$$가 모두 $$0$$부터 $$m-1$$ 사이이므로 이는 $$i=j$$일 때만 가능하다. 따라서 이 제한된 key 집합에서는 서로 다른 $$i$$가 서로 다른 슬롯에 매핑된다.

하지만 모든 key가 $$m$$의 배수이면 $$m$$이 소수여도 전부 0번 슬롯으로 간다. 또한 서로 다른 key가 $$m$$개 슬롯에 매핑될 때 key가 $$m$$개보다 많으면 pigeonhole principle에 의해 적어도 한 충돌은 반드시 생긴다. 소수 크기는 규칙적 key와 공약수로 생기는 일부 편향을 줄일 뿐 충돌 해결 전략을 대신하지 않는다. 여기서 $$k,c,i,j,q,r,m,p$$는 모두 정수 또는 개수를 나타내므로 무차원이다.

## 9. 다른 해시 함수 아이디어

| 방법 | 아이디어 |
|---|---|
| Mid-Square Method | key를 제곱한 뒤 가운데 비트들을 사용한다. |
| Folding Approach | key를 여러 조각으로 나누어 합친 뒤 mod 연산을 한다. |

두 방법 모두 key의 여러 부분이 해시값에 섞이도록 만들어 특정 패턴에 덜 민감하게 하려는 목적이 있다.

## Study Guide

몇 개의 key를 h(k)=k mod m에 대입해 index를 계산하고, 같은 slot으로 가는 충돌을 직접 표시한다. 평균 O(1)은 좋은 hash distribution과 낮은 충돌을 전제로 하며 range search에는 정렬 구조보다 불리하다는 조건을 함께 기억한다. table size가 2의 거듭제곱일 때 하위 bit 편향이 생길 수 있는 이유와 소수 크기를 쓰는 목적을 설명한다.

## Study Notes

해싱은 key를 배열 인덱스로 바꾸어 탐색을 빠르게 만드는 방법이다. 핵심은 큰 key 공간을 실제 테이블 크기 `m` 안으로 압축하는 것이다.

```text
key -> hash function -> table index
```

예를 들어 학생 번호가 8자리라면 가능한 key 범위는 매우 크다. 하지만 실제 학생 수가 100명이라면 1억 칸짜리 배열을 만들 필요가 없다. 해시 테이블은 적절한 크기의 배열을 만들고, 해시 함수를 통해 key를 그 배열의 인덱스로 보낸다.

가장 단순한 방식은 modular hashing이다.

$$
h(k) = k \bmod m
$$

$$m = 12$$, $$k = 100$$이면 $$100\bmod 12 = 4$$이므로 4번 슬롯을 사용한다.

문자열 key는 바로 $$\bmod$$를 적용할 수 없으므로 먼저 정수로 바꿔야 한다. 강의의 다항식 방식은 각 문자를 숫자로 보고 자릿값처럼 계산한다.

$$
\text{"CLRS"} = C\cdot128^3 + L\cdot128^2 + R\cdot128 + S
$$

그 결과에 다시 $$\bmod m$$을 적용한다.

## Collision Handling

충돌은 서로 다른 key가 같은 슬롯으로 가는 상황이다. 좋은 해시 함수는 충돌을 줄이지만, 슬롯 수보다 key 수가 많으면 충돌은 원리적으로 피할 수 없다.

대표적인 해결 방법은 다음과 같다.

| 방법 | 아이디어 |
|---|---|
| separate chaining | 각 슬롯에 리스트를 두고 같은 슬롯의 원소들을 연결 |
| open addressing | 충돌이 나면 테이블 안의 다른 빈 슬롯을 탐색 |

이 강의에서는 좋은 해시 함수와 테이블 크기 선택을 특히 강조한다. `m`이 2의 거듭제곱이면 하위 비트 패턴에 민감해질 수 있다. 그래서 `m`을 소수로 잡으면 특정 key 패턴이 슬롯 일부에만 몰리는 현상을 줄일 수 있다.

## Load Factor

해시 테이블의 성능은 load factor와 관련이 깊다.

> **작성자 보충:** Source PDF 1--27쪽에는 load factor 식이 직접 나오지 않는다. 아래는 원문의 `key 수에 비슷한 테이블 크기`와 충돌 조건을 연결하기 위한 표준 정의이며, 원문 공식으로 간주하지 않는다.

$$
\alpha = \frac{n}{m}
$$

여기서 $$n$$은 저장된 원소 수, $$m>0$$은 테이블 슬롯 수이며 $$\alpha$$는 단위가 없는 비율이다. Separate chaining에서 단순 균등 해싱을 가정하면 슬롯당 기대 원소 수가 $$n/m=\alpha$$이므로 평균 chain 길이가 $$\alpha$$에 비례한다. Open addressing은 각 슬롯에 하나만 저장하므로 반드시 $$\alpha<1$$이어야 한다.

load factor가 너무 커지면 한 슬롯에 몰리는 원소가 많아지고 충돌 비용이 증가한다. 그래서 실제 해시 테이블 구현은 일정 비율을 넘으면 더 큰 테이블로 rehashing을 수행한다. 균등 해싱이 깨지면 $$\alpha$$가 작아도 특정 슬롯에 key가 몰릴 수 있으므로, 낮은 load factor만으로 $$O(1)$$을 보장하지는 않는다.

## Common Pitfalls

| 실수 | 올바른 이해 |
|---|---|
| 해시 테이블은 항상 $$O(1)$$이라고 말한다. | 평균 $$O(1)$$이며 충돌이 심하면 느려진다. |
| 해시 함수가 key를 유일한 index로 바꾼다고 생각한다. | 서로 다른 key가 같은 index로 갈 수 있다. |
| 테이블 크기는 아무 숫자나 가능하다고 본다. | key 패턴과 맞물리지 않도록 소수 크기를 자주 사용한다. |
| 해싱이 정렬 탐색에도 좋다고 생각한다. | 해싱은 exact search에 강하고 range search에는 약하다. |
