# Lecture 5: Merge Sort and Quick Sort

Source PDF: [5 Sorting (2).pdf](/assets/pdfs/study/algorithms/05-sorting-02.pdf)

병합 정렬은 정렬된 두 구간을 합치고, 퀵 정렬은 피벗을 기준으로 구간을 나눈다. 강의 자료의 두 알고리즘을 **구간, 불변식, 재귀식**으로 비교한다. 슬라이드 의사코드에서 생략한 빈 구간의 종료 조건과 동점 원소 처리는 **Source Check**에 원문과 구분해 적었다. 2–4쪽의 과제·시험 일정은 강의 당시의 공지이므로 본문에서 다루지 않는다.

> **핵심:** 병합 정렬은 먼저 양쪽을 정렬한 뒤 선형 시간에 합쳐 어떤 입력에도 $$\Theta(n\log n)$$이다. 퀵 정렬은 선형 시간에 피벗의 최종 위치를 정한 뒤 양쪽을 재귀적으로 정렬한다. 분할이 균형 잡히면 $$\Theta(n\log n)$$이지만, 극단적으로 치우치면 $$\Theta(n^2)$$이다.

## 1. Sorting as Divide and Conquer

앞 강의에서 다룬 Bubble·Selection·Insertion Sort는 비교하거나 이미 정렬된 부분을 한 원소씩 늘리는 방식으로 이해할 수 있다(5–6쪽). 이번 강의는 길이 $$n$$인 문제를 더 작은 부분 문제로 **분할(divide)** 하고, 부분 문제를 재귀적으로 **해결(conquer)** 한 후 답을 **결합(combine)** 한다. 여기서 중요한 질문은 “매 단계 크기가 얼마나 줄어드는가?”뿐 아니라 “각 단계에서 일을 얼마나 하는가?”이다. 절반으로 줄어 깊이가 $$\log_2 n$$이어도, 매 깊이에서 배열 전체를 다루면 총 시간은 $$n\log n$$이 된다.

아래 두 알고리즘은 모두 배열의 반열린 구간 $$[l,r)$$을 사용한다. $$l$$은 포함하고 $$r$$은 제외하므로 길이는 $$r-l$$이다. 예를 들어 `arr[2:5]`는 인덱스 2, 3, 4를 뜻한다. 빈 구간 $$[l,l)$$과 한 원소 구간 $$[l,l+1)$$은 이미 정렬되어 있다.

## 2. Merge Sort

### 2.1 Recursive structure

`merge_sort(arr, l, r)`는 중간점 $$m=\lfloor(l+r)/2\rfloor$$을 잡아 $$[l,m)$$과 $$[m,r)$$을 각각 정렬한 후 병합한다(11–13쪽). 두 부분의 길이는 최대 1 차이이므로 재귀 깊이는 $$\Theta(\log n)$$이다. 다음은 빈 배열까지 안전하게 처리하고, 동점 원소의 기존 순서를 유지하도록 정리한 버전이다. 원문 코드와 다른 조건은 Source Check에서 설명한다.

```python
def merge_sort(arr, l=0, r=None):
    if r is None:
        r = len(arr)
    if r - l <= 1:
        return

    m = (l + r) // 2
    merge_sort(arr, l, m)
    merge_sort(arr, m, r)

    left = arr[l:m]
    right = arr[m:r]
    i = j = 0
    for k in range(l, r):
        if i == len(left):
            arr[k] = right[j]
            j += 1
        elif j == len(right):
            arr[k] = left[i]
            i += 1
        elif left[i] <= right[j]:
            arr[k] = left[i]
            i += 1
        else:
            arr[k] = right[j]
            j += 1
```

슬라이드(14, 16쪽)는 두 부분을 하나의 `tmp = arr[l:r]`에 복사하고, 왼쪽 포인터 `i=0`, 오른쪽 포인터 `j=m-l`, 출력 위치 `k=l`을 사용하는 동등한 병합 구조를 보여 준다. 위 코드는 좌우를 별도 조각으로 표현해 포인터 경계를 읽기 쉽게 한 작성자 재구성이다.

### 2.2 Why merging works

전제는 재귀 호출 이후 **왼쪽과 오른쪽이 각각 이미 정렬**되어 있다는 것이다. 두 부분의 아직 선택되지 않은 첫 원소가 각 부분의 최솟값이므로, 둘 가운데 더 작은 것을 다음 출력 칸에 놓으면 그 칸에는 전체 잔여 원소의 최솟값이 놓인다. 이 선택을 반복하면 결과 구간은 항상 정렬된 접두부가 된다. 한쪽이 소진되면 다른 쪽의 나머지는 이미 정렬되어 있으므로 순서대로 복사하면 된다.

병합의 반복 불변식은 “출력 구간의 첫 $$k-l$$개 원소는 양쪽 입력에서 소비한 원소들의 정렬된 합이며, 아직 소비하지 않은 원소보다 크지 않다”이다. 루프 한 번에 포인터 하나가 이동하므로 정확히 $$r-l$$개의 값을 채우고 종료한다. 비교 횟수는 최대 $$r-l-1$$번이며, 복사·쓰기까지 포함한 시간은 $$\Theta(r-l)$$이다. 임시 배열은 크기 $$\Theta(r-l)$$이다.

예를 들어 슬라이드의 `[4, 3, 9, 8, 7, 6, 5, 2]`(12쪽)는 왼쪽 `[3, 4, 8, 9]`, 오른쪽 `[2, 5, 6, 7]`로 각각 정렬된다. 병합에서는 양쪽 맨 앞 `3`과 `2` 중 `2`를 먼저 고르고, 이어 `3`, `4`, `5`를 고르는 식으로 진행하여 `[2, 3, 4, 5, 6, 7, 8, 9]`를 만든다.

### 2.3 Correctness and cost

정확성은 구간 길이에 대한 귀납으로 증명할 수 있다. 길이 0 또는 1에서는 정렬 상태가 자명하다. 길이 $$n\ge2$$에서 두 재귀 호출이 각각 정렬된 결과를 만든다고 가정하면, 앞의 병합 불변식에 따라 두 결과를 합친 전체 구간도 정렬된다. 재귀 호출이 길이를 줄이고 기저 조건에 도달하므로 종료한다.

분할한 두 길이를 정확히 반영한 시간 재귀식은 다음과 같다.

$$
T(n)=T(\lfloor n/2\rfloor)+T(\lceil n/2\rceil)+\Theta(n),\qquad n\ge2.
$$

각 깊이에서 처리하는 모든 구간의 길이 합이 $$n$$이고 깊이가 $$\Theta(\log n)$$이므로 $$T(n)=\Theta(n\log n)$$이다. 입력의 원래 순서가 달라져도 병합은 각 깊이에서 모든 원소를 복사·기록하므로 이 차수는 최선·평균·최악 모두 같다. 동시에 살아 있는 병합용 임시 저장 공간은 $$\Theta(n)$$, 재귀 호출 스택은 $$\Theta(\log n)$$이어서 총 보조 공간은 $$\Theta(n)$$이다.

안정성(stability)은 **키가 같은 원소의 상대 순서가 유지되는 성질**이다. 왼쪽과 오른쪽의 맨 앞 키가 같을 때 **왼쪽을 먼저** 택하면 원래 왼쪽에 있던 원소가 먼저 남아 안정적이다. 위 재구성 코드의 `<=`가 그 선택이다. 반대로 슬라이드의 비교 연산자 `<`는 동점일 때 오른쪽을 먼저 택하므로 그 코드 그대로라면 안정적이지 않다.

## 3. Quick Sort

### 3.1 Partition before recursion

퀵 정렬은 먼저 피벗을 기준으로 구간을 분할한다(18–22쪽). 슬라이드는 마지막 원소 `arr[r-1]`을 피벗으로 잡는다. 분할 결과 피벗 위치를 $$p$$라고 하면, 왼쪽 $$[l,p)$$에는 피벗 이하의 원소, 오른쪽 $$[p+1,r)$$에는 피벗보다 큰 원소가 놓인다. 이때 피벗은 최종 정렬 위치에 있으므로 양쪽만 재귀적으로 정렬하면 된다.

```python
def partition(arr, l, r):
    pivot = arr[r - 1]
    i = l
    for j in range(l, r):  # 마지막 반복에서 피벗 자체도 처리한다.
        if arr[j] <= pivot:
            arr[i], arr[j] = arr[j], arr[i]
            i += 1
    return i - 1


def quick_sort(arr, l=0, r=None):
    if r is None:
        r = len(arr)
    if r - l <= 1:
        return
    p = partition(arr, l, r)
    quick_sort(arr, l, p)
    quick_sort(arr, p + 1, r)
```

이 코드는 슬라이드의 분할 방식(22, 24쪽)을 따른다. 흔히 소개되는 Lomuto 분할은 피벗 직전까지만 훑고 마지막에 피벗을 교환하지만, **여기서는 `range(l,r)`가 피벗까지 포함**한다. 마지막 반복에서 피벗을 `arr[i]`로 옮기므로 별도의 마지막 교환은 필요 없다.

### 3.2 Partition invariant and example

피벗을 처리하기 전, 인덱스 $$j$$의 반복을 시작할 때 구간은 다음처럼 나뉜다.

| 구간 | 불변식 |
|---|---|
| $$[l,i)$$ | 피벗 이하인 원소 |
| $$[i,j)$$ | 피벗보다 큰 원소 |
| $$[j,r-1)$$ | 아직 검사하지 않은 원소 |
| $$r-1$$ | 피벗 자체 |

`arr[j] <= pivot`이면 그 값을 `i`와 바꾸어 왼쪽 구간을 한 칸 키운다. 그렇지 않으면 큰 값 구간만 한 칸 늘어난다. 마지막 $$j=r-1$$에서는 피벗이므로 조건이 참이고 `arr[i]`로 이동한다. 따라서 반환값 $$i-1$$은 피벗의 최종 위치이며, 좌우 구간의 조건도 성립한다. 각 원소를 한 번 검사하므로 분할 시간은 $$\Theta(n)$$, 분할 자체의 추가 공간은 $$\Theta(1)$$이다.

슬라이드의 예시 `[4, 3, 9, 8, 7, 2, 5, 6]`(20–24쪽)에서는 피벗 `6`을 택해 첫 분할 결과 `[4, 3, 2, 5, 6, 9, 8, 7]`을 얻는다. `6`의 인덱스 4가 확정된다. `[4,3,2,5]`와 `[9,8,7]`을 각각 정렬하면 최종 `[2,3,4,5,6,7,8,9]`이다. 분할 직후의 왼쪽·오른쪽 내부는 **아직 정렬되어 있지 않다**는 점이 병합 정렬과 다르다.

정확성 역시 귀납법으로 보인다. 길이 0·1은 자명하다. 길이 $$n$$의 분할이 피벗을 최종 위치에 놓고, 더 짧은 두 구간을 재귀 호출이 정렬한다고 가정하면 전체가 정렬된다. 각 재귀 호출의 길이는 최대 $$n-1$$이므로 종료한다.

### 3.3 Case analysis and pivot choice

분할 비용은 항상 $$\Theta(n)$$이지만, **분할 크기**가 전체 시간을 좌우한다(25–27쪽).

| 피벗 위치의 분포 | 재귀식의 형태 | 시간 |
|---|---|---|
| 매번 거의 중앙 | $$T(n)=2T(n/2)+\Theta(n)$$ | $$\Theta(n\log n)$$ |
| 매번 최소 또는 최대 | $$T(n)=T(n-1)+\Theta(n)$$ | $$\Theta(n^2)$$ |
| 피벗 순위가 매 단계 균등 무작위라는 가정 | 여러 분할 크기를 평균 | 기대 $$\Theta(n\log n)$$ |

평균 분석의 전제는 중요하다. 예를 들어 입력이 서로 다른 키의 무작위 순열이거나 매 단계 임의 위치를 피벗으로 선택하면 피벗 순위를 $$0,\ldots,n-1$$ 사이에서 균등하게 볼 수 있다. 이때 기대 시간은 대략

$$
E[T(n)] = \frac1n\sum_{q=0}^{n-1}\bigl(E[T(q)]+E[T(n-q-1)]\bigr)+\Theta(n)
=\Theta(n\log n).
$$

마지막 등호를 좀 더 구체적으로 볼 수 있다. **서로 다른 키의 무작위 순열**에서 정렬 순위가 $$i<j$$인 두 원소가 비교되는 사건을 $$X_{ij}=1$$이라 하자. 두 원소가 처음 같은 부분 문제에 있을 때, 순위 $$i,\ldots,j$$ 중 처음 피벗으로 선택되는 원소가 양 끝의 $$i$$ 또는 $$j$$일 때만 둘은 비교된다. 따라서 $$P(X_{ij}=1)=2/(j-i+1)$$이다. 지시변수의 기댓값을 모두 더하면 피벗과 **서로 다른 원소** 사이 비교 횟수 $$C_n$$은

$$
E[C_n]
=\sum_{1\le i<j\le n}\frac{2}{j-i+1}
=2(n+1)H_n-4n
=\Theta(n\log n),\qquad
H_n=\sum_{k=1}^{n}\frac1k.
$$

슬라이드의 `partition`은 피벗 자신도 마지막 반복에서 비교하므로 위 $$C_n$$에 포함되지 않은 자기 비교가 분할 호출마다 한 번 있다. 분할 호출 수는 최대 $$n-1$$이어서 $$O(n)$$을 더할 뿐 기대 점근 차수는 변하지 않는다. 이 결과의 단위는 **키 비교 횟수**이며, 배열 접근·교환까지 포함한 실행 시간도 분할마다 선형 작업이므로 기대 $$\Theta(n\log n)$$이다.

하지만 슬라이드 코드처럼 **항상 마지막 원소를 피벗으로 고정**하면 임의의 고정 입력에 대해 위 평균을 보장하는 것은 아니다. 이미 정렬된 배열이나 역순 배열에서는 매번 극단적 분할이 나올 수 있다. 이 코드의 `<=`에서는 모든 값이 같은 배열도 왼쪽에 $$n-1$$개가 모여 $$\Theta(n^2)$$이 된다.

분할에는 큰 임시 배열이 필요 없지만 재귀 스택은 필요하다. 균형 분할이면 깊이 $$\Theta(\log n)$$, 최악의 편향 분할이면 $$\Theta(n)$$이다. 이 구현은 장거리 교환을 하므로 일반적으로 안정 정렬이 아니다.

## 4. Comparison

| 기준 | Merge Sort | Quick Sort (슬라이드 방식) |
|---|---|---|
| 핵심 연산의 순서 | 양쪽 재귀 정렬 → 병합 | 분할 → 양쪽 재귀 정렬 |
| 시간: 최선 / 최악 | $$\Theta(n\log n)$$ / $$\Theta(n\log n)$$ | $$\Theta(n\log n)$$ / $$\Theta(n^2)$$ |
| 평균 시간 | $$\Theta(n\log n)$$ | 피벗 순위 무작위 가정 아래 기대 $$\Theta(n\log n)$$ |
| 보조 공간 | 임시 배열 포함 $$\Theta(n)$$ | 재귀 스택 $$\Theta(\log n)$$ 균형, $$\Theta(n)$$ 최악 |
| 안정성 | 동점에서 왼쪽 우선이면 안정적 | 보통 불안정 |

| 12–13쪽 | 병합 정렬 종료 조건 `l + 1 == r` | 길이 0인 `arr=[]`에서 이 조건은 참이 아니므로 그대로 재귀하면 끝나지 않는다. `r-l <= 1`로 보완했다. |
| 14, 16쪽 | 병합의 비교가 `tmp[i] < tmp[j]` | 같은 키라면 오른쪽을 먼저 선택한다. 일반적인 “병합 정렬은 안정적”이라는 설명은 이 코드에는 그대로 적용되지 않는다. 안정성이 필요하면 `<=`로 바꾼다. |
| 19, 22쪽 | 개념 그림은 왼쪽 `< pivot`, 오른쪽 `> pivot`처럼 설명하나 실제 코드는 `<= pivot` | 구현에 맞춰 왼쪽 **이하**, 오른쪽 **초과**로 표기했다. 동점이 많은 입력의 최악 사례도 이에 따라 분석했다. |
| 22, 24쪽 | `for j in range(l,r)`로 피벗도 루프에서 처리 | 피벗의 마지막 교환을 별도 추가하면 이 구현에서는 중복·오류가 된다. 반환값 `i-1`이 실제 위치다. |

## 마지막 핵심 정리

- Merge Sort의 선형 병합은 모든 높이에서 일어나므로 최선·최악 모두 $$\Theta(n\log n)$$이다. 슬라이드 코드의 동점 선택은 안정적이지 않다.
- Quick Sort의 분할 결과는 피벗의 위치만 확정한다. 분할이 균형이면 $$\Theta(n\log n)$$, 극단적이면 $$\Theta(n^2)$$이다.
- 평균 $$\Theta(n\log n)$$은 **무작위 순열 또는 무작위 피벗**이라는 확률 전제 아래의 기대값이다. 고정된 마지막 피벗은 모든 입력에서 그 시간을 보장하지 않는다.

다음 강의는 이 비교에 **Heap Sort**를 추가한다. 힙 정렬은 큰 병합용 임시 배열 없이도 최악의 경우 $$O(n\log n)$$을 보장한다.

## Study Guide

1. 반열린 구간 $$[l,r)$$의 길이와 종료 조건을 먼저 확인한다. 특히 빈 배열을 함수에 넣어 보자.
2. 병합의 입력은 **이미 정렬된 두 구간**, 분할의 입력은 **정렬되지 않은 한 구간**이다. 두 알고리즘에서 선형 작업이 일어나는 시점이 다르다.
3. 병합과 분할 각각의 루프 불변식을 말로 쓴 뒤, 반복 한 번 후에도 유지되는지 확인한다.
4. 재귀식을 쓸 때 $$\Theta(n)$$ 분할·병합 비용과 두 하위 문제의 크기를 별도로 적는다. “깊이가 로그”라는 사실만으로 총 시간이 로그가 되지는 않는다.
5. 안정성·평균 시간은 알고리즘 이름만으로 단정하지 말고 **비교 연산자와 피벗 선택 가정**을 확인한다.

## 복습 질문

<details markdown="block">
<summary markdown="span">Q&A: Why is merge sort not just $$O(\log n)$$ if it halves the array?</summary>

답변: 재귀 깊이는 로그이지만, 한 깊이에서 여러 구간을 합친 병합 비용은 $$\Theta(n)$$이다. 깊이별 $$n$$을 $$\Theta(\log n)$$번 더해 $$\Theta(n\log n)$$이 된다.

</details>

<details markdown="block">
<summary>Q&A: When is merge sort stable?</summary>

답변: 양쪽 맨 앞의 키가 같을 때 원래 앞쪽에 있던 왼쪽 원소를 먼저 출력해야 한다. 슬라이드의 `<` 비교는 동점에서 오른쪽을 택해 안정성을 깨뜨릴 수 있고, 이 글의 `<=` 비교는 왼쪽을 택한다. 예컨대 `[(1, A), (1, B)]`가 좌우로 나뉘면 원문 방식은 `B, A` 순서가 될 수 있다.

</details>

<details markdown="block">
<summary>Q&A: Does partition sort either side?</summary>

답변: 아니다. 분할 직후 보장되는 것은 “왼쪽의 모든 값 $$\le$$ 피벗, 오른쪽의 모든 값 $$>$$ 피벗”과 피벗의 최종 위치뿐이다. 양쪽 내부 순서는 재귀 호출이 정렬한다.

</details>

<details markdown="block">
<summary>Q&A: Why can equal keys make this quick sort quadratic?</summary>

답변: 조건이 `<= pivot`이므로 모두 같은 배열에서는 피벗 외의 $$n-1$$개가 전부 왼쪽으로 간다. 매번 크기 $$n-1$$인 하위 문제 하나와 선형 분할 작업이 생겨 $$T(n)=T(n-1)+\Theta(n)=\Theta(n^2)$$이다.

</details>
