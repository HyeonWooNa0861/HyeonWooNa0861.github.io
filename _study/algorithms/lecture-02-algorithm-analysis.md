# Lecture 2: Algorithm Analysis

Source PDF: `02-algorithm-analysis.pdf`

이 글은 국민대학교 Youngwook Kim 교수의 *Algorithms* 2강 자료를 바탕으로, 알고리즘의 효율을 기본 연산 수로 표현하고 이를 점근 표기법으로 해석하는 과정을 자세히 정리한 강의 노트다. 슬라이드의 빈칸형 예제는 사용한 연산 계수 규칙과 가정을 명시해 풀이했으며, 강의에서 직접 다루지 않은 엄밀한 증명 방식이나 흔한 오해는 **작성자 보충**으로 구분했다.

> **핵심:** 알고리즘 분석은 실제 실행 시간을 초 단위로 맞히는 작업이 아니라, **입력 크기 \(n\)이 커질 때 문제 해결에 필요한 기본 연산 수 \(T(n)\)이 어떤 속도로 증가하는지 설명하는 작업**이다. 같은 문제도 알고리즘에 따라 \(\Theta(1)\), \(\Theta(n)\), \(\Theta(n^2)\)처럼 성장률이 달라지며, Big-O·Big-\(\Omega\)·Big-\(\Theta\)는 각각 상한·하한·tight bound를 표현한다.

## 1. 문제와 알고리즘

강의는 **문제(problem)** 를 입력(input)과 출력(output)의 관계로 설명한다. 알고리즘은 그 관계를 실제로 만족시키기 위한 절차나 방법을 공식화한 표현이다. 따라서 알고리즘을 분석하기 전에 먼저 무엇이 입력이고 무엇이 정답인지 분명히 해야 한다.

> **작성자 보충:** 슬라이드는 정렬과 최단 경로의 입력·출력 칸을 학습자가 채우도록 비워 두었다. 아래 명세는 그 빈칸을 대표적인 문제 정의로 완성한 것이다.

### 1.1 정렬 문제

정렬 문제를 다음처럼 명세할 수 있다.

| 항목 | 내용 |
|---|---|
| 입력 | 비교 가능한 \(n\)개의 원소로 이루어진 수열 \((a_1,a_2,\ldots,a_n)\) |
| 출력 | 입력과 같은 원소를 가지며 \(a'_1 \le a'_2 \le \cdots \le a'_n\)을 만족하는 수열 |

입력과 출력만 정했다고 해서 해결 방법까지 하나로 정해지는 것은 아니다. Selection Sort, Merge Sort, Heap Sort처럼 서로 다른 절차가 같은 정렬 결과를 만들 수 있다. 알고리즘 분석은 이 여러 절차를 자원 사용량으로 비교한다.

### 1.2 최단 경로 문제

최단 경로 문제의 한 가지 명세는 다음과 같다.

| 항목 | 내용 |
|---|---|
| 입력 | 가중 그래프 \(G=(V,E)\), 시작 정점 \(s\), 필요하면 도착 정점 \(t\) |
| 출력 | \(s\)에서 \(t\)까지의 경로 가운데 가중치 합이 최소인 경로와 그 비용 |

가중치가 모두 음이 아닌지, 음수 간선이 있는지, 모든 정점까지의 거리가 필요한지에 따라 적합한 알고리즘이 달라진다. 즉 **문제의 입력 조건은 알고리즘 선택과 분석의 전제**다.

> **작성자 보충:** 복잡도에서 쓰는 \(n\)은 보통 입력의 숫자값 자체가 아니라 입력 크기를 나타낸다. 이 강의의 제곱 예제에서는 코드가 정수 \(n\)만큼 반복되므로 \(n\ge 0\)인 반복 횟수로 사용하지만, 일반적인 분석에서는 배열 길이, 정점 수, 간선 수처럼 크기를 명확히 정의해야 한다.

## 2. 좋은 알고리즘과 자원 효율

같은 문제를 해결하는 알고리즘이 여러 개라면, 강의는 한정된 자원을 더 적게 쓰는 알고리즘을 **효율적인 알고리즘**으로 본다.

| 자원 | 의미 | 이 강의에서의 비중 |
|---|---|---|
| Time | 결과를 얻기까지 필요한 실행량 또는 실행 시간 | 주된 분석 대상 |
| Space | 실행 중 필요한 메모리 | 비교 관점으로 소개 |

> **작성자 보충:** 시간과 공간은 항상 동시에 최소화되지 않는다. 계산 결과를 저장해 두면 시간을 줄이는 대신 메모리를 더 쓸 수 있고, 메모리를 아끼기 위해 같은 계산을 반복하면 시간이 늘 수 있다. 따라서 “좋다”는 말은 정답 여부뿐 아니라 **어떤 자원 제약에서 비교하는가**까지 포함한다.

### 2.1 같은 \(n^2\)을 만드는 세 알고리즘

강의는 정수 \(n\)의 제곱을 만드는 세 방법을 비교한다.

```python
# Algorithm 1: n을 n번 더한다.
total = 0
for i in range(0, n):
    total = total + n
```

```python
# Algorithm 2: 1을 n × n번 더한다.
total = 0
for i in range(0, n):
    for j in range(0, n):
        total = total + 1
```

```python
# Algorithm 3: 곱셈을 한 번 사용한다.
total = n * n
```

세 코드는 같은 값을 만들지만 반복 구조는 전혀 다르다. Algorithm 1의 핵심 연산은 \(n\)번, Algorithm 2는 \(n^2\)번, Algorithm 3은 입력 크기와 무관한 상수 횟수로 실행된다.

## 3. 기본 연산으로 \(T(n)\) 만들기

강의는 시간 복잡도 함수 \(T(n)\)을 **입력 \(n\)에 대해 실행되는 기본 연산의 수**로 정의한다. 예로 든 기본 연산은 다음과 같다.

| 연산 종류 | 예시 |
|---|---|
| 산술 연산 | `+`, `-`, `/`, `*` |
| 대입 연산 | `=` |
| 비교 연산 | `<`, `>`, `==` |

정확한 횟수를 세려면 먼저 계수 모델을 정해야 한다. 강의의 제곱 예제는 문제 해결에 직접 기여하는 대입·덧셈·곱셈을 세고, `for`문의 loop variable 증가처럼 반복 제어를 위한 연산은 제외한다.

### 3.1 강의의 계수 규칙으로 세기

| 구분 | Algorithm 1 | Algorithm 2 | Algorithm 3 |
|---|---:|---:|---:|
| 초기 대입 | \(1\) | \(1\) | \(1\) |
| 덧셈 | \(n\) | \(n^2\) | \(0\) |
| 반복문 안 대입 | \(n\) | \(n^2\) | \(0\) |
| 곱셈 | \(0\) | \(0\) | \(1\) |
| 합계 \(T(n)\) | \(2n+1\) | \(2n^2+1\) | \(2\) |

Algorithm 1은 `total = total + n`에서 덧셈 1회와 대입 1회가 매 반복마다 실행되므로 \(2n+1\)이다. Algorithm 2의 같은 두 연산은 이중 반복 때문에 \(n^2\)번 실행되어 \(2n^2+1\)이 된다. Algorithm 3은 곱셈과 대입만 실행하므로 2다.

### 3.2 무엇을 세는지가 달라도 결론은 유지되는가?

> **작성자 보충:** 어떤 교재는 loop variable 증가, 반복 조건 비교, 배열 접근까지 모두 센다. 그러면 정확한 \(T(n)\)의 계수와 상수항은 달라질 수 있다. 그러나 한 모델을 일관되게 적용하면 이 예제의 성장 차수는 각각 선형, 이차, 상수로 유지된다. 점근적 분석이 구현 언어와 세부 계수의 영향을 줄여 주는 이유가 여기에 있다.

정확한 계수와 점근적 차수는 구분해야 한다.

| 질문 | 답의 형태 |
|---|---|
| 강의 규칙으로 기본 연산이 정확히 몇 번 실행되는가? | \(2n+1\), \(2n^2+1\), \(2\) |
| 큰 입력에서 얼마나 빠르게 증가하는가? | \(\Theta(n)\), \(\Theta(n^2)\), \(\Theta(1)\) |

## 4. Best, Worst, Average Case

입력 크기가 같더라도 입력의 내용과 배열 순서에 따라 실행되는 연산 수가 달라질 수 있다. 강의는 순차 탐색(sequential search)으로 이를 설명한다.

```python
def sequential_search(nums, q):
    for i, x in enumerate(nums):
        if x == q:
            return i
    return -1
```

배열 길이를 \(n\)이라 하고, 핵심 연산을 `x == q` 비교로 잡는다.

### 4.1 Best case

찾는 값 \(q\)가 첫 번째 원소라면 비교를 한 번 하고 바로 반환한다.

$$
T_{\mathrm{best}}(n)=1 \in \Theta(1)
$$

### 4.2 Worst case

찾는 값이 마지막 원소에 있거나 배열에 전혀 없다면 모든 원소를 확인한다.

$$
T_{\mathrm{worst}}(n)=n \in \Theta(n)
$$

### 4.3 Average case

> **작성자 보충:** 강의 슬라이드는 average case를 빈칸으로 남겨 둔다. 아래 계산은 **탐색이 성공하고, \(q\)가 \(n\)개 위치 중 어디에 있을 확률도 동일하다**는 가정을 둔 풀이다.

위치가 1번째면 1번, 2번째면 2번, \(n\)번째면 \(n\)번 비교하므로 기대 비교 횟수는 다음과 같다.

$$
\begin{aligned}
T_{\mathrm{avg}}(n)
&= \frac{1+2+\cdots+n}{n} \\
&= \frac{n(n+1)}{2n} \\
&= \frac{n+1}{2}
\end{aligned}
$$

따라서 성공 위치가 균등하다는 가정에서는 average case도 \(\Theta(n)\)이다. 실패 탐색을 포함하거나 위치별 확률이 다르면 기대값 식은 달라진다. **Average case는 입력 분포에 대한 가정 없이 하나의 숫자로 정할 수 없다.**

### 4.4 Case와 점근 표기법은 서로 다른 축이다

> **작성자 보충:** Big-O를 worst case의 다른 이름으로, Big-\(\Omega\)를 best case의 다른 이름으로 외우면 안 된다. Best·worst·average는 **어떤 입력 상황의 \(T(n)\)을 분석하는가**를 정하고, \(O\)·\(\Omega\)·\(\Theta\)는 **그 함수의 성장률을 어떤 bound로 표현하는가**를 정한다.

예를 들어 순차 탐색의 worst-case 함수 \(T_{\mathrm{worst}}(n)=n\)은 동시에 \(O(n)\), \(\Omega(n)\), \(\Theta(n)\)으로 표현할 수 있다. Best-case 함수 \(T_{\mathrm{best}}(n)=1\)은 \(\Theta(1)\)이다.

## 5. 점근적 분석

점근적 분석(asymptotic analysis)은 \(n\)이 충분히 커질 때 \(T(n)\)의 성장 양상을 본다. 정확한 실행 초나 모든 낮은 차수 항을 비교하기보다, 입력 증가에 따라 어느 항이 전체 비용을 지배하는지 찾는다.

### 5.1 최고차항이 지배하는 과정

강의의 예제는 다음 함수다.

$$
T(n)=n^2+n+1
$$

| \(n\) | \(T(n)\) | \(n^2\)이 차지하는 비율 |
|---:|---:|---:|
| 1 | 3 | 약 33.3% |
| 10 | 111 | 약 90% |
| 100 | 10,101 | 약 99% |
| 1,000 | 1,001,001 | 약 99.9% |

\(n\)이 커질수록 \(n\)과 1의 상대적 영향은 줄고 \(n^2\)이 전체 증가를 지배한다. 그래서 점근적 차수는 \(n^2\)으로 요약한다.

상수 계수도 성장 차수를 바꾸지 않는다. \(3n^2\)과 \(100n^2\)은 실제 연산 수는 다르지만 입력이 두 배가 될 때 주된 항이 약 네 배가 된다는 같은 이차 성장 특성을 갖는다.

> **작성자 보충:** 낮은 차수 항과 상수 계수가 실제 실행에서 언제나 무의미하다는 뜻은 아니다. 입력이 작거나 상수가 매우 크거나, cache·I/O·병렬화 같은 구현 차이가 크면 실제 성능 순위가 달라질 수 있다. 점근 표기법은 충분히 큰 입력에서의 **성장률 비교 도구**다.

### 5.2 세 알고리즘의 점근적 결론

| 알고리즘 | 정확한 기본 연산 수 | 지배항 | Tight bound |
|---|---:|---:|---:|
| Algorithm 1 | \(2n+1\) | \(n\) | \(\Theta(n)\) |
| Algorithm 2 | \(2n^2+1\) | \(n^2\) | \(\Theta(n^2)\) |
| Algorithm 3 | \(2\) | \(1\) | \(\Theta(1)\) |

입력 \(n\)이 두 배가 될 때 Algorithm 1의 주된 비용은 약 두 배, Algorithm 2는 약 네 배가 된다. Algorithm 3의 연산 수는 변하지 않는다. 세 방법이 같은 출력을 만든다는 사실만으로는 효율이 같다고 볼 수 없다.

## 6. 성장률의 서열

강의의 수치표는 충분히 큰 \(n\)에서 \(\log n<n<n\log n<n^2<n^3<2^n\) 순으로 증가한다는 점을 보여 준다. 같은 슬라이드의 아래 그래프에는 \(2^n\)보다 빠르게 증가하는 \(n!\)도 함께 표시되어 있다. 상수 함수까지 포함해 정리하면 다음과 같다.

$$
1 < \log n < n < n\log n < n^2 < n^3 < 2^n < n!
$$

> **작성자 보충:** 아래 표의 알고리즘 예시는 각 성장률을 기억하기 위한 전형적인 대응이다. 구체적인 알고리즘은 입력 조건과 구현에 따라 다른 차수를 가질 수 있으므로, 이름만 보고 복잡도를 결정하지 않고 실제 반복·재귀 구조를 분석해야 한다.

| 차수 | 대표적인 직관 | 입력이 커질 때의 특성 |
|---|---|---|
| \(\Theta(1)\) | 인덱스로 한 원소 접근 | 입력 크기와 무관한 상수 작업 |
| \(\Theta(\log n)\) | 탐색 범위를 절반씩 축소 | 입력이 크게 늘어도 증가가 완만함 |
| \(\Theta(n)\) | 모든 원소를 한 번 확인 | 입력 크기에 비례 |
| \(\Theta(n\log n)\) | 효율적인 비교 정렬의 전형적 차수 | 선형보다 크지만 이차보다 작음 |
| \(\Theta(n^2)\) | 모든 원소 쌍을 확인 | 입력 두 배 시 주된 비용 약 네 배 |
| \(\Theta(n^3)\) | 세 겹의 독립 반복 | 입력 두 배 시 주된 비용 약 여덟 배 |
| \(\Theta(2^n)\) | 모든 부분집합 탐색 | 작은 \(n\) 증가도 비용을 크게 키움 |
| \(\Theta(n!)\) | 모든 순열 탐색 | 지수 함수보다도 빠르게 증가 |

슬라이드의 수치표는 \(n=10\)일 때 \(2^n\)이 약 \(10^3\)이지만 \(n=100\)이면 약 \(10^{30}\)으로 커지는 모습을 보여준다. 반면 \(n=1{,}000{,}000\)일 때 \(\log_2 n\)은 약 19.93이며, 슬라이드 표는 이를 정수 19로 표시한다. 성장률의 차이는 입력 규모가 커질수록 압도적으로 벌어진다.

## 7. Big-O: 점근적 상한

강의의 정의를 수식으로 정리하면 다음과 같다.

$$
O(f(n))
=\left\{g(n)\mid \exists c>0,\exists n_0>0,\ g(n)\le c f(n)\text{ for all }n\ge n_0\right\}.
$$

즉 충분히 큰 \(n\)에서 \(g(n)\)이 어떤 양의 상수배 \(cf(n)\)를 넘지 않으면 \(g(n)\in O(f(n))\)이다. \(n_0\)보다 작은 구간은 점근적 판정에서 중요하지 않다.

### 7.1 작성자 보충: 포함을 증명하는 방법

목표는 다음 부등식을 만족하는 구체적인 \(c\)와 \(n_0\)를 하나 찾는 것이다.

$$
T(n)\le c f(n)\qquad(n\ge n_0)
$$

예를 들어 \(T(n)=3n^2+100\)이 \(O(n^2)\)임을 보이자. \(n\ge 10\)이면 \(100\le n^2\)이므로 다음이 성립한다.

$$
3n^2+100\le 3n^2+n^2=4n^2.
$$

따라서 \(c=4\), \(n_0=10\)을 선택할 수 있고, \(3n^2+100\in O(n^2)\)이다.

### 7.2 작성자 보충: 왜 \(n^2\notin O(n)\)인가?

만약 \(n^2\in O(n)\)이라면 충분히 큰 모든 \(n\)에 대해 \(n^2\le cn\)인 고정 상수 \(c\)가 있어야 한다. 양변을 \(n>0\)으로 나누면 \(n\le c\)가 되지만, \(n\)은 어떤 고정된 \(c\)보다도 커질 수 있다. 따라서 그런 상수는 존재하지 않는다.

## 8. Big-\(\Omega\): 점근적 하한

Big-\(\Omega\)는 충분히 큰 입력에서 함수가 적어도 어느 정도 빠르게 증가하는지를 나타낸다.

$$
\Omega(f(n))
=\left\{g(n)\mid \exists c>0,\exists n_0>0,\ g(n)\ge c f(n)\text{ for all }n\ge n_0\right\}.
$$

증명하려면 다음을 만족하는 \(c\)와 \(n_0\)를 찾는다.

$$
T(n)\ge c f(n)\qquad(n\ge n_0)
$$

> **작성자 보충:** 다음은 슬라이드에 제시된 포함·비포함 예제를 실제 상수와 부등식으로 전개한 증명이다.

\(T(n)=3n^2+100\)에 대해 \(n\ge1\)이면 \(3n^2+100\ge3n^2\)이므로 \(c=3\), \(n_0=1\)을 선택할 수 있다. 따라서 \(3n^2+100\in\Omega(n^2)\)이다.

반면 \(n\notin\Omega(n^2)\)이다. \(n\ge cn^2\)이려면 \(1\ge cn\)이어야 하는데, 양의 고정 상수 \(c\)에 대해 이 부등식은 충분히 큰 모든 \(n\)에서 유지될 수 없다.

## 9. Big-\(\Theta\): 점근적으로 tight한 bound

강의는 Big-\(\Theta\)를 Big-O와 Big-\(\Omega\)의 교집합으로 정의한다.

$$
\Theta(f(n))=O(f(n))\cap\Omega(f(n)).
$$

동일한 내용을 두 상수로 쓰면 다음과 같다.

> **작성자 보충:** 아래의 양쪽 부등식은 슬라이드의 교집합 정의를 증명에 바로 사용할 수 있도록 풀어 쓴 동치 형태다.

$$
\Theta(f(n))
=\left\{g(n)\mid \exists c_1,c_2>0,\exists n_0>0,\ c_1f(n)\le g(n)\le c_2f(n)\text{ for all }n\ge n_0\right\}.
$$

상한과 하한이 같은 \(f(n)\)으로 잡히므로 \(\Theta\)는 함수의 점근적 차수를 tight하게 표현한다.

### 9.1 세 표기법 비교

| 표기 | 필요한 부등식 | 의미 |
|---|---|---|
| \(T(n)\in O(f(n))\) | \(T(n)\le cf(n)\) | 점근적 상한 |
| \(T(n)\in\Omega(f(n))\) | \(T(n)\ge cf(n)\) | 점근적 하한 |
| \(T(n)\in\Theta(f(n))\) | \(c_1f(n)\le T(n)\le c_2f(n)\) | 상한과 하한이 일치하는 tight bound |

### 9.2 작성자 보충: \(2n+1\in\Theta(n)\) 증명

\(n\ge1\)일 때 다음 두 부등식이 성립한다.

$$
2n\le2n+1\le3n.
$$

하한은 \(c_1=2\), 상한은 \(c_2=3\), 기준점은 \(n_0=1\)로 잡을 수 있다. 따라서 \(2n+1\in\Theta(n)\)이다.

같은 방식으로 \(2n^2+1\in\Theta(n^2)\), \(2\in\Theta(1)\)을 보일 수 있다.

## 10. Tight bound를 선택해야 하는 이유

상한과 하한은 하나만 존재하지 않는다. 예를 들어 \(2n+1\)은 \(O(n)\)이면서 \(O(n^2)\), \(O(n^3)\)이기도 하다. 또한 \(\Omega(n)\)이면서 \(\Omega(1)\)이기도 하다. 모두 참이지만 정보량은 다르다.

| 함수 | 참이지만 느슨한 표현 | 가장 유용한 tight 표현 |
|---|---|---|
| \(2n+1\) | \(O(n^2)\), \(\Omega(1)\) | \(\Theta(n)\) |
| \(2n^2+1\) | \(O(n^3)\), \(\Omega(n)\) | \(\Theta(n^2)\) |
| \(2\) | \(O(n)\) | \(\Theta(1)\) |

강의에서 “upper bound와 lower bound를 tight하게 잡아야 한다”는 말은 단지 참인 넓은 집합을 고르는 데 그치지 말고, 실제 성장률을 가장 정확하게 나타내라는 뜻이다.

## 11. Practice 풀이

강의 마지막의 세 코드 조각을 같은 계수 규칙으로 분석한다.

> **작성자 보충:** 슬라이드는 문제만 제시하고 정답을 표시하지 않는다. 아래 풀이는 앞에서 사용한 계수 모델을 유지하되, 표기 관례가 달라도 점근적 결론이 보존되는 지점을 함께 설명한다.

### 11.1 Example 1: 한 번의 대입

```c
a = b;
```

대입 연산 한 번이므로 입력 크기와 무관하다.

$$
T(n)=1\in\Theta(1)
$$

### 11.2 Example 2: 한 겹 반복문

```c
sum = 0;
for (i = 0; i < n; i++)
    sum += n;
```

강의의 규칙에 따라 반복 제어 연산을 제외하고 `sum += n`을 덧셈과 대입으로 각각 한 번씩 세면, 초기 대입 1회와 반복당 2회가 있다.

$$
T(n)=1+2n\in\Theta(n)
$$

### 11.3 Example 3: 삼각형 반복과 독립 반복

```c
for (j = 1; j <= n; j++)
    for (i = 1; i <= j; i++)
        sum++;

for (k = 0; k < n; k++)
    A[k] = k;
```

첫 번째 중첩 반복에서 안쪽 문장은 \(j\)번 실행된다. 전체 실행 횟수는 다음 삼각수다.

$$
1+2+\cdots+n=\frac{n(n+1)}{2}.
$$

두 번째 반복의 대입은 \(n\)번 실행된다. 강의처럼 반복 제어 연산을 제외하고 `sum++`을 한 번의 갱신으로 세면 다음과 같다.

$$
T(n)=\frac{n(n+1)}{2}+n\in\Theta(n^2)
$$

`sum++`을 덧셈과 대입의 두 연산으로 나누어 세면 삼각수 부분이 두 배가 된다.

$$
T(n)=n(n+1)+n=n^2+2n\in\Theta(n^2)
$$

따라서 정확한 계수는 달라져도 이차 성장이라는 결론은 같다.

## 12. 작성자 보충: 분석 절차를 하나의 루틴으로 만들기

코드를 보자마자 Big-O부터 추측하기보다 다음 순서를 따르면 실수를 줄일 수 있다.

1. **입력 크기를 정의한다.** 배열 길이인지, 정점 수와 간선 수인지 명확히 적는다.
2. **기본 연산을 선택한다.** 비교, 대입, 산술 연산 가운데 문제 해결을 대표하는 연산을 정한다.
3. **실행 횟수를 센다.** 순차문은 더하고, 독립된 중첩 반복은 곱하고, 범위가 변하는 반복은 합으로 쓴다.
4. **case를 구분한다.** 입력 내용에 따라 경로가 달라지면 best, worst, average를 각각 정의한다.
5. **정확한 \(T(n)\)을 만든다.** 가능한 경우 계수와 상수항까지 적는다.
6. **지배항을 찾는다.** 충분히 큰 \(n\)에서 가장 빠르게 증가하는 항을 선택한다.
7. **bound를 증명한다.** 필요한 경우 \(c\), \(n_0\) 또는 \(c_1\), \(c_2\), \(n_0\)를 제시한다.
8. **tight한 표기를 선택한다.** 단순히 참인 Big-O보다 실제 차수를 보여 주는 Big-\(\Theta\)를 우선 확인한다.

## 13. 작성자 보충: Common Pitfalls

| 흔한 실수 | 올바른 이해 |
|---|---|
| Big-O는 항상 worst case다. | Case 선택과 bound 표기는 다른 축이다. Worst-case 함수에도 \(O\), \(\Omega\), \(\Theta\)를 모두 적용할 수 있다. |
| Big-\(\Omega\)는 항상 best case다. | Big-\(\Omega\)는 선택한 함수의 점근적 하한이다. |
| Average case는 best와 worst의 단순 평균이다. | 입력마다 발생할 확률을 반영한 기대값이며 확률 분포 가정이 필요하다. |
| \(O(n^2)\)라고 쓰면 정확한 차수가 이차다. | 선형 함수도 \(O(n^2)\)에 포함된다. 정확한 이차 성장은 \(\Theta(n^2)\)로 표현한다. |
| 반복문이 두 개 보이면 무조건 \(n^2\)이다. | 순차 반복은 비용을 더하고, 중첩 범위와 실행 조건을 따로 계산해야 한다. |
| 상수와 낮은 차수 항은 실제 성능에도 전혀 중요하지 않다. | 점근적 성장률에서는 제거하지만 실제 작은 입력과 구현에서는 영향을 줄 수 있다. |
| 연산 계수 방식은 하나뿐이다. | 분석 목적에 맞는 모델을 정하고 일관되게 적용하는 것이 중요하다. |

## 14. 다음 강의 연결: Recurrence

슬라이드는 다음 강의 주제로 **Recurrence(재귀, 점화식)** 를 예고한다. 이번 강의에서는 반복 횟수를 직접 세어 \(T(n)\)을 만들었지만, 재귀 알고리즘은 자기 자신을 호출하므로 전체 비용을 더 작은 입력의 비용과 연결해 표현해야 한다.

> **작성자 보충:** 예를 들어 입력을 절반으로 줄이는 재귀는 \(T(n)=T(n/2)+c\), 같은 문제를 두 개 만들고 선형 결합 비용을 쓰는 재귀는 \(T(n)=2T(n/2)+cn\) 같은 형태로 나타낼 수 있다. 다음 단계에서는 이런 점화식을 풀어 이번 강의에서 배운 Big-O·Big-\(\Omega\)·Big-\(\Theta\)로 성장률을 표현하게 된다.

## 마지막 핵심 정리

1. **알고리즘은 입력과 출력의 관계를 해결하는 공식화된 절차다.** 같은 문제에도 서로 다른 알고리즘이 존재할 수 있다.
2. **효율은 자원 사용량으로 비교한다.** 이 강의는 시간, 즉 기본 연산 수를 중심으로 본다.
3. **\(T(n)\)은 계수 모델에 따라 정확한 식이 달라질 수 있다.** 그러나 일관된 모델에서는 주된 성장 차수가 유지된다.
4. **순차 탐색은 같은 길이의 배열에서도 case가 달라진다.** Best는 1회, worst는 \(n\)회이며, 성공 위치가 균등하면 average는 \((n+1)/2\)회 비교다.
5. **점근적 분석은 큰 입력에서 지배항을 본다.** \(n^2+n+1\)은 \(n^2\)이 전체 성장을 지배한다.
6. **Big-O는 상한, Big-\(\Omega\)는 하한, Big-\(\Theta\)는 tight bound다.** Case와 bound를 혼동하지 않는다.
7. **참인 bound 중에서도 가장 tight한 표현이 유용하다.** \(2n+1\)은 \(O(n^2)\)이기도 하지만 핵심 결론은 \(\Theta(n)\)이다.
8. **반복 횟수는 구조에서 도출한다.** 독립된 \(n\times n\) 중첩은 \(n^2\), \(1+2+\cdots+n\) 형태도 \(\Theta(n^2)\)이다.

## Study Guide

시험 대비 우선순위는 다음 네 가지다.

1. **Operation counting:** 세 제곱 알고리즘의 빈 표를 직접 채워 \(2n+1\), \(2n^2+1\), 2를 재현한다.
2. **Case assumptions:** 순차 탐색의 best와 worst를 즉시 구하고, average에는 성공 여부와 위치 확률에 관한 가정이 필요하다고 적는다.
3. **Formal proof:** \(3n^2+100\) 같은 식에 실제 \(c\)와 \(n_0\)를 제시해 상한·하한을 각각 증명한다.
4. **Tightness:** 참이지만 느슨한 \(O(n^2)\)와 실제 차수를 드러내는 \(\Theta(n)\)을 구분한다.

마지막으로 아래 세 문장을 빈 종이에 재현해 부등식 방향을 확인한다.

1. \(T(n)\in O(f(n))\)이면 충분히 큰 \(n\)에서 \(T(n)\le cf(n)\)이다.
2. \(T(n)\in\Omega(f(n))\)이면 충분히 큰 \(n\)에서 \(T(n)\ge cf(n)\)이다.
3. \(T(n)\in\Theta(f(n))\)이면 충분히 큰 \(n\)에서 \(c_1f(n)\le T(n)\le c_2f(n)\)이다.

</details>

<details>
<summary>2. 순차 탐색의 average 비교 횟수가 \((n+1)/2\)이 되려면 어떤 가정이 필요한가?</summary>

답변: 탐색이 성공하고, 찾는 값이 \(n\)개 위치 중 어느 위치에 있을 확률도 동일하다고 가정해야 한다. 실패 가능성이나 위치별 확률이 다르면 기대 비교 횟수도 달라진다.

</details>

<details>
<summary>3. Big-O를 worst case와 같은 뜻으로 사용하면 왜 잘못인가?</summary>

답변: Worst case는 입력 크기 \(n\)에서 가장 많은 연산을 요구하는 입력을 골라 함수 \(T_{\mathrm{worst}}(n)\)을 정의하는 방법이다. Big-O는 이미 선택한 함수의 점근적 상한을 표현하는 표기다. Worst-case 함수뿐 아니라 best-case나 average-case 함수에도 Big-O를 적용할 수 있다.

</details>

<details>
<summary>4. \(3n^2+100\in O(n^2)\)임을 보이는 \(c\)와 \(n_0\)의 한 예를 제시하라.</summary>

답변: \(n\ge10\)이면 \(100\le n^2\)이므로 \(3n^2+100\le4n^2\)이다. 따라서 \(c=4\), \(n_0=10\)을 선택할 수 있다. 가능한 상수 조합은 하나로 정해지지 않는다.

</details>

<details>
<summary>5. \(2n+1\)이 \(O(n^2)\)이면서도 보통 \(\Theta(n)\)으로 쓰이는 이유는 무엇인가?</summary>

답변: \(O(n^2)\)은 참이지만 느슨한 상한이라 실제 선형 성장 정보를 잃는다. \(2n+1\)은 위와 아래에서 모두 \(n\)의 상수배로 묶을 수 있으므로 \(\Theta(n)\)이 더 tight하고 유용한 표현이다.

</details>

<details>
<summary>6. 순차로 놓인 두 반복문과 중첩된 두 반복문의 비용을 어떻게 구분하는가?</summary>

답변: 순차로 실행되는 반복문은 각각의 비용을 더한다. 각자 \(n\)번 실행되면 \(n+n=2n\)이므로 \(\Theta(n)\)이다. 한 반복문 안에서 다른 반복문이 매번 \(n\)번 실행되면 \(n\times n=n^2\)이므로 \(\Theta(n^2)\)이다. 단, 반복 범위가 서로 의존하면 실제 합을 계산해야 한다.

</details>

<details>
<summary>7. \(1+2+\cdots+n\)번 실행되는 문장의 시간 복잡도는 무엇이며 왜 그런가?</summary>

답변: 합은 \(n(n+1)/2=(n^2+n)/2\)이므로 최고차항이 \(n^2\)이다. 상수 계수와 낮은 차수 항을 제거하면 tight bound는 \(\Theta(n^2)\)이다.

</details>

<details>
<summary>8. 반복 제어 연산을 세는 분석과 세지 않는 분석의 \(T(n)\)이 달라도 둘 다 유효할 수 있는 이유는 무엇인가?</summary>

답변: 정확한 연산 수는 어떤 연산을 기본 단위로 정했는지에 의존한다. 계수 모델을 먼저 밝히고 전체 코드에 일관되게 적용했다면 비교가 가능하다. 일반적으로 반복 제어를 추가해도 상수 계수와 낮은 차수 항만 달라져 점근적 차수는 유지된다.

</details>
