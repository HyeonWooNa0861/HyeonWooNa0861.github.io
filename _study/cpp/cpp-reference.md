## 1. 참조란?

참조(reference)는 기존 변수에 붙는 **별명(alias)** 이다.

```cpp
int x = 42;

int* p = &x; // 포인터: x의 주소 저장
int& r = x;  // 참조: x의 별명
```

사용 비교:

```cpp
printf("%d\n", *p); // 포인터는 역참조 필요
printf("%d\n", r);  // 참조는 변수처럼 직접 사용
```

`r`은 새로운 값을 담는 독립 변수가 아니라 `x`의 다른 이름이다.

## 2. 참조의 규칙

참조는 반드시 선언과 동시에 초기화해야 한다.

```cpp
int x = 10;
int& r = x; // 가능

// int& r2; // 오류
```

또한 일반 참조에는 null 참조가 없다.

```cpp
int* p = nullptr; // 가능
// int& r = ???; // null 참조 개념 없음
```

참조는 항상 유효한 대상을 가리키도록 강제되는 문법이다.

## 3. 참조와 포인터 비교

| 항목 | 포인터 `int* p` | 참조 `int& r` |
|---|---|---|
| 초기화 | 선언 후 대입 가능 | 선언 시 필수 |
| null 가능성 | `nullptr` 가능 | 불가능 |
| 재지정 | `p = &y` 가능 | 불가능 |
| 값 접근 | `*p` 필요 | `r`로 직접 접근 |
| 주소 접근 | `p` 자체가 주소 | `&r`은 원본 주소 |
| 포인터 연산 | `p++`, `p + n` 가능 | 불가능 |

참조는 포인터보다 문법이 단순하지만, null이나 재지정이 필요할 때는 포인터를 사용해야 한다.

## 4. 함수 인자 전달

C 스타일에서는 원본을 수정하려면 포인터를 전달한다.

```cpp
void swap(int* a, int* b) {
    int tmp = *a;
    *a = *b;
    *b = tmp;
}
```

C++에서는 참조를 사용해 더 자연스럽게 쓸 수 있다.

```cpp
void swap(int& a, int& b) {
    int tmp = a;
    a = b;
    b = tmp;
}
```

호출:

```cpp
swap(x, y);
```

참조 전달은 포인터처럼 원본을 수정할 수 있지만, 함수 내부에서 `*a`처럼 역참조할 필요가 없다.

## 5. const 참조

`const T&`는 원본을 복사하지 않고 읽기 전용으로 참조한다.

```cpp
const int& r = x;
```

읽기는 가능하지만 수정은 불가능하다.

```cpp
printf("%d\n", r);
// r = 10; // 오류
```

크기가 큰 객체를 함수에 전달할 때는 `const T&`가 자주 쓰인다.

```cpp
void print(const std::string& s) {
    printf("%s\n", s.c_str());
}
```

이 방식은 복사를 피하면서도 함수가 원본을 바꾸지 않는다는 보장을 제공한다.

## 6. 참조 반환

참조를 반환하면 함수 호출 결과를 통해 원본을 직접 다룰 수 있다.

```cpp
int g_value = 10;

int& get_value() {
    return g_value;
}

get_value() = 20;
```

하지만 지역 변수의 참조를 반환하면 안 된다.

```cpp
int& danger() {
    int local = 10;
    return local; // 절대 금지
}
```

`local`은 함수가 끝나면 사라지므로, 반환된 참조는 더 이상 유효하지 않은 대상을 가리키게 된다.

## 7. 언제 참조를 쓰고 언제 포인터를 쓰는가?

| 상황 | 권장 |
|---|---|
| 함수에서 원본을 반드시 수정 | `void f(T& x)` |
| 큰 객체를 읽기 전용 전달 | `void f(const T& x)` |
| 인자가 없을 수도 있음 | `void f(T* p)` |
| 다른 대상을 다시 가리켜야 함 | 포인터 |
| 배열 순회나 포인터 연산 필요 | 포인터 |

참조는 “항상 유효한 대상이 있다”는 전제를 표현하기 좋고, 포인터는 “없을 수도 있다” 또는 “대상이 바뀔 수 있다”는 전제를 표현하기 좋다.

## 마지막 핵심 정리

| 개념 | 꼭 기억할 점 |
|---|---|
| 참조 | 기존 변수의 별명 |
| 초기화 | 선언과 동시에 해야 한다. |
| null | 일반 참조에는 null이 없다. |
| 재지정 | 참조는 다른 대상을 다시 가리킬 수 없다. |
| 함수 인자 | 원본 수정이나 큰 객체 전달에 유용하다. |
| const 참조 | 복사를 피하면서 읽기 전용 보장을 제공한다. |
| 참조 반환 | 지역 변수 참조 반환은 금지다. |

참조는 C++에서 포인터보다 안전하고 읽기 쉬운 원본 접근 방법이다. 단, null 가능성이나 재지정이 필요한 상황에서는 포인터가 더 적합하다.

## Study Guide

참조는 "주소를 직접 다루지 않는 원본 접근"으로 이해하면 좋다. 포인터는 `nullptr`일 수 있고 다른 대상을 다시 가리킬 수 있지만, 일반 참조는 반드시 어떤 객체의 별명으로 시작하고 대상이 바뀌지 않는다.

함수 인자에서 참조가 중요한 이유는 복사 비용과 원본 수정 여부를 표현하기 때문이다. `T&`는 원본을 수정할 수 있음을 나타내고, `const T&`는 복사를 피하면서 읽기만 하겠다는 의미를 준다. 큰 객체를 함수에 넘길 때 이 차이를 분명히 이해해야 한다.

참조 반환은 특히 조심해야 한다. 전역 변수, static 변수, 객체 내부 멤버처럼 함수가 끝난 뒤에도 살아 있는 대상은 참조로 반환할 수 있지만, 지역 변수는 함수 종료와 함께 사라지므로 절대 참조로 반환하면 안 된다.

## 복습 질문

<details>
<summary>1. 참조(reference)는 포인터와 달리 어떤 특징을 가지는가?</summary>

답변: 참조는 기존 변수의 별명이며 반드시 선언과 동시에 초기화해야 한다. 일반 참조는 null이 될 수 없고, 한 번 어떤 대상을 참조하면 다른 대상으로 다시 바꿀 수 없다.

</details>

<details>
<summary>2. 큰 객체를 함수에 전달할 때 `const T&`를 자주 쓰는 이유는 무엇인가?</summary>

답변: 객체 복사를 피하면서도 함수가 원본을 수정하지 못하게 보장할 수 있기 때문이다. 그래서 `std::string`, 큰 구조체, 클래스 객체를 읽기 전용으로 전달할 때 유용하다.

</details>

<details>
<summary>3. 지역 변수의 참조를 반환하면 안 되는 이유는 무엇인가?</summary>

답변: 지역 변수는 함수가 끝나면 사라진다. 그 변수의 참조를 반환하면 이미 수명이 끝난 대상을 가리키는 dangling reference가 되어 정의되지 않은 동작을 일으킬 수 있다.

</details>
