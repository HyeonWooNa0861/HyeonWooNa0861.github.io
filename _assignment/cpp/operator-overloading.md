# 연산자 오버로딩

Source PDF: `Operator Overloading.pdf`

## 과제 개요

이 과제는 C++의 연산자 오버로딩을 Python의 특수 메서드와 비교하며 정리한 내용이다. 연산자 오버로딩은 사용자가 정의한 타입도 기본 타입처럼 자연스럽게 연산할 수 있도록 만드는 기능이다. C++에서는 연산자를 함수 호출로 해석하고, Python에서는 `__add__`, `__eq__`, `__getitem__` 같은 특수 메서드를 통해 연산 동작을 정의한다.

두 언어 모두 객체에 자연스러운 연산 의미를 부여한다는 공통점이 있다. 다만 C++은 컴파일 시점의 타입, 참조, 값 범주, 암시적 변환을 강하게 고려하고, Python은 런타임의 동적 디스패치와 프로토콜 중심 설계를 따른다.

## 1. 산술 연산자

C++에서 산술 연산자는 멤버 함수 또는 비멤버 함수로 구현할 수 있다. 멤버 함수 방식에서는 왼쪽 피연산자가 항상 현재 객체인 `*this`가 된다. 따라서 `a + b`는 `a.operator+(b)`처럼 해석된다.

멤버 함수 방식은 구현이 단순하고 private 멤버에 접근하기 쉽다. 하지만 왼쪽 피연산자가 사용자 정의 타입이 아닐 때는 사용할 수 없다. 예를 들어 `1.0 + complex`처럼 기본 타입이 왼쪽에 오는 경우 멤버 함수만으로는 처리하기 어렵다.

비멤버 함수 방식은 두 피연산자를 모두 매개변수로 받는다. 이 방식은 `double + Complex`처럼 왼쪽 피연산자가 기본 타입인 경우에도 대응하기 쉽다. private 멤버 접근이 필요하면 `friend`로 선언할 수 있다.

Python에서는 `a + b`가 먼저 `a.__add__(b)`를 호출하고, 왼쪽 객체가 처리하지 못하면 오른쪽 객체의 reflected method인 `b.__radd__(a)`를 시도한다. C++에는 `__radd__`와 완전히 같은 별도 프로토콜은 없지만, 비멤버 연산자 오버로드를 피연산자 순서에 맞게 제공해 비슷한 사용성을 만들 수 있다.

## 2. 복합 대입 연산자

C++에서 `operator+=`는 보통 현재 객체를 직접 수정한 뒤 `*this`를 참조로 반환한다. 반환 타입을 참조로 두는 이유는 `a += b += c` 같은 체이닝을 가능하게 하고, 불필요한 복사를 줄이기 위해서이다.

`operator+=`를 구현한다고 해서 `operator+`가 자동으로 생기지는 않는다. 두 연산자는 별도로 정의해야 한다. 다만 일반적으로 `operator+` 내부에서 `operator+=`를 재사용해 중복을 줄인다.

Python에서는 `a += b`가 먼저 `a.__iadd__(b)`를 호출한다. `__iadd__`가 없거나 `NotImplemented`를 반환하면 `__add__` 또는 `__radd__`를 사용한 뒤 이름을 새 객체에 다시 바인딩한다. 따라서 Python의 `+=`는 객체가 mutable인지 immutable인지에 따라 실제 동작이 달라진다.

## 3. 비교, 단항, 첨자 연산자

C++20 이전에는 `operator==`를 정의해도 `operator!=`가 자동으로 생기지 않았다. C++20부터는 비교 연산자 재작성 규칙과 `<=>` 연산자가 도입되어 비교 연산을 더 일관적으로 만들 수 있다. Python에서는 `__eq__`만 정의해도 일반적으로 `!=`가 그 결과를 부정하는 방식으로 동작한다.

단항 연산자는 C++에서 매개변수 개수로 이항 연산자와 구분된다. 예를 들어 단항 `operator-()`는 매개변수가 없고, 이항 `operator-(const T& rhs)`는 오른쪽 피연산자를 받는다. Python은 `__neg__`, `__pos__`, `__invert__`처럼 이름이 명확히 분리되어 있다.

C++의 첨자 연산자는 `operator[]`로 구현한다. 읽기와 쓰기가 별도의 함수로 분리되는 것이 아니라, 반환 타입이 참조인지 값인지, 객체가 const인지에 따라 쓰기 가능성이 결정된다. Python은 `obj[index]`를 읽을 때 `__getitem__`, `obj[index] = value`를 수행할 때 `__setitem__`을 호출하므로 읽기와 쓰기 프로토콜이 명확히 나뉜다.

## 4. 함수 호출 연산자와 람다

C++에서 `operator()`를 구현한 객체는 함수처럼 호출할 수 있다. 이런 객체를 함수 객체 또는 functor라고 부른다. 함수 객체는 일반 함수와 달리 멤버 변수를 가질 수 있어, 상태를 보관하면서 함수 호출 문법으로 실행될 수 있다.

C++ 람다도 내부적으로는 호출 연산자를 가진 익명 함수 객체에 가깝다. 캡처 목록을 사용하면 람다 바깥의 지역 변수를 람다 내부에 저장하거나 참조할 수 있다. Python에서도 `__call__`을 구현하면 객체를 함수처럼 호출할 수 있으며, 람다는 함수 객체를 생성한다는 점에서 C++ 람다와 개념적으로 연결된다.

## 5. 출력 연산자와 문자열 표현

C++에서 `std::ostream`에 대한 출력 연산자는 일반적으로 비멤버 함수로 정의한다. `cout << f`에서 왼쪽 피연산자는 `std::ostream`이므로, 사용자 정의 타입의 멤버 함수로 만들면 자연스러운 출력 문법을 만들 수 없다. 그래서 `operator<<`는 보통 비멤버 함수로 구현하고, 필요한 경우 `friend`를 사용한다.

반환 타입을 `std::ostream&`로 두는 이유는 체이닝 때문이다. `cout << a << b`는 `(cout << a) << b`처럼 이어지므로 첫 번째 출력 결과가 다시 스트림 참조를 반환해야 한다.

Python에서는 `__str__`와 `__repr__`이 객체의 문자열 표현을 담당한다. C++의 `operator<<`는 출력 대상인 스트림에 직접 내용을 기록하지만, Python의 `__str__`와 `__repr__`은 문자열을 반환할 뿐 실제 출력 대상은 `print`, f-string, 파일 객체 등이 결정한다.

## 6. bool 변환과 C++에만 있는 연산자

C++에서는 `operator bool()`을 구현해 객체의 truth value를 정의할 수 있다. 보통 `explicit`을 붙여 의도하지 않은 암시적 변환을 막는다. Python에서는 `__bool__`이 truth value를 정의하고, `__bool__`이 없으면 `__len__` 결과가 0인지 여부로 판단하는 규칙이 있다.

C++에는 Python에서 같은 방식으로 오버로딩할 수 없는 연산자도 있다. 예를 들어 `++`, `--`, `->`, `&&`, `||`, `new`, `delete`는 Python의 연산자 오버로딩 대상과 직접 대응되지 않는다. Python은 증가/감소 연산자를 별도로 두지 않고, 논리 연산 `and`, `or`는 단락 평가를 보존해야 하므로 사용자 정의 오버로딩 대상으로 제공하지 않는다.

## 7. Fraction 구현 정리

과제에서는 C++과 Python으로 `Fraction` 클래스를 구현했다. 두 구현 모두 분모가 0이면 예외를 발생시키고, 생성과 연산 후에는 항상 기약분수 상태를 유지한다. 또한 분모는 양수로 저장하고, 산술 연산, 복합 대입, 비교, bool 변환, 첨자 접근, 문자열 출력을 제공한다.

C++ 구현에서는 `<numeric>` 헤더의 `std::gcd`를 사용해 분수를 약분했다. Python 구현에서는 `math.gcd`를 사용했다. 두 언어 모두 표준 라이브러리의 gcd 함수를 사용함으로써 “분모는 양수이고 분자와 분모는 서로소”라는 불변식을 쉽게 유지할 수 있었다.

실행 결과는 `1/2 + 1/3 = 5/6`, `1/2 * 1/3 = 1/6`, `1/2 == 1/2 : true/True`, `a += b : 5/6`처럼 두 언어에서 같은 수학적 의미를 보여준다. 다만 C++은 `std::boolalpha`를 사용하면 `true`, `false`로 출력되고, Python은 기본 문자열 표현이 `True`, `False`이다.

## 결론 및 학습 성과

연산자 오버로딩은 사용자 정의 타입을 더 자연스럽게 표현할 수 있게 해 주지만, 의미가 직관적일 때만 효과적이다. `Fraction`처럼 수학적 의미가 분명한 타입에서는 `+`, `*`, `==`, `[]`, `<<` 같은 연산자가 코드 가독성을 높인다.

반면 연산자의 의미가 모호한 타입에 남용하면 오히려 코드를 읽기 어려워질 수 있다. C++은 타입 안정성과 세밀한 제어를 중시하고, Python은 객체 프로토콜의 일관성과 표현력을 중시한다. 두 언어의 차이를 비교하면서 연산자 오버로딩은 문법을 꾸미는 기능이 아니라 타입의 의미를 설계하는 도구라는 점을 정리할 수 있었다.
