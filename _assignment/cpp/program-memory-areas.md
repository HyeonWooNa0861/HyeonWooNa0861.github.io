# 프로그램 메모리 영역

## 과제 개요

이 과제는 C++ 프로그램이 실행될 때 메모리가 어떤 영역으로 나뉘어 관리되는지 정리한 내용이다. 핵심 주제는 Code, Data, Stack, Heap 영역의 역할과 차이이며, Stack과 Heap이 서로 반대 방향으로 확장되는 이유, 메모리 단편화, 메모리 누수와 해결 방법까지 함께 다룬다.

## 1. 프로그램 메모리 영역

C++ 프로그램의 메모리는 일반적으로 Code, Data, Stack, Heap 영역으로 구분된다. Code 영역은 컴파일된 기계어 명령을 저장하는 공간이며, 프로그램 실행 중 내용이 바뀌지 않는 읽기 전용 영역으로 취급된다.

Data 영역은 전역 변수와 `static` 변수를 저장한다. 초기값이 있는 데이터는 Initialized Data 영역에 저장되고, 초기값이 없는 데이터는 BSS 영역에 저장되며 보통 0으로 초기화된다.

Stack 영역은 함수 호출과 함께 생성되는 지역 변수, 매개변수, 반환 주소 등을 저장한다. LIFO 구조로 동작하며, 함수가 종료되면 해당 함수의 스택 프레임이 자동으로 제거된다. 관리가 빠르고 단순하지만 크기에 제한이 있다.

Heap 영역은 `new`나 `malloc`처럼 실행 중 동적으로 할당되는 메모리를 저장한다. 필요한 만큼 유동적으로 사용할 수 있지만, 프로그래머가 직접 해제해야 하므로 메모리 누수나 잘못된 해제 문제가 발생할 수 있다.

## 2. Stack과 Heap의 확장 방향

Stack과 Heap은 보통 서로 반대 방향으로 확장된다. Stack은 높은 주소에서 낮은 주소 방향으로 커지고, Heap은 낮은 주소에서 높은 주소 방향으로 확장된다. 이렇게 설계하면 두 영역이 같은 메모리 공간을 효율적으로 나누어 사용할 수 있다.

두 영역이 서로 마주 보며 확장되면 실제 실행 중 필요한 만큼 공간을 사용할 수 있고, 어느 한쪽이 지나치게 커져 충돌할 경우 overflow를 감지할 수 있다. 즉, 고정된 크기를 미리 나누기보다 실행 상황에 따라 유연하게 메모리를 활용하기 위한 구조라고 볼 수 있다.

## 3. 메모리 단편화

메모리 단편화는 할당과 해제가 반복되면서 메모리 공간이 비효율적으로 사용되는 현상이다. 내부 단편화는 필요한 크기보다 큰 블록이 할당되어 블록 내부에 남는 공간이 생기는 경우이다. 예를 들어 10바이트만 필요하지만 16바이트 블록이 할당되면 6바이트가 낭비된다.

외부 단편화는 전체 여유 공간은 충분하지만 연속된 공간이 부족해서 큰 메모리 블록을 할당할 수 없는 경우이다. Heap에서 다양한 크기의 메모리를 반복적으로 할당하고 해제할 때 주로 발생한다.

Paging은 메모리를 고정 크기 페이지와 프레임으로 나누어 외부 단편화를 줄인다. 다만 프로세스 크기가 페이지 크기의 배수가 아니면 마지막 페이지 내부에 남는 공간이 생겨 내부 단편화가 발생할 수 있다. Segmentation은 코드, 데이터, 스택처럼 논리적 단위로 메모리를 나누는 방식이며 구조를 이해하기 쉽지만 외부 단편화가 발생할 수 있다.

## 4. 메모리 누수와 해결 방법

메모리 누수는 동적으로 할당한 메모리를 해제하지 않아 더 이상 사용할 수 없는 상태로 남는 현상이다. C/C++에서는 `malloc`으로 할당한 메모리에 `free`를 호출하지 않거나, `new`로 만든 객체를 `delete`하지 않으면 누수가 발생할 수 있다.

메모리 누수를 줄이는 대표적인 방법에는 Garbage Collection과 Smart Pointer가 있다. Garbage Collection은 사용되지 않는 객체를 자동으로 탐지해 제거하는 방식이며 Java, Python 같은 언어에서 주로 사용된다. 안전성이 높지만 런타임 오버헤드가 생길 수 있다.

C++에서는 `std::unique_ptr`, `std::shared_ptr` 같은 Smart Pointer를 사용해 RAII 방식으로 자원을 관리할 수 있다. 객체의 수명이 끝나면 소멸자가 자동으로 호출되어 메모리가 해제되므로, 수동 `delete`에 비해 안전하고 예외 상황에서도 자원 누수를 줄일 수 있다.

## 5. 핵심 정리

- 프로그램 메모리는 Code, Data, Stack, Heap 영역으로 나뉜다.
- Stack은 함수 호출과 지역 변수 관리를 담당하며 자동으로 관리된다.
- Heap은 동적 할당을 위한 공간이며 프로그래머의 관리 책임이 크다.
- Stack과 Heap은 메모리 효율성을 위해 서로 반대 방향으로 확장된다.
- 단편화는 내부 단편화와 외부 단편화로 나뉘며, Paging과 Segmentation으로 완화할 수 있다.
- C++에서는 Smart Pointer를 활용해 메모리 누수를 줄이고 자원 관리를 더 안전하게 만들 수 있다.

## 결론 및 학습 성과

이 과제를 통해 C++의 메모리 구조는 단순한 이론이 아니라 성능, 안정성, 오류 발생 가능성과 직접 연결된다는 점을 정리할 수 있었다. 특히 Stack과 Heap의 차이를 이해하면 지역 변수와 동적 할당 객체의 수명을 더 명확히 구분할 수 있고, 메모리 누수나 단편화 문제를 더 구체적으로 설명할 수 있다.
